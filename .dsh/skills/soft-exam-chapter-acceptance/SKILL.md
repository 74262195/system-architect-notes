# 章节联合验收

## 运行时必读

按顺序读取当前 main 上的规则文件（本技能不复述门槛条款）：

1. `AGENTS.md`
2. `prompts/66-章节三轮审查.md`（章节完成门槛与联合验收流程的唯一真源）
3. `prompts/65-教材证据与笔记校验.md`（事实、机制与解释深度的判据）

涉及原子卡被改动时追加 `prompts/10-原子考点卡生成.md`；涉及图表追加 `prompts/40-Mermaid与Obsidian样式修复.md`。

## 执行要点

- 只做**一次联合验收**，不把同一批 Atom 分成三轮反复复述。
- 验收三个维度：范围覆盖（Atom 全集是否 `unmapped = 0`、`partial = 0`）、事实与机制（对照教材与真题证据）、软考可用性（能做题、能复习、可维护）。
- 逐项复查只针对**发现风险项**与**本次改动的 Atom**；未涉及的内容不重复展开。
- 发现的问题必须修复并复查后才能宣称章节完成；仍存在应补正文的占位卡时不得标记完成。
- 记录落盘风格与位置对齐仓库现有验收记录（例如 `00_Inbox/审核中/` 下同类文件），先看同目录既有记录的写法再动手。

## 交付与校验

- 输出一份可追溯验收记录：范围、证据、结论、遗留问题与下一步。
- 在 Vault 根执行 `node scripts/check-vault.mjs`。
- Git 交付按 `AGENTS.md`；除非用户明确要求，不自动 commit / push。
