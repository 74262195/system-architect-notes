# 章节建设与重构

## 运行时必读

按顺序读取当前 main 上的规则文件（本技能不复述条款）：

1. `AGENTS.md`
2. `prompts/00-全局写作规范.md`
3. `prompts/20-章节检查与重构.md`（章节工作流与章节覆盖契约的唯一真源）
4. `prompts/66-章节三轮审查.md`（章节完成门槛与联合验收）

按任务追加：落地原子卡 → `prompts/10-原子考点卡生成.md`；教材证据与解释深度 → `prompts/65-教材证据与笔记校验.md`；正文画图 → `prompts/40-Mermaid与Obsidian样式修复.md`；章节看板 → `prompts/30-Excalidraw章节知识看板.md`。

## 执行要点

- 固定顺序：先读最新适用考试大纲并拆出**大纲原子项全集**与稳定 `Atom ID`，再读当前章节知识库与真实目录；不从“现有目录看起来有什么”反推“应该有什么”。
- 一个批次只推进一个章节，先把该章真实缺口连续补齐，再转下一章；不要跨库零散补卡。
- 保持仓库既有文件命名与短 wikilink 习惯；移动文件后同步更新引用它的 Markdown、Excalidraw 与脚本。
- 仓库目录编号不等于官方教材目录，除非用户明确要求对齐最新教材目录，否则不要顺手重排。
- 占位卡/骨架是章节建设清单，不因优先级低而删除；章节内仍有该补正文时不得宣称完成。

## 交付与校验

- 产出可追溯的覆盖矩阵（`unmapped / partial / covered / link_only`）与本次批次的实际改动清单。
- 在 Vault 根执行 `node scripts/check-vault.mjs`。
- Git 交付按 `AGENTS.md`；除非用户明确要求，不自动 commit / push。
