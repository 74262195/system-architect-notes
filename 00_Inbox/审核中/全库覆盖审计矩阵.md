# 全库覆盖审计矩阵

> [!important] 本表不是“全章已经审核完”的证明
> 本表是全库控制矩阵：把 `[[全库综合知识大纲Atom母表]]` 的官方范围与仓库当前真实承接状态对齐，决定后续是迁移复核、在途收口、章级 Atom 审计，还是新知识域审计。
>
> `covered / partial / unmapped / link_only` 只能由各知识域稳定 Atom 矩阵逐项证明；本表不越权用目录或关键词替代章节覆盖契约。

## 一、反向检查方法（历史方法保留）

控制面继续使用三类证据：

1. **真实目录/文件树**：确认综合知识实际有哪些章节与学习入口；
2. **已有审核、交接和 Atom 矩阵**：只承认当前可追溯的在途/完成证据；
3. **反向关键词检索**：对可靠性、架构演化、未来技术、知识产权、标准化、应用数学、专业英语等主题判断是否已有可复用正文。

检索结果继续按以下边界解释：

- 私有仓库代码搜索存在索引延迟或漏召回，0 结果不能单独证明“绝对没有”；
- 教材原文、提示词、审核报告、索引中出现关键词，不计为独立综合知识正文覆盖；
- 案例/论文素材出现同主题，只能作为复用候选，不能自动替代综合知识主事实源；
- 只有可独立学习正文 + 明确主事实源 + 稳定 Atom 证据，才允许最终标 `covered`。

## 五、8～13 的建章判定门禁

“无同名顶层目录”不等于立即创建目录。每个候选新知识域必须先经过**只审计、不写正文**的范围批次：

1. 回看官方大纲原 PDF，确认章节/子项；
2. 按 `20` 原子化为稳定 Atom；
3. 搜索全库正文，确定已有主事实源、可复用散点和重复风险；
4. 按 `65` 锁主教材解释深度；
5. 按可靠真题确认优先级/做题动作；
6. 决定是否需要新顶层章、哪些 Atom 应 `link_only`、哪些是真 `unmapped`；
7. 完成上述步骤后才允许进入样稿门禁。

特别注意：

- 8 软件可靠性与 7 质量属性、4 软件测试有交叉；
- 9 架构演化与维护与 6.2 ABSD 的“演化”有交叉；
- 10 未来信息技术控制深度，不扩成技术百科；
- 11 标准化与知识产权注意法规/标准版本；
- 12 应用数学以考试动作决定拆卡；
- 13 专业英语优先“术语 + 阅读识别 + 真题词汇链”的轻量入口。

## 六、全库任务类型

全库后续仍只允许从以下五类任务进入：

1. `MIGRATE`：旧完成章节迁移到当前 Atom 规则；
2. `CLOSE`：已有稳定 Atom 矩阵的在途章节清零 `unmapped/partial`；
3. `AUDIT`：有章但没有当前完整覆盖契约，先建立 Atom 矩阵；
4. `NEW-DOMAIN-AUDIT`：8～13 候选缺章先做范围/主事实源审计；
5. `REVIEW-DEBT`：已有新正文但尚未经过独立三轮审核。

不得出现“看目录觉得缺什么就直接写什么”的第六类任务。
