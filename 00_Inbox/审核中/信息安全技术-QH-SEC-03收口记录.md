## 四、实际修改

### 1. [[CSRF跨站请求伪造]]

保留攻击链、Token、SameSite、Origin/Referer 和 XSS 边界，不重写 CSRF 机制；只增强应用安全出口：

- 明确 SQL 注入、XSS、CSRF 分别处理数据库解释、浏览器执行和请求真实性边界；
- 补上“修好一种漏洞 ≠ 已形成完整安全体系”；
- 建立稳定桥：**单点安全技术解决‘某一种攻击怎样防’；安全架构与治理继续解决‘怎样从整体风险出发，让多种控制分层配合、持续生效，并在单点失效后仍有其他防线’**；

## 六、修改后的完整主链

> **保护具体应用通信通道**
> → **但应用仍会错误处理输入/请求**
> → **防数据库解释边界被改变**
> → **防浏览器执行不可信脚本**
> → **防借用户已有身份伪造请求**
> → **但单点控制仍然分散**
> → **治理明确目标、责任、制度和持续运行**
> → **安全架构把控制组织到正确层次**
> → **纵深防御让单点失效后仍有其他防线**

对应技术与主题：

`TLS与HTTPS → SQL注入 → XSS跨站脚本 → CSRF跨站请求伪造 → 信息系统安全为什么需要治理 → 安全架构设计 → 纵深防御`

闭卷边界保持：

- HTTPS ≠ 应用安全；
- SQL 注入 ≠ XSS；
- XSS ≠ CSRF；
- 漏洞修复 ≠ 安全治理；
- 安全治理 ≠ 安全架构；
- 安全架构 ≠ 纵深防御；
- 纵深防御 ≠ 堆安全产品。
