# RC1 阅读理解与软考达标笔记质量计划

## 1. 目标和边界

本计划承接 [[ZB5-FINAL-ACCEPT收口记录-2026-09-24]]，不重新声称尚未完成的 592 篇逐篇深读，也不把过去的 `covered` 当成读者已经学会。目标是让零基础读者沿当前笔记的真实学习顺序，**看懂一个知识点，并能按考试的原题型使用它**。论文和专业英语继续跳过；因此本计划的“达标”只指纳入范围的笔记质量与对应作答准备，不承诺整场考试通过或代替个人练习。

- **读得懂**：标题和开头交代对象、问题、当前卡在模块中的位置；术语先有具体对象，机制在同一例子里走通；下一站自然承接。
- **做得出**：综合知识按完整题干和原选项判断；审核者能从正文指出决定选项的条件与关键干扰项的排除依据。计算题写清题设、单位和中间步骤。不得要求用户无选项背答案或口头解释后才算笔记合格。
- **答得准**：案例分析按原题材料、图表与小问组织答案。原件缺失的小问明确标“仅部分可练/待核”，不由笔记虚构题面或参考答案。
- **事实可靠**：大纲定范围，可靠真题定实际考法，主教材定解释深度；历史资料、回忆版和教学自编例都显式标明身份。

## 2. 审核单位：学习路径与具体卡片

从 [[软考架构设计师索引]] 和真实章节索引进入，不另造平行目录。每批沿一条实际学习路径，核“前置卡 → 当前卡 → 下一卡 → 相应题型”，而非只看单篇长度或栏目数量。先处理三类明确风险：用户点名难懂的卡、ZB5 中已改且属 P0/P1 的卡、来源/图示/案例材料受限的卡。其他卡按学习路径抽查；若同一模块出现两篇同类断点，就扩展检查该模块同类卡，避免漏掉系统性问题。

单篇只记录可复现的阅读断点：**文件与小节 → 首读者缺少的前提或中间步骤 → 大纲/教材/可靠题目依据 → 最小修复 → 修复后复查**。结论限于“通过、局部修复、机制修复、事实待核、合法回链”；已有充分解释的 P2/P3 卡不因短而重写。涉及新 Atom 时回到既有章节矩阵处理 `partial/unmapped`，不以本计划替代覆盖契约。

按真实章节推进，路径至少覆盖下列范围；每条路径选本轮最高风险的主事实源卡、必要相邻卡与对应题型，不把所有旧“通过”卡重新写一遍：

| 路径 | 本轮连接点 |
| --- | --- |
| 计算机系统基础 | 组成原理 → 操作系统 → 网络 → 软件与语言 → 多媒体；重点核首次术语、计算步骤及跨模块前置。 |
| 综合知识中段 | 信息系统 → 信息安全 → 软件工程 → 数据库 → 软件架构设计；重点核从业务需求到技术判断的过渡。 |
| 质量与后续章节 | 质量属性与评估 → 可靠性 → 架构演化 → 未来技术 → 标准/知识产权 → 应用数学；重点核条件、版本口径和题设数据。 |

## 4. 阅读与考试验收尺

一张进入本轮修复的笔记，完成时应满足：

1. **开篇可进入**：没有依赖聊天记录才能理解的对象、缩写或未交代的“上一步”；读者知道本篇要解决什么。
2. **过程可跟随**：动态机制的触发、当前数据、判断、动作与结果在一组例子中能串起来；比较题让方案处理同一条件；公式讲清变量、单位、适用条件。
3. **结论可使用**：综合知识保留选项，用正文判据选对并识别关键干扰项；案例能按题面证据写出对应小问的要点。没有可靠原题时只验教学动作，不编“真题通过”。
4. **边界不误导**：历史口径、简化模型、自编场景与现实/教材事实分开；来源不足就明确待核。
5. **呈现可阅读**：链接有效，公式、表格、图和折叠答案在实际 Obsidian 中可读；只对真实打开过的页面写视觉通过。

这把尺用于**笔记质量**，不以用户一次答题表现直接证明笔记有错。错题先区分知识未学、题干误读、笔记跳步、题源瑕疵，再决定是否修文。
