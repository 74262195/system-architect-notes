## 第二轮已修：真题优先级

### 为什么不能直接沿用旧趋势雷达

仓库的趋势雷达统计的是“软件测试、软件过程、需求工程、OO/UML”等**上位主题**。这些主题整体可以是 P0，但章节规范明确要求：**优先级必须回到原子卡重新判断。**

例如：

- “软件测试”整体持续活跃，不代表 [[AB测试]]、[[测试自动化]]、[[Web链接与表单测试]] 都应 P0；
- “敏捷/过程模型”整体重要，不代表 XP、Scrum、水晶、FDD 四张卡全部 P0/P1；
- “OO/UML”整体活跃，也不能把 OOA、OOD、OOP、ORM 的所有下位机制机械升到同一级。

因此本轮按独立题目标识、当前大纲和教材深度重新判断每张卡。

### 题库可信度边界

- 2009–2018：A 级标准化，可用于可靠历史统计；
- 2019–2022：B 级 first-pass，题号/资料答案连续，已有去重标识，可用于核对直接考法；
- 2023–2026：回忆题池/来源索引，只作趋势信号，不伪装成精确题频。

同一道题同时出现在“试卷、答案、解析”多个文件中，不重复计数。

### 近期直接证据示例

- 2019-H2-综合知识-24/25：需求变更管理；
- 2020-H2-综合知识-24/25：需求基线，以及需求开发与需求管理的衔接；
- 2020-H2-综合知识-39/40：螺旋模型、构件复用模型；
- 2021-H2-综合知识-22：CMMI；
- 2021-H2-综合知识-24/25：需求管理、需求跟踪；
- 2021-H2-综合知识-28：RUP 九类工作流；
- 2021-H2-综合知识-42/43：静态测试、黑盒测试；
- 2022-H2-综合知识-22：增量开发；
- 2022-H2-综合知识-23：CMMI；
- 2022-H2-综合知识-40：白盒覆盖。

这些证据用于确定“题目实际从哪里问”，而不是拿关键词出现次数冒充考频。

## 仍未完全解决

### 1. 范围缺口：以联合覆盖矩阵为准

当前优先修复 [[软件知识域联合覆盖矩阵]] 中的软件工程 `unmapped / partial`。这些问题优先级高于继续润色已经完整的正文。

### 2. P0/P1 正文的真题考法显式化

本轮已经回答“先学什么”，但章节规范还要求：有可追溯真题的卡，正文不能只靠 `priority_reason` 或索引说明考试价值。

后续正文复核重点是逐张检查 P0/P1：

**题干从什么角度问过 → 第一反应是什么 → 正文哪条机制支撑这个判断 → 快速复习卡能否直接用于做题。**

### 3. CMMI 版本数字细节

保持当前保守写法。除非能绑定本考试指定教材版本的明确表述，否则不扩展版本敏感数字。

### 4. 逆向工程 / 形式化方法的深度

两者属于当前大纲范围，但主教材展开有限。维持“考试定位 + 核心机制 + 易混点”的深度，不扩展成专业课程。

## 最终学习主线

**软件工程定位 → 过程模型选择 → 需求工程 → 结构化/面向对象分析设计 → 软件测试 → 净室/CBSE → 软件项目管理**

其中：
- RUP、敏捷是过程方法的扩展；
- CMMI 是过程改进；
- OOA → OOD 后需要接入 UML 建模表达，再进入 OOP；
- 测试先分清分类维度，再学测试层次和场景；
- **学习顺序看知识依赖，复习优先级看拿分价值，两者不能混为一谈；覆盖完成与卡片数量也不能混为一谈。**
