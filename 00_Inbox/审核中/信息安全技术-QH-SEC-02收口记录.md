## 四、实际修改

### 1. [[RBAC基于角色访问控制]]

保留用户—角色—权限、职责分离等既有事实，仅增强访问控制模块出口：

- 明确访问控制解决“谁能对资源做什么”，但不自动保护请求经过的网络路径；
- 补上互联网、内部网段和不同信任域的剩余风险；
- 下一站先进入 [[网络安全-从漏洞威胁到安全措施]]，不再直接跳 [[防火墙]]。

### 2. [[网络安全-从漏洞威胁到安全措施]]

保留“漏洞—威胁—措施”上位框架，但重新挂接到当前学习主线：

- 承接 [[身份认证]] 与 [[访问控制基础]]；
- 明确稳定桥：**认证和访问控制管“谁能操作资源”，网络与通信安全继续管“这些合法或非法请求在通信路径上怎样被控制、检测和保护”**；
- 增加防火墙、IDS/IPS、VPN、TLS/HTTPS 的职责递进；
- 修复原来的下一站回跳 [[安全风险评估]]，改为进入 [[防火墙]]，风险评估降为“上位框架回看”。

### 3. [[防火墙]]

事实内容无需重写，仅做主线接线：

- 上一篇改为网络安全入口；
- 开头补一问“哪些流量允许穿过网络边界/信任域控制点”；
- 保持“仅控制谁能进，不代表进来的流量一定正常 → IDS/IPS”的原有边界。

### 4. [[TLS与HTTPS]]

保留证书、握手、会话密钥和版本边界，只增强网络模块出口：

- 明确 VPN 偏受保护的网络/逻辑通道，TLS/HTTPS 直接保护具体应用连接；
- 增加“HTTPS 安全了，应用为什么仍会被攻击”的最小桥；
- 明确 HTTPS 不能阻止 SQL 注入、XSS、CSRF；
- 同时保留 [[无线网络安全]] 作为网络模块后续，并给出跨模块进入应用安全的物理链接。

四张实质修改的学习正文均设置 `review_status: 待复习`，并更新 `updated: 2026-09-11`。

## 六、修改后的完整主链

> **验证主体是谁**
> → **限制主体能做什么**
> → **但请求还要经过不可信网络**
> → **控制哪些流量能通过**
> → **检测和阻断异常流量**
> → **保护跨不可信网络的通信**
> → **保护具体应用连接**

对应技术：

`身份认证 → 访问控制基础 → DAC / MAC / RBAC → 网络安全入口 → 防火墙 → IDS与IPS → VPN → TLS与HTTPS`

闭卷边界保持：

- 认证 ≠ 授权；
- 授权 ≠ 网络通信安全；
- 防火墙 ≠ IDS/IPS；
- IDS ≠ IPS；
- VPN ≠ TLS；
- HTTPS ≠ 应用安全完成；
- 网络安全 ≠ 只有防火墙。
