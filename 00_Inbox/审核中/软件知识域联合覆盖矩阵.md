# 一、规则闭环与本轮结构原则

当前规则固定为：

> **单篇教学闭环**：承接与定位 → 具体问题 → 大白话直接答案 → 核心机制 → 考试动作 → 收口与下一站。
>
> **章节覆盖闭环**：大纲全集 → Atom → 主事实源 → 正文具体落点 → 教材/真题核验 → 正向反向检查 → `unmapped=0` → `partial=0`。

抽象概念第一次解释默认采用：

> **具体场景/对象 → 发生了什么问题 → 大白话一句话答案 → 正式术语/教材口径 → 考试动作。**

当前额外原则：

1. **考试归属不等于最佳教学位置。** UML 的大纲归属仍在建模语言，但完整教学放在软件工程 OOA/OOD 主线中；
2. **跨章节只能有一个完整主事实源。** 非主事实源只做本地定位 + 有效 wikilink；
3. **Atom ID 不随文件移动重编号。** 文件位置改变不改变稳定 Atom；
4. **生命周期六阶段 ≠ ABSD 六子过程。** 前者回答“架构在哪些软件生命周期阶段持续工作”，后者回答“采用基于架构的软件开发方法时怎样推进”；
5. 架构描述层次必须分清：**ADL 是专门的架构描述语言类别；UML 是通用建模语言；4+1 是多视图组织模型；IEEE 1471-2000 是软件密集型系统架构描述推荐实践/标准语境。**
6. **架构风格先按“主要组织机制”识别。** 数据怎么走、控制怎么走、是否围绕共享数据、是否存在解释执行环境、构件是否靠消息/事件协作，是五类风格的第一层判断；同一分类问题下的固定成员不机械拆成大量碎卡。
7. **架构复用不能退化成“复制代码”。** 05 的主事实源固定回答“经过验证的架构及相关资产怎样被系统化获取、管理、检索、定制和再次使用”；构件基础只链接现有主事实源，DSSA 留给 06。

`ARCH-A020–A025` 虽然是 6 个稳定 Atom，但它们共同回答一个分类判断问题：

> **看到系统结构描述后，主要应该根据什么组织机制判断它属于哪种架构风格？**

`prompts/10` 允许“同一分类问题下的固定成员”保留在同一张卡。因此本批直接把原 `04` 骨架大幅重写为一个比较型主事实源，没有为了原子化机械制造五张低收益碎卡；每个 Atom 仍分别映射到具体标题和段落。

## 9.3 本批核心考试动作

正文不要求读者先背十几个子风格，而是固定先问：

1. **数据是不是按步骤向前加工？** → 数据流；
2. **控制是不是沿调用/服务关系传递？** → 调用-返回；
3. **大家是不是围绕中央共享数据工作？** → 数据中心；
4. **系统是不是先建立解释/规则执行环境？** → 虚拟机；
5. **相对独立构件是不是靠消息/事件协作？** → 独立构件。

再在大类内部根据批处理/管道、仓库/黑板、解释器/规则系统、进程通信/事件系统等题眼细分。

## 9.4 边界与减负

- 真实大型系统可以混合多种风格；考试识别时看题干当前段落最突出的组织机制，不把“五类风格”写成现实世界互斥绝对规则；
- 优缺点只保留会影响识别的部分，没有扩写成架构风格百科；
- 架构风格的完整主事实源只有 04，一张卡承载六个紧密相关 Atom，但每个 Atom 均有明确正文落点；
- `exam_priority: P0` 来自仓库趋势雷达的历史/近年信号，只代表复习优先级，不声称官方权重或精确题频。
