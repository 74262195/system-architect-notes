> [!important] 当前用途

>
> **教学闭环**负责“一张卡是否真正学得懂”；**章节覆盖闭环**负责“该章应该学的是否全部有真实落点”。两者不能互相替代。
>
> 批次 3.1 根据用户实际学习反馈调整了 UML 的**教学主事实源**：官方大纲中的“计算机语言 → 建模语言”归属不变，但完整 UML 正文迁入 `软件工程基础知识/03_分析与设计`；计算机软件与语言只保留归属定位和跳转。

# 一、规则闭环与本轮结构原则

当前规则固定为：

> **单篇教学闭环**：承接与定位 → 具体问题 → 大白话直接答案 → 核心机制 → 考试动作 → 收口与下一站。
>
> **章节覆盖闭环**：大纲全集 → Atom → 主事实源 → 正文具体落点 → 教材/真题核验 → 正向反向检查 → `unmapped=0` → `partial=0`。

抽象概念第一次解释默认采用：

> **具体场景/对象 → 发生了什么问题 → 大白话一句话答案 → 正式术语/教材口径 → 考试动作。**

本轮额外确认：

1. **考试归属不等于最佳教学位置。** 大纲把 UML 放在建模语言下，但完整学习主线可以放在软件工程 OOA/OOD 之后；
2. **跨章节只能有一个完整主事实源。** 计算机软件与语言不再保留第二套 UML 正文；
3. **Atom ID 不随文件移动重编号。** `CS-SW-A014/A015/A016/A019–A022` 仍代表大纲“建模语言”范围，但其主事实源可以登记为软件工程 UML 知识组；
4. UML 层级固定为：`UML → 基本构造块（事物 + 关系） / 图 / 公用机制`；四类事物、四种关系、13 种图分别是下位分类；五种视图是观察角度，不是第四个组成部分。

# 二、状态定义与当前统计

## 2.1 状态定义

- `covered`：主事实源已有可独立阅读的真实正文，并达到当前 Atom 的最小考试闭环；
- `partial`：已有实质正文，但缺必要机制、边界、辨析、考试动作或跨章承接；
- `unmapped`：没有实质正文落点，或只有一句提及/骨架/TODO；
- `link_only`：当前章节不是主事实源，本地完成最小定位后链接到另章已经 `covered` 的唯一主事实源。

## 7.3 UML 层级修正

当前 [[UML总览]] 只先建立一棵主树：

> **UML 三大组成 = 基本构造块 + 图 + 公用机制**  
> **基本构造块 = 事物 + 关系**

所有容易混的词都放回这棵树：

| 术语 | 正确层级 |
| --- | --- |
| 四类事物 | `基本构造块 → 事物 → 结构/行为/分组/注释` |
| 四种基本关系 | `基本构造块 → 关系 → 依赖/关联/泛化/实现` |
| 13 种图 | `UML → 图 → 具体图类型` |
| 五种视图 | “从哪个角度看同一个系统”，**不属于三大组成中的第四项** |
| 图 vs 视图 | 图是画出来的一张具体图；视图是观察系统的关注角度 |

这样不再把“组成、事物、关系、图、视图”当成五套平级分类。
