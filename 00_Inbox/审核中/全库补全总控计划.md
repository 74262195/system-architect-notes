# 全库补全总控计划

> [!important] 本文件的角色
> `[[全库综合知识大纲Atom母表]]` 定全局范围 → `[[全库覆盖审计矩阵]]` 定处置类型 → 本文件定批次、门禁、并发协议和停点 → 各知识域稳定 Atom 矩阵定具体正文任务 → 独立三轮审核决定是否完成。

## 一、总目标

最终建立可追溯链：

> **官方大纲 → 稳定 Atom → 唯一主事实源 → 零基础教学正文 → 真题/考试动作 → 案例分析 → 论文素材 → 真题反向验收**

全库完成条件保持不变：

- 大纲范围无漏项；
- 所有保留 Atom 最终只允许 `covered / 合法 link_only`；
- `unmapped = 0`、`partial = 0`；
- 假覆盖与重复主事实源冲突为 0；
- P0/P1/P2 有可独立学习正文；
- 三轮独立审核完成；
- 索引、学习路线、正文、优先级、矩阵一致；
- 真题能够反向落到稳定 Atom 与主事实源。

## 二、并发仓库协议

每个批次必须：

1. 写入前重新获取远端最新 `main`；
2. 读取最新 `AGENTS.md` 与任务路由 prompts；
3. 读取本计划、全库矩阵、本知识域矩阵/交接；
4. 若其他会话已经推进 `main`，以新 HEAD 为父提交重新读取受影响文件并合并；
5. 不覆盖其他在途任务线，不 force push；
6. 一个逻辑批次原则上只形成一个可追溯提交；
7. 工具支持时执行 `node scripts/check-vault.mjs` 与 `git diff --check`；不支持时必须明确记录“未执行”，禁止写成“通过”。

## 三、正文 95 分启动门禁

新增或大幅重写正文前仍按 100 分门禁：

| 项目 | 分值 |
| --- | ---: |
| 大纲 Atom 与所属范围已确定 | 15 |
| 主教材证据已定位 | 15 |
| 真题证据已核验 | 10 |
| 唯一主事实源已确定 | 10 |
| 当前正文/占位状态已读 | 10 |
| 上一站与下一站已读 | 10 |
| 唯一主问题可一句话表达 | 10 |
| 零基础具体场景可建立 | 10 |
| 考试动作已确定 | 5 |
| 无证据硬阻断 | 5 |
| **合计** | **100；≥95 才可进入正文** |

即使达到 95，只要大纲归属、教材定义、主事实源、Atom 拆分或版本口径存在硬冲突，仍停止正文并登记阻断。

## 四、批次大小与样稿门禁

- P0 复杂机制/计算/体系：默认 1 篇/批；
- 普通 P0/P1：1～2 篇/批；
- P2 简单定位：最多 3 篇/批；
- 跨章节主事实源迁移：1 个知识组/批；
- 章级覆盖审计：1 个知识域/批；
- 三轮审核：1 轮 = 1 个独立批次。

首次进入新知识域，或一次计划新增/大幅重写 3 篇及以上，必须先做 1 篇代表样稿并通过用户门禁，不能用“矩阵已明确”绕过。
