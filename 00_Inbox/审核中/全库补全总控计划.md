# 全库补全总控计划

> [!important] 当前最高原则
> **先保证全大纲有正文 → 再统一提质量。**
>
> 当前第一目标不是继续把已有章节反复打磨，而是先让官方综合知识 01～13 都有真实、可学习、可导航的正文载体。已有章节中的 `partial`、快速复习卡缺口、第三轮审查债务、图示/措辞优化等，若不构成事实错误或主事实源冲突，统一登记为质量债务，不阻塞 08～13 建章。

> [!important] 本文件角色
> 本文件是“补全 GitHub 笔记”的执行控制面，不替代章节知识索引，也不替代知识域 Atom 矩阵。
>
> 固定关系：
>
> `[[全库综合知识大纲Atom母表]]` 定全局范围  
> → `[[全库覆盖审计矩阵]]` 定当前覆盖事实  
> → 本文件定阶段、优先级、并发边界和换聊天节点  
> → 各知识域稳定 Atom/章节蓝图定具体正文任务  
> → 章节联合验收判断 `coverage_complete`  
> → 后续全库质量阶段再判断 `quality_complete`。

## 一、总目标：分两遍完成，而不是前几章反复打磨

最终仍建立可追溯链：

> **官方大纲 → 稳定 Atom → 唯一主事实源 → 零基础教学正文 → 考试动作 → 复习入口 → 案例/论文 → 真题反向验收**

但施工顺序明确拆成两层：

### 第一层：覆盖完成 `coverage_complete`

章节达到以下条件即可转入下一章，不等待最终质量精修：

- 官方/主教材确认的保留范围都有 Atom 去处；
- 所有保留 P0/P1/P2 Atom 都有真实正文或合法 `link_only`，不留“以后再补”的空卡；
- 正文至少形成“承接与定位 → 具体问题 → 直接答案 → 核心机制/边界 → 考试动作 → 收口与下一站”的最小教学闭环；
- P0/P1/P2 只控制讲解深度与复习优先级，不控制有没有正文；
- 每张正文同步具备 20～40 秒快速复习入口；
- 每张正文有有意义的上一站/下一站，章节之间主线不断；
- 没有事实性硬错误、明显主事实源冲突、失效链接或应保留 Atom 无正文。

### 第二层：质量完成 `quality_complete`

待 01～13 全部完成第一层覆盖后，再统一处理：

- `partial` 和历史质量债务；
- 零基础解释深度与措辞；
- Mermaid/Excalidraw 图示质量；
- 易混边界与跨章主事实源；
- 快速复习卡质量；
- 章节导航与跨章学习路线；
- 真题反向覆盖；
- 全库最终联合验收。

**`coverage_complete` 不等于 `quality_complete`。前者允许继续下一章，后者留到统一质量阶段。**

## 三、新章施工方式：覆盖优先，但有最低教学质量门槛

新知识域不再采用“审计一轮 → 样稿一轮 → 等确认 → 多轮正文 → 三轮审核”才出现正文的串行模式。

首次建设统一采用同一批次内闭环：

> **范围锁定 → Atom 全量拆分 → 主事实源/复用判断 → P0/P1/P2 减负分级 → 章节主线设计 → 分批生成正文 → 同步快速复习卡 → 上一站/下一站 → 轻量覆盖验收**

范围、教材和主事实源仍必须核实，但它们是同一建设批次的前置动作，不再单独占用一个“只审计、不建章”的阶段。

如果出现以下硬阻断，才允许暂停对应 Atom：

- 大纲归属有实质争议；
- 主教材关键定义只能依赖不可靠 OCR；
- 两章都可能成为完整主事实源且尚未裁决；
- 版本/法律/标准术语存在实质冲突。

硬阻断只阻塞相关 Atom，不得让整章其他已确认范围停止施工。

## 四、每章必须先形成“章节施工蓝图”

章节蓝图不是独立审计报告，而是建章时立即产出的施工控制表。至少包含：

| 字段 | 要解决的问题 |
| --- | --- |
| 官方/教材范围 | 本章实际需要覆盖哪些二级/三级知识 |
| 稳定 Atom | 哪些问题可独立出题、独立解释 |
| 主事实源 | 新建、复用还是合法 `link_only` |
| 学习主线 | 为什么按这个顺序学 |
| 前置知识 | 需要承接 01～07 的哪些概念 |
| 易混边界 | 最容易与哪些概念混淆 |
| 减负级别 | P0/P1/P2，控制正文深度而非是否生成 |
| 考试动作 | 题干信号与第一步判断/计算动作 |
| 快速复习 | 20～40 秒应召回什么 |
| 上一站/下一站 | 卡内和章间如何连续 |

蓝图完成后立即进入正文，不等待第二轮“确认蓝图正确”才施工；发现问题在本章内修正即可。

## 五、减负规则：不删范围，只控制深度

- **P0：必须真正理解。** 通常保留背景、完整核心机制、典型考试动作、关键边界和必要图示；阅读预算约 5～8 分钟。
- **P1：理解 + 会判断。** 保留定位、主要机制、相邻概念区别、题干入口；阅读预算约 3～5 分钟。
- **P2：识别 + 不混淆。** 至少有一句定位、一个典型场景/作用、一个关键区别、一个考试识别信号；阅读预算约 2～3 分钟。

不得把“减负”解释成删除大纲有效知识点，也不得把 P2 变成空占位。

## 六、零基础正文最低闭环

每张新正文默认按理解顺序完成：

> **承接与定位 → 具体场景/问题 → 大白话直接答案 → 正式术语 → 核心机制/关系 → 易混边界 → 考试动作 → 快速复习 → 下一站**

这不是要求机械创建固定标题，而是要求读者不自行补桥。

硬要求：

- 标题能看出知识对象与核心问题；
- 抽象术语前先让读者看到具体对象/问题；
- 标题提出问题后尽快直接回答；
- 动态机制优先使用正式 Mermaid 图，不用 ASCII/TXT 图；
- 一篇只解决一个主问题；
- 不把教材目录机械复制成正文目录；
- 不为了“完整”扩成百科全书。

## 七、主线穿插与下一站

### 卡片级

上一站不能只写文件名，要说明关系：

- 上一站解决了什么；
- 当前为什么自然出现；
- 本篇解决后还剩什么问题；
- 因此下一站为什么出现。

### 章节级

08～13 的总主线暂定为：

> **07 系统质量属性与架构评估：架构到底好不好？**  
> → **08 软件可靠性技术：系统怎样尽量少失败？**  
> → **09 软件架构的演化和维护：系统长期变化时，架构怎样保持健康？**  
> → **10 未来信息综合技术：新技术环境会带来哪些新的系统形态？**  
> → **11 标准化与知识产权：技术系统还受哪些标准、法律和权利边界约束？**  
> → **12 应用数学：需要定量分析和决策时，用什么数学工具？**  
> → **13 专业英语：如何识别已经学过的架构知识的英文表达？**

第 13 章优先做“英文表达 → 已学中文 Atom”的反向映射，不再重复造一套完整知识正文。

## 八、快速复习卡：随正文同步生成

不再允许“正文先写完，复习卡以后补”。每张首次建设正文同步生成 20～40 秒快速复习入口，默认只保留：

- 核心结论；
- 题干信号；
- 第一动作；
- 1～2 个关键易错边界。

快速复习卡不是第二篇正文，不重复长解释、长案例和大段定义。
