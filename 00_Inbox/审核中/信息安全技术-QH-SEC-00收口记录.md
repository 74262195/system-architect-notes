## 二、本轮实际修改

### 1. 新增零基础开篇

新增：

`01_综合知识/03_信息安全技术/00_信息安全技术开篇：系统建好了，为什么还不够.md`

使用“网上办事系统”贯穿用户、账号、材料、审批结果、数据库、服务器和网络，从“系统会做业务”自然进入“系统还要在攻击、误用和故障面前保护资产并持续提供业务”。

建立全章核心因果链：

> **资产 → 威胁 → 脆弱性 → 攻击 → 风险 → 安全目标 → 安全机制 → 剩余风险**

同时建立技术递进链：

> **保护数据 → 管住身份与权限 → 保护通信路径 → 防应用攻击 → 把零散控制组成安全体系**

开篇只负责章节心智地图和教学桥，不复制后续原子卡的算法、协议和产品正文。

### 2. 重构学习路线入口，但保留“五站”

修改：

`01_综合知识/03_信息安全技术/学习路线.md`

调整后的第一次学习顺序为：

`开篇 → 信息安全基本目标 → 信息安全范围与保护对象 → 安全风险评估 → 密码学与 PKI → 身份认证与访问控制 → 网络与通信安全 → 应用安全与攻击防护 → 安全架构与治理`

原有第 1～5 站仍保留；新增的是每站之间的因果桥：上一站解决了什么、现在还缺什么、为什么必须继续。

`信息系统安全为什么需要治理` 不再挡在风险评估之前，而是后移到第 5 站：用户已经理解“风险 + 技术控制”以后，再回答“为什么一堆零散控制仍不等于安全体系”。

## 四、统一教学模板

后续信息安全质量增强继续使用：

> **承接：为什么现在学这个 → 当前问题 → 直接答案 → 核心机制 → 易混边界 → 考试动作 → 已解决什么 → 还留下什么问题 → 下一站**

核心验收问题不是“这一篇够不够长”，而是：

- 读者进入前能否回答“为什么现在必须学它”；
- 读完后能否回答“它解决了什么，但为什么还不能停”。

## 六、验收结论

入口层现在能让零基础读者从已学过的系统建设知识继续回答：

1. 为什么“系统能运行”不等于“系统能安全运行”；
2. 资产、威胁、脆弱性、攻击和风险怎样连起来；
3. CIA 等安全目标为什么从资产可能遭受的伤害中出现；
4. 为什么先需要密码学；
5. 为什么加密以后仍要认证和访问控制；
6. 为什么身份权限之后仍要保护网络与通信路径；
7. 为什么网络边界安全以后还要处理 SQL 注入、XSS、CSRF 等应用安全；
8. 为什么最后还需要安全架构、纵深防御、等保和治理。

本轮验收结论：

> **`QH-SEC-00 = PASS / teaching_entry_closed / coverage_unchanged`**

03 原有 coverage 状态继续保持通过，没有新增第二套重复正文，也没有破坏既有 stable Atom 主事实源。
