## 一、为什么旧“第三轮通过”后还要做这一轮

旧 SW-09C-SE 已经证明本章大部分正文**事实正确、能用于做题**，但本次用户学习反馈暴露出更高一级的问题：

> 单篇正确，不等于零基础学习链连续。

新的样例 [[软件工程的定位]] 不只回答定义，还明确建立：

1. 当前知识在整章中的层级；
2. 为什么现在要学这个；
3. 一个具体问题和大白话直接答案；
4. 正式概念与机制；
5. 与相邻概念的边界；
6. 题干出现后第一步怎么判断；
7. 上一站解决了什么；
8. 下一站为什么自然出现。

因此本轮的目标是把整章从“**一组正确考点卡**”提升到“**一条零基础能顺着学下去的知识链**”。

## 二、本次样例门槛

后续正文不机械复制 [[软件工程的定位]] 的栏目，但至少满足下面八项。

| 检查项 | 通过标准 |
| --- | --- |
| 1. 承接定位 | 开头能说明上一站已经解决什么、当前卡处于哪一层 |

## 五、固定学习主链

### A. 软件过程

`软件工程定位 → 瀑布 → 迭代/增量 → 螺旋 → 原型 → 构件组装 → RUP → 敏捷方法 → CMMI`

这一段要让读者看到“过程模型为什么一个接一个出现”：

- 瀑布：先建立最基础的阶段顺序基线；
- 迭代/增量：解决反馈太晚、可用成果出现太晚；
- 螺旋：在迭代基础上突出“每轮围绕风险”；
- 原型：需求本身说不清时，先做可交互样品帮助澄清；
- 构件组装：已有成熟构件时，不必全部从头开发；
- RUP：把迭代增量、用例和架构组织成更完整的过程框架；
- 敏捷：进一步强调短周期、持续反馈与团队协作；
- CMMI：视角从“一个项目怎么开发”切换到“组织的软件过程能力怎样成熟”。

### B. 需求工程

`需求层次 → 需求开发/管理总览 → 获取 → 规格与确认验证 → 变更控制 → 双向追踪`

重点建立两条线：
- 把需求弄清楚；
- 把已经形成的需求长期管住。

### C. 分析与设计

`结构化方法总览 → DFD/数据字典 → 模块设计（信息隐藏/内聚/耦合）→ 详细设计工具 → 面向对象总览 → OOA → OOD → UML → 实体/边界/控制 → OOP → 持久化 → 逆向工程/形式化方法`

重点防止把“分析方法、设计阶段、UML 表达语言、编程实现”混成同一层。

### D. 软件测试

先按**分类维度**建立坐标，再学具体技术：

`是否运行：静态/动态 → 是否利用内部结构：黑/白/灰 → 黑盒用例/白盒覆盖 → V&V → 测试层次 → 性能/回归/Alpha Beta/A-B/自动化`

任何后续卡都必须说明自己属于“分类维度、测试技术、测试层次、测试目的、测试场景”中的哪一层。

### E. 净室 / CBSE / 项目管理

- 净室：`净室整体思想 → 盒子结构`
- CBSE：`构件模型与容器 → CBSE过程 → 组装方式 → 接口适配`
- 项目管理：`管理范围 → WBS → 活动依赖/进度 → 配置管理 → 版本/基线 → SQA → 风险管理`
