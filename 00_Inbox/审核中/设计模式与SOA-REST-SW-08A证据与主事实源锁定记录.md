## 八、易混淆点与后续正文约束

若未来证据门禁通过，后续专用执行规格至少必须显式解决：

### 设计模式候选卡

1. 设计模式 vs 架构风格：不能把不同抽象层级的问题解决方案混成同义词；
2. 设计模式 vs 框架：不能把可复用设计思想与可直接承载代码/控制反转的实现骨架混成同一概念；
3. “目录存在” vs “稳定考点”：有骨架不等于已经进入大纲 Atom；
4. 教学扩展 vs 考试主干：扩展卡必须有明显边界标识。

### SOA/REST 候选卡

1. SOA 与 REST 不能未经教材核验就写成同一种架构风格；
2. “服务”与“资源”应按各自主问题解释，不能只堆术语；
3. Web 架构、SOA、REST 的教材归属要先锁定，避免跨章节制造第二主源；
4. 任何具体原则、约束、特征数量必须来自可复核证据，不凭记忆列固定表。
