# 章节建设推进计划

> [!important] 当前推进原则
> **先保证全大纲有正文 → 再统一提质量。**
>
> 本文件从“逐章慢审查队列”切换为“全大纲覆盖优先队列”。当前不再让数据库、SW-09C/D、历史快速复习卡债务或 01～07 深审阻塞 08～13 建章。

## 一、当前工作节奏

每个新知识域优先在同一建设任务内完成：

> **范围锁定 → Atom 拆分 → 主事实源/复用判定 → P0/P1/P2 减负 → 章节主线 → 正文 → 快速复习卡 → 上一站/下一站 → 轻量覆盖验收**

不再为新知识域单独排一个“只审计、不生成正文”的长批次。

章节达到 `coverage_complete` 后即可进入下一章；最终阅读性、图示、历史质量债务、第三轮审查等统一放到后续 `QUALITY-HARDENING`。

## 二、coverage_complete 最低门槛

一个章节首次建设结束时至少满足：

1. 大纲/主教材保留范围都有 Atom 去处；
2. P0/P1/P2 均有真实正文或合法 `link_only`，不得保留应写正文的空卡；
3. P0/P1/P2 只控制深度，不控制是否生成；
4. 每张正文面向零基础，至少能完成“为什么学 → 是什么 → 怎么工作/关键关系 → 易混边界 → 考试动作”；
5. 每张正文同步生成 20～40 秒快速复习入口；
6. 每张正文有有意义的上一站/下一站；
7. 章节有一条能解释学习顺序的主线；
8. 没有明显事实错误、主事实源冲突、失效链接或大纲有效知识无正文。

通过以上门槛标记为 `coverage_complete / quality_pending`，立即转入下一章。

## 三、减负口径

- **P0：必须真正理解**——背景、核心机制、典型考试动作、关键边界，通常 5～8 分钟；
- **P1：理解 + 会判断**——定位、主要机制、主要区别、题干入口，通常 3～5 分钟；
- **P2：识别 + 不混淆**——一句定位、一个作用/场景、一个关键区别、一个考试识别信号，通常 2～3 分钟。

减负不等于删大纲，也不等于把 P2 留成占位卡。

## 四、零基础正文与主线

正文优先按以下理解顺序组织，而不是机械套固定栏目：

> **承接与定位 → 具体问题 → 大白话直接答案 → 正式术语 → 核心机制/关系 → 易混边界 → 考试动作 → 快速复习 → 下一站**

要求：

- 抽象术语前先给具体对象或问题；
- 标题提出问题后尽快直接回答；
- 一篇一个主问题；
- 动态过程需要图时优先 Mermaid，不使用 ASCII/TXT 图；
- 不扩成百科全书；
- 上一站/下一站必须说明关系，不只写文件名。

08～13 章节主线暂定：

> **07 架构到底好不好？**  
> → **08 系统怎样尽量少失败？**  
> → **09 系统长期变化时架构怎样保持健康？**  
> → **10 新技术环境会带来哪些系统形态？**  
> → **11 技术系统受哪些标准、法律和权利边界约束？**  
> → **12 定量分析和决策时使用什么数学工具？**  
> → **13 如何识别已经学过知识的英文表达？**

## 五、快速复习卡同步生成

每张新正文必须同步具备 20～40 秒快速复习入口，只保留：

- 核心结论；
- 题干信号；
- 第一动作；
- 1～2 个关键易错边界。

不得把快速复习卡写成第二篇长正文，也不得留到以后统一补。

## 九、每次运行的决策规则

1. 先获取远端最新 `main`，不能机械沿用历史 SHA；
2. 读取最新 `AGENTS.md` 和任务路由 prompts；
3. 读取 [[全库补全总控计划]]、[[全库综合知识大纲Atom母表]]、目标章节真实目录和必要相邻正文；
4. 先形成本章“章节施工蓝图”，但不把它拆成单独的审计批次；
5. 蓝图完成后立即进入正文建设；
6. 新正文同步生成快速复习卡和上一站/下一站；
7. 发现硬证据阻断时只阻塞相关 Atom，继续处理本章其他确定项；
8. 达到 `coverage_complete` 即转场，不等待 `quality_complete`；
9. 写入前再次确认最新 `main`，并发变化时基于新 HEAD 重建修改；
10. 不 force push；工具支持时运行 `node scripts/check-vault.mjs` 与 `git diff --check`，不支持要明确记录。
