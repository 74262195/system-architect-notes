# Excalidraw 章节知识看板

用于创建或维护系统架构设计师知识库的 Excalidraw 可视化看板。

## 目标

把已经存在的 Markdown 章节知识库转换成**清晰、可点击、低干扰的卡片式视觉入口**。Excalidraw 不是知识结构的唯一事实源，不得脱离 Markdown 章节知识库自行发明章节或考点。

## 执行前必须读取

1. `AGENTS.md`
2. 对应章节知识库 Markdown
3. 当前章节目录及已有原子知识卡
4. 已存在的 Excalidraw / Canvas 看板
5. 需要时读取 `prompts/00-全局写作规范.md`

## 默认布局

- 顶部：章节标题 + 一句话用途。
- 主体：按章节/专题分区排列卡片。
- 每张卡片代表一个**知识块**，不是一个文件预览。
- 卡片内部用 Obsidian wikilink 指向原子笔记。
- 底部可放学习路线、考前速记、错题、高频计算等辅助卡片。
- 默认采用网格/看板布局，不使用树状结构。

## 卡片内容规则

每张卡片通常包含：

1. 简短知识块标题；
2. 2~7 个核心 wikilink；
3. 可选的一行关键词；
4. 不复制原子笔记正文；
5. 不展示 frontmatter；
6. 不把文件名和正文标题重复显示两遍；
7. 链接显示名应简短自然，例如 `[[CPU内部组成-寄存器体系|寄存器体系]]`。

## 视觉规则

- 同一分区使用统一视觉风格。
- 同级卡片尺寸尽量一致。
- 卡片间必须保留足够留白。
- 章节之间通过位置、分区和背景区分，不靠密集连线区分。
- 标题明显大于正文。
- 内容多时增加画布尺寸，不压缩字号，不堆叠文字。
- 不为了“看起来丰富”增加无价值装饰、重复文本或关系线。

## 连线规则

**默认 0 条连线。**

只有用户明确要求关系图，或存在必须强调的少量关系时才允许添加，例如：

- 明确前置依赖；
- 明确因果关系；
- 明确数据/调用流程；
- 高频且重要的跨章节关系。

每条线必须能够用一句话说明其语义；普通学习顺序不得用大量箭头表达。

## 文件规则

- Excalidraw 统一放在 `05_画图素材/Excalidraw/`。
- 总知识库可视化：`系统架构设计师知识库.excalidraw`。
- 章节可视化：`<章节名>知识看板.excalidraw`。
- Markdown 是章节结构与链接的事实源；Excalidraw 只做视觉导航。
- Canvas 可作为兼容或快速编辑入口，但新建视觉首页优先 Excalidraw。
- 保留已有文件时，不因视觉重构随意移动原子笔记。

## 内容校验

完成后检查：

- 卡片内所有 wikilink 对应真实笔记；
- 没有孤立的重要知识块；
- 没有重复卡片；
- 没有文件名/标题双重重复；
- 默认没有无语义连线；
- 看板与章节知识库结构一致；
- 新增/删除知识点后同步更新 Markdown 章节知识库。

## Git 交付

PR 模式下：

1. 在当前任务分支修改；
2. 更新对应 Markdown 章节知识库入口；
3. 必要时同步更新总知识库；
4. 运行仓库校验与 `git diff --check`；
5. 报告 Excalidraw 卡片数量、是否存在连线、修改文件列表。
