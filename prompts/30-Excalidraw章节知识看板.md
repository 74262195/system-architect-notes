# Excalidraw 章节知识看板

用于创建或维护系统架构设计师知识库的 Excalidraw 可视化看板。

## 目标

把已经存在的 Markdown 章节知识库转换成**清晰、可点击、低干扰的卡片式视觉入口**。Excalidraw 不是知识结构的唯一事实源，不得脱离 Markdown 章节知识库自行发明章节或考点。

## 执行前必须读取

1. `AGENTS.md`
2. 对应章节知识库 Markdown
3. 当前章节目录及已有原子知识卡
4. 已存在的 Excalidraw / Canvas 看板
5. 需要时读取 `prompts/00-全局写作规范.md`

## 默认布局

- 顶部：章节标题 + 一句话用途。
- 主体：按章节/专题分区排列卡片。
- 每张大卡片代表一个**知识块**，不是一个文件预览。
- 卡片内部每个知识点必须是**独立的可点击元素**。
- 底部可放学习路线、考前速记、错题、高频计算等辅助卡片。
- 默认采用网格/看板布局，不使用树状结构。

## 链接实现：强制要求

Excalidraw 看板的核心不是“显示 wikilink 文本”，而是**元素本身能够打开 Obsidian 文件**。

每个知识点必须满足：

1. 独立 text 或 shape 元素；
2. 元素的 `link` 属性必须非空；
3. `link` 格式使用 `[[真实笔记路径]]`；
4. 推荐同一行的文字元素与背景点击区域都设置相同 `link`；
5. 显示文字使用简短标题，例如“Cache”“进程调度”，不要显示完整路径；
6. 禁止把 2~7 个 `[[wikilink]]` 仅作为普通文本塞进一个大 text 元素并声称“可点击”；
7. 若一个知识块含多个目标文件，必须拆成多个独立链接元素。

示例：

- 显示：`↗ 寄存器体系`
- 元素 link：`[[01_综合知识/01_计算机基础知识/01_计算机组成与体系结构/CPU内部组成-寄存器体系]]`

官方 Obsidian Excalidraw 插件支持为元素设置 `link` 指向 `[[...]]` 内部链接；生成文件时必须使用这一机制。

## 卡片内容规则

- 简短知识块标题；
- 2~7 个核心可点击知识点；
- 可选一行关键词；
- 不复制原子笔记正文；
- 不展示 frontmatter；
- 不把文件名和正文标题重复显示两遍。

## 视觉规则

- 同一分区使用统一视觉风格。
- 同级卡片尺寸尽量一致。
- 卡片间必须保留足够留白。
- 章节之间通过位置、分区和背景区分，不靠密集连线区分。
- 标题明显大于正文。
- 内容多时增加画布尺寸，不压缩字号，不堆叠文字。
- 不为了“看起来丰富”增加无价值装饰、重复文本或关系线。

## 连线规则

**默认 0 条连线。**

只有用户明确要求关系图，或存在必须强调的少量关系时才允许添加。

## 文件规则

- Excalidraw 统一放在 `05_画图素材/Excalidraw/`。
- 总知识库可视化：`系统架构设计师知识库.excalidraw`。
- 章节可视化：`<章节名>知识看板.excalidraw`。
- Markdown 是章节结构与链接的事实源；Excalidraw 只做视觉导航。
- Canvas 可作为兼容或快速编辑入口，但新建视觉首页优先 Excalidraw。

## 内容校验

完成后必须检查：

- 所有 `element.link` 指向真实文件；
- 知识点独立可点击，不依赖“大文本块中包含多个 wikilink”；
- 链接元素数量与看板内可点击入口数量相符；
- 没有孤立的重要知识块；
- 没有重复卡片；
- 没有文件名/标题双重重复；
- 默认没有无语义连线；
- 看板与章节知识库结构一致。

## Git 交付

PR 模式下：

1. 在当前任务分支修改；
2. 更新对应 Markdown 章节知识库入口；
3. 必要时同步更新总知识库；
4. 运行仓库校验与 `git diff --check`；
5. 报告 Excalidraw 元素总数、非空 link 元素数、是否存在连线、修改文件列表。
