# Excalidraw 章节知识看板

用于创建或维护系统架构设计师知识库的 Excalidraw 可视化看板。

## 核心原则

1. **先看真实目录，再画看板。**
2. Markdown 章节知识库是事实源，Excalidraw 只做视觉导航。
3. 若章节目录下有多个子目录，先建立目录总览，再按子目录一对一建立详细看板。
4. 不把整章所有原子知识点塞进一张超宽画布。
5. 每个知识点只保留一个真实 Excalidraw 链接。

## 执行前必须读取

- `AGENTS.md`
- 对应章节知识库 Markdown
- 当前章节目录和直接子目录
- 每个子目录中的实际文件列表
- 已存在的 Excalidraw / Canvas 看板

## 目录映射规则

例如计算机系统基础目录实际为：

- `01_计算机组成与体系结构/`
- `02_操作系统/`
- `03_计算机网络/`
- `04_计算机软件与语言/`
- `05_多媒体/`

则可视化必须对应：

- 一张“计算机系统基础知识看板”作为 5 目录总览；
- 五张详细看板分别对应上述五个目录。

不得在总览层自行改成“CPU / 存储 / 网络 / 复习”等与真实一级目录不一致的主导航。

## 紧凑卡片规则

- 总览卡片建议 3 列或 2~3 列布局。
- 默认单卡宽度约 380~460，不使用 700~1000 的无必要大宽卡。
- 详细看板内部再按知识块分组，例如“数据表示与编码”“CPU 与指令系统”。
- 一个知识块通常 2~7 个知识点。
- 内容多时增加行数，不无限增加卡片宽度。
- 保持足够留白，但避免大片空白画布。

## 链接实现：强制要求

- 每个知识点必须有独立的标题 text 元素。
- **标题 text 元素的 `link`** 使用 `[[真实笔记路径]]`，背景 shape 的 `link` 必须为空。
- 显示文字保持简短，例如“Cache”“进程调度”，不再额外显示 `↗`。
- **同一个目标只设置一个 link**，默认就是标题文字本身。
- 禁止背景和文字同时绑定同一目标，否则会出现两个链接图标。
- 看板保存 `appState.viewModeEnabled: true`。查看模式下直接单击标题跳转；编辑模式下使用 `Cmd/Ctrl + 单击标题`。
- 禁止把多个 `[[wikilink]]` 作为普通大文本替代真实元素链接。

## 连线

默认 0 条。只有明确的流程、依赖、因果关系才添加。

## 校验

完成后检查：

- 总览层与真实直接子目录一一对应；
- 详细看板只引用对应子目录内文件（返回按钮等导航除外）；
- 每个知识点只有一个链接元素；
- `unique target` 数量与知识点入口数量一致；
- 所有导航链接都绑定在标题 text 元素上，背景 shape 无 link；
- 没有背景+文字重复链接；
- 没有大面积无效宽卡；
- 没有无语义连线；
- 所有目标文件真实存在。

## Git 交付

PR 模式下完成修改、校验、提交并合并；报告新增看板、链接数量和目录映射结果。
