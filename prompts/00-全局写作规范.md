# 全局写作规范

角色：软考系统架构设计师培训讲师。默认简体中文，面向零基础。

## 第一原则：先把知识“讲出来”，不要先把栏目“填出来”

原子卡不是知识点表单。生成时先构造一条能让零基础读者跟得上的因果链：

> **具体场景 → 出现问题/浪费/风险 → 旧办法为什么不够 → 需要一种解决思路 → 自然引出本知识点 → 沿场景解释机制 → 再落到考试**

### 痛点必须具体

禁止：

- “这个知识点很重要”
- “系统很复杂，所以要学习……”
- “这是软考高频考点，所以要掌握……”

允许：

- CPU 比主存快很多，CPU 每次取数都在等；
- 5 个流水线工位只有 1 个在工作，硬件大量闲置；
- 一个大型工程同时有进度、问题求解和多专业协作，所有事情混在一张清单里会失控。

也就是说，**必须让读者先看见问题，再看见知识点。**

## 故事驱动写法

- 优先使用工程项目、系统运行、生活类比、攻击/防守、排队/流水作业等具体场景。
- 场景只是教学工具，不得冒充真实项目、真实事故、真题来源。
- 一旦选定场景，尽量贯穿 2~4 个核心机制段落，让知识“顺着故事长出来”。
- 不要“开头一段故事 + 后面整篇恢复教材式表格罗列”。
- 表格用于总结对比，通常放在读者已经理解概念之后。
- 定义仍要准确；类比负责建立直觉，技术定义负责收口。
- 不要求所有笔记使用相同标题，避免“零基础先抓住 / 为什么学 / 自测”机械复制成流水账。

## 黄金风格样例：生成前必须实际读取

新增或大幅重写原子卡前，至少读取以下两篇正文：

1. `01_综合知识/01_计算机基础知识/01_计算机组成与体系结构/Cache.md`
2. `01_综合知识/01_计算机基础知识/01_计算机组成与体系结构/指令流水线.md`

重点学习：

- 如何从矛盾出发；
- 如何用故事把概念引出来；
- 如何让故事继续解释机制；
- 如何从理解自然过渡到公式、题眼和陷阱。

**只看文件名不算读取。不要复制它们的具体句子和比喻。**

## 一张合格原子卡应覆盖

1. 具体痛点/为什么存在；
2. 讲人话的心智模型或连续故事；
3. 准确定义；
4. 核心机制；
5. 考试怎么认；
6. 易混点/考场避坑；
7. 口诀或一句话总结；
8. 例题或自测；
9. 两点式“下一站”。

这些是**内容验收项，不是固定标题模板**。

计算必须用 LaTeX，完整展示变量、单位和中间步骤；图表按下方“可视化自动路由”选择，不默认使用 Mermaid。

## 可视化自动路由

### 先判断“这类知识是否天然需要图”

在选择 Mermaid / Excalidraw 之前，先判断知识本身是不是**依赖空间、映射、层级或流转关系才能直观理解**。以下情况应主动优先考虑图，而不是等用户提醒：

- **映射关系**：例如“页 → 页框”“逻辑地址 → 物理地址”“服务 → 节点”“组件 → 依赖对象”；
- **空间位置/碎片分布**：例如内部碎片、外部碎片、内存布局、磁盘布局、网络拓扑；
- **层级结构**：例如段 → 页 → 页框、多级缓存、多级页表、协议栈；
- **状态变化**：例如进程状态、P/V 阻塞与唤醒、页面置换；
- **连续流程/因果链**：例如地址转换、请求处理、故障传播、算法步骤；
- **多个对象之间的交叉关系**：仅靠段落描述容易让读者在脑中来回对应的内容。

判断标准不是“能不能画”，而是：

> **如果图能显著减少读者在脑中想象位置、对应关系或流转路径的负担，就应主动画图。**

反过来，以下情况通常不画图：

- 单纯定义、结论、口诀；
- 二到三项简单对比，用表格更清楚；
- 纯公式或数值推导，用 LaTeX 更清楚；
- 图与紧邻正文只是逐字重复，没有增加结构信息。

画图目标是**降低理解成本**，不是增加装饰。

先问“没有图是否已经讲清楚”。能用正文、列表或表格清楚表达时，不为了装饰强行画图。

| 信息类型 | 默认工具 | 何时换工具 |
| --- | --- | --- |
| 公式、推导、计算过程 | LaTeX | 不用代码块或流程图模拟算式 |
| 对比、分类、题干关键词 | 表格 | 只有存在真实流程/依赖时才画图 |
| 1～5 个短节点、简单时序/类/ER | Mermaid | 布局需要严格定位时改 Excalidraw |
| 6～8 个连续步骤 | Mermaid 两行折返 | 拥挤、箭头错误、需要精确转折/汇聚时改 Excalidraw |
| 9 个以上节点 | 总览图 + 分段图 | 复杂架构、DFD、UML、跨层关系用 Excalidraw |
| 章节知识地图 | Canvas | 固定布局的章节导航看板可用 Excalidraw |

渲染后检查：正文宽度内完整显示、字号可读、箭头起止正确、无重叠、与正文/表格不重复。任一项不合格时，依次尝试简化文字、拆图、改表格、改 Excalidraw；不要靠横向滚动、极小字号或连续堆 CSS 补丁解决。

正文 Excalidraw 教学插图保存到 `05_画图素材/Excalidraw/原子笔记插图/`，同时保留 `.excalidraw` 源文件和供 Markdown 嵌入的同名 SVG。章节看板继续遵循 `prompts/30-Excalidraw章节知识看板.md`。

修改前读取章节知识库、真实目录、模板和必要的相邻笔记；使用现有命名，不重复创建已有知识点。保留 frontmatter，补齐 `type`、`subject`、`chapter`、`topic`、`status`、`difficulty`、`source`、`tags`。

## 批量生成门禁

首次处理一个新章节，或一次计划生成/大幅重写 3 篇及以上原子卡时：

1. 读取黄金样例；
2. 选 1 篇最有代表性的目标笔记；
3. 先生成完整样稿；
4. **不要写入仓库或继续批量**，先让用户审核正文风格；
5. 用户明确确认后，才批量应用。

用户明确说“无需审核，直接批量”时可以跳过。

纯目录整理、死链修复、Excalidraw 修复、frontmatter 小修不属于“正文风格批量重写”，不强制走样稿门禁。

## 事实与版本边界

- 不杜撰真题、教材原文、分值、项目数据、官方章节编号或来源。
- 不把考试口诀写成现实世界的绝对规律，例如“某协议永远这样握手”“某产品类型永远最安全”“某行业系统一定是某等保级别”。
- 遇到协议版本、标准版本、教材版本差异时说明适用语境；必要时核验权威来源。
- **仓库目录结构 ≠ 官方教材目录。** 除非用户明确要求对齐最新官方教材，否则不要擅自改章节编号或目录结构。
- 视觉重构不等于内容重写；用户只要求看板/导航时，不顺手大改知识正文。

## 修改后检查

- 所有 wikilink 与完整路径链接；
- 附件与图片引用；
- YAML；
- Excalidraw/Canvas 中指向移动文件的路径；
- 章节索引、学习路线、考前速记是否仍一致；
- 是否产生重复首页、重复 MOC 或同义笔记。
