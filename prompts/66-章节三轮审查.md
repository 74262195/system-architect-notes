# 章节三轮审查

用于任何“整章生成、整章补全、整章重构、章节是否完成”的任务。目标不是把同一批文字重复看三次，而是用三个不同问题分别验收。

## 一、章节完成硬门槛

只有同时满足以下条件，才允许写“章节完成 / 已审核 / 可进入下一章”：

1. 章节范围内保留的原子卡都有可独立阅读的正文；
2. 至少经过三轮**目的不同**的审查；
3. 每轮发现的问题已经修复并重新检查；
4. 三轮结果有章节级审核报告或等价可追溯记录；
5. 索引、学习路线、优先级和正文状态一致；
6. 仓库结构/链接检查通过。

**P0/P1/P2 只决定复习优先级和讲解深度。P1/P2 不能因为优先级低而长期只有标题或占位说明。**

## 二、第 1 轮：范围与遗漏审查

### 只回答一个问题

**该章应该有的内容是否都被承接，而且是真正文，不是目录幻觉？**

### 固定顺序

1. 读新版考试大纲，确定章节边界和能力要求；
2. 把大纲条目映射到现有原子卡；
3. 检查主教材是否存在大纲条目的必要子机制，而当前笔记完全没有入口；
4. 检查空文件、`待生成`、`占位`、只有一句定义的假完成卡；
5. 检查重复卡、同义卡、错归章节和断掉的导航。

### 通过标准

- 大纲范围无实质遗漏；
- 每个保留的 P0/P1/P2 都有正文；
- “当前不写”的内容必须有明确的越界/重复/版本依据，而不是因为优先级低。

## 三、第 2 轮：概念、机制与边界审查

### 只回答一个问题

**每张卡讲得是否准确，层次有没有混，边界有没有被绝对化？**

### 证据顺序

执行 `prompts/65-教材证据与笔记校验.md`：

**大纲 → 可靠真题 → 官方最新版主教材 → 当前笔记。**

### 至少检查

- 定义是否准确；
- “为什么存在”是否讲清；
- 核心机制/步骤是否缺环；
- 前置概念与当前概念是否混层；
- 条件、例外、版本口径是否被写成绝对规律；
- 公式/计算是否真的需要、变量是否完整；
- 相邻卡之间是否重复或互相矛盾；
- 大纲弱要求内容是否被教材篇幅误抬成重点；
- 旧真题是否越过新版大纲强行扩张章节范围。

### 通过标准

发现的概念、机制和边界问题全部修复；不能用“考试大概不会考”跳过错误。

## 四、第 3 轮：软考可用性与阅读性审查

### 只回答一个问题

**一个零基础学习者读完后，能否定位知识、理解机制，并在题目里认出来？**

### 至少检查

- 每张考点卡先有知识定位，不直接掉进术语/公式；
- 快速复习卡能在 20–40 秒内召回关键结论；
- 有可靠真题证据的卡，正文中能看到“考过什么判断点”；
- 计算题有可执行动作链，不只留公式；
- P1/P2 仍然可读，只是篇幅和复习权重低于 P0；
- 不出现“高频/必考”等无证据标签；
- 学习路线使用知识关系和优先级，不把“第一轮/第二轮”当成正文完成度；
- 上一站/下一站、章节索引和 wikilink 连通；
- 需要图才能避免误解的空间/结构问题，按 `40` 补图，不能用 ASCII 图凑数；
- 文字没有为了覆盖教材而堆成章节摘要。

### 通过标准

章节既能当知识库，也能直接用于软考复习；不是“资料都在，但不知道怎么学”。

## 五、审核报告必须记录什么

至少记录：

- 日期、章节、原子卡数量、P0/P1/P2 分布；
- 使用的大纲/教材/真题证据层级；
- 第 1 轮发现的问题、修复、复查结果；
- 第 2 轮发现的问题、修复、复查结果；
- 第 3 轮发现的问题、修复、复查结果；
- 有争议或暂不纳入的范围边界及理由；
- 最终是否允许标记“章节完成”。

如果某一轮没通过，报告写“未通过/待修复”，不得为了推进学习路线而提前宣布完成。

## 六、优先级与正文深度

减负的正确方式是**不同深度，不是有无正文**：

- **P0 核心掌握**：完整机制 + 做题动作 + 可靠真题判断点 + 易错点；
- **P1 建议掌握**：完整定义/机制 + 主要判断入口 + 必要真题/易混点；
- **P2 了解定位**：至少说明是什么、属于哪里、为什么存在、关键结论、题干如何识别；不扩写低收益细节；
- **P3 暂不复习/扩展**：只有证据明确为低信号或扩展时使用，仍需在索引中说明为何降级。

因此，发现 P1/P2 是空占位时，应补成“短但完整”的正文，而不是直接升优先级或删除。

## 七、与其他提示词的关系

- 原子卡正文怎么写：`10-原子考点卡生成.md`
- 通用语言和公式门禁：`00-全局写作规范.md`
- 章节结构怎么拆：`20-章节检查与重构.md`
- 真题证据怎么去重：`60-历年真题解析与索引.md`
- 教材证据优先级：`65-教材证据与笔记校验.md`
- 图表：`40-Mermaid与Obsidian样式修复.md`

本文件只负责：**三轮分别审什么，以及什么时候才允许说“这一章完成了”。**
