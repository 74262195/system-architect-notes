# 章节联合验收

用于“整章生成、整章补全、整章重构、章节是否完成”的任务。目标是用**一次不重复的联合验收**确认章节可学习、可做题、可维护，而不是把同一批 Atom 分成三轮反复复述。

本文件只负责章节完成门槛与联合验收流程；Atom ID 与覆盖矩阵执行 `20`，教材证据执行 `65`，原子卡正文执行 `10`。

## 一、章节完成门槛

只有同时满足以下条件，才允许标记“章节完成 / 可进入下一章”：

1. 已按 `20` 建立本章大纲 Atom 全集、稳定 Atom ID 与完整覆盖矩阵；
2. `unmapped = 0`、`partial = 0`，每个 Atom 均为可验证的 `covered` 或合法 `link_only`；
3. 范围内保留的 P0、P1、P2 Atom 都有可独立阅读的正文；
4. 不存在假覆盖、重复主事实源、无效 `link_only`、正文孤岛或无法解释的超纲扩写；
5. 当前索引、学习主线、优先级、正文状态与矩阵一致；
6. 一次联合验收记录了发现、修复、复查和最终结论；
7. 仓库结构与链接检查通过。

优先级只决定复习顺序和篇幅，不得把 P1/P2 长期留作空占位。

## 二、一次联合验收：固定顺序

### 1. 覆盖与结构

从矩阵正向检查 `Atom → 主事实源 → 正文具体落点 → 状态`，并从正文反向检查独立教学段是否有 Atom 或明确补充理由。重点处理漏项、目录假覆盖、重复主事实源、胖卡、正文孤岛及失效的跨章链接。

### 2. 事实、机制与边界

按 `65` 的顺序核验：**大纲 → 可靠真题 → 主教材 → 当前正文落点**。只对以下对象逐 Atom 展开证据与结论：

- 本次新增、大幅重写或修复的 Atom；
- 矩阵、相邻正文或可靠证据显示可能有事实、机制、条件或边界风险的 Atom；
- 抽查中发现“covered”实际只有定义、题干动作或必要机制缺失的 Atom。

不得为了凑验收而对无风险、未改动的正文重复抄写同一组定义；但一旦发现问题，必须先退回 `partial`，修复后再复查。

### 3. 软考可用性与阅读性

对本次改动的主事实源，以及高优先级或抽查发现风险的正文，确认六要素实际落点：承接定位、具体问题、直接答案、核心机制、考试动作、收口与下一站。检查快速复习卡是否能召回关键结论，可靠真题的判断点是否已进入正文，链接和导航是否自然有效。

这一步是联合验收的收口，不是对全章无差别再做一次独立审查。

## 三、验收记录与修复

联合验收记录至少保留：

- 日期、章节、Atom 总数及 `covered / link_only / partial / unmapped` 统计；
- 矩阵位置或完整矩阵链接；
- 正向和反向检查结论；
- 本次逐 Atom 核验的对象、证据、正文锚点和结论；
- 发现的问题、修复动作、复查结果；
- 六要素落点（仅本次改动或抽查对象）；
- 索引/学习主线同步情况与仓库校验结果；
- 是否允许标记章节完成，及下一项未生成内容或下一章计划。

没有发现问题时，记录“无风险项抽查范围、证据来源和未做重复改写的理由”即可；不需要另建第二、第三份同义审查报告。

## 四、进入下一章的节奏

章节存在 `unmapped / partial` 时，优先生成或补强真实缺口；不得为了完成验收而连续重复审查已稳定正文。满足本文件第一节门槛后，应进入下一章或下一个明确的未生成 Atom；只有后续编辑、教材证据变化或链接检查发现新风险时，才进行定点复查。

- 原子卡正文、样稿门禁：`10-原子考点卡生成.md`
- 通用教学与写作：`00-全局写作规范.md`
- 章节矩阵、主事实源和重构：`20-章节检查与重构.md`
- 真题资料：`60-历年真题解析与索引.md`
- 教材证据：`65-教材证据与笔记校验.md`
