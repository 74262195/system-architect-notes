# Mermaid 与 Obsidian 样式修复

本文件是仓库**唯一的详细正文可视化规范**，负责“要不要画、选什么工具、怎么排版、怎么验收”。其他提示词只引用本文件，不复制 Mermaid 节点数、Excalidraw 路由或样式参数。

## 硬禁令：不得用 text/plaintext/ASCII 代码块画教学图

以下做法一律视为不合格并必须重构：

- 用 `text`、`plaintext` 或无语言代码块写 `A ↓ B ↓ C`；
- 用 `┌─┐`、`│`、`└─┘` 模拟框图；
- 用 `├─`、`└─`、多级缩进模拟树/层级；
- 用等宽文本拼 inode、索引块、页表、协议栈、网络拓扑、状态流转等结构。

代码块只用于真正的代码、命令、配置、日志、报文等需要等宽保真的内容。

## 一、先判断是否需要图

画图目标是**降低理解成本**，不是装饰。

应主动考虑图：映射关系、空间位置、层级结构、状态变化、连续流程/因果链、多个对象的交叉关系。

通常不画：单纯定义/口诀、简单对比、纯公式推导，以及正文或表格已经清楚表达的内容。

**一图一主要问题。** 两个概念合并后会导致字号变小、画布过宽、节点拥挤或来回找对应关系时，拆成多张图。宁可多一张图，也不要牺牲正文宽度内的可读性。

## 二、工具路由

按“最小可用工具”选择：

| 信息类型 | 默认工具 | 升级/降级条件 |
| --- | --- | --- |
| 公式、推导、计算 | LaTeX | 不用流程图模拟算式 |
| 对比、分类、题干关键词 | 表格 | 有真实流程/空间关系时再画图 |
| 1～5 个短节点、简单时序/类/ER | Mermaid | 需要严格定位时改 Excalidraw |
| 6～8 个连续步骤 | Mermaid 两行折返 | 拥挤、精确转折、多路汇聚时改 Excalidraw |
| 9 个以上节点 | 总览 + 分段 | 复杂架构、DFD、UML、跨层关系用 Excalidraw |
| 章节知识地图 | Canvas | 固定布局导航看板使用 Excalidraw，并执行 `30` |

不要默认“已有 Mermaid 就继续修 Mermaid”。图重复就删；表格更清楚就改表格；Mermaid 太密就拆图或改 Excalidraw。

正文 Excalidraw 教学插图保存到 `05_画图素材/Excalidraw/原子笔记插图/`，保留 `.excalidraw` 源文件并导出同名 SVG 供 Markdown 嵌入。不得混入章节导航看板目录。

## 三、阅读与去重

- 默认以 Obsidian 正文宽度正常字号阅读，不依赖放大、横向滚动或极小字号。
- 相邻位置重复展示同一状态/映射时，保留信息更强的一张；后文引用前图或只画变化动作。
- 优先级：先保证看懂，再保证完整，最后才考虑紧凑。
- 图太密时依次处理：删次要文字 → 拆图 → 调整方向 → 改表格/Excalidraw；不要持续堆 CSS 补丁。
- 对比不等于必须同图；分图讲清后可用一句话或小表格收束。

## 四、Mermaid 流程图规则

- Mermaid SVG 必须适配当前视口宽度，横向滚动不是默认方案。
- 超长节点用 `<br/>`、缩短文字或拆图；横向节点尽量控制在 2～6 个汉字。
- 1～5 个节点使用紧凑 `flowchart LR`。
- 6～8 个连续步骤优先使用 `block-beta` 两行折返：`columns 4`，上排左→右，下排右→左，必要时用 `space` 补位。
- 阶段节点使用圆角矩形；折返箭头必须连接真实节点，不连接虚构的行/容器节点。
- 逐条核对箭头起点、终点、上下排转折和阅读顺序。
- `block-beta` 仍拥挤、箭头压边或无法形成自然留白时，停止补丁，改用 Excalidraw。
- 9 个以上节点拆成“短标签总览 + 分段说明”。
- Mermaid 使用自然尺寸居中；小图不强制拉满整栏。
- 使用 `%%{init: {...}}%%` 时采用浅色 `theme: 'base'` 和高对比 `themeVariables`。

## 五、主题与样式

- 节点背景浅灰/白，边框中灰，节点文字和边标签使用深色。
- 不依赖主题默认白字/黑底；必要时覆盖 `.nodeLabel`、`.edgeLabel`、`.labelBkg`、`foreignObject` 和 SVG `text`。
- 不用颜色作为唯一语义，状态差异同时使用文字或形状。
- 先检查仓库级 CSS 是否用 `width/max-width !important` 错误覆盖 Mermaid 自然尺寸，再考虑单图补丁。

## 六、验收

生成/修改后实际检查：

- 正文宽度内是否完整、正常字号可读；
- 是否需要横向滚动；
- 节点/文字是否重叠；
- 箭头是否指向真实节点、顺序正确；
- 是否与紧邻正文/表格重复；
- 浅色/深色主题、阅读/编辑模式、窄屏是否可读；
- 是否残留 `text/plaintext` 伪图。

失败时重新选表达方式，不以缩小字号或不断追加 CSS 作为最终解决方案。

章节导航看板还必须追加执行 `prompts/30-Excalidraw章节知识看板.md` 的 JSON/link 验收。
