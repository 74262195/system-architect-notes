# 原子考点卡生成

本文件是**原子卡边界、生成流程和验收方式的唯一详细规范**。通用教学语言执行 `prompts/00-全局写作规范.md`；章节覆盖契约执行 `prompts/20-章节检查与重构.md`；教材证据执行 `prompts/65-教材证据与笔记校验.md`；可视化执行 `prompts/40-Mermaid与Obsidian样式修复.md`。

输入：目标知识点、所属章节、章节覆盖矩阵、真实目录、相邻笔记、考试优先级和可靠来源。

## 一、生成前

1. 确认是否已有同名或同义笔记；
2. 若任务属于整章补全、章节重构、覆盖缺口修复或批量生成，先读取 `20` 产生的**章节覆盖矩阵**，确认本卡对应的 `Atom ID`、当前状态、主事实源章节、最小考试闭环和预期动作；不得直接从当前目录或模型印象挑选“应该补什么”；
3. 新卡候选只能来自矩阵中的 `unmapped`，或经原子性判断确实需要拆分的 `partial`。若已有其他章节的 `covered` 主事实源，本章原则上改为 `link_only`，不得重复造完整正文；
4. 若只是单篇独立写作、暂不处于章节建设任务中，也必须明确它承接的大纲/教材范围；后续纳入章节验收时仍需按 `20` 回填 Atom ID 和覆盖矩阵，不能用“单篇已写过”代替章节映射；
5. 读取直接前置和后续笔记，写出“上一站已解决什么、本篇为什么出现、下一站还剩什么”；
6. 用一句话写出本卡的**唯一主问题**；无法概括时先拆卡；
7. 根据卡片类型只读取一篇最相近的参考样例，不要求每次读取全部样例。

### 参考样例

- 概念/比较型：`01_综合知识/01_计算机系统基础知识/01_计算机组成与体系结构/06_体系结构与并行处理/冯·诺依曼结构与哈佛结构.md`
- 机制过程型：`01_综合知识/01_计算机系统基础知识/03_计算机网络/07_应用层/01_名称与地址配置/DNS域名解析.md`
- 计算判断型：`01_综合知识/01_计算机系统基础知识/01_计算机组成与体系结构/01_CPU与指令系统/流水线吞吐率.md`

样例只用于观察“承接 → 问题 → 解释 → 考试 → 下一站”的组织方法，不继承具体比喻、栏目、长度和事实。如果样例路径失效或正文已不符合当前规范，停止模仿并报告；不得仅凭文件名继续生成。

## 二、覆盖与原子性

### 两个层级不能混

- **章节覆盖矩阵**负责保证考试大纲原子项有可验证落点；
- **原子卡**负责让读者理解一个可以独立提问的主问题。

不能因为大纲一节列了很多名词，就把它们塞进一篇；也不能因为一张卡只讲一个问题，就把理解这个问题所必需的背景和同级成员删掉。

### Atom ID 与正文的关系

- 一个正文文件可以承载多个紧密相关的 Atom ID，但每个 Atom ID 都必须回填到正文中的**具体标题、段落或明确锚点**，不能只写文件名；
- 一个 Atom ID 可以因为跨章节承接在多个位置出现，但只能有一个负责完整定义、机制和边界的**主事实源**；其他位置只做本地定位和链接；
- 文件名、目录、frontmatter、tag、alias、一句话定义、TODO、占位卡均不能单独证明 Atom ID 已覆盖；
- 生成或大幅重写完成后，必须回填矩阵中的“正文文件、正文具体落点、覆盖状态、修复动作”；若实际正文仍达不到最小考试闭环，状态只能是 `partial`，不能为了结束任务标 `covered`。

### 默认拆卡

出现以下任一情况时优先拆：

- 多个平级知识点能够被真题分别提问；
- 标题需要用多个“与/及/和”连接不构成天然比较的问题；
- 正文存在多个互不依赖的“为什么、怎么工作、怎么计算”；
- 删除其中一大段后，剩余内容仍是完整考点。

### 可以保留在同一张卡

- 比较本身就是主问题，如 CISC 与 RISC；
- 同一递进体系必须放在一起才能看出层级，如 1NF、2NF、3NF、BCNF；
- 同一分类问题下的固定成员，如 Flynn 四分类；
- 一个计算模型不可分割的连续步骤；
- 索引、复习总纲、考前速记等明确的聚合页。

最终判断：删掉标题后，正文是否始终在回答同一个主问题？

## 三、正文采用最小教学闭环

按 `00` 的五个动作自然展开，并落实“问题后先直接回答”的要求，不机械使用固定标题：

1. **承接与定位**：用 1～3 句话补足最低前提，必要时链接上一站；
2. **具体问题**：先让读者看到为什么需要当前概念；
3. **直接答案 + 讲懂机制**：问题提出后先用一句完整结论回答，再用一个小例子走完核心变化；
4. **考试动作**：给题干信号和第一步判断/计算动作；
5. **收口与衔接**：说明本篇解决了什么，以及下一站为什么出现。

其中只强制“内容存在”，不强制栏目独立。口诀、第二个例子、详细对比表、可视化、自测和历史年份只有在增加独立学习价值时才加入。

### 零基础最低自包含

进入正文前检查：

- 标题中的核心名词是否已经用人话定位；
- 当前机制依赖的前置术语是否已用一句话提醒或链接；
- 是否交代了当前卡在所属模块要解决的总问题中负责哪一部分；
- 是否说明了该技术的主要能力、依赖前提和不解决的边界，而非只给定义；
- 新对象是否在参与动作前出现；
- 对比型主题是否说明双方是什么、处于什么关系、为什么要比较；
- 读者是否需要依靠聊天记录补出前提。

最低自包含不等于重复上一张卡的全部正文。详细前置机制应链接回上一站。

### 篇幅控制

执行 `00` 的阅读时间软预算。超出前依次检查：

1. 是否混入第二个主问题；
2. 是否存在重复定义、重复总结或多组相似例子；
3. 是否把教材完整分类抄成正文，但大纲和真题只需要定位；
4. 是否存在可以链接到其他原子卡的详细前置；
5. 是否有无意义栏目。

不得通过删除背景、关键中间步骤或大纲要求的同级知识来强行缩短。

### 标题验收

生成标题后单独检查：

1. 是否明确写出本卡的知识对象，而不是只写比喻或宣传式表达？
2. 是否指出要解释的问题、动作或比较关系？
3. 零基础读者是否不依赖正文或聊天上下文，也能大致判断本卡在讲什么？
4. 如果标题使用比喻，是否同时保留了真实术语或具体场景？

标题不通过时，先改标题再继续写正文；不要用正文补救一个读者无法理解的标题。

## 四、考试信息怎样进入正文

先按 `65` 确认对应 Atom ID 的大纲、教材和真题证据，再决定保留什么：

- 大纲决定 Atom 是否属于当前范围；
- 主教材决定核心定义、机制、边界和必要同级知识应解释到多深；
- 可靠近年真题决定复习优先级、题干信号和做题动作；
- 旧题只支持理解该题所需的最小历史补充。

有可追溯真题时，正文应说明“考什么判断点、对应怎样做”，不机械逐年列题。年份只有在确实帮助判断趋势且已经核验时才出现。没有可靠证据时不得写“高频、必考、历年常考”。

## 五、快速复习卡片

快速复习卡只用于学完后的召回，不负责首次教学。

新建或大幅重写时，默认放在正文开头并使用折叠形式，保证首次学习者可以跳过它直接阅读正文：

```markdown
> [!summary]- 快速复习卡片（学完再看）
> **作用/定位**：……
> **核心结论**：……
> **题干信号 → 第一反应**：……
> **易错点**：……
```

规则：

- 通常 4～6 行，只保留能决定选项、计算步骤或关键边界的内容；
- 计算题写动作链，不只写公式；
- 非计算题写题干信号和最小区分标准；
- 没有独立价值的字段可以合并；
- 不重复正文背景和完整例子；
- 公式只执行 `00` 的统一门禁，本文件不另设条件。

## 六、自测题与答案

- 自测题默认放在正文末尾；**题干必须是普通展开正文，只有“答案与解析”允许折叠**，避免 Obsidian 的嵌套 callout 把后续题干一起吞进折叠块；
- 禁止把多道题连续放在一个 `> [!question]` 外层 callout 中，再使用 `> > [!answer]-` 二级折叠；这种结构在部分主题/Obsidian 渲染下会出现“后续题干被折叠，只剩答案框”的问题；
- 每道题必须紧跟对应的**一级**默认折叠答案 callout（`> [!answer]-`）；题干与答案一一对应，下一道题必须在前一道答案 callout 结束后重新以普通正文出现；
- 每道题必须有简短解析，答案不能省略或只写“见正文”；
- 题目优先检查主线理解、机制因果和考试判断，不为凑数量添加低价值题；
- 通常保留 2～4 题；简单主题可以更少，复杂主题可以增加，但必须有独立学习价值。

```markdown
## 自测

1. 问题……

> [!answer]- 第 1 题答案与解析
> **答案**：……
> **解析**：……

2. 问题……

> [!answer]- 第 2 题答案与解析
> **答案**：……
> **解析**：……
```

## 七、批量样稿门禁

首次处理一个新章节，或一次计划生成/大幅重写 3 篇及以上原子卡：

1. 样稿候选必须从章节覆盖矩阵中的真实 `unmapped / partial` 缺口选择，不能从当前目录、模型偏好或“顺手想补的主题”中挑选；
2. 选择一篇有代表性的卡；
3. 完成一篇完整样稿；
4. 用下方验收问题检查，并回填该 Atom ID 的正文具体落点和状态；
5. 交用户确认后再批量写入。

用户明确要求无需样稿、直接批量时可跳过。目录整理、死链、frontmatter、纯样式修复和只建立跨章节链接不属于正文批量重写；局部补强若不构成大幅重写也不触发本门禁。**覆盖矩阵已经证明缺口明确，不等于可以绕过样稿门禁。** 若本轮只有一张真正需要新增/大幅重写的卡，就只处理这一张，不为凑批量数量制造第二张卡，也不得跨章节拼凑样稿。

## 八、验收问题

生成后必须能给出具体答案：

1. 本卡对应哪些 Atom ID？它们在矩阵中的原状态和目标状态是什么？
2. 本卡唯一主问题是什么？
3. 它承接哪一站，读者需要知道的最低前提是什么？
4. 具体什么问题促使这个概念出现？紧接问题后的直接答案是什么？
5. 零基础读者能否跟一个例子说清核心机制或层级变化？
6. 大纲要求的必要同级知识是否有落点？
7. 读者看到典型题干后，第一步知道做什么吗？
8. 哪些内容因低收益被删掉，或因已有主事实源而只链接到别处？
9. 下一站解决什么尚未解决的问题？
10. 完成后矩阵中的正文文件、具体落点和覆盖状态是否已回填？

只回答“有、已覆盖、符合”不算验收，必须指出正文中的具体落点。

## 九、落库

- 不复制样例或教材的大段内容，不杜撰真题和来源；
- 同步章节覆盖矩阵、索引和必要的前后主线链接，不新增重复 MOC；
- 若本章不是某知识的主事实源，只保留本地定位 + 有效 wikilink，不重复正文；
- 样稿尚未批准时只输出样稿，不批量写入；
- 批量任务获批后按 `AGENTS.md` 交付，并执行仓库校验。
