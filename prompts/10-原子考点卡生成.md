# 原子考点卡生成

输入：目标知识点、所属章节、章节知识库、真实目录、相邻笔记和可靠来源。

## 生成前

1. 先确认仓库是否已有同名/同义笔记，避免重复卡。
2. 实际读取黄金风格样例：
   - `01_综合知识/01_计算机基础知识/01_计算机组成与体系结构/Cache.md`
   - `01_综合知识/01_计算机基础知识/01_计算机组成与体系结构/指令流水线.md`
3. 再读取目标知识点的前后相邻笔记，确定它在整条学习主线里的“上一集”和“下一集”。
4. 若原材料包含多个可独立成文的平级概念，先拆分，不把多个考点硬塞进一篇。

## 正文生成方法

不要先列标题再填内容。先在脑中完成这条推导：

> **读者遇到什么具体问题？ → 为什么原办法不够？ → 如果你是设计者会想到什么改进？ → 这个改进就是/引出了什么知识点？**

然后按自然叙事写出正文。

要求：

- 开头必须是一个具体矛盾、场景或问题，不得使用“这个知识很重要/常考”充当痛点。
- 一个好场景要尽量贯穿核心机制；不要只在开头装饰性类比一次。
- 技术定义放在读者已经有直觉之后，并保证准确。
- 表格、口诀和考试题眼是**总结工具**，不要成为正文主体。
- 允许根据知识特点调整标题，不机械复制同一套“零基础先抓住”栏目。
- 教学故事可虚构，但要保持常识合理，不能声称是真实项目/事故/真题。

最终内容覆盖：

- 具体痛点/故事；
- 讲人话与准确定义；
- 核心机制；
- 考试怎么认；
- 易混/避坑；
- 口诀或一句话总结；
- 例题/自测；
- 下一站。

若有计算，给公式、变量、完整示例、单位和易错点。涉及流程、结构或对比时，先按下方规则判断是否真的需要图。

## 可视化决策

1. 正文、列表或表格已经清楚时不画图，禁止为了满足模板机械插图。
2. 对比、分类、题干关键词用表格；公式和推导用 LaTeX。
3. 1～5 个短节点、简单时序/类/ER 图优先 Mermaid。
4. 6～8 个连续步骤先尝试 Mermaid 两行折返；需要严格对齐、精确转折、多路汇聚，或实际渲染拥挤时改用 Excalidraw。
5. 9 个以上节点先拆成总览与分段；复杂架构、DFD、UML、跨层关系直接使用 Excalidraw。
6. 章节知识地图使用 Canvas；固定布局的章节导航看板按专用 Excalidraw 看板提示词执行。

完成后必须实际验收：图不能横向滚动，不能靠极小字号适配；箭头必须指向真实节点；图与表格/正文不得重复。失败时按“简化 → 拆分 → 改表格 → 改 Excalidraw”重新选择，不持续追加局部 CSS 补丁。

正文 Excalidraw 教学插图放入 `05_画图素材/Excalidraw/原子笔记插图/`，保存可编辑源文件并导出同名 SVG 嵌入正文。

不复制黄金样例或已有笔记的大段内容，不杜撰真题或来源。

同步章节知识库与相邻主线链接；不要额外创建重复 MOC/首页。

## 批量门禁

如果这是某章节第一次按新风格生成，或计划一次生成/大幅重写 3 篇及以上：

- 先只完成 1 篇代表性样稿；
- 把样稿给用户审核；
- **用户未明确确认前，不写入 GitHub、不继续批量**；
- 用户明确说可直接批量时除外。

## Git

手动样稿模式：只输出正文，不写仓库。

PR 模式：用户已经确认样稿风格后，创建 `ai/<topic>-YYYYMMDD` 分支，写入目标路径，同步索引和相邻链接，运行仓库校验并提交 PR。若用户已有“完成后直接合并 main”的明确约定，校验通过后 squash merge；仍不得绕过 PR 直接写 main。
