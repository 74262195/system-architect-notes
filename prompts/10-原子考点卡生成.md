# 原子考点卡生成

本文件是**原子卡唯一详细规范**。通用教学语言遵守 `prompts/00-全局写作规范.md`；可视化只引用 `prompts/40-Mermaid与Obsidian样式修复.md`，不在这里复制画图规则。

输入：目标知识点、所属章节、章节知识库、真实目录、相邻笔记和可靠来源。

## 一、生成前

1. 确认是否已有同名/同义笔记，避免重复卡。
2. 实际读取两篇黄金样例正文：
   - `01_综合知识/01_计算机系统基础知识/01_计算机组成与体系结构/冯·诺依曼结构与哈佛结构.md`
   - `01_综合知识/01_计算机系统基础知识/01_计算机组成与体系结构/数据表示与编码-定点与浮点.md`
3. 读取目标知识点前后相邻笔记，明确学习主线中的上一站和下一站。
4. 写出本卡准备回答的**唯一主问题**。无法用一句话概括时，先拆卡。

黄金样例只学习叙事方法：具体矛盾 → 直觉 → 机制 → 考试。必须实际读取正文，不得只看文件名，也不得复制具体句子和比喻。

> [!warning] 黄金样例失效规则
> 如果用户明确指出某篇黄金样例存在“公式堆砌、缺少为什么、结构难懂、关系断裂”等教学问题，该笔记立即失去样例资格。本次任务不得继续模仿它，应先更换为已经符合当前规范的样例，再重写目标笔记。

## 二、原子性硬门禁

判断原子性看**主问题数量，不看字数**。

### 默认拆卡

出现以下任一信号时优先拆：

- 多个平级知识点都能被真题单独提问；
- 标题必须用多个“与 / 及 / 和”连接不同机制，而它们不是天然比较对；
- 正文准备出现 3 个以上彼此独立的“为什么 / 怎么工作 / 怎么计算”核心；
- 为了覆盖教材，把不同层次主题塞进一篇；
- 删除其中一个大段后，剩余内容仍能独立成为完整考点卡。

教材章节负责范围，原子卡负责一个问题。知识联系通过章节索引、wikilink、上一站/下一站表达，**连接不等于合并**。

### 可以保留在同一张卡

- 比较本身就是学习目标，如 CISC vs RISC、TCP vs UDP；
- 同一分类问题下的固定成员，如 Flynn 四分类、Cache 映射方式；
- 一个计算模型内部不可分割的连续步骤；
- 明确的聚合型页面，如章节索引、复习总纲、考前速记。

最终验收：**删掉标题后，正文是否始终围绕同一个主问题？** 中途明显换成另一个独立问题就应拆卡。

## 三、知识定位硬门禁

原子卡可以只回答一个主问题，但**不能让读者失去父概念**。面向零基础学习者时，正文进入机制、比较或计算前，必须先完成“知识定位”。

至少回答下面三件事：

1. **它是什么**：用一句人话给核心术语下定义；缩写首次出现时写出中文含义，必要时补英文全称。
2. **它属于哪里**：明确它的上位概念或所在层次，例如“SRAM/DRAM 都属于 RAM”“ROM/Flash 属于非易失性半导体存储”“Cache 位于 CPU 与主存之间”。
3. **为什么现在学它**：说明它与上一站、当前主问题、下一站之间的关系，让读者知道这张卡在整条学习链上的位置。

### 抽象层切换额外要求

如果相邻知识点从“功能概念”切换到“物理实现 / 具体部件 / 数据结构 / 协议报文”等更具体层次，必须先把两层关系说清，不能默认零基础读者知道它们是一回事。

例如从“存储器”进入“存储芯片”时，必须先说明：

- **存储器**是功能层概念：负责保存二进制数据的存储部件；
- **存储芯片**是常见物理实现：把大量存储单元、地址选择和读写接口集成到一颗芯片中；
- 一套实际存储器可以由一颗或多颗存储芯片，再配合译码/控制电路组成；
- 后续“位扩展、字扩展”是在回答“一颗芯片容量或位宽不够时，怎样组合多颗芯片”。

同理，出现“协议 → 报文”“文件系统 → inode”“虚拟内存 → 页表项”“CPU → 寄存器”等层次切换时，也要先补这座桥。

### 对比型标题额外要求

标题出现“A 与 B / A vs B”时，不允许直接进入差异表。必须先分别说明：

- A 是什么；
- B 是什么；
- A、B 是同一层级的两种方案、上下位关系，还是只是在教材语境下常被放在一起比较；
- 比较它们到底要解决什么问题。

例如 `ROM与Flash` 不能只写“断电后都能保存”，而应先说明 ROM 是什么、Flash 是什么、它们在存储体系中的位置，再比较改写方式。

### 原子化边界

“补父概念”不等于把父概念整篇合回来。定位只负责建立坐标，详细机制仍留在对应原子卡。若读者必须先读另一篇才能知道标题里的名词是什么，则这张卡的定位不合格。

## 四、正文组织

按照 `00-全局写作规范.md` 的故事驱动方式自然展开，最终应覆盖：

- 具体矛盾/为什么存在；
- 讲人话的心智模型；
- 准确定义；
- 核心机制；
- 考试怎么认；
- 易混点/避坑；
- 口诀或一句话总结；
- 例题/自测；
- 快速复习卡片；
- 下一站。

这些是内容验收项，不是固定标题模板。

## 五、快速复习卡片

所有 `type: 考点` 的原子卡，默认在标题后、正文展开前放一张 **“快速复习卡片”**。索引、资料、来源页不强制。

统一使用：

```markdown
> [!summary] 快速复习卡片
> **作用/定位**：……
> **核心结论**：……
> **经典题型怎么做 / 题干怎么认**：……
> **易错点 / 考试重点**：……
```

卡片目标是让学习者在 **20～40 秒内完成一次闭卷召回**，不是把正文重新缩写一遍。

### 内容规则

- **作用/定位**：一句话回答“这个知识点在解决什么问题”。
- **核心结论**：只保留考试最需要记住的 1～2 个结论。
- **经典题型怎么做**：只要该知识点存在稳定、反复出现的经典题型，就必须写“考试实际怎么做”，用动作链或编号步骤表达，不只写公式或概念。
- **题干怎么认**：非计算型考点写题干关键词、判断入口或排除思路，让学习者看到题目时知道先想到什么。
- **易错点 / 考试重点**：优先写最容易混淆、最容易算错或最常被干扰项利用的地方。
- 卡片通常控制在 **4～6 行**；没有独立价值的字段可以合并，不为了凑模板制造废话。
- 公式仍严格遵守 `00-全局写作规范.md` 的公式门禁。能用“100 份法”“先定方向再累计”“先算 Need 再找可完成进程”等做题动作讲清，就优先写动作，不额外塞字母公式。
- 卡片里的“经典题型怎么做”必须是**可直接拿去做题的步骤**。禁止写成“理解概念”“掌握公式”“注意区分”这类没有动作的信息。

### 真题考点必须进入复习卡

复习卡片不是正文摘要。只要目标知识点存在可追溯真题、回忆题或已核验的经典软考考法，生成/重写卡片前必须先提取这些题真正考的**判断点**，并优先写入卡片。

执行顺序：

1. 先看该原子知识点对应的真题/题库证据，提取题目实际问过什么；
2. 把考法压缩成“**题干信号 → 第一反应 → 选择/计算动作**”；
3. 再补最少量定义，帮助理解这些考点；
4. 最后才考虑教材中未被题目直接使用的扩展概念。

卡片内容优先级：

**已考判断点 / 经典计算动作 > 高频易错项 > 必要定义 > 背景解释 > 低频扩展。**

硬门禁：

- 真题明确考过“共享什么 / 不共享什么、谁保存什么、谁指向什么、状态如何转换”等具体判断时，卡片必须直接写这些具体结论，不能只保留“隔离、资源拥有、抽象管理”等上位概念。
- 一个抽象术语如果本身没有独立考查价值，只能作为理解辅助，不得占据快速复习卡片的核心结论位置。
- 同一张卡能放下的考点有限时，优先保留**能直接决定选项对错**的结论。
- 若当前没有可靠真题证据，不得伪造“高频/必考”；此时再依据教材核心机制和易混点组织卡片。
- 用户在做题或学习中指出“这个才是考试重点 / 这个选项怎么判断 / 笔记漏了这个考法”时，应把该具体考点同步回快速复习卡，而不是只在正文补解释。

### 经典题型卡的优先级

遇到下列情况，复习卡片必须突出“怎么做”而不是“是什么”：

- 计算题：给出第一步、连续步骤、最终判定方式；
- 判断/选择题：给出题干信号 → 对应知识点 → 排除干扰项；
- 算法/过程题：给出当前状态 → 按什么规则选下一步 → 状态如何更新；
- 易混概念题：给出最小区分标准，不堆长表格。

用户在学习中明确指出“这种题以后考试要会做”或“这是经典题型”时，应把该做题方法同步进入快速复习卡片；不要只在聊天里解释一次。

## 六、机制型卡的额外要求

一张机制型卡仍只有**一个主问题**，但可以围绕它列 3～5 个**子问题/检查项**，例如：

1. 什么时候触发？
2. 正常情况下怎么动作？
3. 满载/异常时怎么动作？
4. 状态如何更新？
5. 最终依据什么做选择？

不得把这些子问题误写成 3～5 个彼此独立的主考点。

相近机制容易混时：
- 先拆清概念边界；
- 尽量使用同一个输入制造结果分叉；
- 计算过程同时展示“状态”和“判定依据”；
- 先讲动作，再给口诀。

若有计算，严格执行 `00-全局写作规范.md` 的公式门禁：默认用自然语言、具体数字、单位和完整步骤讲清；不要因为“是计算题”就自动补公式。只有主教材明确强调的重要公式才保留。

## 七、可视化

只执行 `prompts/40-Mermaid与Obsidian样式修复.md`。本文件不维护 Mermaid 节点数、Excalidraw 路径、布局等第二套规则。

## 八、批量样稿门禁

首次按当前风格处理一个新章节，或一次计划生成/大幅重写 **3 篇及以上原子卡**：

1. 先读黄金样例；
2. 只完成 1 篇代表性完整样稿；
3. 交用户审核正文风格；
4. 用户明确确认后，再批量写入当前章节。

用户明确要求“无需样稿，直接批量”时可跳过。

纯目录整理、死链修复、Excalidraw 修复、frontmatter 小修不属于正文风格批量重写，不强制走样稿门禁。

## 九、落库

- 不复制黄金样例或已有笔记的大段内容，不杜撰真题或来源。
- 同步章节知识库、索引和必要的相邻主线链接，不新增重复 MOC/首页。
- 样稿审核阶段若用户尚未批准，只输出样稿，不写仓库。
- 已通过样稿或用户明确允许直接批量时，按 `AGENTS.md` 直接交付到 `main` 并执行仓库校验。
