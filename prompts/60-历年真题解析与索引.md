# 历年真题解析与索引

用于把 `历年真题/AI题库/原始文本/` 中的自动抽取文本，整理成可搜索、可去重、可映射到 Obsidian 知识点的标准化真题库。

本提示词处理的是**真题资料**，不是原子笔记正文。不要套用原子卡故事写法，也不要为了好看改写题干事实。

## 一、事实来源与可信度

处理前必须读取：

- `AGENTS.md`
- `STYLE.md`
- `prompts/00-全局写作规范.md`
- `历年真题/真题索引.md`
- `历年真题/AI题库/README.md`
- 本次目标 `原始文本/*.md`

如果需要把题目映射到已有笔记，再读取对应章节知识库与候选原子笔记。

### 来源等级

标准化题库必须保留 `source_kind`，至少区分：

1. 来源明确且内容完整的真题资料；
2. 真题解析资料；
3. 回忆版；
4. 网友版；
5. 整理版；
6. 来源待核验资料。

**不得因为题目“看起来像真题”就写成官方真题。**

## 二、先判断原始文本能不能用

读取原始文本 frontmatter 中的：

- `extract_status`
- `source_file`
- `source_kind`

规则：

- `可解析`：可以继续。
- `需OCR`：停止内容级解析，只报告需要 OCR。
- `LFS未拉取`：停止，先解决 LFS。
- `失败`：停止，先修复抽取问题。

不要从空白或严重乱码内容推断题目。

## 三、标准化目标

标准化题库默认按“**年份/批次 + 科目**”组织，不默认一题一个文件，避免产生数千个碎片文件。

建议路径：

`历年真题/AI题库/标准化题库/<年份-批次>/<科目>.md`

例如：

`历年真题/AI题库/标准化题库/2018-下半年/综合知识.md`

单个文件中的每道题用三级标题：

`### 第 17 题`

## 四、每道题的最小结构

综合知识题默认记录：

- 题号
- 题干
- 选项
- 答案
- 解析
- 知识点
- 对应笔记
- 来源
- 来源可信度
- 去重标识

案例分析默认记录：

- 题号 / 问题号
- 案例背景
- 问题
- 参考答案
- 解题关键点
- 知识点
- 对应笔记
- 来源
- 来源可信度

论文题默认记录：

- 题目
- 题目要求
- 主题领域
- 可关联知识点
- 来源
- 来源可信度

### 缺失内容

原始资料没有答案时：

`答案：待补充`

没有可靠解析时：

`解析：待补充`

不得调用模型记忆“补成官方答案”。

如果为了教学给出 AI 自己的推理答案，必须显式写：

`AI 推导（非原资料答案）：...`

## 五、去重规则

这是高优先级步骤。

仓库同时存在：

- 逐年资料；
- 2019—2024 汇总资料；
- 真题及解析合集；
- 回忆版；
- 网友版。

同一道题可能出现多次。

### 判断重复时依次比较

#### 固定卷面资料（主要适用于 2009–2022）

1. 年份 / 批次；
2. 科目；
3. 题号；
4. 题干核心文本；
5. 选项或案例关键数据。

题号可以作为重要辅助键，但仍不能只按题号去重。

#### 机考回忆资料（2023 起优先采用）

2023 起已经确认存在**同一批考试、不同回忆来源题序不同，甚至同一道题选项顺序不同**的情况。

因此：

1. **不得使用“同年份 + 同题号”作为跨来源唯一键**；
2. 先比较完整题干或稳定的题干核心语义；
3. 再比较题目中的对象、条件、数字、公式、表格数据和核心概念；
4. 再比较选项的**语义内容**；
5. 最后比较“被选中的答案语义”，不能直接比较 A/B/C/D 字母；
6. 各来源自己的题号只保留为 `source_label`；
7. 无法证明两条记录是同一道题时，保持两个独立回忆实体，不强行合并。

已验证的典型情况：

- 同一道题在两个回忆来源中可能分别是“第 24 题”和“第 1 题”；
- 同一道题即使题干一致，正确选项的字母也可能因选项重排从 A 变成 B；
- 2023 的两套回忆资料已经出现完全不同的 1–75 顺序。

仅仅排版不同、空格不同、题号格式不同，不算新题；但机考回忆版的**题号不同也不代表是新题**。

### 重复题处理

- 保留一个标准化题目实体；
- `sources` 可记录多个来源；
- 优先保留文本更完整的版本；
- 不因为同一题出现在 3 个 PDF 中就统计为“考了 3 次”。

### 回忆版冲突

若两个回忆版题干或选项存在差异：

- 不擅自拼成一个“官方版本”；
- 先判断是 OCR 差异、题序差异、选项重排，还是真正的题面冲突；
- 如果只是选项重排，记录“答案语义一致”，不要制造 A/B/C/D 假冲突；
- 如果题干/选项语义真的不同，保留各自来源版本；
- 在 `source_notes` 中记录差异和核验依据；
- 无法判断时标记“回忆存在差异”。

## 六、知识点映射

真题的价值不只是存题，而是和现有笔记连接。

### 映射原则

1. 优先链接已有原子笔记；
2. 使用现有文件名和 `[[wikilink]]`；
3. 不为了一个同义标签新建重复笔记；
4. 一道题可以关联 1～3 个主要知识点；
5. 不把泛化标签堆成十几个。

例如：

`知识点：[[页面置换算法]]、[[LRU]]`

如果没有合适笔记：

`对应笔记：待补充`

不要在真题解析任务中顺手批量新建原子卡。

## 七、真题频次统计

建立 `历年真题/AI题库/知识点索引/` 时，以**去重后的独立题目**为统计单位。

每个知识点建议记录：

| 字段 | 含义 |
| --- | --- |
| 出题年份 | 哪几年出现 |
| 科目 | 综合知识 / 案例分析 / 论文 |
| 独立题数 | 去重后的数量 |
| 最近出现 | 最近年份 |
| 典型考法 | 识别、计算、分析、设计、论文 |
| 对应笔记 | Obsidian wikilink |
| 资料可信度 | 是否含回忆版 |

不得用“文件中出现次数”替代“考试出现次数”。

## 八、与学习笔记联动

当用户要求“检查笔记是否覆盖真题”时：

1. 读取目标知识点笔记；
2. 读取对应真题索引；
3. 列出真题真实考法；
4. 检查笔记是否覆盖：
   - 定义识别；
   - 完整机制；
   - 计算方法；
   - 题干关键词；
   - 易错选项；
   - 案例分析需要的表达；
5. 只报告缺口，除非用户明确要求直接修改笔记。

判断优先级可参考：

- 教材明确要求 + 真题多次出现 + 当前笔记缺失 → 高优先级；
- 真题出现但仅回忆版可证实 → 标注可信度后再判断；
- 只有 AI 通用知识、无教材或真题依据 → 不冒充软考高频考点。

## 九、输出格式示例

```markdown
### 第 17 题

**题干：** …

A. …  
B. …  
C. …  
D. …

**答案：** C

**解析：** …

**知识点：** [[LRU]]、[[页面置换算法]]

**对应笔记：** [[虚拟存储与页面置换]]

**来源：**
- 2018 年下半年综合知识
- 原始文件：`历年真题/...`

**来源可信度：** 真题解析资料（来源待核验）

**去重标识：** 2018-H2-综合知识-17
```

格式可以因题型调整，不要机械要求案例分析和论文也长成选择题模板。

## 十、禁止事项

- 不杜撰官方题干、答案、年份、分值和出处。
- 不把回忆版写成正式原卷。
- 不因为汇总 PDF 再次出现同一道题就重复计数。
- 不大段改写原题导致题意变化。
- 不在真题库中使用 ASCII / 纯文本画图替代原题结构图。
- 原题包含图片但抽取文本缺失时，标记“题图待补”，不要凭上下文想象图片内容。
- 不自动把整个真题库一次性重写；默认按年份/科目分批处理并做去重。

## 十一、完成检查

处理完成后检查：

- [ ] 来源属性保留；
- [ ] 题号和科目没有串年；
- [ ] 汇总版与逐年版已考虑去重；
- [ ] 2023+ 机考回忆版未按固定题号强行对齐；
- [ ] 跨来源答案比较使用答案语义而不是只比较 A/B/C/D；
- [ ] 回忆版冲突已显式记录；
- [ ] 缺失答案没有被模型伪造；
- [ ] 知识点链接使用现有笔记；
- [ ] 真题频次按独立题目统计；
- [ ] 生成文件能被 Obsidian 正常读取。
