# 教材证据与笔记校验

用于使用 `官方教材/AI教材库/` 中的 AI 可读教材文本，检查、补全或重写现有软考系统架构设计师笔记。

本文件只负责**教材证据优先级、证据可靠性和校验流程**。真正改原子卡时追加执行 `prompts/10-原子考点卡生成.md`；涉及图表时追加执行 `prompts/40-Mermaid与Obsidian样式修复.md`，不在这里复制原子性或画图细则。

## 一、处理前读取

至少读取：

- `AGENTS.md`
- `官方教材/AI教材库/README.md`
- `官方教材/AI教材库/教材索引.md`
- `官方教材/AI教材库/抽取报告.md`
- 本次主题相关教材原始文本块
- 本次目标笔记

若用户要求结合真实考试情况，再读：

- `历年真题/真题索引.md`
- `历年真题/AI题库/README.md`
- `prompts/60-历年真题解析与索引.md`
- 对应标准化真题或原始文本

## 二、先判断教材文本能否作为证据

读取教材块 frontmatter：

- `source_file`
- `pdf_page_start`
- `pdf_page_end`
- `source_kind`
- `source_priority`
- `extract_status`

规则：

- **可解析**：正常使用。
- **部分可解析**：文字可用；图片、表格、公式或断裂处必须回看原 PDF。
- **需OCR**：不能据此判断“教材没有讲”。
- **LFS未拉取**：先解决抽取流程。
- **失败**：停止内容级判断并报告。

不得从空白、乱码、缺图或断裂文本推断教材结论。

## 三、证据优先级

### 1. 考试范围：大纲

优先 `系统架构第二版 大纲.pdf`。

用于判断：是否属于范围、掌握/熟悉/了解要求、知识域归属。大纲不是详细教材，不能因只有一句话就把机制压缩成一句话。

### 2. 概念与机制主干：主教材

优先 `系统架构设计师教程第二版可搜索.pdf`。

用于定义、原理、机制、公式、分类、典型过程和教材覆盖范围。

### 3. 抽取交叉核验

`【带搜索】系统架构设计师第二版.pdf` 主要用于主教材文字层缺失、页码/段落异常和同处内容交叉核验；文字更清楚不代表来源级别更高。

### 4. 应试辅导

两本“32 小时”资料用于题眼、记忆方法、高频归纳、例题切入和易混比较，不得单独推翻大纲或主教材。

### 5. 扩展理论

`软件体系结构原理、方法与实践_第2版.pdf` 用于深入理解架构理论、风格和方法。超纲内容必须标“扩展理解”，不得包装成必考。

## 四、教材与真题共同决定补全优先级

### 高优先级

满足任一：

- 大纲明确要求 + 主教材有完整内容 + 当前笔记缺失；
- 主教材重点机制 + 真题多次出现 + 当前笔记只写定义；
- 真题出现真实计算/判断/案例考法，而笔记未覆盖对应能力。

### 中优先级

- 教材明确覆盖，但当前真题库暂未发现高频；
- 真题数量少或来源可信度一般；
- 笔记已有主体，但缺机制、条件或易混点。

### 低优先级 / 扩展

- 主要见于扩展参考；
- 大纲无明显要求；
- 真题也缺证据；
- 对理解有帮助但考试价值有限。

不得把扩展内容包装成“高频必考”。

## 五、落库统一使用 P0–P3

| 级别 | 含义 | 默认动作 |
| --- | --- | --- |
| P0 | 当年可信回忆题直接命中，或历史高频且近年持续活跃 | 必读 |
| P1 | 历年常考、重要前置或近年仍有信号 | 重点 |
| P2 | 大纲内低频、辅助知识或暂缺强真题信号 | 了解 |
| P3 | 当前低信号或扩展内容 | 暂不复习 |

落库字段统一使用：`exam_priority`、`review_level`、`priority_reason`、`priority_updated`。没有完成证据审查时写 `exam_priority: 待评估`，不得凭印象标高频。

### 删除门禁

- “当年未出现”只能降低复习优先级，不能单独成为删除理由；
- 可以删除：纯空壳/占位、内容完全重复、已过时且有替代卡、证据明确的超纲噪音；
- 删除前检查索引和 wikilink，删除结果应能从 Git 历史恢复。

## 六、单篇校验流程

### 1. 明确目标主问题

先确定目标笔记回答什么。教材决定“要学什么”，不决定“一篇装多少”。若教材一节包含多个独立考点，按 `prompts/10-原子考点卡生成.md` 拆分后分别校验。

### 2. 定位证据

按顺序定位：

1. 大纲相关页；
2. 主教材相关页；
3. 必要时交叉教材；
4. 辅导资料；
5. 扩展参考。

只读取相关页码块，不默认把整本书全部读入上下文。

### 3. 检查现有覆盖

至少判断：

- 定义是否准确；
- 为什么存在；
- 核心机制/关键步骤是否完整；
- 公式、变量、适用条件是否完整；
- 易混概念是否区分；
- 考试识别点是否存在；
- 是否过度绝对化。

### 4. 写出具体缺口

缺口必须可执行，例如：

- “LRU 只写了淘汰原则，没有解释访问后如何更新最近性顺序”；
- “只写容量公式，没有解释一级/二级间接索引块本身是什么”；
- “大纲明确要求，但章节没有任何入口”。

禁止只写“知识点不全面”。

### 5. 用真题决定深度

- 定义识别题 → 至少补题眼和易混点；
- 计算题 → 补完整计算过程；
- 案例题 → 补决策依据和表达方式；
- 反复出现 → 提高复习优先级。

没有真题证据，也不能删除大纲明确要求的内容。

### 6. 修改笔记

真正落库时：
- 原子卡执行 `10`；
- 通用写作执行 `00`；
- 可视化执行 `40`；
- 不把教材摘要直接粘贴成笔记正文。

## 七、可追溯性

教材证据使用稳定定位：

- `source_file`
- 原 PDF 页码范围

校验报告优先写“来源文件 + PDF 第 X–Y 页”。不要用自动生成 Markdown 行号代替原 PDF 页码。

正文如需来源，只在 frontmatter 或简洁“依据与校验”区域保留，不要每段堆出处。

## 八、缺图与抽取异常

出现“如下图所示”“见图 X-X”“如下表”、公式缺项、表格严重错位时：

1. 标记“需回看 PDF 原页”；
2. 不猜节点、数据或公式；
3. 能读取原 PDF 时做视觉核验；
4. 无法核验则保留待补充。

若需要重绘原图表达，先核实原页事实，再执行 `40`；不得根据残缺抽取文本臆造图。

## 九、资料冲突

主教材、辅导书、扩展参考说法不同时：

1. 判断是否为版本、术语层级或适用范围差异；
2. 检查大纲考试口径；
3. 检查主教材上下文；
4. 查看真题实际采用的口径；
5. 仍不确定时避免绝对化并记录“资料口径存在差异”。

禁止自行拼接多个版本制造不存在的“官方统一定义”。

## 十、默认输出

用户只要求检查时，优先输出：

| 项目 | 结论 |
| --- | --- |
| 当前笔记覆盖 | 已覆盖 / 部分覆盖 / 缺失 |
| 大纲要求 | 简述 |
| 主教材关键机制 | 简述 |
| 真题证据 | 有 / 无 / 待解析 |
| 主要缺口 | 具体缺什么 |
| 修改优先级 | 高 / 中 / 低 |
| 教材页码 | 原 PDF 页码 |

用户明确要求直接优化笔记时，再落库。

## 十一、完成检查

- [ ] 没把辅导书当大纲裁决来源；
- [ ] 没把扩展内容冒充必考；
- [ ] 教材页码可追溯；
- [ ] 需 OCR / 缺图内容未被臆测；
- [ ] 真题频次未用重复文件次数冒充；
- [ ] 补全深度与真实考法匹配；
- [ ] 改原子卡时已执行 `10`；
- [ ] 画图时已执行 `40`。
