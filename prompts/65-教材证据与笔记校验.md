# 教材证据与笔记校验

用于使用 02、最新教材-新大纲(第二版)/AI教材库/ 中的 AI 可读教材文本，检查、补全或重写现有软考系统架构设计师笔记。

本提示词处理的是**教材证据与笔记之间的校验关系**。真正修改原子笔记正文时，仍必须同时遵守 AGENTS.md、prompts/00-全局写作规范.md，以及对应的原子卡/章节提示词。

## 一、处理前必须读取

至少读取：

- AGENTS.md
- 02、最新教材-新大纲(第二版)/AI教材库/README.md
- 02、最新教材-新大纲(第二版)/AI教材库/教材索引.md
- 02、最新教材-新大纲(第二版)/AI教材库/抽取报告.md
- 本次主题相关的教材原始文本块
- 本次目标笔记

如果用户要求结合真实考试情况，再读取：

- 历年真题/真题索引.md
- 历年真题/AI题库/README.md
- prompts/60-历年真题解析与索引.md
- 对应标准化真题或真题原始文本

## 二、先检查教材文本能不能作为证据

读取教材块 frontmatter：

- source_file
- pdf_page_start
- pdf_page_end
- source_kind
- source_priority
- extract_status

规则：

- 可解析：正常使用。
- 部分可解析：可以使用文字，但涉及图片、表格、公式或明显断裂处必须回看原 PDF。
- 需OCR：不能据此判断“教材没有讲这个知识点”。
- LFS未拉取：先解决抽取流程。
- 失败：停止内容级判断并报告问题。

不要从空白页、乱码页或缺图文本推断教材结论。

## 三、证据优先级

### 1. 判断考试范围

优先：系统架构第二版 大纲.pdf

适合回答：

- 是否属于考试范围；
- 要求掌握、熟悉还是了解；
- 哪些主题属于同一考试知识域。

大纲通常不是详细教材，不能因为大纲只写一句话就认为机制只需要学一句话。

### 2. 判断概念与机制主干

优先：系统架构设计师教程第二版可搜索.pdf

适合回答：

- 定义；
- 原理；
- 机制；
- 公式；
- 分类；
- 典型过程；
- 教材章节覆盖范围。

### 3. 主教材抽取疑点

使用：【带搜索】系统架构设计师第二版.pdf

主要用于：

- 主教材文字层缺失；
- 页码或段落抽取异常；
- 同一处内容交叉核验。

不能仅因为该文件文字更清楚，就自动提高其来源身份等级。

### 4. 应试辅导

使用两本“32 小时”资料。

适合补充：

- 题眼；
- 记忆方法；
- 高频归纳；
- 例题切入角度；
- 容易混淆的比较。

不得用辅导资料单独推翻大纲或主教材。

### 5. 扩展理论

使用：软件体系结构原理、方法与实践_第2版.pdf

适合深入：

- 软件体系结构理论；
- 架构风格；
- 设计与分析方法；
- 教材只简述但用户希望真正理解的背景知识。

扩展参考中的超纲知识必须标明“扩展理解”，不得写成软考必考要求。

## 四、教材与真题如何共同决定笔记优先级

不要把“教材”和“真题”当成二选一。

判断优先级：

### 高优先级补全

满足任一情况：

- 大纲明确要求 + 主教材有完整内容 + 当前笔记缺失；
- 主教材重点机制 + 真题多次出现 + 当前笔记只写定义；
- 真题出现真实考法，但当前笔记没有相应计算、判断或案例表达。

### 中优先级补全

例如：

- 教材明确覆盖，但当前真题库暂未发现高频；
- 真题只出现过少量或来源可信度一般；
- 当前笔记已有内容，但缺少机制解释或易混点。

### 低优先级/扩展

例如：

- 只在扩展参考中详细出现；
- 大纲没有明显要求；
- 真题也没有证据；
- 对理解有帮助但对考试价值有限。

不要把扩展内容包装成“高频必考”。

## 五、检查一篇笔记时的固定流程

### 第一步：明确目标知识点

先确定当前笔记到底回答什么问题，不要因为教材相关章节很长就把整个章节塞进一篇原子卡。

### 原子性优先于教材段落完整性

教材证据用于决定“要学什么”，不用于决定“一篇笔记装多少”。

- 教材同一节连续介绍多个可独立考试的概念时，先拆成多个知识点，再分别校验笔记。
- 不以“把教材这一节补完整”为目标扩写单卡；目标是“让每张卡完整回答一个主问题”。
- 真题如果分别考 A、B、C 三个机制，即使教材把它们放在同一段，也优先对应 3 张原子卡。
- 发现现有卡已经承担多个主问题时，先建议拆卡，再决定向哪个目标卡补证据。
- 只有比较关系本身就是考试对象、或属于同一固定分类体系时，才允许多个成员保留在一张卡中。

### 第二步：搜索教材证据

优先定位：

1. 大纲相关页；
2. 主教材相关页；
3. 必要时交叉教材；
4. 辅导资料；
5. 扩展参考。

只读取真正相关的页码块，不默认把整本书全部读入上下文。

### 第三步：列出现有笔记覆盖

至少判断：

- 定义是否准确；
- 为什么存在；
- 核心机制是否完整；
- 关键步骤是否缺失；
- 公式是否完整；
- 适用条件是否写清；
- 易混概念是否区分；
- 考试识别点是否存在；
- 是否有过度绝对化表述。

### 第四步：列出教材缺口

缺口必须具体，例如：

- “当前只说明 LRU 淘汰最近最少使用页，但没有解释访问后如何更新最近性顺序”；
- “教材还区分一级间接、二级间接，当前笔记只写容量公式，没有解释索引块本身是什么”；
- “大纲要求掌握某主题，但当前章节完全没有入口”。

不要只写“知识点不够全面”。

### 第五步：结合真题判断补全深度

如果有标准化真题：

- 真题只考定义识别：笔记至少覆盖题眼与易混点；
- 真题考计算：必须补完整计算过程；
- 真题考案例：必须补决策依据和表达方式；
- 真题反复出现：提高复习优先级。

如果没有真题证据，也不能因此删除大纲明确要求的知识。

### 第六步：修改笔记

真正落库时，继续遵守仓库的故事驱动、可视化路由、LaTeX、wikilink 和 frontmatter 规则。

不要把“教材摘要”直接粘进笔记；要重新组织成适合零基础学习者理解的教学内容。

## 六、引用与可追溯性

教材证据的稳定定位方式：

- source_file
- PDF 页码范围

推荐在校验报告中写：

- 依据：系统架构设计师教程第二版可搜索.pdf，PDF 第 120–123 页
- 大纲依据：系统架构第二版 大纲.pdf，PDF 第 18–19 页

不要用自动生成 Markdown 的行号替代原 PDF 页码。

如果正文确实需要保留来源，可以在笔记的 source/frontmatter 或“依据与校验”区域保存简洁来源；不要每个段落都堆教材出处导致阅读体验变差。

## 七、避免大段复制教材

AI 教材层的目的不是把教材重新出版成笔记。

生成笔记时：

- 优先理解后转述；
- 公式、定义和专有名词保持准确；
- 不连续复制大段教材原文；
- 保留页码以便核验；
- 对图片、复杂表格优先重新画成适合教学的 Mermaid / Excalidraw / 表格，而不是凭文字抽取结果臆测原图。

## 八、教材抽取缺图时的处理

如果文字出现：

- “如下图所示”
- “见图 X-X”
- “如下表”
- 公式明显缺项
- 表格列严重错位

则：

1. 标记“需回看 PDF 原页”；
2. 不猜图中节点或数据；
3. 不把缺失内容写成确定事实；
4. 如果当前工具能够读取 PDF 原页，再进行视觉核验；
5. 无法核验时保留待补充。

## 九、发生资料冲突时

例如主教材、辅导书、扩展参考说法不同：

1. 先确认是不是版本、术语层级或适用范围不同；
2. 检查大纲是否规定考试口径；
3. 检查主教材上下文；
4. 查看真题实际采用哪种口径；
5. 仍不能确定时，在笔记中避免绝对化，并记录“资料口径存在差异”。

禁止自行拼接多个版本，制造不存在的“官方统一定义”。

## 十、输出建议

用户只要求检查时，优先输出：

| 项目 | 结论 |
| --- | --- |
| 当前笔记覆盖 | 已覆盖 / 部分覆盖 / 缺失 |
| 大纲要求 | 简述 |
| 主教材关键机制 | 简述 |
| 真题证据 | 有 / 无 / 待解析 |
| 主要缺口 | 具体缺什么 |
| 修改优先级 | 高 / 中 / 低 |
| 教材页码 | 原 PDF 页码 |

用户明确要求“直接优化笔记”时，再修改仓库正文。

## 十一、完成检查

- [ ] 没有把辅导书当成大纲裁决来源；
- [ ] 没有把扩展内容冒充必考；
- [ ] 教材页码可追溯；
- [ ] 需OCR/缺图内容没有被臆测；
- [ ] 真题频次没有用文件重复次数冒充；
- [ ] 补全深度与真实考法匹配；
- [ ] 真正修改笔记时仍遵守 AGENTS.md 和对应写作提示词。
