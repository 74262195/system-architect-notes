# 教材证据与笔记校验

用于使用 `官方教材/AI教材库/` 中的 AI 可读教材文本，检查、补全或重写现有软考系统架构设计师笔记。

本文件只负责**教材证据优先级、证据可靠性和 Atom 级解释深度校验**。章节覆盖矩阵与 Atom ID 的建立执行 `prompts/20-章节检查与重构.md`；真正改原子卡时追加执行 `prompts/10-原子考点卡生成.md`；涉及图表时追加执行 `prompts/40-Mermaid与Obsidian样式修复.md`，不在这里复制原子性或画图细则。

## 一、处理前读取

至少读取：

- `AGENTS.md`
- `官方教材/AI教材库/README.md`
- `官方教材/AI教材库/教材索引.md`
- `官方教材/AI教材库/抽取报告.md`
- 本次主题相关教材原始文本块
- 本次目标笔记

若属于章节检查、章节完工、覆盖缺口修复或跨章节联合审查，还必须读取：

- `prompts/20-章节检查与重构.md`
- 当前章节完整覆盖矩阵；
- 本轮需要核验的 Atom ID、正文文件、正文具体落点和当前覆盖状态。

若用户要求结合真实考试情况，再读：

- `历年真题/真题索引.md`
- `历年真题/AI题库/README.md`
- `prompts/60-历年真题解析与索引.md`
- 对应标准化真题或原始文本

## 二、先判断教材文本能否作为证据

读取教材块 frontmatter：

- `source_file`
- `pdf_page_start`
- `pdf_page_end`
- `source_kind`
- `source_priority`
- `extract_status`

规则：

- **可解析**：正常使用。
- **部分可解析**：文字可用；图片、表格、公式或断裂处必须回看原 PDF。
- **需OCR**：不能据此判断“教材没有讲”。
- **LFS未拉取**：先解决抽取流程。
- **失败**：停止内容级判断并报告。

不得从空白、乱码、缺图或断裂文本推断教材结论。

## 三、证据优先级

### 1. 考试范围：大纲

优先 `系统架构第二版 大纲.pdf`。

用于判断：是否属于范围、掌握/熟悉/了解要求、知识域归属。大纲不是详细教材，不能因只有一句话就把机制压缩成一句话。

### 2. 概念与机制主干：主教材

优先 `系统架构设计师教程第二版可搜索.pdf`。

用于定义、原理、机制、公式、分类、典型过程和教材覆盖范围。

### 3. 抽取交叉核验

`【带搜索】系统架构设计师第二版.pdf` 主要用于主教材文字层缺失、页码/段落异常和同处内容交叉核验；文字更清楚不代表来源级别更高。

### 4. 应试辅导

两本“32 小时”资料用于题眼、记忆方法、高频归纳、例题切入和易混比较，不得单独推翻大纲或主教材。

### 5. 扩展理论

`软件体系结构原理、方法与实践_第2版.pdf` 用于深入理解架构理论、风格和方法。超纲内容必须标“扩展理解”，不得包装成必考。

## 四、固定审查顺序：大纲 → 真题 → 主教材 → 当前笔记

所有“审查、减负、优先级校准、复习卡重写”任务，必须按以下顺序执行，不得从教材目录或当前笔记反推考试范围：

1. **大纲**：先确认 Atom 是否在范围内，以及要求到了解/熟悉/掌握哪一层。
2. **真题**：再确认实际问过什么、题干如何设问、近年是否仍活跃；真题决定复习重点和做题动作，但不能推翻大纲明确范围。
3. **主教材**：只补足大纲要求 + 真题考法所需的定义、机制、条件、边界和必要计算深度；教材篇幅不能直接等同于考试重要度。
4. **当前笔记具体落点**：最后判定该 Atom 当前是 `unmapped / partial / covered / link_only`，以及应保留、压缩、拆卡、补充、降级或标为扩展。

硬门禁：

- **大纲是范围与能力层级的第一裁决源。**
- “近几年没考”不能单独删除大纲明确要求的知识点。
- “教材讲得很长”不能单独把大纲弱要求、真题低信号的知识点升为重点。
- 真题已经出现的具体判断点，必须进入正文与快速复习卡片；不能只保留上位抽象概念。
- 教材只负责事实、定义、机制、条件、边界和解释深度，**不能单独决定考试频率或 P0–P3 优先级**。
- 审查报告必须能回答四句话：**大纲要求什么？真题怎么考？教材需要讲到多深？当前正文具体落点是否真的讲到了？**

## 五、Atom 级证据记录是章节任务的强制产物

章节级任务不得只给“这篇笔记大致符合教材”的整篇结论。覆盖矩阵中的每个 Atom 都必须能单独追溯。

每个 Atom 至少记录：

| 字段 | 要求 |
| --- | --- |
| Atom ID | 与 `20` 的章节覆盖矩阵一致 |
| 大纲证据 | 范围、能力层级或上位覆盖依据 |
| 真题证据 | 实际考法/题干信号；没有可靠证据明确写无/待核验 |
| 主教材证据 | 来源文件 + 原 PDF 页码范围 |
| 最小解释深度 | 本 Atom 至少要讲清哪些定义、机制、条件、边界或计算动作 |
| 正文文件 | 当前承载文件 |
| 正文具体落点 | 标题/段落/明确锚点，不能只写文件名 |
| 深度结论 | 足够 / 不足 / 无实质落点 |
| 覆盖状态建议 | `covered / partial / unmapped / link_only` |

### “教材提到”不等于“正文已覆盖”

以下情况即使教材中存在该术语，也不得判当前 Atom 已 `covered`：

- 当前正文只有一句定义，教材/真题要求理解机制、关系、条件或判断动作；
- 只有目录、文件名、frontmatter、tag、alias 出现关键词；
- 只有占位、TODO、待生成骨架；
- 正文只讲上位概念，却没有该 Atom 的具体落点；
- 当前章只有跨章节链接，但目标主事实源仍是 `unmapped / partial`；
- 教材证据只能证明“出现过”，无法证明解释深度已达到最小考试闭环。

若原状态为 `covered`，但教材核验证明解释深度不足，必须退回 `partial`；若没有任何实质正文落点，退回 `unmapped`。不能为了保持章节“已完成”状态而保留错误标记。

### 教材发现新的必要子机制时怎么处理

若主教材表明某个大纲 Atom 为完成其最小考试闭环必须包含一个当前矩阵没有的、可独立核验的必要子机制：

1. 不要直接把大量内容塞进当前卡；
2. 回到 `20` 判断它应作为原 Atom 的必要解释，还是新增稳定 Atom ID；
3. 只有确实可以独立出题/独立核验时才新增 Atom；
4. 再由 `10` 决定是否需要拆卡。

## 六、按四层证据决定补全优先级

### 高优先级

满足任一：

- 大纲明确要求 + 主教材有完整内容 + 当前 Atom `unmapped`；
- 主教材重点机制 + 真题多次出现 + 当前正文只写定义；
- 真题出现真实计算/判断/案例考法，而正文未覆盖对应能力。

### 中优先级

- 教材明确覆盖，但当前真题库暂未发现高频；
- 真题数量少或来源可信度一般；
- 笔记已有主体，但缺机制、条件或易混点。

### 低优先级 / 扩展

- 主要见于扩展参考；
- 大纲无明显要求；
- 真题也缺证据；
- 对理解有帮助但考试价值有限。

不得把扩展内容包装成“高频必考”。

## 七、落库统一使用 P0–P3

| 级别 | 含义 | 默认动作 |
| --- | --- | --- |
| P0 | 当年可信回忆题直接命中，或历史高频且近年持续活跃 | 必读 |
| P1 | 大纲要求明确，且历年重复考查或近年仍有直接信号 | 重点 |
| P2 | 大纲内低频、辅助知识或暂缺强真题信号 | 了解 |
| P3 | 当前低信号或扩展内容 | 暂不复习 |

落库字段统一使用：`exam_priority`、`review_level`、`priority_reason`、`priority_updated`。没有完成证据审查时写 `exam_priority: 待评估`，不得凭印象标高频。

### 删除门禁

- “当年未出现”只能降低复习优先级，不能单独成为删除理由；
- 占位卡/待生成骨架默认保留，它们代表后续章节建设任务，不得按“空壳”直接删除；
- 可以删除：用户明确批准的占位、内容完全重复、已过时且有替代卡、证据明确的超纲噪音；
- 减负优先通过 P0–P3、复习队列过滤和独立生成清单实现；
- 删除前检查索引和 wikilink，删除结果应能从 Git 历史恢复。

## 八、单篇 / 单 Atom 校验流程

### 1. 明确 Atom 与目标主问题

章节任务先从覆盖矩阵读取 Atom ID、最小考试闭环和主事实源；单篇任务则先确定目标笔记回答什么。教材决定“要学什么”，不决定“一篇装多少”。若教材一节包含多个独立考点，回到 `20` 原子化并按 `10` 判断拆分。

### 2. 定位证据

按审查顺序定位：

1. 大纲相关页，先确定范围和能力层级；
2. 对应标准化真题/可信回忆题，提取实际考法；
3. 主教材相关页，确定解释到什么深度；
4. 必要时交叉教材；
5. 当前目标正文**具体落点**；
6. 辅导资料和扩展参考仅作补充，不得改变前三层裁决顺序。

只读取相关页码块，不默认把整本书全部读入上下文。

### 3. 检查现有落点

至少判断：

- 定义是否准确；
- 为什么存在；
- 核心机制/关键步骤是否完整；
- 条件、边界和例外是否完整；
- 公式、变量、适用条件是否完整；
- 易混概念是否区分；
- 考试识别点/计算动作是否存在；
- 是否过度绝对化；
- 该段正文是否真的承担本 Atom，而不是仅顺带提到名词。

### 4. 写出具体缺口

缺口必须可执行，例如：

- “LRU 只写了淘汰原则，没有解释访问后如何更新最近性顺序”；
- “只写容量公式，没有解释一级/二级间接索引块本身是什么”；
- “SE-A017 在矩阵中只有文件名，没有任何正文段落解释关系和判题动作，应退回 `unmapped`”。

禁止只写“知识点不全面”。

### 5. 用真题决定深度与考试动作

- 定义识别题 → 至少补题眼和易混点；
- 计算题 → 补完整计算过程；
- 案例题 → 补决策依据和表达方式；
- 反复出现 → 提高复习优先级。

没有真题证据，也不能删除大纲明确要求的内容。

### 6. 修改笔记并回填矩阵

真正落库时：

- 原子卡执行 `10`；
- 通用写作执行 `00`；
- 可视化执行 `40`；
- 不把教材摘要直接粘贴成笔记正文；
- 修改后回填 Atom 的教材证据、正文具体落点、深度结论和覆盖状态。

## 九、跨章节主事实源的证据规则

对于 `link_only`：

1. 当前章只核验本地定位是否准确、链接是否有效；
2. 目标主事实源必须能够定位到真实正文，并且对应 Atom 在目标章已经 `covered`；
3. 如果目标只是占位、一句话定义或 `partial`，当前章不能标 `link_only` 通过；
4. 同一事实若多个章节都完整展开，应将“重复主事实源”交回 `20/66` 处理，而不是分别证明两份正文都正确后继续保留重复。

## 十、可追溯性

教材证据使用稳定定位：

- `source_file`
- 原 PDF 页码范围

校验报告优先写“来源文件 + PDF 第 X–Y 页”。不要用自动生成 Markdown 行号代替原 PDF 页码。

正文如需来源，只在 frontmatter 或简洁“依据与校验”区域保留，不要每段堆出处。

## 十一、缺图与抽取异常

出现“如下图所示”“见图 X-X”“如下表”、公式缺项、表格严重错位时：

1. 标记“需回看 PDF 原页”；
2. 不猜节点、数据或公式；
3. 能读取原 PDF 时做视觉核验；
4. 无法核验则保留待补充。

若需要重绘原图表达，先核实原页事实，再执行 `40`；不得根据残缺抽取文本臆造图。

## 十二、资料冲突

主教材、辅导书、扩展参考说法不同时：

1. 判断是否为版本、术语层级或适用范围差异；
2. 检查大纲考试口径；
3. 检查主教材上下文；
4. 查看真题实际采用的口径；
5. 仍不确定时避免绝对化并记录“资料口径存在差异”。

禁止自行拼接多个版本制造不存在的“官方统一定义”。

## 十三、默认输出

### 单篇任务

用户只要求检查单篇时，优先输出：

| 项目 | 结论 |
| --- | --- |
| 当前笔记覆盖 | 已覆盖 / 部分覆盖 / 缺失 |
| 大纲要求 | 简述 |
| 主教材关键机制 | 简述 |
| 真题证据 | 有 / 无 / 待解析 |
| 主要缺口 | 具体缺什么 |
| 修改优先级 | 高 / 中 / 低 |
| 教材页码 | 原 PDF 页码 |

### 章节任务

章节级任务必须按 Atom ID 输出/回填，不得只给整章概述：

| Atom ID | 大纲要求 | 真题考法 | 教材深度 | 正文具体落点 | 深度结论 | 状态建议 |
| --- | --- | --- | --- | --- | --- | --- |

用户明确要求直接优化笔记时，再落库正文；只要求审查时，可以只更新审核记录/覆盖矩阵。

## 十四、完成检查

- [ ] 没把辅导书当大纲裁决来源；
- [ ] 没把扩展内容冒充必考；
- [ ] 教材页码可追溯；
- [ ] 需 OCR / 缺图内容未被臆测；
- [ ] 真题频次未用重复文件次数冒充；
- [ ] 每个本轮核验 Atom 都有正文具体落点或明确判为 `unmapped`；
- [ ] 没把“教材提到/文件存在/一句定义”误判为 `covered`；
- [ ] `covered` 的解释深度与大纲 + 真题实际考法匹配；
- [ ] 教材核验发现深度不足时已退回 `partial`，没有维护假完成状态；
- [ ] `link_only` 的目标主事实源真实存在、链接有效且已 `covered`；
- [ ] 改原子卡时已执行 `10`；
- [ ] 画图时已执行 `40`。
