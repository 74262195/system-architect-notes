# 章节检查与重构

用于整章查漏、拆目录、纠错、补链和重建导航。本文件只规定**章节级工作流与章节覆盖契约**；原子卡正文执行 `10`，教材证据深度执行 `65`，一次联合验收执行 `66`，可视化执行 `40`，章节看板执行 `30`。

## 一、先建立“大纲全集”，再读取当前目录

章节审查不能从“现有目录看起来有什么”反推“本章应该有什么”。固定顺序是：

1. 先读取最新适用考试大纲，确认综合知识、案例分析、论文中属于本章的范围和能力要求；
2. 将大纲拆成可独立核验的**大纲原子项全集**，建立稳定 `Atom ID`；
3. 再读取当前章节知识库、真实目录、直接子目录、现有原子笔记、学习路线、考前速记和 Excalidraw；
4. 需要判断解释深度时执行 `65`，需要判断实际考法与优先级时读取可靠真题；
5. 最后把“应该有的原子项全集”映射到“当前实际正文”，不能反过来用当前文件名决定原子项集合。

同时必须读取：

- `AGENTS.md`、`prompts/00-全局写作规范.md`；
- 当前章节知识库、真实目录和直接子目录；
- 现有原子笔记文件名及必要正文；
- 学习路线、考前速记和 Excalidraw；
- 高风险、疑似漏项、疑似重复主事实源或疑似“变胖”的笔记正文。

先确认：

1. 当前真实目录是什么；
2. 哪些文件已存在，哪些只是缺入口，哪些只有占位或一句定义；
3. 用户要整理当前仓库，还是明确要求按最新官方教材目录对齐。

未经明确要求，不根据仓库编号猜官方教材编号，也不顺手重编号。

## 二、阶段 A0：建立章节覆盖契约（强制产物）

### 2.1 大纲原子项与稳定 Atom ID

`Atom ID` 是章节覆盖审查的稳定追踪单位，不等于文件 ID，也不跟随文件拆分/合并随意变化。

规则：

- 原子项来源必须是**最新适用大纲的原子化结果**，不是当前目录；
- 一个大纲条目若包含多个可以独立出题、需要不同判断/计算动作、或需要分别核验解释深度的内容，应拆成多个 Atom；
- 一个 Atom 应能用一句话说清“考试至少需要会什么”；
- 同一知识点后续只因文件移动、改名、合并或拆卡，不重新编号旧 Atom；
- 后续发现真正漏掉的大纲项时追加新 Atom，不通过重排旧 ID 掩盖遗漏历史；
- ID 前缀按章节/知识域稳定命名，例如 `CS-SW-A001`、`SE-A001`、`ARCH-A001`；具体前缀一旦在该章审查记录中使用，就应保持稳定。

### 2.2 强制覆盖矩阵

每次整章检查、章节重构或章节完工验收，都必须在章节审核报告或本次可追溯工作记录中维护完整矩阵。不得只输出“主线完整/基本覆盖”。

矩阵至少包含：

| 字段 | 必填要求 |
| --- | --- |
| Atom ID | 稳定唯一 ID |
| 大纲原文/依据 | 保留可核验的大纲表述或定位 |
| 原子项 | 可独立核验的最小考试知识单元 |
| 最小考试闭环 | 至少需要会到什么程度、做什么动作 |
| 主事实源章节 | 哪一章负责讲完整定义、机制与边界 |
| 正文文件 | 实际承载文件；没有则留空 |
| 正文具体落点 | 二/三级标题、段落或明确锚点；不能只写文件名 |
| 教材证据 | 由 `65` 核验定义、机制、条件、边界和深度 |
| 真题证据 | 核验实际考法、辨析点和优先级；无可靠证据要明确写无/待核验 |
| 覆盖状态 | `unmapped / partial / covered / link_only` |
| 修复动作 | 新增原子卡 / 补强原卡 / 建立链接 / 合并降级 / 无需修改等 |
| 跨章链接 | 非主事实源章节如何承接到主事实源 |

### 2.3 覆盖状态只有四种

- `unmapped`：没有可验证的实质正文落点，或只有目录/文件名/占位等假覆盖；
- `partial`：已有实质正文，但尚未达到该 Atom 的最小考试闭环，例如缺机制、条件、边界、辨析或考试动作；
- `covered`：主事实源已有真实正文落点，并经证据核验达到该 Atom 的最小考试闭环；
- `link_only`：当前章节不是主事实源，本地只负责说明它在本章为什么出现，并通过有效 wikilink 承接到另一个已经 `covered` 的唯一主事实源。

### 2.4 以下一律不得计为 covered

- 目录、README、索引或章节名存在；
- 文件名存在；
- frontmatter、tag、alias 出现关键词；
- 只有一句定义；
- TODO、`待生成`、占位卡、空壳卡；
- 以上位主题名代替下位逐项映射，例如“面向对象分析与设计”存在就推断所有 UML 原子项都已覆盖；
- 只写“主线完整、内容基本齐全、教材已提及”等主观结论；
- 只存在一个跨章节链接，但链接失效，或目标自身仍是 `unmapped / partial`；
- 术语在别章被顺带提到，却没有登记唯一主事实源和具体正文落点。

### 2.5 正向与反向检查都必须执行

**正向检查：**

`大纲 Atom → 主事实源 → 正文文件 → 正文具体落点 → 教材/真题证据 → 覆盖状态`

用于发现“应该有但没有”的漏项。

**反向检查：**

`当前正文集合 → 每张实质考点卡/承担知识教学的主要段落 → 对应 Atom ID 或明确的补充内容理由`

用于发现：

- 正文孤岛；
- 没有大纲/教材/真题合理依据却无限扩写的枝节；
- 同一事实和机制在多个章节重复讲完整；
- 文件名看似命中关键词，但正文实际上没有承担该 Atom；
- 一个正文承担过多互不依赖的 Atom，已经违反原子性。

反向检查不是要求所有辅助过渡句都有 Atom ID；它针对**承担独立知识教学价值的卡片和主要段落**。

### 2.6 跨章节只允许一个主事实源

同一知识的完整定义、机制、条件和边界原则上只保留一个主事实源：

- 最符合大纲知识归属、教材组织和学习主线的章节负责讲完整；
- 其他章节只保留当前场景下的最小定位 + 有效 wikilink；
- 非主事实源章节可以有本地例子，但不得复制整套事实、关系、分类和判题逻辑；
- 若多个章节都存在完整正文，必须确定唯一主事实源，其余合并为链接或缩减到本地定位；
- `link_only` 只有在目标主事实源已经 `covered` 且链接有效时才能成立，否则仍是 `unmapped / partial`。

## 三、由矩阵形成“覆盖—减负”处置清单

章节审查不是只给“完整/不完整”的结论。先按**大纲 → 可靠真题 → 主教材 → 当前笔记**为每个 Atom 建立证据映射，再逐项作出可执行处置：

| 处置 | 适用条件 | 直接动作 |
| --- | --- | --- |
| 新增 | Atom 为 `unmapped`，且没有其他章节的已覆盖主事实源 | 按 `10` 新建符合原子性要求的考点卡，并接入矩阵、索引与学习主线 |
| 保留/补强 | 已有卡是唯一主事实源，但 Atom 为 `partial` | 在原卡补齐缺失机制、边界、题干判断或链接，不为同一主问题另造同义卡 |
| 建立链接 | 当前章不是主事实源，其他章节已有 `covered` 主事实源 | 本章保留最小定位，建立有效 wikilink，矩阵标 `link_only` |
| 合并/降级 | 多张卡解释同一主问题，或内容属于范围内但当前题频低 | 保留一个事实源；其余卡合并为链接或将优先级降至 P2/P3 |
| 删除 | 已确认内容完全重复且已有替代卡、明显过时且无保留价值，或大纲无合理上位覆盖且教材也未展开的超纲噪音 | 直接删除，并在审查报告写明删除理由、替代入口或“无替代但超纲”的证据 |

用户已授权本仓库的章节审查可直接执行新增与删除；因此一旦证据满足上表，不要仅列建议。不得因为低频、篇幅长或暂时没有真题就删除大纲范围内的卡；占位卡若仍代表未覆盖范围，优先补正文或降级，而不是删除。

**后续新增/重写任务必须来自矩阵中的 `unmapped / partial`，或来自反向检查确认的重复/胖卡修复；不得脱离矩阵凭当前目录自由发挥。** 章节覆盖矩阵的建立、状态标记和结构诊断本身不受 `10` 的样稿门禁限制；真正新增或大幅重写原子卡时再执行 `10`。

## 四、检查十三个维度

1. **覆盖度**：大纲 Atom 是否全部建立并有可验证状态；
2. **事实与公式**：是否错误、过时或绝对化；
3. **原子性**：是否存在承担多个平级主问题的“胖卡”；
4. **重复内容**：是否有同义卡、重复首页/MOC、重复主事实源；
5. **知识联系**：主线和前后依赖是否清楚；
6. **导航完整性**：章节知识库、路线、速记、看板、下一站是否一致；
7. **复习卡片**：`type: 考点` 是否按 `prompts/10-原子考点卡生成.md` 配有快速复习卡片；存在经典题型时，卡片是否真正写了“考试怎么做”，而不是只重复定义；
8. **重点密度**：复习卡和开篇是否把“考试真正需要带走的 1～3 个判断入口”放在最前面。禁止把教材摘要、平级分类、低频扩展同时塞进概述卡，导致高价值结论被稀释；
9. **优先级一致性**：正文不得出现“几乎年年考 / 高频必考”等表述，却同时将该卡标为 P2/P3；凡是频率性结论都必须与当前真题证据和 `exam_priority` 一致；
10. **做题反推**：抽取至少一个该知识点的典型真题考法，反问“只看快速复习卡，能否知道第一步想什么、如何排除干扰项”。若不能，即使正文概念完整，也判定复习质量不合格；
11. **历年考点正文覆盖**：存在可追溯历年真题/已核验回忆题时，相关知识必须在笔记正文中显式体现，不能只停留在 `priority_reason`、frontmatter 或快速复习卡。正文应让读者看出“历年从什么角度考过 → 对应要掌握什么知识/判断结论”；可核验年份时可标年份，重复考法应合并总结，不机械逐年堆题。若只是旧纲遗留/历史补充，只保留最小必要说明，不为了体现旧题扩写整套知识；
12. **问题闭环**：标题、小标题、开篇或复习卡提出的问题，后续正文是否在具体情境中及时回答。必须能指出“谁遇到什么困难 → 哪个结论回应它 → 后文怎样解释”。如果问句后生硬抛出“不是”或抽象定义、问题后只罗列相关知识，或读者必须读完整篇才能自己归纳答案，判定正文质量不合格；
13. **上下文连续性**：是否突然出现前文没有建立的新对象、新比喻、新动作或模糊指代。重点扫描“插上线以后 / 这个 / 它 / 上一步 / 这种方式 / 这里 / 前者后者”等表达；若前文没有明确对应对象，必须补前置桥接或重写。事实正确但依赖读者自行补前提，也判定不合格。

### 问题闭环专项抽查

章节审核不能只看目录和 frontmatter。对每批正文至少抽查以下问题：

- 标题中的“为什么 / 怎么 / 有什么区别 / 解决什么”是否真的被回答；
- 快速复习卡“作用/定位”是否和正文开头一致；
- 一个小标题若是问句，读者在得到结论前是否看清对象与矛盾，结论是否及时且自然，再解释原因；
- 文中举例所需的对象是否在例子开始前建立；
- 新术语是否先定义再参与后续推理；
- 当前笔记能否在不依赖聊天补充解释的情况下独立读懂。

发现这类问题时，不能只机械加一句过渡语；应判断是否是整篇叙事顺序错误，并按“前置与情境 → 实际矛盾 → 自然回应 → 解释 → 下一步”调整正文。

发现内容缺口时，先把对应 `unmapped / partial` Atom 转换成**独立主问题清单**，具体拆卡标准直接执行 `prompts/10-原子考点卡生成.md`。

## 五、考试优先级校准（P0–P3）

章节检查如果涉及 `exam_priority`，必须在**原子卡/Atom 实际考试能力层级**重新判断，不能把上位主题的优先级机械复制给所有子卡。

先执行 `prompts/00-全局写作规范.md` 的“考点范围与减负”门禁。这里进一步规定章节校准方法。

### 证据职责固定，不得混用

1. **现行考试大纲决定范围**：同时检查综合知识、案例分析和论文范围。大纲明确要求的内容不能仅因近年题少而删除。
2. **官方最新版教材决定展开深度**：大纲写上位概念时，以最新版教材判断其下位知识应学到哪一步。教材写得多也不意味着全部进入复习卡。
3. **近年真题决定优先级和考法**：优先看新版大纲实施后的真题/已核验回忆题，再结合可靠历史频次判断哪些考法值得投入时间。
4. **旧真题只作补充证据**：单个旧真题不能把边缘知识从 P3 提升为 P2/P1/P0，也不能据此要求补完整算法家族、产品列表或工程细节。
5. **前置关系只决定学习顺序**：不能单独把一个知识点升为 P1。

禁止把证据职责写成“真题决定范围”或“教材出现就必须全学”。一句话：**大纲定范围，教材定深度，近年真题定优先级。**

### P0–P3 判定

- **P0**：现行大纲范围内，原子考点在近年直接命中且仍有持续性，或历史高频并在新版大纲实施后仍活跃；必须优先拿分。
- **P1**：现行大纲明确或被其上位概念明确覆盖，官方最新版教材把它作为核心机制展开，并有重复考查/稳定经典题型证据；属于主线必学。
- **P2**：现行大纲内、最新版教材明确，但直接题频较低；或属于主线的辅助机制、分类项、第二轮知识。大纲明确要求“掌握/熟悉”但暂缺强近年题频时，也优先保留在 P2。
- **P3**：仅历史真题出现、现行大纲没有明确点名且最新版教材弱化/未系统展开；或属于教材较深扩展、当前直接题频低的内容。旧纲遗留/历史真题补充默认放这里，时间紧可跳过。

### 超纲与旧纲遗留判定

- **大纲没有逐字出现某术语，不足以判超纲。** 若大纲上位概念可以合理覆盖，且最新版教材明确展开，按大纲内处理。
- 大纲中的“基本原理 / 基本知识 / 相关技术”等宽口径条目，必须结合最新版教材判断边界，禁止仅靠关键词匹配。
- 只有“大纲缺少合理上位覆盖 + 最新教材未展开 + 仅旧真题/旧教辅支撑”时，才优先标记为“旧纲遗留/历史真题补充”。
- 近年回忆题若来源不稳定，只能作为观察信号，不能单独把边缘知识升级为 P1/P0。

### 强制减负门禁

- **单个旧真题不得单独升 P2 以上。** 如果一个知识点唯一证据是旧题，默认 P3，只补做懂该题型所需的最小知识。
- 一道旧题考到某算法时，不自动补它的全部同类算法；一道题出现某产品时，不自动补完整产品谱系。
- “可能会考”“教辅常讲”“网上题库有”不能成为新增原子卡或提高优先级的充分理由。
- 审核发现边缘知识过细时，优先**降级、删深度、删枝节、合并重复解释**；不要用新增更多笔记解决所有真题差异。
- 旧纲题可以保留链接或最小说明，但不得拿来判断用户对当前章节是否掌握。
- 如果现有卡片只由旧题支撑，却被标成 P0/P1/P2，必须降级并在 `priority_reason` 中写明“旧纲遗留/历史真题补充”。

其他硬门禁：

- “Cache 是 P1”不能推出“Cache 的所有子卡都是 P1”；“总线与 I/O 是 P1”同理。
- 连续一组原子卡几乎全部 P1 时，必须重新检查是否发生了**主题级优先级下放**。
- `priority_reason` 必须写出为什么这张**原子卡本身**处于该级别；禁止继续使用“历年常考或核心前置”这种无法区分主次的笼统理由。
- 校准后报告本章 P0/P1/P2/P3 数量、P0/P1 清单，并额外标出“大纲明确要求但近年低频”的保留项，以及“旧纲遗留/历史真题补充”的 P3 项，让用户能直接按梯度减负。

## 六、区分结构任务与正文任务

建立/更新 Atom ID、覆盖矩阵、主事实源登记、目录整理、重命名、死链、索引、frontmatter 小修、纯看板修复可以直接执行。

新增或大幅重写原子卡时：

- 追加读取 `prompts/10-原子考点卡生成.md`；
- 候选必须来自矩阵中的真实缺口或反向检查确认的重构任务；

## 七、推荐实施顺序

1. 建立/更新本章大纲原子项全集与稳定 Atom ID；
2. 完成“Atom → 主事实源 → 正文具体落点”的第一次正向映射，并标 `unmapped / partial / covered / link_only`；
3. 对当前正文集合执行反向检查，处理重复主事实源、胖卡和正文孤岛；
4. 执行 `65` 补齐教材证据和解释深度判断，结合真题校准实际考法；
5. 形成新增/补强/链接/合并降级/删除的修复清单；
6. 确认/创建真实子目录并修复 frontmatter、短链和旧完整路径；
7. 对需要正文修复的 Atom 按 `10` 执行样稿门禁和正文修改；
8. 回填每个 Atom 的正文具体落点与最终状态；
9. 补章节学习主线、章节知识库、学习路线与考前速记；
10. 最后依据真实目录同步 Excalidraw；
11. 更新总索引和全局导航；
12. 按 `66` 完成一次章节联合验收。

章节 Excalidraw 看板执行 `30` + `40`。

## 八、移动与批量操作

- 大规模移动/归档优先批量处理。
- 文件移动后至少检查短 wikilink、Markdown 旧完整路径、Excalidraw link、Dataview/脚本路径。
- 视觉重构、官方目录对齐、大规模正文重写等性质明显不同的任务分开实施。
- 批量修改正文前，覆盖矩阵必须先稳定到足以明确本批真实缺口；不得边猜大纲范围边批量生成。

4. 正向检查发现的漏项；
5. 反向检查发现的正文孤岛、重复主事实源、胖卡；

7. 每项删除的证据与替代入口；
