# 模块复习总纲生成

用于为章节下一个真实子目录生成 5～15 分钟快速复习总纲。总纲位于原子卡与全章考前速记之间，不是新的知识事实源。

## 读取范围

生成前读取：

- `AGENTS.md`、`prompts/00-全局写作规范.md`、`prompts/65-教材证据与笔记校验.md`；
- 目标模块全部原子卡或模块索引；
- 可用的考试大纲范围、标准化真题/近年趋势证据；
- 上一级章节知识库与全章考前速记；
- 相邻模块总纲。

复习总纲也遵守固定审查顺序：**考试大纲 → 真题 → 主教材 → 当前原子卡**。

- 大纲决定“这一模块哪些能力不能丢”；
- 真题决定“第一轮先抓哪些判断/计算动作”；
- 主教材只补到足够理解和做题的深度；
- 当前原子卡决定链接与复习路径。

只从已审核原子卡和章节知识库提炼。发现知识缺失时记录待完善项，不在总纲里假装补齐。

## 保存目录

- 综合知识模块总纲统一放在 `01_综合知识/00_复习总纲/<章节目录>/<模块目录>/`；
- 目录沿用原学习笔记编号与名称，不重新发明分类；
- 文件名统一为 `<模块名>-复习总纲.md`；
- frontmatter：`type: 考前速记`，`topic: 模块复习总纲`；
- 原学习目录通过短 wikilink 连接总纲。

## 固定内容

1. **用法**：预计复习时长；先闭卷，卡住再点原子卡。
2. **大纲边界 + 优先级**：先说明大纲要求到哪里；P0/P1 作为第一轮，P2 第二轮，P3 时间紧可跳过。
3. **30 秒主线**：3～6 句或紧凑链路，直接链接真实原子卡。
4. **题干关键词 → 第一反应**：优先表格，写“题干信号 → 判断/计算动作”，不是只列知识名。
5. **核心做题动作 / 必要公式**：默认先用自然语言和具体数字步骤。只有大纲、主教材或可靠真题明确要求且用公式明显更清楚时，才保留公式；公式必须说明用途、符号、单位、读法和适用条件。
6. **高频对比**：三种以上概念用“核心区分、典型例子、考试问法/陷阱”表格。
7. **最容易丢分的地方**：解释为什么错，不只给口诀。
8. **跨模块联系**：连接上一模块、下一模块或相关底层知识。
9. **闭卷自测**：按体量给 8～12 题，答案能在链接原子卡中找到。
10. **下一站**：沿复习主线前进，并能回到上一模块或全章入口。

## 表达要求

- 大模块约 10～15 分钟，小模块 5～8 分钟；不为统一长度重复内容。
- 不复制原子卡完整教学过程，不重新展开长例题。
- **禁止因为“是计算题”就自动生成公式区。** 能用“第一步算什么 → 第二步查什么 → 第三步得到什么”讲清楚的，优先不用公式。
- 确有必要保留的公式必须解释用途、符号、单位、读法和适用条件；`Σ`、取整、模运算、赋值等不直观符号首次出现要解释。
- 单位能够约掉或统一，明确提醒 bit/Byte、Hz/kHz、s/ms 等换算。
- 不把“上位主题高频”机械下放给每张子卡；总纲只把**原子级直接题眼**放进第一轮抓分区。
- 不创建重复 MOC；入口同步到上级章节知识库、现有模块索引和全章考前速记。
- 涉及可视化时直接执行 `prompts/40-Mermaid与Obsidian样式修复.md`，本文件不维护第二套节点数和布局规则。

## 验收

- 每个关键结论都有真实原子卡可回看；
- 每条被保留的公式都有明确来源必要性，并写明用途、符号中文含义、单位、中文读法和适用条件；
- 模块间下一站形成主线，上一站可返回；
- 上级索引能一跳进入全部模块总纲；
- 运行 `node scripts/check-vault.mjs` 与 `git diff --check`。
