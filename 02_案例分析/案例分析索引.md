## 先学会一种做题动作

案例分析最容易出现的问题不是“完全不知道知识点”，而是：题干给了很多背景，知道概念却不知道应该抓哪句话、答哪几个点。

当前统一做题链：

1. **先看问题在要求什么动作**：列举、判断、分析、比较、给策略、计算还是画图；
2. **再圈题干证据**：数字约束、故障现象、业务目标、已有方案、限制条件；
3. **把证据映射到已学知识**：例如性能、可用性、安全性、可修改性、数据库设计、架构风格等；
4. **按得分点输出**：先给结论，再贴题干证据，最后给理由、策略或步骤。

详细方法：[[案例分析通用答题框架]]。

## 已形成的八类代表答题动作

1. [[2009年下半年/试题一-在线交易平台质量属性]]：**题干证据 → 质量属性 → 架构策略**；同样是时间数字，先判断时间在量什么动作。
2. [[2009年下半年/试题五-B2C安全架构]]：**威胁层次 → 认证 → 授权侵犯/抗抵赖**；不能把完整安全架构压成防火墙和 IDS。
3. [[2010年下半年/试题二-集中式与分布式数据架构]]：**业务增长 → 数据架构选型 → 单点识别 → 读写路径 → Scale Up / Scale Out**。
4. [[2011年下半年/试题四-SOA与REST架构选型]]：**业务对象/数据特征 → 主要操作 → 服务还是资源 → 交互代价 → 约束匹配**；架构选型必须贴题干，不能背“某技术一定更好”。
5. [[2015年下半年/试题三-软件可靠性与容错设计]]：**可靠性问题层次 → 失效来源 → 故障处理动作 → 容错技术**；先理解为什么失效，再识别恢复块、N 版本、冗余、双机或集群。
6. [[2017年下半年/试题三-嵌入式实时约束与ROS通信模型]]：**领域约束 → 时间确定性 → 通信关系 → 控制面/数据面 → 通信模型**；先判断实时约束和交互语义，再落到 Topic、Service、Action 或发布/订阅。
7. [[2018年下半年/试题五-异构银行系统SOA与ESB集成]]：**异构现状 → 集成障碍 → 稳定服务契约 → ESB 转换/路由/解耦 → 安全横切保障**；先识别为什么旧系统难以直接协作，再说明集成基础设施具体消除了什么差异。
8. [[2016年下半年/试题四-应用服务器与N层电子商务架构]]：**业务增长/7×24 → 旧架构边界 → 公共运行能力 → N 层职责拆分 → 多节点扩展 → 故障接管**；先判断新问题是否已超过旧架构能力，再谈平台和部署。

## 真题来源边界

仓库已有 2009—2018 等年份的案例分析原始资料；AI 可读抽取层只能作为整理入口，**不能把自动抽取文本或解析资料直接包装成官方标准答案**。

案例整理统一执行：[[历年真题/真题索引]] 与 `prompts/60-历年真题解析与索引.md` 的来源、可信度和去重规则。

当前已使用的 2009、2010、2011、2015、2016、2017、2018 题面均来自“资料版（来源待核验）”，答案解析来自“真题解析资料（来源待核验）”。

## 为什么不机械按题号做

G5 优先建立**可复用答题能力样本**，不是为了把整卷搬进笔记。

2009 试题二、三、四存在数据流图、表格或系统示意图依赖；2010 试题一的比较表和架构图也存在文本抽取不完整问题。2011 试题四的第一问包含表格空格，但其三问的核心场景、比较维度和 REST 解析均能由文本层独立核验，因此本批只训练不依赖缺失表格内容的架构选型动作，不臆造表格答案。

## 案例页固定结构

从现在开始，所有正式案例训练页统一按这个顺序：

1. **原题在最前面**：先给题干和问题，不提前暴露答案；
2. **先独立作答**：题目涉及缺失图表时明确标记，不猜图、不补不存在的空格；
3. **再进入解析**：第一动作、题干证据、考点映射、资料答案要点；
4. **最后复盘**：答题骨架、易错点、理论回链和可复用动作。

G5-01～G5-08 均执行“**先题目，后解析**”；以后新增案例继续遵守同一规则。

## 做完一道题要留下什么

每个正式训练条目至少留下：

- **题目要求**：到底让你做什么；
- **题干证据**：哪些句子决定答案；
- **知识映射**：回链现有笔记，不复制一套新的综合知识库；
- **作答骨架**：答案怎么分点；
- **漏答/误判风险**：容易把什么看错；
- **来源属性**：原卷、解析资料、回忆版或待核验资料必须区分。
