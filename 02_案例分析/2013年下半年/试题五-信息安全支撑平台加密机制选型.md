# 2013 下半年试题五：加密方案要按业务约束选，不是先挑算法

## 原题｜先独立作答

> [!warning] 先做题，再展开后面的解析
> 以下题面按仓库“资料版（来源待核验）”整理，只做换行和排版，不改变问题要求。

某软件公司拟开发一套信息安全支撑平台，为客户的局域网业务环境提供信息安全保护。该支撑平台的主要需求如下：

1. 为局域网业务环境提供用户身份鉴别与资源访问授权功能；
2. 为局域网环境中交换的网络数据提供加密保护；
3. 为服务器和终端机存储的敏感持久数据提供加密保护；
4. 保护的主要实体对象包括局域网内交换的网络数据包、文件服务器中的敏感数据文件、数据库服务器中的敏感关系数据和终端机用户存储的敏感数据文件；
5. 服务器中存储的敏感数据按安全管理员配置的权限访问；
6. 业务系统生成的单个敏感数据文件可能会达到数百兆的规模；
7. 终端机用户存储的敏感数据为用户私有；
8. 局域网业务环境的总用户数在 100 人以内。

### 问题 1

在确定该支撑平台所采用的用户身份鉴别机制时，王工提出采用基于口令的简单认证机制，而李工则提出采用基于公钥体系的认证机制。项目组经过讨论，确定采用基于公钥体系的机制，请结合上述需求具体分析采用李工方案的原因。

### 问题 2

针对需求（7），项目组经过讨论，确定了基于数字信封的加密方式。请结合需求说明对文件数据进行加密时，应采用对称加密的块加密方式还是流加密方式，为什么？并对该机制中的数据加密与解密过程进行描述。

### 问题 3

对数据库服务器中的敏感关系数据进行加密保护时，客户业务系统中的敏感关系数据主要是特定数据库表中的敏感字段值，客户要求对不同程度的敏感字段采用不同强度的密钥进行防护，且加密方式应尽可能减少安全管理与应用程序的负担。目前数据库管理系统提供的基本数据加密方式主要包括加解密 API 和透明加密两种，请用 300 字以内的文字对这两种方式进行解释，并结合需求说明应采用哪种加密方式。

---

> [!summary]- 快速复习卡片（学完再看）
> **第一动作**：三问都不是“选最强算法”，而是**从需求和约束反推机制**——先圈出需求编号，再对号入座。
> **问题 1**：口令是双方共享的秘密、易受认证攻击；公钥体系私钥不上网、且能为用户私有数据提供独有秘密；用户规模 ≤100 且局域网，性能可接受 → 选公钥体系。
> **问题 2**：单个文件数百兆 → 数据量大 → 选**流加密**效率更高；数字信封＝对称密钥加密数据 ＋ 用户公钥加密该对称密钥存在文件头。
> **问题 3**：要“按字段配不同强度密钥”且“减少安全管理与应用负担” → 选**透明加密**（DBA 配置、DBMS 自动加解密；加解密 API 灵活但构建管理复杂）。
> **总判断**：这是一道“约束 → 机制选型”题，答案都能从需求编号里推出来。

## 这道题真正考什么

题干给的不是“请设计一个加密系统”，而是**一堆带编号的业务约束**：网络数据要加密、持久数据要加密、用户私有、文件可达数百兆、总用户 100 人以内、要减少安全管理与应用程序负担。三问分别把这些约束映射到三类选择上：

1. **身份鉴别**：口令认证还是公钥体系认证（问题 1）；
2. **文件数据加密方式**：块加密还是流加密，以及数字信封的加解密流程（问题 2）；
3. **数据库字段加密的实现方式**：加解密 API 还是透明加密（问题 3）。

所以本页训练的动作不是背算法参数，而是 [[案例分析通用答题框架]] 里的第一步：**先把题干约束圈出来并编号，再让每个约束去决定一个机制选择**。这也是它与 [[2009年下半年/试题五-B2C安全架构|2009 试题五]] 的区别：那一题考“威胁 → 认证 → 抗抵赖”的安全架构分层，这一题考“**约束 → 机制选型**”。

## 问题 1：先找口令的弱点，再证明公钥的代价可接受

**题干证据**：需求 (1) 要求身份鉴别与资源访问授权；需求 (7) 终端机数据为用户私有；需求 (8) 总用户数 100 人以内、局域网环境。

本题资料答案给三点：

| 资料答案要点 | 它在回答题干哪个条件 |
| --- | --- |
| 口令认证实现简单，但受口令复杂度与管理制约，**易受认证攻击**；公钥体系在认证过程中**私钥不在网络上传输**，可有效防止认证攻击 | 需求 (1)：要的是“可用于鉴别的认证机制”，不是“最简单的机制” |
| 口令是用户与认证服务器**共享**的，没有用户独有的直接秘密信息；公钥体系中可基于**用户私钥**保护用户私有数据 | 需求 (7)：终端机数据是用户私有的，需要“只有本人能解开”的能力 |
| 公钥体系协议与计算更复杂、开销高于口令，但**用户数在 100 人以内、又是局域网**，效率可接受 | 需求 (8)：用规模和网络环境论证“代价可接受” |

### 第一动作

看到“为什么采用某方案”，不要只写“公钥更安全”。本题的得分点是**两段式论证**：先指出被否方案的弱点（口令易受认证攻击、且无用户独有秘密），再用题干给的规模/环境条件论证新方案的代价可接受。相关机制回看 [[非对称加密]] 与 [[身份认证]]。

> [!important] 别把旧题答案扩成现代认证规范
> 现在学习 [[身份认证]] 时应掌握“所知／所有／所是”与多因素认证等通用框架；但答这道旧题时，先按资料给的三点组织，不要把后来的工程口径冒充原题答案。

## 问题 2：先按数据量选加密方式，再描述数字信封

**题干证据**：需求 (7) 数据为用户私有且需要加密保护；需求 (6) 单个敏感数据文件可能达到数百兆。

资料答案明确：**应采用流加密方式**，理由是文件数据量较大，使用流加密可以获得更高的加解密效率。

**数字信封的加解密过程**（资料答案原文口径）：

- 加密：首先生成一个**对称密钥**，使用**用户公钥**加密这个对称密钥后存放在**文件头**，然后用生成的对称密钥加密文件数据存储；
- 解密：用户首先使用**自己的私钥**解密被加密的对称密钥，再用该对称密钥解密出数据原文。

这个结构就是 [[对称加密]] 与 [[非对称加密]] 的分工：非对称加密只用来保护那把短小的对称密钥，真正的大数据量交给对称加密。

### 第一动作

题干出现“文件大小／数据量”时，先把加密方式的效率差异当第一判据；出现“数字信封”时，直接按“**对称密钥加密数据 ＋ 用户公钥加密对称密钥**”两段写，并说明对称密钥存在文件头。

> [!warning] 别把“流加密”背成绝对结论
> 资料答案的判据是**本题的数百兆文件规模**。答题时要把这条需求编号带上，不要写成“文件加密一律用流加密”。

## 问题 3：两种实现方式不是比安全强度，而是比“管理负担”

**题干证据**：需求 (5) 敏感数据按安全管理员配置的权限访问；客户要求不同敏感字段用不同强度的密钥；并要求**尽可能减少安全管理与应用程序的负担**。

资料答案对两种方式的界定：

| 方式 | 资料答案含义 | 代价 |
| --- | --- | --- |
| 加解密 API | DBMS 提供可在 SQL 语句中调用的加解密 API，应用利用这些 API 构建自己的基础架构并对数据加密保护 | **灵活性强，但构建和管理复杂** |
| 透明加密 | 安全管理员为数据库敏感字段选择加密方式与密钥强度；应用只需使用口令打开或关闭密钥表，加密解密由 DBMS 自动完成 | **管理简单、应用程序负担轻，但灵活性较差** |

需求要求“尽量减少安全管理与应用程序的负担”，因此资料答案选择**透明加密**。相关背景可回看 [[数据库安全与完整性设计]] 与 [[信息安全范围与存储安全]]。

### 第一动作

看到“两种方式选一个 + 要求减少负担”，先按**管理成本**建立对照表，再让题干的条件去决定。这里的陷阱是去比两种方式的加密强度——题干根本没有在问强度，问的是配置与运维负担。

## 本题的稳定答题动作

把三问放在一起看，这道题只训练一个可复用的动作：

1. **圈约束并编号**：把题干里带编号的需求逐条圈出，标出每条是“安全目标”还是“现实条件”（规模、数据量、用户数、管理要求）。
2. **一句约束对一个选择**：认证机制 ← 用户私有与规模；加密方式 ← 数据量；字段加密实现 ← 管理负担。
3. **被否方案也要写弱点**：凡是“为什么不用 A 而用 B”，都要写出 A 的具体弱点，而不是只夸 B。
4. **代价要论证可接受**：当新方案有明显代价（计算复杂、开销高）时，用题干给出的规模/环境条件说明它可接受。
5. **不越界**：题干没问强度的地方不比强度，题干没给的算法参数不写。
