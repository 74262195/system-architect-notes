# 数据导向与流程导向架构：先抓数据还是先抓业务流程

> [!summary]- 快速复习卡片（学完再看）
> **数据导向**：先把数据对象、关系和质量理清，常从主题域 → 业务对象 → 对象关系 → 数据模型切入。
> **流程导向**：先把端到端业务流程理清，常从价值链 → 流程分析/分解 → 业务组件 → 服务与流程编排切入。
> **典型倾向**：MDM/数据中心偏数据导向；SOA 偏流程导向。
> **易错点**：两者不是二选一；流程传递数据，数据也有产生、变更、分发等流程，最终需要互补。

上一站 [[信息化总体架构：建设时为什么不能只看功能]] 说明了信息化建设不能只盯功能。真正开始规划总体架构时，还要选一个切入口：

> 企业系统很多、数据也很多，应该先统一“数据是什么”，还是先统一“业务怎么流转”？

**数据导向先从数据对象和关系入手；流程导向先从端到端业务流程入手。两者关注点不同，但最终必须结合。**

## 用“客户下单”看两种切法

假设销售、仓库、财务系统都保存了“客户”和“订单”，但字段定义不一致，流程也互相断开。

### 数据导向：先问“这些数据到底是什么”

它会先处理：

1. 哪些主题域需要统一，例如客户、订单、商品；
2. 每个主题域有哪些业务对象；
3. 对象之间是什么关系；
4. 形成概念模型，再逐步落到逻辑模型和物理模型；
5. 继续管理数据的产生、变更、使用和废弃。

所以它的核心关注是：**数据模型、数据关系和数据质量。**

题干如果突出“统一客户视图、主数据、数据质量、数据模型”，第一反应偏向数据导向。

### 流程导向：先问“这件业务从头到尾怎么走”

它会先处理：

1. 从企业价值链找到关键业务；
2. 分析和分解端到端流程；
3. 划分承担职责的业务组件；
4. 从组件关系中识别可提供的服务；
5. 通过服务和流程编排把跨系统业务串起来。

所以它的核心关注是：**端到端流程整合，以及架构能否适应流程变化。**

题干如果突出“跨部门流程、服务组合、流程编排、端到端整合”，第一反应偏向流程导向。

## 为什么不能只选一种

如果只做流程导向，可能把每个接口的数据定义好，却没有企业级统一数据模型，最后出现：

- 同一个“客户”在不同服务里含义不同；
- 数据质量问题没有统一治理；
- 组合多个服务时数据难以复用。

反过来，如果只做数据导向，把数据模型整理得很漂亮，却不考虑数据怎样在真实业务流程中产生、变化和分发，也无法支撑完整业务。

因此教材强调：**两种架构没有严格边界，是相互配合和补充的。**

可以用 MDM 与 SOA 建立考试直觉：

- MDM（主数据管理）更偏数据导向，擅长统一数据、质量和视图；
- SOA 更偏流程导向，擅长通过服务支持跨系统流程组合；
- SOA 不能单独替代数据质量治理，MDM 也不能单独替代服务化的实时分发与流程协作。

## 考试怎么判断

看到题干先圈“主要矛盾”：

| 题干主要在抱怨什么 | 第一判断 |
| --- | --- |
| 数据定义冲突、主数据不一致、质量差 | 数据导向 |
| 跨系统业务断裂、流程变化难适应 | 流程导向 |
| 既要统一数据又要跨系统协同 | 两者结合 |

不要看到“SOA”就直接回答“所有问题都由流程导向解决”。如果题干的核心矛盾是统一数据和数据质量，仍需要数据导向能力。

## 自测

1. 多个系统中的“客户编号”含义不同，导致统计结果互相矛盾，第一步更适合哪种架构切入？

> [!answer]- 第 1 题答案与解析
> **答案**：数据导向。
> **解析**：主要矛盾是数据对象定义、关系和质量不统一。

2. 企业希望把“下单 → 库存确认 → 发货 → 开票”跨系统串成完整流程，第一步更偏哪种架构？

> [!answer]- 第 2 题答案与解析
> **答案**：流程导向。
> **解析**：题干重点是端到端流程整合和跨系统协作。

3. 为什么数据导向和流程导向不是互斥方案？

> [!answer]- 第 3 题答案与解析
> **答案**：因为流程运行时必须传递和修改数据，而数据本身也要经历产生、变更、使用和分发过程。
> **解析**：两者观察同一企业信息系统的不同侧面，实际建设需要互补。
