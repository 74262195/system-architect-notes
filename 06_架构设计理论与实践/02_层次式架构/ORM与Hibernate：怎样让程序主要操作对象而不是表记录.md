# ORM与Hibernate：怎样让程序主要操作对象而不是表记录

> [!summary]- 快速复习卡片（学完再看）
> **ORM**：在程序对象和关系数据库记录之间建立映射。
> **直接价值**：减少重复的数据访问代码，让开发者更多面对对象。
> **Hibernate**：教材列举的 Java ORM 框架，提供对象与表的映射及持久化服务。
> **CMP 2.0**：EJB 2.0 的容器管理持久化；部署描述符声明持久字段，容器负责映射和保存；2.0 还增加实体 Bean 间的容器管理关系。

## 为什么“保存一个订单”常常会写出很多重复代码

程序里通常按“订单对象”处理数据：有订单号、商品、金额和状态；关系数据库里却按表、行和字段保存。若每次保存、读取、删除对象都手写相似的数据访问代码，业务开发很容易被重复的细节淹没。

**ORM 的直接答案是：建立对象和关系数据库记录之间的对应关系，让程序主要按对象操作，框架负责完成必要的数据转换。**

ORM 是 Object-Relation Mapping 的缩写。它不是不要数据库，也不是完全不需要理解数据；它解决的是对象表示和关系表示之间的转换工作。

## 保存和读取怎样经过映射

```mermaid
flowchart LR
    A[订单对象] --> B[ORM 映射规则]
    B --> C[订单表中的记录]
    C --> B
    B --> A
```

当程序保存订单时，ORM 根据映射规则把对象属性转换为表中的记录；读取时再把记录恢复为程序可操作的对象。教材将这种转换描述为“对象到关系数据库记录”以及反向转换。

因此，ORM 的重点不是把 SQL 这个词藏起来，而是把重复的持久化细节交给映射层，使业务代码能更集中于业务功能。

## Hibernate 在这里是什么

教材把 Hibernate 作为开放源代码的对象关系映射框架示例：它对 JDBC 做对象层面的封装，提供 Java 类与数据表的映射，以及数据查询和恢复机制。

第一次学习不必背它的配置文件或 API。做题时只要能判断：

- 对象和表之间映射 → ORM；
- 题干点名 Java、Hibernate、JDBC 的对象封装 → Hibernate 是 ORM 框架示例；
- 业务层不想重复编写大量 CRUD 访问代码 → ORM 解决的正是这种重复。

## CMP 2.0 是谁替实体 Bean 保存数据

把一个雇员实体 Bean 的姓名和工资存进数据库时，开发者可以自己写保存和读取逻辑，也可以把持久化工作交给 EJB 容器。CMP 是 Container-Managed Persistence（容器管理持久化）：开发者在部署描述符中声明哪些实体字段要持久化，容器据此把实体状态映射到数据库并负责保存。相对地，BMP（Bean-Managed Persistence，Bean 管理持久化）由 Bean 实现代码自行处理存取。

EJB 2.0 的增量识别点是 CMR（Container-Managed Relationships，容器管理关系）：除了持久字段，描述符还可声明实体 Bean 之间的一对一或一对多关系，由容器管理这些关系及其引用完整性。用订单和订单明细理解：实体对象之间有关联，CMR 让旧版 EJB 容器按声明管理这种关系；这仍是特定 EJB 技术里的持久化设计，不是 ORM 的通用同义词，也不是 Hibernate 的别名。细节见 [Oracle EJB 2.0 CMP 迁移说明](https://docs.oracle.com/cd/E19159-01/819-3676/abmcm/index.html) 和 [Oracle CMP Entity Beans 指南](https://docs.oracle.com/cd/A97688_16/generic.903/a97677/cmp.htm)。

## ORM 也有边界

ORM 可以减少重复代码和隔离一部分存储细节，但不代表所有性能、查询设计或数据建模问题会自动消失。教材也指出，Hibernate 虽灵活，体系结构会较复杂，并有不同运行方式。复杂查询场景可能需要更直接地控制 SQL；ORM 是否满足性能要求，应按具体工作负载验证，不能只凭“ORM”这个名称断定快或慢。

所以题干若强调“对象与表的映射、减少重复持久化代码”，选 ORM；若只是问“数据库连接怎么创建”，应回到工厂或其他数据访问设计，而不是泛选 ORM。

## 考试怎样判断

先抓三个识别点：

- **对象 ↔ 关系数据库记录** → ORM；
- **Java 对象封装、Hibernate、JDBC 映射** → Hibernate。
- **EJB 2.0、部署描述符、CMP/CMR** → 容器管理持久字段或实体关系；与由 Bean 自己编写存取逻辑的 BMP 区分。

### 方案选择题怎样答

2017 年下半年综合知识题干给出“程序员缺少数据库开发经验、应用简单”，要求比较在线访问与 ORM 并说明选择理由。该标准化资料标注解析来源待核验，因此这里依据可读题干训练分析，不把附带解析当成已核实的标准答案：先指出直接 SQL 能直接表达复杂查询、控制空间较大，但团队需要 SQL 能力并承担更多访问代码维护；ORM 用对象映射减少重复代码和 SQL 编写负担，适合题干中的经验不足与简单应用。若应用后来出现复杂查询、数据库特性深度利用或性能瓶颈，再按实际需求评估 SQL 映射或直接 SQL；不要把任何一方概括为永远更快或更好。

## 自测

1. 程序对订单对象进行保存，框架把对象属性转换成订单表记录。这体现了什么？

> [!answer]- 第 1 题答案与解析
> **答案**：ORM。
> **解析**：ORM 的核心是程序对象与关系数据库记录之间的映射和相互转换。

2. Hibernate 在教材本节中主要作为哪一类技术的例子？

> [!answer]- 第 2 题答案与解析
> **答案**：对象关系映射框架。
> **解析**：教材说明它提供 Java 类与数据表之间的映射，并提供数据持久化相关能力。

3. EJB 2.0 中，部署描述符声明了实体 Bean 的持久字段；若还声明两个实体 Bean 的关系，分别对应什么机制？

> [!answer]- 第 3 题答案与解析
> **答案**：持久字段由 CMP 管理；实体 Bean 之间的关系由 CMR 管理。
> **解析**：CMP 是容器管理实体数据持久化；EJB 2.0 的 CMR 扩展到实体 Bean 间关系，由容器管理已声明的关系。二者属于 EJB 2.0 语境，不应与 Hibernate 名称互换。

4. 某小型应用的团队缺少数据库开发经验，题干也没有复杂查询需求。比较直接 SQL 与 ORM 时，至少应说明哪两项取舍？

> [!answer]- 第 4 题答案与解析
> **答案**：直接 SQL 对查询表达和数据库控制更直接，但要求 SQL 能力并需维护访问代码；ORM 能降低重复映射代码和 SQL 编写负担，但复杂查询或性能要求仍需具体验证。
> **解析**：把选择理由绑定到题干给出的团队能力和应用复杂度，不把性能结论泛化为所有系统都成立。
