# XML 统一界面描述：为什么一份配置能生成不同界面

> [!summary]- 快速复习卡片（学完再看）
> **问题**：同一功能同时要支持网页和桌面窗口，两套界面容易重复维护。
> **做法**：用 XML 记录控件、属性和层次，再由不同解析器生成目标界面。
> **核心价值**：维护一份与具体界面技术无关的描述。
> **边界**：XML 描述“界面是什么样”，不负责业务规则。

## 为什么不直接写两套界面

假设同一个办事系统既要提供网页，又要提供桌面窗口。两边都有“申请人”输入框和“提交”按钮。如果各写一套，增加一个输入项时就必须同时修改两处，还可能出现一边已更新、另一边忘了改的情况。

**XML 统一表现层的思路，是先用一份通用数据描述界面，再把这份描述转成网页或桌面窗口。**

## XML 在这里记录什么

这里不需要先学会编写 XML。只需知道，XML 可以把界面元素当成数据记录：

- 这是按钮还是输入框；
- 它显示什么文字；
- 它放在什么位置；
- 它是否可见；
- 它属于哪个容器，与其他控件是什么层次关系。

因为 XML 能表示树形层次，所以可以描述“面板里面有按钮”这种包含关系。

## 一份描述怎样变成不同界面

1. 界面开发人员维护一份 XML 界面描述；
2. 网页解析器读取它，生成网页中的输入框和按钮；
3. 桌面窗口解析器读取同一份描述，生成对应的窗口控件。

同一个“提交按钮”在不同平台上可以由不同技术实现，但它们来自同一份界面描述。因此，新增一个字段时，首先修改统一描述，而不是手工在每种界面里重复加一次。

## 它解决什么，不解决什么

| 它负责 | 它不负责 |
| --- | --- |
| 描述控件、属性和层次 | 判断申请是否符合业务规则 |
| 让不同解析器生成不同表现形式 | 替代业务层或数据库 |
| 减少多平台界面描述的重复维护 | 保证任何复杂界面都能无成本跨平台 |

教材把这种“根据目标表现技术选择对应解析器”的思路归入策略模式。考试时如果问机制，先抓住“**统一描述 + 不同解析器**”，不要被具体平台名称带跑。

## 自测

1. 一套系统希望只维护一份界面描述，再生成网页和桌面窗口。XML 在其中的主要作用是什么？

> [!answer]- 第 1 题答案与解析
> **答案**：以通用数据形式描述界面控件、属性和层次，供不同解析器转换为目标界面。
> **解析**：题眼是“一份描述”和“多种表现形式”。

2. XML 界面配置能否代替“优惠券是否有效”的业务判断？

> [!answer]- 第 2 题答案与解析
> **答案**：不能。
> **解析**：XML 在本考点中负责描述界面，业务规则仍由业务处理部分承担。
