# 数据库连接池：连接用完为什么通常要归还而不是关闭

> [!summary]- 快速复习卡片（学完再看）
> **数据库连接**：程序与数据库通信时使用的通道。
> **连接池**：预先准备并统一管理一批可复用的连接。
> **核心动作**：申请时借出空闲连接；用完后归还池中；不要每次访问都新建并彻底关闭连接。

## 为什么每次查一条数据都重新连数据库会慢

程序要查询订单，先要建立数据库连接。若每个请求都重新建立连接、用完马上销毁，系统会不断支付分配和释放资源的开销；并发请求多时，这种开销会直接影响性能。

**连接对象管理的直接答案是：把可共享的数据库连接放入连接池，按规则分配、使用和归还。**

教材把资源池描述为解决共享资源频繁分配、释放问题的设计模式；把它用于数据库连接，就是数据库连接池。

## 一条连接怎样被借出和归还

```mermaid
flowchart LR
    A[系统初始化：按配置创建连接] --> B[连接池中的空闲连接]
    B --> C[请求数据库连接]
    C --> D{有空闲连接吗？}
    D -->|有| E[标记已分配并借出]
    E --> F[执行数据访问]
    F --> G[归还池中，等待复用]
    D -->|没有| H[按池的分配策略处理]
```

教材的静态连接池做法是：系统初始化时按配置创建一批连接放入池中；后续访问从池中取得连接。客户端释放连接时，如果没有使用者，应把它放回池中，而不是关闭。这样可以减少反复建立和关闭的开销。

## “没有空闲连接”时，不是随便拿一条

连接池不仅是一个装连接的容器，还必须有分配和释放策略。教材说明，分配时要识别池中未分配的连接并标记已分配；没有空闲连接时，由既定策略决定后续处理。

零基础做题只需守住这条边界：**连接必须被统一管理，不能让多个请求不受控制地同时占用同一条连接。**题干若只说“连接池能复用连接、减少频繁创建和关闭开销”，就是本考点；具体的等待队列、超时或扩容策略，题干没有给出时不自行假定。

## 它和事务、工厂模式怎么分工

| 问题 | 应想到什么 |
| --- | --- |
| 多步修改怎样一起成功或一起撤销 | [[事务处理：多步修改失败时怎样回到原状|事务处理]] |
| 数据库类型变化时怎样选择相应的数据访问实现 | [[数据访问层工厂模式：换数据库时为什么调用方不用改一片|工厂模式]] |
| 怎样反复、高效地取得数据库通信通道 | 连接对象管理 / 连接池 |

连接池可以为事务提供需要的连接，但“借到连接”不等于事务边界已经设计正确；事务仍要明确何时提交、何时回滚。

## 考试怎样判断

先抓住题干中的动作：

- 系统启动时创建一批连接、请求时取用、用完归还 → 连接池；
- 减少频繁建立和释放共享资源的开销 → 资源池思想；
- 多条 SQL 要么全成功要么回滚 → 事务，而不是连接池。

## 自测

1. 系统把若干数据库连接预先创建好，请求到来时借出，用完后放回。这是什么设计？

> [!answer]- 第 1 题答案与解析
> **答案**：数据库连接池。
> **解析**：它通过复用连接减少频繁建立、关闭连接的开销。

2. 连接池能否替代事务的提交和回滚设计？

> [!answer]- 第 2 题答案与解析
> **答案**：不能。
> **解析**：连接池管理的是连接资源；事务管理的是一组数据修改的整体成败。
