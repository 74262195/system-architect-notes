# 表现层动态生成：怎样用配置在运行时生成和定制界面

> [!summary]- 快速复习卡片（学完再看）
> **核心思路**：把界面长什么样写进配置，程序运行时再读取配置并生成界面。
> **三部分**：界面配置负责初始定义；动态生成负责构造界面；界面定制负责保存用户调整。
> **直接价值**：修改配置即可调整界面，减少界面描述与功能代码的绑定。
> **题眼**：XML 配置、元数据、运行时生成、菜单/工具栏定制并保存。

## 为什么不在代码里把界面全部写死

假设同一套管理系统要提供给柜台人员、审批人员和管理员使用。三类用户需要的菜单和按钮不同。如果每种界面都直接写在代码里，调整一个菜单也可能要修改和重新发布程序。

**动态生成的直接答案是：把界面描述放进配置文件，程序运行时再根据配置创建界面元素。**

## 三个部分怎样配合

```mermaid
flowchart LR
    A[XML配置] --> B[读取元数据]
    B --> C[生成界面]
    C --> D[用户定制]
    D --> A
```

1. **界面配置**：先在 XML 配置中写好初始菜单、工具栏、文字、位置等界面信息。这是界面的静态初始定义。
2. **界面动态生成**：程序运行时读取 XML 中的界面信息，同时读取界面要显示的业务数据，然后创建实际界面元素。
3. **界面定制**：程序运行时，用户可以调整菜单、工具栏、快捷键、图标或位置。退出时保存结果，下次启动再恢复。

图中最后的回箭头表示：用户定制结果被保存后，会成为下次生成界面时的配置输入。

## 一次运行时生成过程

以“审批人员界面”为例：

1. 程序启动后读取该角色的 XML 配置；
2. 配置说明审批人员需要“待审批”菜单，但不需要“系统设置”菜单；
3. 动态生成模块按配置创建对应菜单和列表，并把待审数据填入列表；
4. 用户把常用的“通过”按钮移到工具栏前端，系统保存这项定制；
5. 下次启动时，系统根据初始配置和用户已保存的定制重新生成界面。

## 与“XML 统一界面描述”有什么不同

| XML 统一界面描述 | 表现层动态生成 |
| --- | --- |
| 关心“一份界面描述如何转成不同平台界面” | 关心“程序运行时怎样根据配置生成和定制界面” |
| 关键是通用描述 + 不同解析器 | 关键是配置 + 动态生成 + 运行时定制 |

两者都可以使用 XML，但主问题不同。做题时，看到“多种表现技术”优先想统一描述；看到“运行时、配置、定制并保存”优先想动态生成。

## 自测

1. 系统启动时读取 XML 配置，根据用户角色创建不同菜单。这个过程的核心思想是什么？

> [!answer]- 第 1 题答案与解析
> **答案**：表现层动态生成。
> **解析**：界面没有全部写死在代码中，而是在运行时根据配置生成。

2. 用户在运行时修改工具栏位置，退出后系统保存了修改结果。这属于三个部分中的哪一个？

> [!answer]- 第 2 题答案与解析
> **答案**：界面定制。
> **解析**：它发生在运行过程中，由用户按习惯修改界面并保存结果。
