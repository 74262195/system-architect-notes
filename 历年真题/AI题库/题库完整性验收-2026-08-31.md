## 2024–2025 恢复后的流水线状态

### 并发取消根因与修复

- 2026-08-31 本轮排查确认：前几次 `Extract exam text` 并非脚本报错，而是被 `concurrency.cancel-in-progress: true` 取消；
- 连续恢复/移动 PDF、DOCX 时，每个新提交都会触发一次 OCR，后一个 run 会取消前一个正在运行的全量 OCR；
- 已将工作流改为 `cancel-in-progress: false`；
- 同时移除“修改 workflow 文件本身就自动触发 OCR”的 push path，保留 `workflow_dispatch` 手动测试；
- 当前正在运行的 OCR 基线已经直接核验为 **56 个 PDF/DOCX**。


当前 Git 树已直接核验为 **56 个 PDF/DOCX**；`历年真题/AI题库/抽取报告.md` 仍记录 **52 个原始资料**，而恢复 5 个历史原件路径后当前应为 **56 个路径**。

因此：

- 不手工修改自动生成的 `抽取报告.md`；
- 本轮已通过一次 workflow 文件触发提交启动抽取条件；截至本验收更新时尚未看到新的自动生成提交，因此不能把 OCR 刷新视为已完成；
- 在工作流重新运行前，2024–2025 恢复原件的“自动抽取完成”不能视为已验收。
