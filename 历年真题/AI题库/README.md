# AI 题库说明

这个目录是 **AI 可读层**，不是原始真题存档。

原始 PDF / DOCX 继续保留在 `历年真题/` 下，并通过 Git LFS 管理；AI 题库只保存从原件抽取、去重、结构化后的 Markdown。

## 三层结构

1. **原始资料层**
   - 位置：`历年真题/**/*.pdf`、`历年真题/**/*.docx`
   - 作用：保留原始证据。
   - 原则：不因为 AI 解析而改写原件。

2. **原始文本层**
   - 位置：`历年真题/AI题库/原始文本/`
   - 生成方式：`scripts/extract-exam-text.py`
   - 作用：把 LFS 中的 PDF/DOCX 转成 ChatGPT、Codex、Obsidian 可直接读取的 Markdown。
   - 注意：这是自动生成层，不建议手工修改。

3. **标准化题库层**
   - 建议位置：`历年真题/AI题库/标准化题库/`
   - 由 AI 按 `prompts/60-历年真题解析与索引.md` 处理。
   - 作用：按年份、科目、题号整理题目、答案、解析、知识点、对应笔记和来源可信度。

## 自动抽取

GitHub Actions 工作流：

`.github/workflows/extract-exam-text.yml`

会在以下情况运行：

- `main` 中新增或更新真题 PDF/DOCX；
- 抽取脚本本身发生变化；
- 手动触发工作流。

工作流会：

1. 拉取 Git LFS 原件；
2. 安装 PDF 文本抽取工具；
3. 运行 `scripts/extract-exam-text.py`；
4. 生成 `原始文本/*.md` 和 `抽取报告.md`；
5. 将生成结果提交回 `main`。

## 扫描版 PDF

如果 PDF 没有文字层，脚本会把它标记为：

`extract_status: "需OCR"`

并在 `抽取报告.md` 中列出。

这类文件不要直接拿空白抽取结果做知识覆盖判断，需要先 OCR。

## 后续 AI 处理原则

- 正式资料、回忆版、网友版、整理版必须区分。
- 不根据回忆版内容杜撰“官方原题”。
- 汇总版和逐年版可能重复，建立统计前必须去重。
- 真题频次统计以“独立题目”为单位，不以文件出现次数为单位。
- 答案解析与题目来源可来自不同文件，但必须分别记录来源。
- 真题应映射到已有 Obsidian 原子笔记，不随意创建同义知识点。
