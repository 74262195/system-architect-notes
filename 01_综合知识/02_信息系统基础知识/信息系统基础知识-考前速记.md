## 3. 核心公式与最小流程

本章没有独立的公式型考点，只有 [[ERP的概念]] 计划链里出现的可手算数量关系；卡片已把下面这套算法标为简化教学假设（原料开工前到齐、不设安全库存、按净需求补料，省略提前期与批量规则）：

$$\text{净需求} = \text{毛需求} - \text{可用库存} - \text{已确认到货} \qquad \text{能力缺口} = \text{需求工时} - \text{可用能力}$$

- 变量口径：毛需求、库存、到货以“件”为单位，需求工时与可用能力以“小时”为单位；算出 MRP 后还要用 CRP 比较负荷，**发现超载必须反馈调整计划，不能只算缺口就当计划可执行**。
- 开发五步链：总体规划 → 系统分析 → 系统设计 → 系统实施 → 系统验收。
- ERP 计划链：销售预测/订单 → 经营计划与生产计划大纲 → MPS → MRP → CRP → 车间作业、采购与库存，财务同步反映成本与资金。
- TPS 处理周期：数据输入 → 业务处理 → 数据库维护 → 文件与报表生成 → 查询处理。
- ES 推理循环：输入事实 → 写入工作存储 → 匹配知识库规则 → 选择并执行规则 → 得到目标结论则输出结论与解释，否则继续匹配。
- BI 处理链：数据准备 → 分析存储 → OLAP/数据挖掘 → 报表与可视化（卡片说明这是学习框架，不是唯一固定技术栈）。
- EAI 集成链：集成层做协议与数据格式转换、路由、调用或消息传递；流程层处理步骤顺序和异常，必要时定义重试、补偿与幂等。

## 4. 易错陷阱：为什么容易错

- **“信息化 = 买硬件或上软件”**：选项常列服务器、数据库和软件选型，看上去像在规划；但企业信息化要求技术从战略、业务运作和管理运作推导，孤立的技术采购不等于完整信息化。
- **诺兰模型 vs 信息系统生命周期**：两者都在讲“阶段”，所以容易对调；分界是描述对象——组织的信息化成熟过程，还是单个系统的一生。
- **把维护写成第五个宏观阶段**：教材把需求分析放在产生阶段，维护属于运行阶段，五步只是开发阶段内部的展开。
- **用“画了图”判断分析还是设计**：ER 图偏设计、DFD 偏分析只是初步识别；真正要看图表达的是业务逻辑还是技术实现。
- **TPS 一律说“实时性极高”**：TPS 也能采用批处理（工资、集中账务），要用“能否等待”区分批处理与联机事务处理。
- **把“七大原则”背成固定七项**：教材展开的是四项基本原则，创新性、整体性、发展性和经济性属于其他原则。
- **把敏捷理解成不要计划与文档**：四项价值观是“更重视”左侧，右侧仍有价值，只是靠短周期反馈及时修正。
- **把“尽早规划测试”当成左侧阶段已执行测试**：V 模型强调测试依据与开发阶段对应，不等于需求阶段已经跑完测试。
- **把数据/接口/流程/界面当唯一固定的四层技术栈**：教材同时还用面向信息、面向过程、面向服务描述集成技术的演进，两组分类不能混成唯一层级。
- **ERP 只当财务软件，或把各部门软件装到同一台服务器**：ERP 的关键是物流、资金流、信息流联动，并把范围延伸到供应链。
- **“界面集成成本低”就推出已经整合**：界面集成只统一入口，底层数据和业务逻辑可能仍未真正打通。

## 5. 高频对比

### 五类传统信息系统

| 系统 | 核心区分 | 典型题眼 | 考试陷阱 |
| --- | --- | --- | --- |
| TPS | 记录并处理重复、结构化的日常业务 | 订单、收付款、出入库、批处理/联机 | 一看到报表就选 TPS；还要看是否加工成管理信息 |
| MIS | 汇总加工信息，为各层管理活动提供信息服务 | 功能/层次矩阵、七个基本子系统 | 把 DSS、ERP、OAS 混成 MIS 的七个子系统 |
| DSS | 用数据和模型帮决策者比较方案 | 模型库、What-if、半结构化 | 说系统自动替管理者拍板 |
| ES | 用领域知识与推理求解特定领域问题 | 知识库、推理机、解释程序 | 只凭“问题复杂”判断；要看知识与推理 |
| OAS | 综合处理文字、数据、声音、图像等办公信息 | 公文、档案、会议、四类组成 | 题干出现“辅助决策”就判成 DSS |

### 四种教材内开发方法

| 方法 | 核心区分 | 更适合的情况 |
| --- | --- | --- |
| 结构化方法 | 阶段控制 + 自顶向下分解 + 文档与审查 | 业务成熟、需求较稳定 |
| 原型法 | 可体验模型 + 用户反复试用评价 | 用户起初说不清需求 |
| 面向对象方法 | 围绕对象、类、状态、行为与协作组织问题域 | 要让数据和行为围绕对象组织 |
| 面向服务方法 | 能力封装为服务，调用者依赖稳定的服务契约 | 跨应用互操作与复用能力 |

> 敏捷、瀑布、V 模型属于软件过程与生命周期模型的交叉内容，**不是**上面这四种信息系统开发方法的同一套分类；本章只区分口径，不比较各过程模型细节。

### 最容易混的几组概念

| 对比 | 核心区分 |
| --- | --- |
| [[4大阶段]] vs [[诺兰模型]] | 前者描述单个系统的一生，后者描述一个组织的信息化成熟过程 |
| 系统分析 vs 系统设计 | 分析回答“要做什么”（业务逻辑），设计回答“怎样实现”（技术方案） |
| [[企业信息化的概念]] vs [[企业信息系统战略规划方法]] | 前者是企业信息化要同时改哪些层面（战略/业务运作/管理运作），后者是规划信息系统可采用的方法（CSF/SST/BSP） |
| [[ERP的概念]] vs [[企业应用集成EAI]] | ERP 用统一计划管理企业资源三流，EAI 让已有异构应用交换信息、协同流程；二者可配合但不是同一概念 |
| 电子政务过程模式 vs 技术模式 | 过程模式管“服务与业务怎样组织”（用户中心、CRM 思想、门户），技术模式管“靠哪些技术管理方式支撑”（网络、信息资源、应用、安全、标准化） |
| [[电子商务]] vs [[电子政务分类]] | 前者核心是市场交易，后者核心是政府管理与公共服务；企业纳税走政务，采购销售走商务 |

> [!warning] 语境提示
> 五类传统系统、诺兰六阶段、三网一库和基于 XML 的电子商务标准都是**教材与考试语境下的识别模型**：现实产品功能会交叉，作答时按题干强调的主要管理对象和给定口径判断，不把它们当成现实世界的唯一分类。
