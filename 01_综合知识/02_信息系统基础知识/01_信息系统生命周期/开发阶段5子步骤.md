# 信息系统生命周期 —— 开发阶段 5 个子步骤

> **软考定位**：⭐⭐⭐ **超高频考点！** 每年必考 2-3 题！核心是 **“区分系统分析 vs 系统设计”**。
> **对应口诀**：**总 分 设 施 验**


## 一、5 个子步骤总览

| 顺序 | 子步骤 | 核心问题 | 关键产出物 | 通俗类比（盖房） |
| :--- | :--- | :--- | :--- | :--- |
| 1 | **总体规划** | 定方向、定资源 | 《可行性报告》、《开发计划》 | 拿到地，决定盖住宅还是商场 |
| 2 | **系统分析** | **做什么（What）** | 《需求规格说明书》、**数据流图（DFD）**、数据字典 | 画施工草图和功能设计 |
| 3 | **系统设计** | **怎么做（How）** | 《系统设计说明书》、**架构图、ER图、模块结构图** | 画详细施工蓝图 |
| 4 | **系统实施** | 编码、测试 | 可执行程序、测试报告 | 工人按图纸施工盖房 |
| 5 | **系统验收** | 确认交付、正式上线 | 《验收报告》、《用户手册》 | 业主验房，收钥匙 |

> **口诀记忆：总 → 分 → 设 → 施 → 验**


## 二、各子步骤详解

### 步骤 1：总体规划（Overall Planning）

| 维度 | 内容 |
| :--- | :--- |
| **核心任务** | 确定系统建设的目标、范围、资源和进度计划 |
| **关键活动** | 可行性分析（技术/经济/法律）、项目立项、制定《项目开发计划》 |
| **关键产出物** | 《可行性分析报告》、《项目开发计划书》 |
| **大白话** | “老板，我们准备花多少钱、用多少人、分几个阶段、做成什么样？” |

> **⚠️ 易混淆**：总体规划是 **“项目怎么管”**（资源、时间）；系统分析是 **“功能怎么定”**（需求、逻辑）。


### 步骤 2：系统分析（System Analysis）—— ⭐ 绝对核心！

| 维度 | 内容 |
| :--- | :--- |
| **核心任务** | 搞清楚系统 **“要做什么（What）”**，建立系统的 **逻辑模型** |
| **关键活动** | 需求调研、业务流程梳理、数据流分析 |
| **关键产出物** | 《需求规格说明书（SRS）》、**数据流图（DFD）**、**数据字典** |
| **大白话** | “用户要什么功能？订单怎么流转？数据从哪来、到哪去？” |

> **⚠️ 注意**：系统分析阶段 **不关心“怎么实现”**，只关心 **“需要什么功能”**。这是和“系统设计”的根本区别！


### 步骤 3：系统设计（System Design）—— ⭐ 绝对核心！

| 维度 | 内容 |
| :--- | :--- |
| **核心任务** | 规划系统 **“怎么做（How）”**，建立系统的 **物理模型** |
| **关键活动** | 架构设计、模块分解、接口设计、数据库设计 |
| **关键产出物** | 《系统设计说明书（SDD）》、**架构图**、**ER图（实体关系图）**、**模块结构图** |
| **大白话** | “用什么技术？数据库建几张表？模块之间怎么调用？” |

> **⚠️ 注意**：系统设计是在 **“已经知道要什么功能（系统分析结果）”** 的基础上，决定 **“用哪些技术来实现”**。


### ⚠️ 步骤 2 vs 步骤 3 —— 系统分析 vs 系统设计（绝对必考！）

这是整个信息系统章节中**最容易丢分的点**，没有之一！请死死记住下面对比表：

| 对比维度 | **系统分析** | **系统设计** |
| :--- | :--- | :--- |
| **回答的问题** | **“做什么（What）”** | **“怎么做（How）”** |
| **产出模型** | **逻辑模型** | **物理模型** |
| **关键产出物** | **数据流图（DFD）**、数据字典 | **架构图**、**ER图**、模块结构图 |
| **关注点** | 业务需求、数据流转 | 技术方案、数据库、接口 |

> **考场秒杀**：
> - 题干说“绘制数据流图（DFD）”→ 选 **系统分析**
> - 题干说“设计数据库ER图”→ 选 **系统设计**
> - 题干说“确定系统采用B/S架构”→ 选 **系统设计**
> - 题干说“梳理订单处理流程”→ 选 **系统分析**


### 步骤 4：系统实施（System Implementation）

| 维度 | 内容 |
| :--- | :--- |
| **核心任务** | 将设计文档转化为可执行的程序和系统 |
| **关键活动** | 编码、单元测试、集成测试、系统安装部署 |
| **关键产出物** | 可执行程序、单元测试报告、集成测试报告 |
| **大白话** | “程序员开工写代码，测试人员找bug，最后把系统装到服务器上。” |

> **⚠️ 易混淆**：系统实施是 **“做系统”**；系统验收是 **“用户确认签收”**。


### 步骤 5：系统验收（System Acceptance）

| 维度 | 内容 |
| :--- | :--- |
| **核心任务** | 用户确认系统符合需求，正式签字交接 |
| **关键活动** | 验收测试（用户测试）、用户培训、《用户手册》编写、系统移交 |
| **关键产出物** | 《验收报告》、《用户手册》、系统移交单 |
| **大白话** | “业主验房，看看房型对不对、有没有漏水，满意了就签字收房。” |


## 三、完整流程（串联）

总体规划 → 系统分析 → 系统设计 → 系统实施 → 系统验收  
↓          ↓         ↓         ↓           ↓  
定方向     画逻辑图   画蓝图    施工建房    业主验房
## 四、核心考点总结

| 考核方向 | 核心内容 |
| :--- | :--- |
| **5 个子步骤顺序** | 总 → 分 → 设 → 施 → 验（顺序不可逆） |
| **系统分析 vs 系统设计（必考！）** | 分析 = **What**（逻辑模型，产出 DFD）；设计 = **How**（物理模型，产出 ER 图/架构） |
| **各子步骤产出物** | 见上方总览表 |
| **与开环闭环的关联** | 系统分析/设计阶段的“反馈闭环”对应开环/闭环结构（详见 MIS 专题笔记） |


## 五、考场避坑清单

| 错误选项 / 易混说法 | 正解 |
| :--- | :--- |
| “数据流图（DFD）是系统设计的产出物” | ❌ DFD 是 **系统分析** 的产出物 |
| “ER 图是系统分析的产出物” | ❌ ER 图是 **系统设计** 的产出物 |
| “总体规划阶段做需求调研” | ❌ 需求调研属于 **系统分析** 阶段；总体规划只做 **可行性分析** |
| “系统实施阶段做验收测试” | ❌ 验收测试属于 **系统验收** 阶段；实施阶段做 **单元测试和集成测试** |
| “系统设计阶段确定系统边界” | ❌ 确定系统边界属于 **系统分析** 阶段 |


## 六、一句话总结

> **总体规划定方向，系统分析画逻辑（DFD），系统设计画蓝图（ER图/架构），系统实施盖房子，系统验收交钥匙。**
>
> **考场铁律：DFD = 系统分析，ER图/架构 = 系统设计。记住这两点，2 分到手！**
