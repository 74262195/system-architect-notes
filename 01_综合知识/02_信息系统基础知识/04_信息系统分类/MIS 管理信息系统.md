# MIS：业务数据怎样变成管理者能用的信息

> [!summary] 快速复习卡片
> **定位**：MIS 收集、传输、存储、加工和使用管理信息，为组织各层管理活动提供信息服务。
> **四个部件**：信息源、信息处理器、信息用户、信息管理者。
> **结构题眼**：既按职能划分七个基本子系统，也按业务处理、运行控制、管理控制、战略计划划分层次。
> **七个子系统**：销售与市场、生产、后勤、人事、财务和会计、信息处理、高层管理。
> **易错点**：MIS 不只服务中层，也不只生成固定报表；“七个子系统”是在按管理职能拆 MIS，不是七种不同的信息系统。

企业每天已经积累了订单、库存和财务数据，但管理者关心的不是每一条流水，而是“销售是否偏离计划、库存是否异常、资源是否需要调整”。MIS 的作用就是把分散数据整理成管理活动能够使用的信息。

## 四个基本部件怎样协作

| 部件 | 作用 |
| --- | --- |
| 信息源 | 产生组织内外的原始信息 |
| 信息处理器 | 采集、传输、存储、加工信息 |
| 信息用户 | 使用信息完成业务、控制或决策 |
| 信息管理者 | 负责系统设计、实施和维护等管理工作 |

## 两个观察方向

MIS 不是只有一张“部门列表”。教材用两个方向组织它：

- **横向按职能**：看企业“哪类管理工作”需要信息支持。
- **纵向按层次**：看同一职能在业务处理、运行控制、管理控制、战略计划等不同层次需要什么信息。

把两个方向交叉起来，就是“功能—层次矩阵”：例如生产职能既有基层生产记录，也有管理控制和更长期的计划信息。

## 七个基本子系统到底在分什么

教材按企业管理职能把 MIS 继续拆成七个基本子系统。它们不是七套互不相干的软件，而是说明一个大的 MIS 可以分别承接不同管理职能。

| 子系统 | 大白话定位 |
| --- | --- |
| 销售与市场子系统 | 看市场、客户、销售等经营信息 |
| 生产子系统 | 看生产计划、生产过程和产出相关信息 |
| 后勤子系统 | 看物资、库存、运输等保障信息 |
| 人事子系统 | 看人员、岗位等人力相关信息 |
| 财务和会计子系统 | 看资金、成本、核算等财会信息 |
| 信息处理子系统 | 为其他子系统提供数据处理和信息服务支撑 |
| 高层管理子系统 | 汇总跨职能信息，支持高层综合管理和战略观察 |

这里最容易漏掉的是**后勤子系统**。如果题目让你从一组名称里识别教材“七个基本子系统”，不要把 DSS、ERP、OAS 这类另一层次的系统类型混进来。

## 与 TPS、DSS 的最小区别

| 系统 | 当前主要问题 |
| --- | --- |
| TPS | 一笔具体业务怎样正确完成并留下记录 |
| MIS | 管理活动需要哪些经过加工的信息 |
| DSS | 面对半结构化、非结构化问题，怎样用数据和模型比较方案 |

不要把现实系统硬切成互不重叠的三套软件；考试主要按题干强调的功能和使用场景判断。

## 考试怎么做

- **题干信号**：管理信息、功能—层次矩阵、销售与市场/生产/后勤/人事/财务和会计/信息处理/高层管理。
- **第一反应**：先判断题目是在问 MIS 的横向职能拆分，还是纵向管理层次；出现“七个基本子系统”就回到横向职能。
- **排除动作**：选项若混入“DSS、ERP、OAS”等完整系统类型，不能把它们当成 MIS 七基本子系统；出现“半结构化决策 + 模型比较”则更偏 DSS。
