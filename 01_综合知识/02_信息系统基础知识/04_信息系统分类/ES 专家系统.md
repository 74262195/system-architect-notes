# ES 专家系统：知识库和推理机怎样一起求解问题

> [!summary] 快速复习卡片
> **定位**：用特定领域知识和推理过程解决通常需要专家经验的问题。
> **核心组件**：知识库保存领域知识，推理机选择并应用规则，综合数据库保存当前事实和中间结果。
> **六个特点**：超越时间限制、操作成本低廉、易于传递与复制、处理手段一致、善于克服难题、适用特定领域。
> **题干怎么认**：知识库、推理机、解释程序；正向是数据驱动，反向是目标驱动。
> **易错点**：DSS 主要靠数据和模型辅助管理决策，ES 主要靠知识和推理求解领域问题。

## 先定位：它是知识驱动的信息系统

**专家系统（Expert System，ES）**使用特定领域的知识与推理过程，求解通常需要领域专家经验的问题。它是人工智能的一个重要分支，不是“装了很多数据的普通程序”，核心差异是把领域知识与通用推理控制尽量分离。

如果还不清楚 ES 为什么属于 AI，先回看 [[人工智能AI]]。

## 六个特点为什么会出现

把专家经验装进系统的价值，不只是“自动执行 if/else”。教材用六个特点强调：专家知识一旦被系统化，就能以软件的方式被保存、复制和重复使用。

| 特点 | 大白话解释 |
| --- | --- |
| 超越时间限制 | 人类专家要休息、离岗，系统建立后可以在需要时持续提供咨询能力 |
| 操作成本低廉 | 建设知识库有成本，但反复使用时不需要每次都请同等水平的专家到场 |
| 易于传递与复制 | 专家个人经验很难大规模复制，系统化知识可以部署到更多地点或用户 |
| 处理手段一致 | 相同知识和规则下，系统不会因为疲劳、情绪等因素随意改变判断方式 |
| 善于克服难题 | 可以利用大量领域知识和启发式规则处理复杂、信息不完全的问题 |
| 适用特定领域 | 强项来自深厚的领域知识，因此通常“专而不全”，不等于通用万能智能 |

### 为什么它不等于普通 if/else

普通程序当然也可以写条件判断，但 ES 的设计重点是把**领域知识**放入知识库，把“怎样使用这些知识”交给推理机。这样系统能够围绕当前事实不断匹配规则、产生中间结论，并解释推理依据。考试看到“知识库 + 推理机 + 启发式经验”，不要只把它理解成一串固定分支语句。

## 六个组成部分各做什么

| 组件 | 作用 |
| --- | --- |
| 知识库 | 保存事实性知识、启发式规则等领域知识 |
| 综合数据库/工作存储 | 保存当前问题事实和推理中的中间结果 |
| 推理机 | 选择并应用规则，控制搜索和推理 |
| 知识获取 | 帮助专家或知识工程师建立、更新知识库 |
| 解释程序 | 说明结论、推理步骤和依据 |
| 人机接口 | 接收问题并呈现咨询结果 |

知识库与推理机是核心，但“修改知识一定完全不用改程序”过于绝对；只有知识表示、接口和推理机制未变化时，才可能主要更新知识库。

## 一次规则推理怎样发生

~~~mermaid
flowchart LR
    A[输入问题事实] --> B[写入工作存储]
    B --> C[匹配知识库规则]
    C --> D[选择并执行规则]
    D --> E{得到目标结论?}
    E -- 否 --> C
    E -- 是 --> F[输出结论与解释]
~~~

推理循环会匹配当前事实与规则条件，解决多条规则同时可用时的选择问题，执行规则并产生新事实，直到得到目标、无规则可用或满足终止条件。

### 用两条设备规则走一遍正向推理

下面是虚构的教学例子，不代表真实设备诊断规则或检修建议。假设知识库中有两条规则：

- **R1**：如果“泵电源稳定”且“泵振动偏高”，就增加事实“轴承可疑”。
- **R2**：如果“轴承可疑”且“泵噪声偏高”，就增加结论“轴承故障可能性高”。

用户输入的已知事实是：“泵电源稳定、泵振动偏高、泵噪声偏高”。推理机按规则匹配：

| 步骤 | 当前事实/动作 | 工作存储变化 |
| --- | --- | --- |
| 初始 | 写入三条用户事实 | 电源稳定；振动偏高；噪声偏高 |
| 匹配 R1 | 两个条件都满足，执行 R1 | 新增“轴承可疑” |
| 再匹配 R2 | “轴承可疑”和“噪声偏高”都已在工作存储中，执行 R2 | 新增“轴承故障可能性高” |
| 输出 | 到达本例目标，停止继续推理 | 给出结论及 R1、R2 的规则链作为解释 |

这里知识库保存 R1/R2，综合数据库（工作存储）保存本次输入事实和新推出的事实，推理机负责匹配并触发规则，解释程序可把结论回溯到输入事实和两条规则。**规则系统给出的是基于已编码知识的判断**；现实设备检修仍需结合测量和专业人员复核。

## 三种推理方向

| 方式 | 起点 | 过程 | 适合题眼 |
| --- | --- | --- | --- |
| 正向推理 | 已知事实 | 条件满足就推出新结论 | 数据驱动、目标解空间较大 |
| 反向推理 | 待证目标 | 反查成立所需条件并逐项验证 | 目标驱动、候选目标较少 |
| 双向推理 | 事实与目标两端 | 正反方向协同，直到相遇或证伪 | 混合推理 |

## 与 DSS 怎么区分

| ES | DSS |
| --- | --- |
| 知识库 + 推理机 | 数据库 + 模型库等 |
| 模拟专家推理 | 为管理决策提供数据和模型支持 |
| 面向特定领域复杂问题 | 常面向半结构化、非结构化决策 |

二者都可能面对复杂问题，所以“复杂”不是唯一判断信号。真正稳定的区分是：**ES 看知识与推理，DSS 看数据、模型与人机方案比较。**

## 考试怎么认

- **题干信号**：专家经验、知识库、推理机、解释程序、启发式规则、特定领域。
- **第一反应**：出现“把专家知识保存并推理”优先定位 ES，再判断问的是组成、推理方向还是六个特点。
- **排除动作**：若核心是模型库、What-if、方案比较并由管理者最终决策，更偏 DSS；若只是固定结构化业务按确定流程执行，也不能因为有 if/else 就判 ES。
