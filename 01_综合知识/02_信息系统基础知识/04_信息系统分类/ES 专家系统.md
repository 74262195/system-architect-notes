# ES 专家系统：知识库和推理机怎样一起求解问题

## 先定位：它是知识驱动的信息系统

**专家系统（Expert System，ES）**使用特定领域的知识与推理过程，求解通常需要领域专家经验的问题。它不是“装了很多数据的普通程序”，核心差异是把领域知识与通用推理控制尽量分离。

## 六个组成部分各做什么

| 组件 | 作用 |
| --- | --- |
| 知识库 | 保存事实性知识、启发式规则等领域知识 |
| 综合数据库/工作存储 | 保存当前问题事实和推理中的中间结果 |
| 推理机 | 选择并应用规则，控制搜索和推理 |
| 知识获取 | 帮助专家或知识工程师建立、更新知识库 |
| 解释程序 | 说明结论、推理步骤和依据 |
| 人机接口 | 接收问题并呈现咨询结果 |

知识库与推理机是核心，但“修改知识一定完全不用改程序”过于绝对；只有知识表示、接口和推理机制未变化时，才可能主要更新知识库。

## 一次规则推理怎样发生

~~~mermaid
flowchart LR
    A[输入问题事实] --> B[写入工作存储]
    B --> C[匹配知识库规则]
    C --> D[选择并执行规则]
    D --> E{得到目标结论?}
    E -- 否 --> C
    E -- 是 --> F[输出结论与解释]
~~~

推理循环会匹配当前事实与规则条件，解决多条规则同时可用时的选择问题，执行规则并产生新事实，直到得到目标、无规则可用或满足终止条件。

## 三种推理方向

| 方式 | 起点 | 过程 | 适合题眼 |
| --- | --- | --- | --- |
| 正向推理 | 已知事实 | 条件满足就推出新结论 | 数据驱动、目标解空间较大 |
| 反向推理 | 待证目标 | 反查成立所需条件并逐项验证 | 目标驱动、候选目标较少 |
| 双向推理 | 事实与目标两端 | 正反方向协同，直到相遇或证伪 | 混合推理 |

## 与 DSS 怎么区分

| ES | DSS |
| --- | --- |
| 知识库 + 推理机 | 数据库 + 模型库等 |
| 模拟专家推理 | 为管理决策提供数据和模型支持 |
| 面向特定领域复杂问题 | 常面向半结构化、非结构化决策 |

## 考试怎么认

- “知识库、推理机、解释程序” → ES。
- “模型库、数据分析、辅助决策” → DSS。
- “正向数据驱动、反向目标驱动” → 专家系统推理方式。
