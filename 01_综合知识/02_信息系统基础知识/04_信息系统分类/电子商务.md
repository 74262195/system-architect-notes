# 电子商务：不同企业的系统为什么必须“说同一种业务语言”

> [!summary] 快速复习卡片
> **定位**：交易各方利用电子信息网络完成交易及相关服务。
> **分类入口**：B2B 企业对企业，B2C 企业对消费者，C2C 消费者对消费者，C2B 消费者需求面向企业。
> **标准的作用**：让不同企业、平台和系统按照共同的数据格式、语义和业务约定交换商务信息，减少“系统都联网了却互相看不懂”的问题。
> **教材代表**：基于 XML 的电子商务标准中重点识别 ebXML、RosettaNet、cnXML 的定位。
> **易错点**：这里的“标准”不是 HTTP、TCP、SSL 等网络协议列表，而是电子商务参与方之间怎样规范交换业务信息和业务流程。

一家制造企业通过网络向供应商自动下采购单。如果采购方把“订单号、数量、交货日期”按自己的格式发送，而供应商系统完全不知道每个字段什么意思，那么即使两边网络已经连通，业务仍然无法自动协同。

所以电子商务不只是“把交易搬到网上”，还需要一套共同约定，让参与交易的系统知道：**传什么、怎么表示、业务步骤怎样衔接。**

## 先看交易双方

| 模式 | 交易关系 | 例子 |
| --- | --- | --- |
| B2B | 企业与企业 | 制造商向供应商采购原料 |
| B2C | 企业向消费者 | 品牌直营网店向个人销售商品 |
| C2C | 消费者与消费者 | 个人在二手平台向另一名个人出售物品 |
| C2B | 消费者需求汇集或由消费者向企业提供价值 | 用户提出定制需求，企业响应 |

模式分类回答的是“**谁和谁交易**”；电子商务标准回答的是“**这些参与方的系统怎样按共同规则交换商务信息**”。两者不要混成同一件事。

## 为什么电子商务需要标准

标准化最直接解决三个问题：

1. **格式统一**：不同系统知道一份订单、报价、发票等商务文档怎样组织。
2. **语义一致**：双方对字段和业务含义理解一致，避免“同一个名字、不同含义”。
3. **流程可协同**：系统知道请求、确认、交付等业务消息怎样衔接，才能进一步自动化 B2B 协作。

因此考试看到“电子商务标准”，第一反应应是**互操作、数据交换、业务流程规范**，而不是去背网络层和传输层协议。

## 基于 XML 的三个代表怎样区分

教材把基于 XML 的电子商务标准作为代表来讲。这里掌握定位即可，不需要展开规范细节。

| 标准/规范 | 最小定位 |
| --- | --- |
| **ebXML** | 面向全球、跨行业的基于 XML 的电子商务信息交换与协作框架，强调不同贸易参与方之间的互操作 |
| **RosettaNet** | 面向开放电子商务流程标准化的行业性规范体系，典型背景是信息技术、电子元件和半导体产业 |
| **cnXML** | 以国际 XML 标准为基础、兼顾我国商业流程特点并力求与相关国际标准互操作的电子商务规范 |

不要把三者理解成三种网络协议。它们解决的是**商务数据和业务协同规则**的问题。

flowchart LR
    A[企业A业务系统] --> B[共同电子商务标准]
    B --> C[统一数据格式与语义]
    C --> D[统一业务消息/流程约定]
    D --> E[企业B业务系统能正确理解并处理]
~~~

## 电子商务和电子政务怎么区分

- **电子商务**：核心是市场交易以及围绕交易发生的信息、资金、商品和服务活动。
- **电子政务**：核心是政府管理、公共服务和政府与社会主体之间的政务互动。

题目里即使都出现“企业 + 网络”，也要看业务目标。如果企业是在纳税、报送政府数据，属于电子政务中的企业对政府；如果企业在采购、销售商品，则是电子商务。

## 考试怎么做

- **题干信号**：B2B/B2C、电子交易、XML、ebXML、RosettaNet、cnXML、商务数据交换、互操作。
- **第一反应**：先判断题目是在问交易主体还是电子商务标准；问“标准”时优先联想到基于 XML 的业务信息交换与流程协同。
- **排除动作**：HTTP/TCP/IP 等只能说明网络通信基础，不能直接替代教材这里的电子商务标准；政府办事、企业纳税等则应回到电子政务。
