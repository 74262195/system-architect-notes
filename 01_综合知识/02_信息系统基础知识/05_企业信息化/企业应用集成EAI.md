# 企业应用集成 EAI：已有系统怎样从信息孤岛变成协作整体

> [!summary] 快速复习卡片
> **定位**：EAI 让已有应用交换信息、调用能力并协同业务流程。
> **先看集成对象**：数据、接口、流程还是界面。
> **题干怎么认**：复制/聚合看信息集成，跨系统步骤看过程集成，SOA 与 Web Services 看面向服务集成。
> **易错点**：数据、接口、流程、界面不是唯一固定的四层技术栈。

## 先定位：EAI 不是一条固定的四层技术栈

**企业应用集成（EAI）**通过适配器、消息、接口、流程或服务等方式，让原本独立的应用交换信息并协同完成业务。数据、接口、流程、界面是常见集成需求视角；教材同时还用**面向信息、面向过程、面向服务**描述集成技术的演进。两组分类不能混成唯一固定层级。

## 先判断要集成什么

| 需求 | 要打通的对象 | 典型方式 | 主要局限 |
| --- | --- | --- | --- |
| 信息/数据集成 | 数据与消息 | 复制、聚合、ETL、消息、适配器 | 语义与一致性治理困难 |
| 接口/应用集成 | 已有应用能力 | API、适配器、消息中间件、ESB | 依赖接口契约 |
| 流程集成 | 跨系统业务步骤 | 工作流/BPM、编排、事件协同 | 流程与异常补偿更复杂 |
| 界面集成 | 用户入口和操作界面 | 门户、SSO、界面组合 | 底层数据和业务逻辑可能仍未真正整合 |

界面集成往往成本较低，但只是统一入口；数据集成也不必然都是离线批处理；API 集成的耦合度也取决于接口设计，不能一律判定“低耦合”。

## 一次跨系统订单怎样走

~~~mermaid
flowchart LR
    A[CRM提交订单] --> B[集成适配/服务]
    B --> C[ERP校验库存]
    C --> D{库存充足?}
    D -- 否 --> E[返回失败原因]
    D -- 是 --> F[创建订单并发布事件]
    F --> G[财务与物流继续处理]
~~~

集成层负责协议与数据格式转换、路由、调用或消息传递；流程层处理步骤顺序和异常。若某一步失败，还要定义重试、补偿、幂等或人工处理，不能只画“系统连起来”就结束。

### 库存不足、重试与补偿：把一笔订单的状态走完

下面是虚构的教学示例。CRM 保存客户下单与沟通状态；ERP 是订单和库存的权威记录；流程协调方负责调用顺序并把结果同步回 CRM。

| 步骤 | 发生什么 | 系统状态与处理 |
| --- | --- | --- |
| 1. 首次尝试 | 客户提交 `ORD-218`，要 2 件；ERP 查询只有 1 件 | ERP 拒绝预留，返回“库存不足”；协调方将订单状态和原因同步回 CRM 为“待补货”，不通知财务或物流，因为这次未形成可履约订单 |
| 2. 库存补足、重试 | 补货后，CRM 因响应超时重复发送同一订单请求 | 两次请求使用相同订单号和操作幂等键；ERP 按该键只创建一次订单并预留 2 件，重复请求返回已处理结果，不再重复扣减库存 |
| 3. 下游支付失败 | ERP 已有订单并预留库存，但支付授权失败 | 协调方触发补偿：请求 ERP 释放这笔预留并将订单标记取消；成功后把“支付失败、订单已取消”同步回 CRM，不发送发货指令 |
| 4. 核对结果 | 检查 CRM 与 ERP 的订单状态和操作记录 | 应只有一笔 `ORD-218`；库存预留已释放；CRM 显示取消原因；财务没有成功扣款记录，物流没有发货任务 |

此例里，同步回 CRM 的是订单号、当前处理状态和失败原因；实际库存数量及预留明细仍由 ERP 负责，避免两个系统各自维护一份可冲突的库存余额。首轮库存不足是在预留前失败，不需要释放库存；后续支付失败发生在 ERP 已预留之后，才需要用补偿动作撤回预留。

这里展示的是流程编排加幂等和补偿的一种解释性方案，不表示所有 EAI 都自动提供这些保证。跨系统步骤通常不能假定成一个整体原子事务；需要记录操作标识和状态，补偿失败时进入可重试/人工处理，并以对账检查确认各系统最终一致。

## 三类教材题眼

- **面向信息的集成**：数据复制、聚合、接口/适配器交换信息。
- **面向过程的集成**：把跨应用过程逻辑从单个系统中分离，由过程层协调。
- **面向服务的集成**：把业务能力封装为服务；基于 SOA 和 Web Services 的 EAI 属于此类。

## EAI 与 BPR

- **BPR**：重新审视和设计业务流程。
- **EAI**：让应用和信息实现集成。

二者可配合，但不存在所有项目都必须“先完成 BPR 才允许 EAI”的通用硬顺序；是否先改流程取决于业务目标和现状。

## 考试怎么认

- 最小代价统一多个既有 C/S 操作入口，题干可能选界面集成。
- SOA + Web Services → 面向服务的集成技术。
- 跨系统审批和业务步骤协调 → 流程/面向过程集成。
- 复制、聚合、适配器与消息 → 面向信息集成。
