# 信息系统基础知识：复习时只抓住一条主线

> [!summary] 30 秒召回
> **信息系统是什么**：人、制度和技术一起完成信息的输入、存储、处理、输出与控制。
> **怎样建设**：先明确需求，再规划、分析、设计、实施、验收，投入运行后持续维护，最终更新或退役。
> **建成后服务谁**：TPS 处理日常事务，MIS 汇总管理信息，DSS 用数据和模型辅助决策，ES 用知识和推理解决领域问题，OAS 支持办公。
> **本章最值得复习**：企业信息化、ERP 与 EAI；其他内容先会定位和区分，不背枝节。

## 先建立坐标：信息系统不等于计算机

一家企业收到订单后，需要有人录入，软件校验库存，网络把信息传给仓库，员工按制度发货，管理者再根据报表调整计划。这里的**计算机只是工具**，完整的信息系统还包括人、信息资源和规章制度。

教材列出的组成包括：计算机硬件、网络与通信设备、软件、信息资源、信息用户和规章制度。它们共同完成五个基本功能：

| 功能 | 复习时怎么理解 |
| --- | --- |
| 输入 | 收集订单、库存、申请等原始数据 |
| 存储 | 把数据保存下来，供以后查询和处理 |
| 处理 | 校验、计算、汇总或分析数据 |
| 输出 | 形成单据、报表、提示或决策信息 |
| 控制 | 管理处理、传输和输出过程，使系统按规则运行 |

一句话区别：**计算机提供处理能力，信息系统把人、制度、数据和技术组织成解决业务问题的整体。**

## 主线一：组织怎样从“零散用电脑”走向“用信息管企业”

诺兰模型讲的是**组织的信息化成熟过程**，不是某一个软件从立项到退役的生命周期。六个阶段依次是：初始、传播、控制、集成、数据管理、成熟。

复习时不必背每阶段的长清单，只抓住变化：

| 阶段 | 组织正在解决什么问题 |
| --- | --- |
| 初始、传播 | 从少数人试用走向大量应用，但开始出现重复建设和数据不一致 |
| 控制 | 意识到无序扩张有代价，开始统一管理 |
| 集成 | 打通分散系统，建立共享基础 |
| 数据管理 | 把信息当作组织资源，统一管理和利用数据 |
| 成熟 | 信息系统能够支撑不同层次的管理与决策 |

题目问“组织的信息化发展到哪一阶段”时看诺兰模型；问“一个系统现在处于开发还是运行”时看信息系统生命周期。

## 主线二：一个信息系统怎样从想法变成可用系统

### 四个生命周期阶段

| 阶段 | 直接回答的问题 |
| --- | --- |
| 产生 | 为什么要建、用户需要什么 |
| 开发 | 怎样把需求变成系统 |
| 运行 | 怎样稳定使用并维护系统 |
| 消亡 | 何时更新、替代或退役 |

开发阶段再分为五步：

1. **总体规划**确定目标、总体架构、资源和实施安排。
2. **系统分析**把业务需求整理成逻辑模型，回答“系统要做什么”。
3. **系统设计**把逻辑要求变成实施方案，回答“系统怎样实现”。
4. **系统实施**把设计落实为可以运行的软件系统。
5. **系统验收**通过试运行检查系统能否满足使用要求并完成移交。

最容易混的是分析与设计：**分析先说清业务要什么，设计再决定技术怎样实现。**

### 四种教材内开发方法

| 方法 | 最小判断入口 | 更适合的情况 |
| --- | --- | --- |
| 结构化方法 | 分阶段、自顶向下分解、文档规范 | 业务较稳定、需求较明确 |
| 原型法 | 快速做出可体验版本，用反馈逐步修正 | 用户起初说不清需求 |
| 面向对象方法 | 用对象及其关系建立问题域模型 | 需要让数据与行为围绕对象组织 |
| 面向服务方法 | 将能力通过服务接口提供，弱化实现耦合 | 多应用需要互操作和复用能力 |

敏捷、瀑布、V 模型等属于软件过程与生命周期模型的交叉内容。本章只需知道它们不是上述四种信息系统开发方法的同一套分类。

### 建设原则只记“为什么”

- 高层管理人员介入：保证系统服务组织总体目标，并能协调跨部门资源。
- 用户参与：真正使用系统的人要参与全过程，避免开发者凭想象做需求。
- 自顶向下规划：先统一目标和信息口径，再设计各子系统，减少信息孤岛。
- 工程化：用规范过程、文档和评审保证可维护、可扩展。
- 其他原则：创新性、整体性、发展性和经济性用于补充判断，不要硬背成另一套固定“七大原则”。

## 主线三：建成的系统分别在帮谁做什么

这些系统可以同时存在，彼此不是简单的升级替代关系。

| 系统 | 主要任务 | 题干信号 |
| --- | --- | --- |
| TPS 业务处理系统 | 记录并处理重复、结构化的日常业务 | 订单、收付款、出入库、批处理或联机事务 |
| MIS 管理信息系统 | 汇总和加工组织内外信息，为管理提供信息服务 | 报表、计划、控制、各管理层信息 |
| DSS 决策支持系统 | 让决策者使用数据和模型分析半结构化、非结构化问题 | 模型库、What-if、辅助而不代替决策 |
| ES 专家系统 | 用领域知识和推理机制求解特定领域问题 | 知识库、推理机、解释程序 |
| OAS 办公自动化系统 | 综合处理文字、数据、声音和图像等办公信息 | 公文、档案、沟通、事务处理与辅助决策 |

最实用的区分：**TPS 先把业务事实记准确；MIS 把事实整理成管理信息；DSS 再用数据和模型帮助人选择方案；ES 依靠领域知识进行推理。**

综合性信息系统把多种能力放到企业全局中使用。大纲明确列出的 ERP、WMS、MES/SFC 和 PDM，不要漏掉：

| 系统 | 管理对象 |
| --- | --- |
| ERP | 企业的物流、资金流和信息流等整体资源 |
| WMS | 仓库货位、收发料、库存与盘点 |
| MES/SFC | 生产现场的过程、工艺、设备与执行控制 |
| PDM | 研发阶段的产品、物料、BOM 与工程变更数据 |

## 主线四：为什么企业最后要做“信息化”与“集成”

单个系统只能解决局部问题。企业不断建设系统后，常见的新矛盾是：各部门都有软件，但数据口径不一致，流程无法跨系统衔接，管理者仍看不到全局。

因此，企业信息化不是“多买几套软件”，而是让信息技术从局部工具逐步融入业务、管理与战略。复习时抓住三件事：

1. **目标**：优化业务活动，提升运行能力、响应速度和竞争力。
2. **规划**：从企业战略、业务运作、管理运作三个层面确定需求；全面规划，分步实施。
3. **方法**：可从流程重构、核心业务、信息系统建设、主题数据库、资源管理和人力资本投资等角度推进。

其中两张最值得单独复习：

- [[ERP的概念]]：把物流、资金流和信息流放进统一计划与管理中。
- [[企业应用集成EAI]]：让已经存在的应用交换数据、调用能力并协同流程。

ERP 更像“企业资源的统一管理平台”，EAI 更像“让异构系统协作的集成办法”，二者可以配合，但不是同一个概念。

## 主线五：电子政务与电子商务只做定位复习

- **电子政务**：政府利用信息技术整合管理与服务职能，覆盖政府内部、政府之间，以及政府与企业、居民之间的互动。
- **电子商务**：交易各方利用电子信息网络完成交易与相关服务。

电子政务题先辨认互动主体和业务方向；电子商务题先辨认参与交易的主体。当前题库趋势中，电子政务为较低优先级，电子商务更低，复习到“会分类、会判断场景”即可。
