# 面向对象方法（Object-Oriented Method）

> **软考定位**：当前最主流的开发方法，关键词 **“对象、类、继承、封装、多态”**。

---

## 一、一句话定义

面向对象方法将现实世界的一切视为 **“对象”** ，每个对象有自己的 **属性（数据）** 和 **行为（方法）** ，通过 **类** 来组织和管理对象。

> **大白话**：**“把现实世界的东西直接映射成程序里的‘对象’，人就是人、车就是车，该有什么属性就有什么属性。”**

---

## 二、四大核心概念（必背！）

| 概念 | 定义 | 通俗理解 |
| :--- | :--- | :--- |
| **对象（Object）** | 现实世界中某个实体的**具体实例** | “我”这个人、“我开的这辆车” |
| **类（Class）** | 具有相同属性和行为的对象的**模板** | “人”这个类、“车”这个类 |
| **继承（Inheritance）** | 子类自动拥有父类的属性和行为 | “学生”继承“人”——学生也是人，有人的所有特征 |
| **封装（Encapsulation）** | 把数据和操作数据的方法**捆绑在一起**，对外隐藏内部细节 | 你开汽车，只需要知道方向盘和油门，不用懂发动机内部原理 |
| **多态（Polymorphism）** | 同一个方法名，不同对象有不同的实现 | “人”都会“叫”，但中国人叫中文，美国人叫英文 |

---

## 三、三大模型（软考拓展考点）

| 模型 | 描述 | 核心要素 |
| :--- | :--- | :--- |
| **对象模型（Object Model）** | 描述系统的**静态结构** | 类、属性、关系（继承/关联/聚合） |
| **动态模型（Dynamic Model）** | 描述系统的**动态行为** | 状态图、时序图、活动图 |
| **功能模型（Functional Model）** | 描述系统的**数据处理** | 用例图、数据流图（DFD） |

---

## 四、优缺点

| 优点 | 缺点 |
| :--- | :--- |
| 1. **复用性好**（类可继承、可组合） | 1. 前期分析阶段**耗时较长**（要识别所有类） |
| 2. **符合人类思维习惯**（更自然） | 2. 对开发人员**要求较高**（需理解面向对象概念） |
| 3. **适应变化能力强**（封装隔离了变化） | 3. 系统运行效率可能**略低**（多一层抽象） |
| 4. **易于维护和扩展** | 4. 不适合所有场景（如简单的数据处理系统） |

---

## 五、适用场景

| ✅ 适合 | ❌ 不适合 |
| :--- | :--- |
| **复杂系统**（多个模块、多层交互） | 简单的小规模系统（用结构化更快） |
| 需求**可能变化**的系统 | 对**运行效率**要求极高的系统（如嵌入式实时系统） |
| 需要**高复用性**的系统 | 团队**缺乏面向对象经验** |
