# 安全性质量属性场景：攻击发生时系统怎样保护服务和数据

安全不只是某个安全产品。真正的架构问题是：

> **有人试图越权、篡改数据或压垮服务时，系统要识别什么、阻止什么、记录什么，而且效果如何衡量。**

教材把安全性概括为：向合法用户提供服务的同时，阻止非授权使用。

| 要素 | 典型内容 |
| --- | --- |
| 刺激源 | 内部/外部个人或系统，已授权或未授权 |
| 刺激 | 查看、修改、删除数据；访问服务；降低服务可用性 |
| 环境 | 在线/离线、联网/断网、有无防火墙 |
| 制品 | 系统服务、系统数据 |
| 响应 | 认证、授权/拒绝、记录、加密、检测异常、通知 |
| 响应度量 | 攻击成功概率、检测概率、绕过成本、受影响范围、恢复程度 |

教材在质量属性定义处还强调机密性、完整性、不可否认性和可控性等目标。

“使用 HTTPS”只是手段，不是完整质量需求；仍要说明谁攻击、攻击什么、系统怎么响应、做到什么程度。
