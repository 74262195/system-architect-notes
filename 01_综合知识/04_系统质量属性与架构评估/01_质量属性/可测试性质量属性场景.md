# 可测试性质量属性场景：为什么“能运行”不等于“容易证明它是对的”

如果系统内部状态完全看不到，外部依赖也无法替换，测试人员只能黑盒碰运气。

可测试性关注：

> **测试能否有效触发条件、观察状态、发现缺陷，并在合理时间内完成验证。**

| 要素 | 典型内容 |
| --- | --- |
| 刺激源 | 开发、验证、验收测试人员或用户 |
| 刺激 | 某阶段工作产品完成，需要验证 |
| 环境 | 设计、开发、编译、部署时 |
| 制品 | 设计、代码段、完整应用 |
| 响应 | 暴露状态值/计算值、准备测试环境 |
| 响应度量 | 测试时间、覆盖比例、故障概率、环境准备时间 |

可测试性高，不是“测试用例多”，而是**系统更容易被观察和控制**。

题眼：“测试执行时间、测试环境准备时间、可观察状态、覆盖率”。
