# 性能质量属性场景：不是“机器快”，而是事件来了以后能多快处理

> [!summary] 快速复习卡片
> **作用/定位**：描述系统在给定负载和环境下的响应速度、处理能力和时限。
> **核心结论**：常见度量包括响应时间、等待时间、吞吐量、期限、抖动、缺失率等。
> **题干怎么认**：延迟、吞吐、并发负载、截止期限、抖动。
> **易错点**：“并发 1 万”只是刺激/负载信息，必须继续问在该负载下响应时间或吞吐量要达到多少。

## 用六要素看性能

| 要素 | 典型内容 |
| --- | --- |
| 刺激源 | 用户或其他系统 |
| 刺激 | 定期、随机或突发事件到达 |
| 环境 | 正常或过载模式 |
| 制品 | 系统/服务 |
| 响应 | 处理事件，必要时改变服务级别 |
| 响应度量 | 响应时间、吞吐量、期限、抖动、缺失率 |

## 响应时间 vs 吞吐量

- 响应时间：单个请求从到达到完成要多久。
- 吞吐量：单位时间能处理多少请求。

## 历年考法落点

性能题经常不直接出现“性能”二字，而用“2 秒内返回、每秒处理多少请求、过载时丢失率”等度量来让你识别。做题优先抓**时间和单位时间处理量**。

看到“用户量增长后加服务器仍维持服务质量”时，还要警惕题目实际在问可伸缩性，而不是单纯性能。
