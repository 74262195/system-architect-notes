# 性能质量属性场景：不是“机器快”，而是请求来了以后能多快处理

架构评估里的性能关注**系统响应能力**：

- 一个事件来了，多长时间完成响应；
- 一段时间内能处理多少事件。

常见度量是响应时间、等待时间、吞吐量、期限、抖动、缺失率等。

## 用六要素看性能

| 要素 | 典型内容 |
| --- | --- |
| 刺激源 | 用户或其他系统 |
| 刺激 | 定期、随机或偶发事件到达 |
| 环境 | 正常或过载模式 |
| 制品 | 系统 |
| 响应 | 处理刺激，必要时改变服务级别 |
| 响应度量 | 等待时间、期限、吞吐量、抖动、缺失率、数据丢失率 |

“并发 1 万”本身不够，还要继续问：

> **在这个负载下，响应时间和吞吐量必须达到多少？**

## 响应时间 vs 吞吐量

- 响应时间：单个请求从到达到完成要多久。
- 吞吐量：单位时间能处理多少请求。

看到“时间、吞吐量、负载、抖动、截止期限”优先想到性能；看到“用户量增长后通过加服务器仍维持服务质量”，更接近**可伸缩性**。
