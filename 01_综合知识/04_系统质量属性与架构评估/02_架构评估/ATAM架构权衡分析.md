# ATAM：为什么架构评估不能只追求一个质量属性

只追求安全，可能让性能下降；只追求性能，又可能牺牲安全、可修改性或可用性。

ATAM 的核心价值，就是在**多个相互竞争的质量属性之间识别敏感点和权衡点**。

教材重点关注性能、安全性、可修改性和可用性。

## 四个活动领域

| 阶段 | 主问题 |
| --- | --- |
| 场景与需求收集 | 真正关心哪些质量目标 |
| 架构视图与场景实现 | 当前架构怎样实现场景 |
| 属性模型构造与分析 | 哪些决策最影响属性 |
| 折中 | 哪些决策同时拉扯多个质量属性 |

教材活动还强调：收集场景/需求 → 描述架构 → 实现场景 → 特定属性分析 → 标志敏感度 → 标志折中。

## ATAM不是给架构打一个总分

更重要的产物是：
- 哪些质量场景最重要；
- 哪些决策是敏感点；
- 哪里存在质量属性间的权衡；
- 哪些假设和风险要继续验证。

## SAAM vs ATAM

| | SAAM | ATAM |
| --- | --- | --- |
| 经典重点 | 可修改性 | 多质量属性权衡 |
| 核心技术 | 场景 | 场景 + 属性分析 + 权衡 |
| 题眼 | 单场景、场景交互 | 敏感点、权衡、多属性 |
