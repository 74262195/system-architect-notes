# 演化方式 · 复习总纲

## 用法

预计 8～12 分钟。先盖住下文，用一句话回答“系统此刻在运行吗、变化条件是不是事先规定的”，再顺着静态或动态推演流程，卡住再点子卡。

## 30 秒主线

四个时期按时间排：**设计时（编译前）→ 运行前（编译后、执行前）→ 有限制运行时（运行中，进入预设安全条件）→ 运行时（运行中直接改结构）**；前两类是**静态演化**，后两类是**动态演化**。

静态按“理解 → 变更分析 → 计划 → 重构 → 测试”走；动态按“监测 → 判断时机 → 生成/选择策略 → 原子实施 → 评估，失败整体撤销”走。

## 题干关键词 → 第一反应

| 题干信号 | 第一反应（先做的判断动作） |
| --- | --- |
| 编译前改设计、模型、实现方案 | 设计时演化（静态） |
| 已编译但尚未执行，此时增删组件 | 运行前演化（静态） |
| 运行中，进入设计时预先规定的安全条件后才改 | 有限制运行时演化（动态） |
| 运行中因当前架构不满足要求，动态增删/替换组件、改拓扑 | 运行时演化（动态），难度最高 |
| 停机升级、发布新版本、环境迁移 | 静态演化；先做影响范围分析 |
| 航空、金融、交通等不能停机，运行中替换组件 | 动态演化；先分离一致性与状态安全 |
| 运行时架构模型本身可被修改并驱动系统调整 | 偏 DSA；增删组件/连接件实例不重定义基本构造则偏 DR |

## 核心流程：先判时期，再走流程

**四时期判定**：① 系统此刻是否正在运行？不在运行只可能是设计时或运行前；② 若在运行，变化条件是不是设计时事先规定的？是则有限制运行时，否则运行时；③ 设计时＋运行前＝静态，有限制运行时＋运行时＝动态。

**静态演化五步**：软件理解 → 需求变更分析 → 演化计划 → 系统重构 → 系统测试；测试发现问题可回到软件理解进入下一轮。一次大改还要拆成原子演化操作（增删模块依赖/接口/模块、拆分或聚合模块、增删消息与对象等），形成 `A0 → A1 → … → An` 中间版本链，用来观察每一步的结构变化与质量影响。

**动态演化主线**：监测变化 → 判断能否/何时演化 → 生成或选择策略 → 原子地实施变化 → 评估与检测；关键步骤失败时整体撤销这组可回退的操作集。

三个动态性等级从浅到深：**交互动态性**（结构固定，数据/交互变）、**结构动态性**（可增删组件和连接件实例）、**架构动态性**（连基本构造都能重定义，最高）。教材归纳动态演化可改四类内容：属性重新定义、行为变化、拓扑结构改变、架构风格变化。

**DR（动态重配置）**从组件、连接件和配置入手，运行中增删组件/连接/关系，偏结构动态性；**DSA（动态软件架构）**让运行时架构成为可感知、可操作的实体，架构信息变化能驱动系统调整，偏架构动态性。

安全底线：运行中修改最怕“半改状态”。要保存当前架构信息、持续监控需求、判断时机和范围，并保证演化操作的**原子性**；注意原子性只覆盖演化操作集，已经发给用户的外部副作用不能自动撤销，需按消息编号核对并用幂等、补发、补偿处理。

## 高频对比

| 易混对 | 核心区分 | 典型例子 | 考试问法与陷阱 |
| --- | --- | --- | --- |
| 静态演化 vs 动态演化 | 静态=设计时+运行前，修改期间系统不运行；动态=有限制运行时+运行时，运行中完成结构调整 | 停机升级 vs 运行中替换风控组件 | 把动态演化写成“无需一致性/安全控制的热改” |
| 有限制运行时 vs 运行时 | 是否进入设计时**预先规定**的安全条件 | 切到安全模式再替换 vs 按当前需求动态改结构 | 只凭“系统在运行”就判运行时 |
| DSA vs DR | 运行时架构模型可感知可操作 vs 从组件、连接件、配置入手增删修改 | 架构信息变化驱动系统调整 vs 运行中增删组件/连接 | 以为只有 DSA 能改结构，或把 DR 说成重定义基本构造类型 |
| 交互/结构/架构动态性 | 只变数据交互 vs 可增删实例 vs 可重定义基本构造 | 配置项热更新 vs 增删服务实例 vs 新增组件类型 | 把三级混成一级，忽略难度递增 |

## 最容易丢分的地方

- **“动态演化＝完全无约束地热改”**：动态演化恰恰要保证一致性、状态安全和原子性；有限制运行时还要求先进入预设安全条件。
- **“静态演化＝停机后随便改”**：停机只消除了运行状态迁移难题，结构依赖和波及仍在，必须先理解与影响分析。
- **把 DR 说成必须重定义基本构造类型**：DR 主要改组件、连接件和配置，偏结构动态性；重定义基本构造属于架构动态性。
- **把操作原子性无限扩大**：它能撤销可回退的架构操作，撤不回已发出的通知等外部副作用；这类副作用要另行核对与补偿。
- **误记静态演化的维护来源**：更正性/适应性/完善性只是教材在本节列出的对应维护方式，不等于普通软件维护永远只有这三类。
- **只凭“是否停机”一个词判时期**：还需要看运行中的变化条件是否事先规定。
