- 第六章复用卡 [[07_软件架构复用：为什么复用不只是复制代码]] 承接“有利于重用”原则，本章不展开复用机制。

## 30 秒主线

会改不等于应该随意改。**18 条原则**是护栏，按“防什么失控”分三组：交付失控、结构失控、未来适应与质量失控；**演化评估**是体检，分两条路线：过程已知就沿 `A0→A1→…→An` 逐版本度量定位突变，过程未知就只能前后比较再逆向推测。

一句话：**原则管“别改坏”，评估管“改完到底好不好”。**

## 题干关键词 → 第一反应

| 题干信号 | 第一反应（先做的判断动作） |
| --- | --- |
| 演化成本接近重做、进度无限拖期、风险失控 | “交付失控”组，先找演化成本控制 / 进度可控 / 风险可控 / 目标一致 |
| 改一个模块牵动大量无关模块、波及不可预估、结构越来越难懂 | “结构失控”组，对应修改局部化 / 影响可控 / 复杂性可控 |
| 绑定特定平台、换环境就不能用、偏离标准、质量属性明显恶化 | “未来适应与质量失控”组 |
| 保留 `A0→A1→A2→…→An` 中间版本与操作记录 | 演化过程已知：逐版本度量 |
| 只保留演化前后两个版本 | 演化过程未知：前后比较并逆向推测 |
| 题干提 ATAM、效用树、敏感点、权衡点 | 那是 07 章一般架构评估，不是本模块的演化评估 |
| 功能正常但可维护性悄悄恶化 | 演化评估要看的正是结构变化与质量变化之间的关系 |

## 核心流程：护栏三组 + 评估两条路线

### 一、18 条原则按“防什么失控”分三组

- **防止项目交付失控**：演化成本控制（贵到不如重做）、进度可控（变更无限拖期）、风险可控（经济/时间/人力/技术/环境风险）、目标一致（局部优化偏离总目标）。
- **防止结构越改越坏**：主体维持、系统总体结构优化、平滑演化、**模块独立演化/修改局部化**、**影响可控**、**复杂性可控**、有利于重构、有利于重用、设计原则遵从性。
- **防止未来适应与质量失控**：适应新技术/技术独立性、环境适应性、标准依从性、质量向好、适应新需求。

重点因果链：**修改局部化**解决“尽量少波及”→ **影响可控**要求“即使有波及也可预测”→ **复杂性可控**关注多轮演化后结构是否仍可理解、可测试、可维护。三者最易混。

### 二、演化评估两条路线

- **过程已知**：如果保留了原子操作和中间版本，就对每个中间版本做同一质量属性度量，观察相邻版本的差异和趋势，找出是哪一次原子操作让指标突然改变；适合影响分析、过程监控、关键变更定位。
- **过程未知**：只拿到旧版本和新版本时，路线反过来——**前后架构分别度量 → 比较质量变化 → 推测可能的演化操作 → 找驱动原因 → 判断结果是否符合预期**。例如目标是“重构提高可维护性”，结果复杂度更高、耦合更强，就说明没达到目标。

重要边界：各步质量属性变化**不能简单相加**成首尾变化；差异用于观察和定位风险，不是机械累加分数。

## 高频对比

| 易混对 | 核心区分 | 典型例子 | 考试问法与陷阱 |
| --- | --- | --- | --- |
| 演化过程已知 vs 未知 | 有中间版本和操作记录，可逐步度量定位 vs 只有前后版本，只能比较后逆推 | 逐版度量找突变 vs 前后比较推断改了什么 | 选项说“未知过程也能直接定位每步操作的实际影响” |
| 演化评估 vs ATAM/一般架构评估 | 对象是版本差异与演化过程 vs 当前方案面对质量场景的风险、敏感点、权衡 | 比较 A0 与 A1 的质量变化 vs 评估当前方案 | 把演化评估当成再做一遍 ATAM |
| 修改局部化 vs 影响可控 vs 复杂性可控 | 尽量少波及 vs 有波及也可预测 vs 多轮后仍可理解维护 | 改一个模块只动一处 vs 能预估牵连范围 vs 结构不越改越乱 | 把三者当同一句口号 |
| 护栏（原则）vs 体检（评估） | 演化过程中防止改坏 vs 用版本和度量检查实际结果 | 18 条原则 vs 相邻版本质量差异 | 只背原则名，答不出防哪类失控 |

## 最容易丢分的地方

- **把 18 条原则背成孤立名词**：它们的价值是“在防哪类失控”，成组理解才答得动情景题。
- **把质量属性差异机械累加**：相邻版本的变化不能简单相加成首尾变化，距离用于观察差异和风险。
- **把演化评估等同于 ATAM**：这里不看效用树和敏感点，只看版本变化与质量变化之间的关系。
- **以为“功能能跑”就等于演化成功**：演化成功还要看成本、结构、原则遵从、质量与未来适应能力。
- **过程未知仍声称能逐步定位**：没有中间版本和操作记录时，只能从前后结果反推，不能直接定位每一步操作的影响。
