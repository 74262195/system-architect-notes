## 核心流程：四块各记一条链

1. **方法**：霍尔管结构化大工程（时间/逻辑/知识三维）；切克兰德处理软问题；并行工程改“串行抛墙”为早期协同；综合集成法面向开放复杂巨系统；WSR 用物理、事理、人理三层同时分析。
2. **生命周期七阶段**：探索性研究 → 概念 → 开发 → 生产 → 使用 → 保障 → 退役（“探概开生使保退”）。**使用与保障可以同时存在**，退役计划可以在较早阶段就被考虑。
3. **生命周期方法**：这四种回答“进入某个开发工作后，团队按什么方式组织需求、设计、构建、测试和部署”，不要和“系统一生有哪几个阶段”混成一个分类。
4. **MBSE**：仍是系统工程，只是把形式化、图形化、关联化的模型更系统地用于需求、分析、设计、验证与确认；三大支柱是**建模语言、建模工具、建模思路**，缺一不可。

本章**没有需要代入计算的公式**，考的是识别、排序与边界判断。

## 高频对比

| 核心区分 | 典型例子 | 考试问法 / 陷阱 |
| --- | --- | --- |
| **霍尔 vs 切克兰德**：系统化分析优化 vs 比较与探寻 | 智慧校园工程 vs 医院就诊体验 | 把切克兰德写成“求数学最优解” |
| **并行工程 vs CPU 并行**：不同专业早期协同 vs 计算任务同时执行 | 设计与制造早期协同 vs 流水线、多核 | 只看到“并行”就选流水线相关选项 |
| **综合集成法 vs WSR**：多知识综合集成处理开放复杂巨系统 vs 物理事理人理协同 | 社会经济、生态系统 vs 医院预约系统落地 | 两者都讲“综合”，忽略 WSR 的三理层次 |
| **生命周期七阶段 vs 霍尔时间维**：两套都含 7 项、都含“生产” | 探概开生使保退 vs 规拟研生安运更 | 强行逐项画等号，或把“规划、安装”放进生命周期 |
| **计划驱动 / 渐进迭代 / 精益 / 敏捷** | 规定流程文档追溯 / 初始能力逐轮演进 / 消除浪费 / 短反馈响应变化 | 用同一条描述判断四种方法，不看题干强调的核心 |
| **MBSE vs SysML**：系统工程方法 vs 建模语言 | 用关联模型贯穿全流程 vs 统一图形与语义表达 | 把两者当同义词；SysML 只是“建模语言”支柱之一 |

## 最容易丢分的地方

- **主教材覆盖 ≠ 每张卡都是重点**：本模块只有敏捷是 P0、霍尔是 P1，其余第一轮可以按一句话判据快速过，不要平均用力。
- **两套“7 个”最容易混**：霍尔时间维是“规拟研生安运更”，生命周期是“探概开生使保退”；都出现“生产”只是重名，不代表两套框架一一对应。
- **霍尔“系统综合”不是做总结**：它是提出多个可能方案，后面才进入系统分析和优化。
- **切克兰德的核心是比较与探寻**，不是追求数学意义上的最优解；模型的作用是引发讨论、修正对问题的理解。
- **并行工程的关键是早期协同**，不是“所有事同一秒做”，也不是 CPU 那种计算并行。
- **开放复杂巨系统的重点不止“大”**：数量大之外还要看类型多、层次多、关系复杂、与外部环境持续交互。
- **生命周期 vs 生命周期方法**：前者回答“系统一生走到哪一段”，后者回答“这一段的工作按什么方式组织”。
- **MBSE 不是一种全新的系统工程**：它没有抛弃分解、综合与全生命周期思想，改变的是信息怎样表达和关联。
- **SysML ≠ MBSE**，也**不是 UML 改了个名字**：它在 UML 2.0 部分内容基础上重用和扩展，面向更广义的系统工程。
