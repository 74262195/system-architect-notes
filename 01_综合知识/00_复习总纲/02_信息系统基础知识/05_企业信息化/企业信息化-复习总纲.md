# 企业信息化 · 复习总纲

> 预计 11 分钟。先闭卷回答“这一步在改哪个层面”，卡住再点原子卡。本模块是本章历史重复考查最集中的一处，P0 只有一张卡，别把整个主题簇都当重点。

## 二、30 秒主线

企业信息化不是买软件，而是让信息技术从局部工具逐步融入业务、管理与战略。规划先分**战略层面 → 业务运作层面 → 管理运作层面**，再由信息系统与信息资源提供支撑、技术平台按业务需要落地；推进要**自上而下结合制度组织创新、自下而上让业务人员受益**；规划信息系统可用 CSF、SST、BSP；多个已有应用之间怎样协同，由 [[企业应用集成EAI]] 回答。

## 三、题干关键词 → 第一反应

| 题干看到什么 | 第一反应与动作 |
| --- | --- |
| 企业信息化规划、企业战略、业务运作、管理运作 | 回忆正式口径“战略—业务运作—管理运作”，检查选项是否偷换成单纯技术采购 |
| 生产过程自动化、管理方式网络化、决策支持智能化、商务运营电子化 | 教材用来描述企业信息化结果的四项 |

| 流程不合理、需要根本性重新设计 | [[企业信息化方法]]：业务流程重构 |
| 资源有限、先支撑直接创造竞争力的业务 | 核心业务应用 |
| 部门局部建设造成信息孤岛 | 主题数据库（按核心业务主题统一数据） |
| ERP、SCM、上下游协同 | 资源管理方法 |
| 咨询、软件等知识密集型企业 | 人力资本投资 |
| 关键因素、关键信息、确定优先次序 | **CSF** |
| 使命/目标/战略转成信息系统目标 | **SST** |
| 企业过程、数据类、自上而下识别、自下而上设计 | **BSP**；注意 C/U 矩阵读法 |
| 已有应用要交换数据、调用能力、协同流程 | [[企业应用集成EAI]]；先分是数据、接口、流程还是界面 |
| SOA + Web Services 的集成 | 面向服务的集成技术 |
| 多个既有 C/S 系统只统一操作入口 | 界面集成；成本低但可能没真正整合 |
| 信息中心是否属于主要职能 | 按“是否围绕信息资源的管理与利用”筛，出现“组织招聘”优先怀疑它 |

## 四、核心做题动作

**动作 A：三个层面按链条判断。** 先问“企业靠什么方向竞争”是战略层面；再问“核心业务流程怎样借助信息技术重组和协同”是业务运作层面；最后问“组织、制度、资源、绩效和决策怎样配合”是管理运作层面。技术平台要从这三层推导出来，**不能把“技术层”误当成独立的一层**。

**动作 B：六类方法先找主要矛盾。** 流程本身不合理 → 业务流程重构；核心业务缺技术支撑 → 核心业务应用；需要系统承接普遍信息处理需求 → 信息系统建设；部门局部建设造成信息孤岛 → 主题数据库；要统筹企业资源与上下游 → 资源管理；主要靠知识智力创造价值 → 人力资本投资。

**动作 C：CSF/SST/BSP 三个入口。** CSF 先找决定目标成败的少数关键因素，再据此确定信息和系统优先次序；SST 把组织的使命、目标和战略转化为信息系统目标；BSP 自上而下识别目标、企业过程和数据类，再自下而上设计系统。BSP 的“过程×数据类”矩阵里，`C` 表示该过程建立/维护该数据类，`U` 表示该过程使用该数据类。

**动作 D：EAI 先判断要集成什么。** 复制/聚合/ETL/消息/适配器 → 面向信息（数据）集成；API、适配器、消息中间件、ESB → 接口/应用集成；工作流/BPM、编排、事件协同 → 流程集成；门户、SSO、界面组合 → 界面集成。教材的演进口径是面向信息、面向过程、面向服务三类，两组分类不能混成唯一固定层级。

**动作 E：跨系统失败先看“发生在哪一步”。** 若失败发生在预留/占用之前（如库存不足直接拒绝），不存在要撤销的东西，不需要补偿；若已预留后再失败（如支付授权失败），必须触发补偿撤回预留。重复请求用相同订单号和操作幂等键识别，保证只创建一次。跨系统步骤通常不能假定成一个整体原子事务，补偿失败要进入可重试/人工处理，并以对账确认最终一致。

本模块没有需要保留的计算公式。

### EAI 的集成视角

| 需求 | 要打通的对象 | 典型方式 | 主要局限 |
| --- | --- | --- | --- |
| 信息/数据集成 | 数据与消息 | 复制、聚合、ETL、消息、适配器 | 语义与一致性治理困难 |
| 接口/应用集成 | 已有应用能力 | API、适配器、消息中间件、ESB | 依赖接口契约 |
| 流程集成 | 跨系统业务步骤 | 工作流/BPM、编排、事件协同 | 流程与异常补偿更复杂 |
| 界面集成 | 用户入口和操作界面 | 门户、SSO、界面组合 | 底层数据和业务逻辑可能仍未整合 |

## 六、最容易丢分的地方

- **“信息化 = 买硬件或上软件”是错的。** 选项常列服务器、数据库和软件选型，看上去像在规划；但技术投入只有与业务和管理变化结合，才可能产生整体价值。
- **三层不是“战略/管理/技术”。** 教材口径是战略层面、业务运作层面、管理运作层面；技术平台必须从这三层推导，不能另列一个孤立的“买什么技术”层面。
- **两条路径不是二选一。** 自上而下保证方向一致，自下而上保证系统真的可用；把“全面规划，分步实施”理解成只做自上而下会丢分。
- **没有“必须先彻底 BPR 再建设系统”的通用顺序。** 业务流程重构可以与系统建设配合，是否先改流程取决于业务目标和现状。
- **信息中心职能题按“是否围绕信息资源管理与利用”筛。** 旧版教材口径对应的是“培养信息资源的管理人员”，而不是由信息中心组织招聘；看到人事招聘动作优先怀疑它就是要选的那一项（该口径来自真题解析资料，来源待核验）。
- **两组集成分类不能混成唯一层级。** 数据、接口、流程、界面是常见的集成需求视角，教材同时还用面向信息、面向过程、面向服务描述演进；说成“固定四层技术栈”就错。
- **界面集成成本低不等于已经整合。** 它只统一入口，底层数据和业务逻辑可能仍未真正打通。
- **幂等与补偿看失败发生的时点。** 首轮库存不足发生在 ERP 预留之前，不需要释放；支付失败发生在已预留之后，必须补偿撤回。
