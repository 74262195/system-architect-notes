# 信息系统建设原则 · 复习总纲

> 预计 5 分钟。先闭卷从“问题”反推原则，卡住再点原子卡。本模块只有一张卡，考法基本是场景归类，不要背成口号。

## 一、大纲边界与优先级

大纲要求的是**基本建设原则**，口径是“高层人员介入、用户参与、自顶向下规划、工程化和其他原则”。也就是说，考试只要求把一段管理场景归到某条原则上，并知道它防的是什么风险。

| 原子卡 | exam_priority | 什么时候做 |
| --- | --- | --- |
| [[7大原则详解]] | P2 | 第二轮；第一轮只要能做“场景 → 原则”归类，不被文件名骗到 |

本模块**没有 P0/P1 卡**。第一轮的最小动作只有两个：记住四类风险对应四条原则；知道文件名里的“7大”不代表教材有固定七项。与它衔接的 [[开发阶段5子步骤]]（P2）和 [[企业信息系统战略规划方法]]（P1）不在本模块，按下文链接按需回看。

## 二、30 秒主线

高层把住企业总体目标 → 核心用户校准真实工作 → 自顶向下统一信息口径 → 工程化保证过程可追踪、可维护；创新性、整体性、发展性、经济性属于补充判断的“其他原则”。一句话：**这四条不是 IT 部门的口号，而是四类失控风险的约束。**

## 三、题干关键词 → 第一反应

| 题干看到什么 | 第一反应与动作 |
| --- | --- |
| 系统是否服务企业总体目标、跨部门资源与决策协调 | **高层管理人员介入**；介入可以是直接参与，也可以是决策、指导和资源支持，CIO 是具体体现之一 |
| 需求与实际工作脱节、使用者不接受 | **用户参与开发**；关键是核心使用者全过程参与 |
| 各部门各建一套、数据或口径不一致 | **自顶向下规划**；先总体规划，再让子系统在其指导下详细设计 |
| 开发依赖个人经验、文档与过程不可追踪、后期难维护 | **工程化**；用规范过程、工具、评审和文档组织开发 |
| 先进性、整体完整、后续发展、投入产出 | **其他原则**（创新性、整体性、发展性、经济性），不要与四项基本原则混列 |
| 题目问“先做企业级总体规划” | 原则上是自顶向下规划，具体方法转到 [[企业信息系统战略规划方法]] |

## 四、核心做题动作

**动作 A：从问题反推原则。** 题干描述的是一个具体麻烦，先问它属于哪类风险：目标跑偏与跨部门协调 → 高层介入；需求失真与不接受 → 用户参与；口径不一致与重复建设 → 自顶向下规划；过程不可控、不可维护 → 工程化。

**动作 B：判断“是原则还是方法”。** 四条原则说明“建设不能失控”，CSF、SST、BSP 说明“怎样规划信息系统、怎样排优先级”，两组不是同一层内容；出现 CSF/SST/BSP 时转到 [[企业信息系统战略规划方法]]。

本模块没有需要保留的计算公式；考法是把场景归到原则，或从原则反推它能防住什么问题。

## 五、高频对比

| 概念 | 核心区分 | 典型场景 | 考试问法或陷阱 |
| --- | --- | --- | --- |
| 高层管理人员介入 | 保证系统服务企业总体目标，协调跨部门资源 | 高层决策、指导、给资源；CIO 是体现之一 | 误以为必须由高层亲手写需求或亲自验收 |
| 用户参与开发 | 核心使用者全过程参与，避免需求失真 | 业务骨干参与需求澄清与阶段评审 | 误以为“验收时让领导签字”就算用户参与 |
| 自顶向下规划 | 先统一总体目标和信息口径，再细分各子系统 | 先总体规划，后子系统详细设计 | 误以为它替代了子系统的详细设计 |
| 工程化 | 用规范过程、工具、评审和文档保证可维护 | 阶段评审、文档作为下阶段输入 | 只记“文档多”，说不出它防的是不可追踪、难维护 |
| 其他原则 | 创新性、整体性、发展性、经济性等补充判断 | 先进性适当、保持整体、考虑发展、重视投入产出 | 把它们硬凑成“固定七大原则”去背 |

## 六、最容易丢分的地方

- **文件名“7大原则详解”不等于固定七项。** 这是为保留既有链接沿用的旧名；正文按“四项展开原则 + 其他原则”校正，大纲也采用四项加其他的口径，所以选项里出现“教材规定七大原则”一类说法要警惕。
- **高层介入不等于领导签字。** 教材允许直接参与，也允许通过决策、指导和资源支持介入；把它窄化成“领导挂名”就会误判。
- **用户参与的落点在全过程。** 核心使用者要参与需求确认、澄清和评审，只在验收环节出现说明不了“避免需求失真”。
- **自顶向下规划不替代详细设计。** 它统一的是总体方向和信息口径；子系统仍要在总体规划指导下做自己的详细设计。
- **原则和方法是两层。** 四条原则是“不能失控”的约束，CSF/SST/BSP 是规划方法；把两者并成一张清单就会答错归类题。

## 八、闭卷自测

- [ ] 四项基本原则分别防止什么风险？能否不看选项说出来？
- [ ] 高层管理人员的“介入”除了直接参加，还包括哪些形式？CIO 处于什么位置？
- [ ] 用户参与开发的关键是“谁来参与、参与到什么时候”？只在验收时签字算不算？
- [ ] 自顶向下规划统一的是什么？它为什么不替代子系统的详细设计？
- [ ] 工程化主要防的是哪类问题？它用什么手段保证可维护和可追踪？
- [ ] 教材的“其他原则”包括哪几项？它们和四项基本原则是什么关系？
- [ ] 为什么文件名写作“7大原则详解”，正文却不把它们当成固定七项？
- [ ] 题干要求“先做企业级总体规划”，应该答原则还是规划方法？方法名称是什么？
