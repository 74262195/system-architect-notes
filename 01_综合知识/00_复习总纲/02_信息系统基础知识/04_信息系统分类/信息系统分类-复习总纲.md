# 信息系统分类 · 复习总纲

> 预计 14 分钟。先闭卷回答“谁在用系统处理什么工作”，卡住再点原子卡。本模块卡最多，但绝大多数题只考**归类**，不考各系统的全部部件。

## 一、大纲边界与优先级

大纲在本章覆盖五类传统信息系统——TPS、MIS、DSS、ES（专家系统，含 AI 的上位定位）和 OAS——以及综合性信息系统（ERP、WMS、MES/SFC、PDM）和电子政务、电子商务。商业智能（BI）在当前笔记里是低频辅助内容。

注意 AI 的定位：大纲是在专家系统概念项下要求人工智能的基本概念、特点和分支，所以 [[人工智能AI]] 只承担“进入 ES 前的上位定位”。

第一轮真正要做的是**分流不串台**；第二轮再补 MIS 的矩阵与七个子系统、DSS 的部件、OAS 的四类组成、电子政务的模式细节与电子商务标准。

## 二、30 秒主线

TPS 先把日常业务事实记准确 → MIS 把事实汇总成管理者能用的信息 → DSS 再用数据和模型帮人比较方案 → ES 换一条路，用领域知识和推理求解特定领域问题 → OAS 综合处理办公信息；[[人工智能AI]] 是 ES 的上位领域，不是与 ES 并列的另一种系统。

综合性信息系统把多种能力放进企业全局：ERP 看企业整体资源，WMS 看仓库，MES/SFC 看生产现场，PDM 看研发数据。电子政务与电子商务分别站在政府侧和市场交易侧，只做定位与分类复习。

## 三、题干关键词 → 第一反应

| 题干看到什么 | 第一反应与动作 |
| --- | --- |
| 订单、收付款、工资、出入库、预订等反复发生的具体业务 | **TPS**；再问“能否等待”区分批处理与联机事务处理 |
| 数据输入 → 业务处理 → 数据库维护 → 文件与报表生成 → 查询处理 | TPS 的五个处理环节 |
| 管理报表、计划与控制、功能/层次矩阵、七个基本子系统 | **MIS**；先画“功能”和“层次”两条轴 |
| 模型库、What-if、方案比较、半结构化/非结构化 | **DSS**；沿“数据 → 模型 → 交互 → 人决策”检查选项 |
| 知识库、推理机、解释程序、启发式规则、特定领域 | **ES**；再看问组成、推理方向还是六个特点 |
| 模仿人类智能、从经验学习、信息不完整时仍能求解 | **AI** 上位概念；出现“ES 属于什么”答“AI 的重要分支” |
| 公文收发、档案归档、日程会议、办公信息一体化 | **OAS**；不要只因出现“辅助决策”就选 DSS |
| 货位、收发料、库存、盘点、库龄 | **WMS** |
| 生产现场、工艺、设备、工序执行、生产防错 | **MES/SFC**；不等于 MRP 算物料需求 |
| 图纸版本、BOM、工程变更、协同研发 | **PDM**；不等于普通文档网盘 |
| 三流集成、MPS/MRP/CRP、供应链协同 | **ERP**；三流是物流、资金流、信息流 |
| 多源数据、数据仓库、OLAP、数据挖掘、经营分析 | **BI**；与 DSS 可重叠，看是否围绕具体决策问题 |
| 政府上网、三网一库、用户中心、政府门户 | **电子政务**；先问互动主体、发展阶段、过程模式还是技术模式 |
| B2B/B2C/C2C/C2B、ebXML/RosettaNet/cnXML | **电子商务**；先分交易主体还是标准问题 |

## 四、核心做题动作

**动作 A：一句话分流链。** TPS 记事实，MIS 出管理信息，DSS 比方案，ES 靠知识推理，OAS 处理办公信息，AI 是上位领域。遇到“都有报表”“问题都复杂”这类重叠描述，回到各自的核心线索，不要靠一个词定答案。

**动作 B：MIS 两轴一清单。** 功能轴回答“管哪件事”（销售与市场、生产、后勤、人事、财务和会计、信息处理、高层管理）；层次轴回答“站在哪一级管”（业务处理、运行控制、管理控制、战略计划）。一个交叉格表示“某职能在某层次需要什么信息支持”；**最容易漏的是后勤子系统**。选项里混入 DSS、ERP、OAS 时，它们不是 MIS 的七个基本子系统。

**动作 C：DSS 两库三部件。** “两库”指数据库和模型库，但教材的两库结构由数据库子系统、模型库子系统、对话子系统三部分组成，所以“两库”不表示没有人机对话部件。判定动作是：有没有模型库和方案比较，最终由不由管理者拍板；说系统自动给出唯一最终决定的不选。

**动作 D：ES 的推理方向与组件。** 知识库保存领域知识，综合数据库（工作存储）保存当前事实和中间结果，推理机选择并应用规则，解释程序说明推理依据。正向推理从已知事实出发（数据驱动），反向推理从待证目标反查条件（目标驱动），双向推理两端协同。

**动作 E：电子政务四步判断。** 先问互动主体（政府与政府、政府对企事业、政府对居民、企业对政府、居民对政府），再问发展阶段（起步、单向互动、双向互动、网上事务处理），再分建设过程模式（用户中心、CRM 思想、政府门户）与技术模式（网络管理、信息资源管理、应用开发、安全体系、标准化）。不要用 B2B/B2C 这类市场交易主体去选电子政务。

本模块没有需要保留的计算公式；都是识别与归类动作。

| 系统 | 核心区分 | 典型例子 | 考试问法或陷阱 |
| --- | --- | --- | --- |

| [[OAS 办公自动化系统]] | 综合处理文字、数据、声音、图像等办公信息 | 公文收发、档案归档、会议协同 | 题干出现“辅助决策”就判成 DSS |

### 两组最容易混的模式

| 对比 | 核心区分 | 典型题眼 | 考试问法或陷阱 |
| --- | --- | --- | --- |
| 电子政务建设过程模式 vs 技术模式 | 前者管服务与业务怎样组织，后者管靠哪些技术管理方式支撑 | 过程：用户中心、CRM 思想、政府门户；技术：网络、信息资源、应用、安全、标准化 | 把“网络管理、安全、标准化”说成过程模式 |
| [[电子商务]] vs [[电子政务分类]] | 前者核心是市场交易，后者核心是政府管理与公共服务 | 采购销售走商务；纳税、报送政府数据走政务 | 都出现“企业 + 网络”时只凭主体名称判断 |
| [[人工智能AI]] vs [[ES 专家系统]] vs [[DSS 支持决策系统]] | AI 是上位技术领域；ES 是它的知识型分支；DSS 是面向管理决策的信息系统类型 | AI 看智能行为与分支；ES 看知识库与推理机；DSS 看数据、模型与方案比较 | 把三者当同一级分类，互相替代 |

## 六、最容易丢分的地方

- **TPS 不是一律实时。** TPS 同时可以采用批处理和联机事务处理，用“这笔业务能不能等”区分，比背“实时性极高”可靠。
- **“有报表”不能证明是 TPS。** 如果题干转而强调把多笔业务加工成管理层的计划、控制信息，要比较 MIS；强调模型比较方案则偏 DSS。
- **MIS 不只服务中层，也不只出固定报表。** 功能/层次矩阵说明同一职能在不同层次有不同信息需求；“功能/层次矩阵”本身不是另一种信息系统。
- **七个子系统是按管理职能拆 MIS。** 它们不是七种不同系统，也不是软件清单；把 DSS、ERP、OAS 混进来就错在分类层级。
- **DSS 的两库不等于只有两个部件。** 两库指数据库和模型库，对话子系统仍在；模型库也不是只读公式仓库，要能建立、调用、修改和管理模型。
- **“问题复杂”不能区分 DSS 与 ES。** 稳定判据是核心组成与用途：ES 看知识与推理，DSS 看数据、模型与人机方案比较。
- **OAS 出现“决策”不等于 DSS。** OAS 的核心仍是办公信息的综合处理，其三段功能里也有辅助决策；DSS 的线索是数据库、模型库和半结构化问题。
- **AI 与 ES 不是同义词，也不是同级分类。** AI 是更大的上位领域，ES 只是其中一个分支；普通程序里有 if/else 也不能因此判成 ES。
- **综合性系统按“管理对象”判断。** 现实产品功能可能重叠，WMS、MES/SFC、PDM 各自的最小定位不要越界。
- **过程模式与技术模式的问法不同。** 问政府门户、用户中心看过程模式；问网络管理、信息资源、安全、标准化看技术模式。
- **电子商务的“标准”不是网络协议。** ebXML、RosettaNet、cnXML 解决的是商务数据格式、语义与流程协同，HTTP/TCP/IP 只能说明通信基础。
- **BI 的处理链是理解框架。** 卡片注明它不表示所有 BI 都必须采用固定四层技术栈；BI 与 DSS 现实中可以重叠。
- **本模块多数分类是教材与考试语境的识别模型。** 五类传统系统、电子政务五类互动与发展阶段都按题干强调的主要管理对象作答，不把它们当成现实产品的唯一分类。
