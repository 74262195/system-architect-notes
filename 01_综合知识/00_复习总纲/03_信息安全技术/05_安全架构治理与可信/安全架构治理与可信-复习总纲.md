# 安全架构治理与可信 · 复习总纲

> [!tip] 用法（约 15 分钟）
> 先闭卷回答自测，卡住再点原子卡。本模块的大问题是：**怎样把零散控制组织成覆盖预防、检测、响应和恢复的整体方案，并让责任、制度和持续改进真正运行起来。**

## 大纲要求到哪里

本模块对应大纲的**安全基本目标与范围、安全系统框架（技术/组织/管理三体系）、风险管理、等级保护、可信计算与治理**（SEC-A01～A08、A22、A23 的落点见 [[信息安全技术-覆盖与减负审查-2026-09-09]]）。要求能回答：

- 安全目标与保护对象各自是什么（[[信息安全基本目标]]、[[信息安全范围与存储安全]]）；
- 风险怎样判断并排序（[[安全风险评估]]）；
- 规则、保护能力与实现手段分别属于哪一类（[[安全模型]]、[[OSI安全体系结构]]）；
- 措施放在哪里、由谁运行（[[安全架构设计]]、[[纵深防御]]、[[数据库安全与完整性设计]]、[[软件脆弱性分析]]）；
- 为什么还需要治理与合规（[[信息系统安全为什么需要治理]]、[[等级保护2.0]]、[[ISO27001信息安全管理]]）；
- 设备状态证据从哪里来（[[可信计算]]、[[零信任架构]]）。

**优先级**：
- 第一轮必抓 **P1**：[[信息安全基本目标]]、[[OSI安全体系结构]]、[[安全架构设计]]；
- 第二轮补 **P2**（本模块主体，10 张）：范围与存储安全、风险评估、安全模型、纵深防御、数据库安全与完整性、软件脆弱性、治理定位、等级保护、可信计算；
- **P3**：[[ISO27001信息安全管理]]、[[零信任架构]]，时间紧只需记住定位。

## 30 秒主线

[[信息安全基本目标]] 把“系统要安全”拆成五项目标 → [[信息安全范围与存储安全]] 再把目标落到设备、数据、内容、行为四类对象 → [[安全风险评估]] 决定先处理哪些风险 → [[安全模型]] 规定“什么访问与信息流才算安全”，[[OSI安全体系结构]] 把攻击、服务、机制放进同一张地图 → [[安全架构设计]] 按风险在不同位置布防，[[纵深防御]] 保证一道失效还有下一道 → 治理线 [[信息系统安全为什么需要治理]]、[[等级保护2.0]]、[[ISO27001信息安全管理]] 让措施长期有人管 → 扩展线 [[可信计算]] 提供设备状态证据，[[零信任架构]] 把它与身份、资源和上下文一起用于访问判决。

## 核心做题动作

### 1. 先认受损目标，再匹配机制（[[信息安全基本目标]]）

“看到了不该看的”→“改了不该改的”→“合法用户用不了”→“事后要追查”→“限制信息怎样流动”。一种措施通常只解决部分目标：加密主要保机密性，备份容灾帮恢复可用性，日志审计要防篡改并限制访问。

### 2. 风险判断：人话因果链 + 定性顺序（[[安全风险评估]]）

**因果链**：威胁利用脆弱性危害资产 → 形成风险 → 安全措施降低风险 → 仍留下**残余风险**。

**填一条可复核记录的六步动作**：明确范围和业务目标 → 识别资产及价值 → 识别威胁与脆弱性 → 判断发生可能性和影响 → 选择规避/降低/转移/接受 → 持续监视残余风险与环境变化。

**教材的定性顺序**：先评资产价值、威胁可能性和脆弱性严重程度，再判断安全事件发生可能性，最后结合资产重要性确定风险值。

> [!warning] 不要把教学等级当通用公式
> 本模块**没有教材规定的通用数值风险公式**；“高/中/低”只是相对等级示例，具体等级或公式必须服从组织采用的评估方法。扫描器报“高危”也不等于全组织风险最高。

### 3. 安全模型判定写全五项（[[安全模型]]）

**主体级别、客体级别、读/写、规则、结论。** 例如“机密主体 → 普通文件 → 写：违反 BLP 不下写，拒绝”。先看题目保护机密性还是完整性，再判读写方向，不要只背四句话。

### 4. OSI 三篮子分类（[[OSI安全体系结构]]）

先问“对方怎么破坏”（安全攻击）、“系统要提供什么保护”（安全服务）、“靠什么实现”（安全机制）。五类安全服务是：**鉴别、访问控制、数据机密性、数据完整性、抗抵赖性**。服务与机制不是一一对应：一种服务可由多种机制实现，一种机制也可支撑多种服务。

### 5. 安全架构案例六步检查清单（[[安全架构设计]]）

①资产/威胁/风险 → ②身份和权限怎么管 → ③网络和通信怎么保护 → ④主机、应用、数据怎么保护 → ⑤怎么审计、检测、响应和恢复 → ⑥谁负责、有什么制度和培训。每一项都写清**解决哪项风险、放在什么位置、由谁维护、用什么证据验证**，答案才闭环。

### 6. 纵深防御认三个词（[[纵深防御]]）

**多点**（边界、主机、应用、数据）、**分层**（一层失败后仍有独立控制）、**支撑设施**（PKI、日志、检测响应平台）。判断标准是独立、互补，不是设备数量。

### 7. 数据库两条控制线（[[数据库安全与完整性设计]]）

访问安全回答“**谁能做什么**”（身份鉴别、最小权限、角色授权、审计）；完整性约束回答“**什么数据状态才合法**”（非空、唯一、检查约束、主键/实体完整性、外键/引用完整性）。能用清晰的声明式约束表达时优先用它；触发器可表达复杂规则但有性能与多级触发风险。

### 8. 软件脆弱性五步分析链（[[软件脆弱性分析]]）

**弱点在哪里 → 为什么产生 → 怎样被到达和利用 → 会造成什么影响 → 如何处置和验证。** 教材生命周期模型：**引入 → 产生破坏效果 → 修补 → 消失**（考试要认这条链，但不能扩展成现实绝对规律）；分析三方向：故障现象、软件开发、软件使用。

### 9. 等级保护先定对象再定等级（[[等级保护2.0]]）

定级第一反应是**保护对象 + 受破坏后的影响**，不是名称。工作主线：**定级 → 备案 → 建设整改 → 等级测评 → 监督检查**，这五个是工作环节不是五种技术，也不表示所有对象都只按单向顺序走一遍。

### 10. 可信计算一条链（[[可信计算]]）

**底层可能先被篡改 → 从开机早期开始检查 → 对启动组件做哈希度量 → TPM/PCR 累积关键状态证据 → 与正常基准比较 → 本地判断或远程证明设备状态。**

## 高频对比

| 对比组 | 核心区分 | 典型例子 | 考试问法 / 陷阱 |
| --- | --- | --- | --- |
| 安全目标 vs 安全范围 | 希望达成什么性质 / 保护哪一面对象 | CIA+可控性+可审查性 / 设备、数据、内容、行为 | 陷阱是把两套口径当互相替代的答案 |
| 安全服务 vs 安全机制 | 要什么保护 / 用什么办法做到 | 数据机密性 vs 加密 | 陷阱是把机制名填进服务清单 |
| BLP vs Biba | 保机密性（不上读、不下写）/ 保完整性（不下读、不上写） | 密级 / 完整性级别 | 陷阱是读写方向说反；两套级别体系不能混成一个 |
| 纵深防御 vs 零信任 | 一道失效还有下一道 / 不因网络位置预先无条件信任 | 多层互补控制 / 资源与请求级判决 | 陷阱是把零信任说成“永远拒绝”或“取消防火墙和分区” |
| 度量启动 vs 安全启动 | 记下来（产生状态证据）/ 不合格就拦下来 | 度量内核并记入 PCR / 签名验证失败拒绝加载 | 陷阱是以为度量本身会阻止启动 |
| 可信计算 vs 零信任 | 设备现在处于什么状态 / 这次访问该不该允许 | TPM/PCR、远程证明 vs 身份+设备+资源+上下文判决 | 陷阱是“设备可信 = 用户有权限” |
| 等级保护 vs 风险评估 vs ISO 27001 | 应达到什么保护等级并建设测评 / 当前风险有多大 / 组织怎样持续运行 ISMS | 定级测评 / 风险排序 / ISMS 闭环 | 陷阱是把三者当同一概念或互相替代 |
| 数据库访问安全 vs 完整性约束 | 谁能做什么 / 什么数据状态合法 | 权限与审计 / 主键、外键、唯一、检查约束 | 陷阱是“有 INSERT 权限就能插任意数据” |
| 网络型 vs 主机型扫描 | 从网络侧探测响应 / 目标侧读取本地状态 | 远程可见征象 / 配置、组件、补丁 | 陷阱是把扫描报告当最终风险结论 |

## 最容易丢分的地方（为什么错）

- **一种措施包办所有目标。** 加密主要保机密性，不自动防篡改、不保证服务不中断；数字签名不隐藏原文；备份不阻止在线数据被读。
- **把“设备可用”和“数据可用”混为一层。** 两者都叫“可用”，但一个描述设备本身，一个描述数据及其使用能力。
- **脆弱性当损失。** 脆弱性只是可被利用的弱点，不等于事件已经发生；风险也不必、通常也不能降为零，措施后要监视残余风险。
- **BLP/Biba 只背口诀。** 不写出主体级别、客体级别、读写方向，就容易说反“上/下”。
- **Chinese Wall 说成“只能服务一个客户”。** 它是按访问历史限制同一利益冲突组中的不同公司数据；不同冲突组不自动封锁，写访问还有额外条件。
- **把 OSI 三部分当执行流程。** 它们是分类与对应关系：攻击说明“要防什么”，服务说明“希望得到什么保护”，机制说明“靠什么实现”。
- **安全架构只列产品名。** 缺了风险、位置、责任人和验证证据，就不是架构而是采购清单。
- **“两台一样的防火墙 = 两层防御”。** 同账号、同配置、同漏洞可能一起失效；纵深强调独立互补。
- **数据库“完整性”理解成备份完整或只防黑客篡改。** 它指数据状态持续满足业务规则，合法主体也可能写入非法状态。
- **软件脆弱性生命周期当现实规律。** 现实中漏洞可能长期未被发现、补丁可能不完整、修复还可能引入新问题；分类法（Landwehr/Aslam/Bishop 等）也不要求背全树状细节。
- **扫描没报问题就以为没有脆弱性。** 网络型看不到很多本地状态；扫描只是分析输入，还要结合资产、暴露条件、威胁路径和影响。
- **等级按名称推定。** “政府系统”“核心系统”不等于某一级；必须针对具体保护对象分析受破坏后的影响。
- **等保五环节当五种技术或固定单遍流程。** 测评发现问题要整改复测；系统边界或业务变化时要重新检查定级与措施。
- **旧五级名称拿来替换现行等级。** “用户自主保护级、系统审计保护级、安全标记保护级、结构化保护级、访问验证保护级”是旧教材、旧题的识别词。
- **可信计算当杀毒。** 度量只产生证据，不等于阻止；TPM 不能保证整个系统绝对安全；PCR 不是普通日志文件。
- **零信任误解三连。** 不是“永远拒绝”，不是“每个数据包重新登录”，也不是“取消防火墙和分区”，而是不把它们当作充分信任依据。

> [!warning] 法规与标准口径（保留卡片时点语境，不要写成“永远如此”）
> 截至 **2026-09-24**，国家标准信息平台仍将 **GB/T 22240-2020《信息安全技术 网络安全等级保护定级指南》**标为现行，实施日期为 **2020 年 11 月 1 日**；标准目录同时显示 **GB/T 22240-2008 已废止**。**2025 年 10 月 28 日**通过的《中华人民共和国网络安全法》修正文本自 **2026 年 1 月 1 日**起施行，第二十三条继续明确实行网络安全等级保护制度。标准目录状态不能代替标准全文，也不能替某个真实系统作等级结论；行业主管部门要求、保护对象边界和实际影响证据仍需针对具体对象核对。**2007 年《信息安全等级保护管理办法》**中的信息系统术语和程序细节，不能脱离后续法律、标准与行业规则，直接当作所有现行网络对象的完整清单。
