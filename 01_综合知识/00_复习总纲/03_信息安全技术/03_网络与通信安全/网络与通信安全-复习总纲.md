# 网络与通信安全 · 复习总纲

> [!tip] 用法（约 10 分钟）
> 先闭卷回答自测，卡住再点原子卡。本模块的判断顺序只有一句：**问题发生在权限、边界、流量检测、不可信网络，还是具体应用通信？**

## 大纲要求到哪里

本模块对应大纲的**网络安全范围与安全措施、防火墙、入侵检测、安全协议（SSL/PGP/IPSec）与 HTTPS**（SEC-A04、SEC-A22 的落点见 [[信息安全技术-覆盖与减负审查-2026-09-09]]）。要求能区分：

- 网络安全的定义、范围与“漏洞—威胁—攻击—风险—措施”闭环；
- 防火墙的分类、特点、功能与实现原理；
- IDS/IPS 的检测与阻断分工；
- VPN 与 IPsec 的 AH/ESP、传输/隧道模式；
- TLS/HTTPS 的握手与数据保护；
- 无线接入的补充保护（WEP/WPA2/WPA3、802.1X/RADIUS）。

**优先级**：
- 第一轮必抓 **P1**：[[防火墙]]、[[VPN]]、[[TLS与HTTPS]]；
- 第二轮补 **P2**：[[网络安全-从漏洞威胁到安全措施]]、[[IDS与IPS]]、[[无线网络安全]]；
- 本模块没有 P3 可跳过项。

## 30 秒主线

[[网络安全-从漏洞威胁到安全措施]] 先把上位风险框架落到网络路径 → [[防火墙]] 在边界按策略放行或拒绝流量 → [[IDS与IPS]] 补上“获准通过的流量里有没有攻击” → [[VPN]] 保护跨不可信公网的整条通信 → [[TLS与HTTPS]] 保护具体 Web 应用连接 → [[无线网络安全]] 是接入链路的补充分支，学完回到攻击识别主线。

## 核心做题动作

### 1. 先贴标签，再选机制（[[网络安全-从漏洞威胁到安全措施]]）

**贴标签**（漏洞/威胁/攻击/风险/措施）→ **找目标**（CIA，还是身份、权限、检测、追责）→ **看位置**（权限、边界、流量检测、不可信网络、具体应用通信）→ **回主事实源**选机制。不要看到“安全”就默认加密，也不要看到“网络”就默认防火墙。

### 2. 防火墙：流量到达 → 匹配规则条件 → 命中允许/拒绝动作 → 未命中按默认策略处理

先看设备这一层能看到什么条件（源/目的 IP、端口、协议、连接状态、应用信息），再判断属于哪一类。

### 3. IDS/IPS 六步闭环

获得流量或行为 → 提取可判断线索 → 与规则或基线比较（特征检测 / 异常检测，都可能误报漏报）→ 形成检测结果并告警 → **IPS 在线丢弃报文、阻断连接或限制流量** → 复核误报并调整规则、阈值或白名单。

### 4. 一份数据穿过站点到站点 VPN（[[VPN]]）

两端网关先完成身份认证、参数协商和密钥准备 → 原始 IP 包交给本地网关 → 按策略选择流量并做 ESP 等安全处理，隧道模式下加新 IP 头 → 公网只按外层 IP 头转发 → 对端网关**先验证、再解密拆封**，把还原的原始包交给内网。验证失败的报文不进入内部网络。

### 5. TLS 建立安全通道五步（[[TLS与HTTPS]]）

浏览器打招呼（能力与建连信息）→ 服务器返回选择结果和证书 → 浏览器核验证书链、站点名称、有效期（以及用途/撤销等条件）→ 双方依据协商信息导出本次连接专用的会话密钥并确认握手未被篡改 → 后续 HTTP 数据用会话密钥高效保护（完整性可查）。

### 6. 无线接入：先接控制端口，再集中认证

终端连接受控端口后，**802.1X 负责接入控制流程**，接入设备把认证请求转给后端认证服务，**RADIUS 常承担集中身份校验并返回授权结果**，通过后才按策略放行。

### 7. 本模块没有必须背的公式

考的是“问题位置 → 机制选择”和协议能力边界；如遇端口号（HTTPS 默认 443），记住**端口号本身不提供安全性**。

## 高频对比

| 对比组 | 核心区分 | 典型例子 | 考试问法 / 陷阱 |
| --- | --- | --- | --- |
| 包过滤 vs 状态检测 vs 应用代理 | 只看报文头字段 / 加连接状态 / 深入应用协议内容 | ACL 规则 / 状态表 / 代理 | 陷阱是“检查越深就一定越安全”；整体安全还看规则质量、覆盖、更新与部署位置 |
| IDS vs IPS | 检测并告警 / 检测后在线阻断 | 旁路镜像 vs 串联在线 | 陷阱是 IDS 写成“只告警、永不联动”，或忽略 IPS 误报会直接伤可用性 |
| AH vs ESP | 不提供机密性 / 核心能力含机密性 | 认证与完整性 / 加密（并可配完整性认证） | 陷阱是写成“ESP 永远无条件提供全部安全服务” |
| 传输模式 vs 隧道模式 | 保护原 IP 上层载荷 / 封装整个原 IP 包 | 端到端保护 / 网关到网关站点互联 | 陷阱是与 AH/ESP 混成一维；“怎样保护报文”和“保护到什么范围”是两个维度 |
| VPN vs TLS/HTTPS | 受保护的网络/逻辑通道 / 具体应用连接保护 | 站点互联、远程接入 / 浏览器访问网站 | 陷阱是互相替代；两者都要与认证、访问控制配合 |
| WEP vs WPA vs WPA2 vs WPA3 | 均已过时与不安全程度不同 / 经典对应算法不同 | WEP-RC4、WPA-TKIP、WPA2-AES/CCMP、WPA3-SAE | 陷阱是把“哪种 Wi-Fi 认证用 AES”答成 WEP 或 WPA |

## 最容易丢分的地方（为什么错）

- **“防火墙只能部署在互联网出口。”** 错在把能力绑死在位置上；它也可部署在主机或内部隔离点，真正决定能力的是部署点与策略。
- **NAT 当成防火墙。** NAT 解决地址转换，防火墙解决策略判决；一台设备可以同时做两件事，但不能因为做了 NAT 就推断完成了访问控制。
- **WAF 与“云防火墙”画等号。** WAF 专门面向 Web/HTTP 应用层攻击，与按网络流量做策略控制的普通防火墙关注对象不同。
- **IDS 写成“只告警、事后发现”。** IDS 可对正在发生的可疑活动实时监控、记录和告警，只是通常不串联直接阻断。
- **只背“IDS 告警、IPS 阻断”。** 漏掉共同的“获得行为 → 提取线索 → 与规则/基线比较 → 告警”过程，以及 IPS 之后的误报复核与策略调整。
- **ESP 写成“永远提供全部安全服务”。** 机密性是核心能力，完整性/认证要看所选算法与配置。
- **“SSL VPN 一定免客户端/一定在应用层”。** 既可能是浏览器门户，也可能需要客户端建立全隧道，只能作为经典简化口径。
- **AH 与 ESP、协议与模式混成一维。** AH/ESP 说“怎样保护报文”，传输/隧道模式说“保护封装到什么范围”。
- **“TLS 永远用服务器公钥加密会话密钥”。** 那是早期可用的 RSA 密钥交换口径；现代 TLS 尤其 TLS 1.3 通常使用 (EC)DHE，证书公钥主要用于身份认证和签名。题干明确给经典 RSA 流程时按题干作答。
- **HTTPS = 网站可信、业务安全。** TLS 只保护传输过程与服务器身份条件，不判断业务输入；地址栏的 HTTPS 不能防 [[SQL注入]]、[[XSS跨站脚本]]、[[CSRF跨站请求伪造]]。
- **隐藏 SSID 当加密。** SSID 不是加密机制，只能降低随意发现的便利性，不能替代接入认证和加密。
- **802.1X 与 RADIUS 混成一个组件。** 前者是终端与接入设备之间的端口访问控制框架，后者常是后端集中认证服务，两者配合。

## 跨模块联系

- 上游：[[RBAC基于角色访问控制]] —— 权限配好了，请求在链路上仍要被控制、检测和保护。
- 应用落点：本模块的 TLS 只管通道，攻击落在应用输入边界，主线交到 [[常见网络攻击]] 与 Web 三卡。
- 治理落点：这些机制怎样组合成覆盖预防、检测、响应和恢复的整体方案，见 [[纵深防御]]（第 5 模块）。
- 基础前置：密码学主链（[[数字证书与PKI]]、[[对称加密]]、[[数字签名]]）是 TLS 与 IPsec 的机制来源。
