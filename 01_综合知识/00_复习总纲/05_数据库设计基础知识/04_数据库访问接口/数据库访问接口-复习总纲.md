# 数据库访问接口 · 复习总纲

## 用法

预计 6～8 分钟。本模块卡片 `exam_priority` 全为 P2，只要求“看到题眼能认到技术”；用「题干关键词」表自测一遍，卡住再点原子卡。ORM 的完整机制不在这里背，直接看 [[对象持久化与ORM]]。

## 大纲边界与优先级

大纲 5.4「用户访问数据库的标准接口」明确点名 **OCI、嵌入式 SQL、ODBC、ORM**。按卡片 `exam_priority`：

- **P2 第一轮即可**：[[数据库访问接口总览]]、[[ODBC与JDBC]]、[[嵌入式SQL与OCI]]、[[ORM访问接口]]。
- JDBC 是主教材对 ODBC 的补充展开，不因日常熟悉 Java 就抬高到与大纲点名项同权重。

边界：本模块只建立“各类接口在解决什么问题”的坐标，不扩写成编程 API 教程；ORM 的唯一完整主事实源在 [[对象持久化与ORM]]，数据库侧只保留定位与导航。

## 30 秒主线

1. 数据库设计解决“数据怎样组织”，但 Java/C/C++ 程序还要能连接、查询、更新数据库，所以需要程序级访问接口 —— [[数据库访问接口总览]]。
2. 接口可分四类坐标：直接调厂商函数库（OCI）、把 SQL 写进宿主语言（嵌入式 SQL）、用统一 API + 驱动访问异构数据库（ODBC/JDBC）、把程序对象与关系记录映射起来（ORM）。
3. 嵌入式 SQL 的识别点是**预编译器**：普通宿主语言编译器不认识 SQL，要先转换成宿主语言可调用的代码 —— [[嵌入式SQL与OCI]]。
4. ODBC 靠驱动和数据源统一不同 DBMS 的连接差异，JDBC 是 Java 访问数据库的标准类和接口 —— [[ODBC与JDBC]]。
5. ORM 处在应用对象模型与关系数据库之间；它不是 DBMS，也不等于不需要 SQL —— [[ORM访问接口]]。

## 题干关键词 → 第一反应

| 题干看到什么 | 第一反应 |
| --- | --- |
| 厂商提供的底层函数库、控制细、与特定数据库绑定强 | OCI 这类库函数级接口 |
| SQL 直接写在 C、COBOL、Java 等宿主语言源程序里 | 嵌入式 SQL |
| 预编译器处理 SQL 与宿主语言的边界 | 嵌入式 SQL |
| Oracle Call Interface、函数调用 | OCI |
| 同一应用经统一接口访问不同厂商数据库 | ODBC（统一 API + 驱动） |
| Java 语言的类和接口、直接执行 SQL | JDBC |
| 对象属性对应表字段、对象关系对应外键/关联关系 | ORM，完整机制看 [[对象持久化与ORM]] |

## 核心流程（按题干找接口）

1. **先看是谁在提供能力**：数据库厂商的函数库 → OCI；统一标准 + 各家驱动 → ODBC 等通用接口。
2. **再看 SQL 写在哪里**：写在宿主语言源程序里、需要预编译 → 嵌入式 SQL，不是通用接口。
3. **再看程序语言生态**：Java 的标准类和接口 → JDBC；不要与 ODBC 的实现生态混为一谈。
4. **最后看抽象层次**：题干问“对象模型怎样映射到关系模型”→ ORM；问“程序怎样连上数据库并执行 SQL”→ ODBC/JDBC；定位不到时回 [[数据库访问接口总览]] 的坐标表，不要按“哪个更高级”排序。

## 高频对比

**ODBC vs JDBC**

| 对比组 | 定位 | 题干信号 |
| --- | --- | --- |
| ODBC | 通过统一 API 和数据库驱动访问异构数据源 | 开放数据库连接、数据源、驱动、异构 DB |
| JDBC | Java 语言访问数据库的标准类和接口 | Java 类与接口、Java 程序执行 SQL |

**嵌入式 SQL vs OCI**

| 对比组 | 做法 | 代价与边界 |
| --- | --- | --- |
| 嵌入式 SQL | 把 SQL 写入宿主语言源程序，用预编译器处理边界 | 还要解决宿主变量、类型转换、游标和事务控制 |
| OCI | 直接调用 Oracle 提供的库函数完成连接、执行 SQL、事务控制 | 更接近数据库底层，灵活但厂商绑定更强、学习和开发复杂度更高 |

**四类接口的坐标**

| 方式 | 核心思路 | 典型特点 |
| --- | --- | --- |
| 库函数级接口 | 直接调用厂商函数库 | 控制细，通常与特定数据库绑定较强 |
| 嵌入式 SQL | SQL 写入宿主程序源代码 | 需要预编译等机制处理 SQL 与宿主语言边界 |
| ODBC 等通用接口 | 统一 API + 驱动访问不同 DBMS | 强调异构数据库统一访问 |
| ORM | 程序对象与关系数据库记录建立映射 | 减少业务代码直接处理关系模型的阻抗 |

## 最容易丢分的地方

- **把 OCI 当通用跨厂商接口**：它是 Oracle 的库函数级 API，通常依赖特定数据库产品。
- **看到 SQL 就选通用接口**：SQL 写在宿主语言里、题干出现“预编译器”时，是嵌入式 SQL。
- **把 ODBC 与 JDBC 混成一个**：ODBC 的线索是统一 API、数据源和驱动；JDBC 的线索是 Java 的类和接口。
- **以为用了统一接口，SQL 方言差异就消失**：统一接口解决连接方式的差异，不同数据库的 SQL 方言和功能差异仍然存在。
- **把 ORM 当 DBMS**：存储、事务、约束、索引仍由数据库系统承担；ORM 只是对象与关系之间的映射。
- **以为 ORM 等于不需要 SQL**：它可以封装或生成部分访问操作，底层关系数据库仍要执行相应数据库操作；这四类接口是解决不同问题的坐标，不是同一技术的四个版本，也不按“谁更高级”排序。
