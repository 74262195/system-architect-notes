# 数据库基础 · 复习总纲

## 用法

预计 8～10 分钟。先合上笔记，用「题干关键词」表做一遍口头判断，卡在哪一行再点对应原子卡；本页只负责复习，不替代第一次学习。

## 大纲边界与优先级

大纲 5.1「数据库基本概念」要求能分清数据库系统里的对象、说清数据管理为什么演进，并掌握数据模型、三级模式和数据库分类。本模块按卡片 `exam_priority` 排：

- **P0 第一轮**：[[数据库三级模式与两级映像]]——模式层次与两种数据独立性；2022-H2-05 直接问过创建聚簇索引改变哪一级模式。
- **P1 第一轮**：[[分布式数据库与透明性]]——分片/位置/复制/逻辑透明性；2019-H2-08、2020-H2-08 有直接判断。
- **P2 第二轮**：[[数据库DB-DBMS-DBS]]、[[数据管理技术三个发展阶段]]、[[数据模型三要素与分类]]、[[DBMS核心功能]]——坐标卡，只要求识别与定位。
- 本模块没有 P3 内容。

范围边界：数据仓库与数据挖掘只保留分类定位，完整处理链在 [[商业智能BI]]；并发控制、日志与恢复只按 [[DBMS核心功能]] 的运行管理职责识别，不在本模块展开。

## 30 秒主线

1. 数据被长期、有组织地保存成 **DB**；**DBMS** 是负责定义、存取、控制和维护的核心系统软件；DB、DBMS、应用、人员和运行环境共同构成 **DBS** —— [[数据库DB-DBMS-DBS]]。
2. 这条分工不是一开始就有：数据管理从人工管理、文件系统演进到数据库系统，逐步把职责从单个应用抽出来交给 DBMS —— [[数据管理技术三个发展阶段]]。
3. DBMS 要先有一套共同语言，即数据模型的**三要素：数据结构、数据操作、数据约束条件**；层次、网状、关系是模型类型 —— [[数据模型三要素与分类]]。
4. 这套语言由 DBMS 的五类功能落地：定义、操作、运行管理、组织存储、建立维护 —— [[DBMS核心功能]]。
5. 应用能少管底层，靠**三级模式 + 两级映像**：外模式管用户视图、概念模式管全库逻辑、内模式管存储 —— [[数据库三级模式与两级映像]]。
6. 数据还要能跨地点组织，于是有分布式数据库和它的各种透明性 —— [[分布式数据库与透明性]]。

## 题干关键词 → 第一反应

| 题干看到什么 | 第一反应 |
| --- | --- |
| 被长期组织、保存、共享的数据集合 | DB |
| 定义、操纵、运行控制与维护数据的核心软件 | DBMS（不是 Navicat 这类客户端工具） |
| DB + DBMS + 应用 + 人员 + 运行环境 | DBS |
| 谁负责规划、授权、备份恢复与日常维护 | DBA |
| 没有专门管理软件、数据面向某个程序、通常不长期保存 | 人工管理阶段 |
| 能长期保存，但文件孤立、联系靠程序构造 | 文件系统阶段 |
| DBMS 统一管理关联数据、共享与独立性提高 | 数据库系统阶段 |
| 树、网、表 | 数据模型类型（层次/网状/关系） |
| 结构、操作、约束 | 数据模型三要素 |
| 不同用户各看一部分数据 | 外模式 |
| 全库有哪些关系、属性和约束 | 概念模式 |
| 创建/调整索引、文件组织、存储位置 | 内模式 |
| 改存储而逻辑结构不动 / 改逻辑结构而用户视图不动 | 物理数据独立性 / 逻辑数据独立性 |
| 建表、增删改查、在线权限并发、存取路径、装载转储 | 数据定义 / 操作 / 运行管理 / 组织存储 / 建立维护 |
| 数据跨节点仍统一使用 | 分布式数据库 |
| 隐藏“切了几片 / 在哪 / 有几份副本” | 分片透明 / 位置透明 / 复制透明 |
| 多个处理资源共同完成一项任务 | 并行数据库 |
| 汇总历史数据供分析 / 从数据里找规律 | 数据仓库 / 数据挖掘 |

## 核心流程（本模块不背公式，只走定位顺序）

1. **先分清对象**：看到“核心软件”答 DBMS，看到“数据集合”答 DB，看到“整体系统”答 DBS，看到“管理职责”答 DBA。
2. **再判阶段**：第一步问“谁在管理数据”，第二步问“应用是否必须理解具体数据组织”。能长期保存不等于数据库系统阶段，底层用文件也不能否定数据库系统。
3. **三要素与模型类型分开答**：问“如何组织 / 能做什么 / 什么不能错”答结构、操作、约束；问“树、网、表”才答模型类型。
4. **DBMS 功能题先圈动词**：描述结构或约束→定义；对已有数据增删改查→操作；在线运行时的权限、完整性、并发、日志、恢复→运行管理；数据字典、存取路径、文件结构→组织存储；初建、装载、转储、重组重构、性能监测→建立维护。
5. **三级模式题只抓三个词**：视图→外模式，全库→概念模式，索引/文件/存储→内模式；再用“哪一层没变”定独立性。
6. **分布式题按透明性对号**：隐藏逻辑关系怎样切片→分片透明，隐藏存在哪个节点→位置透明，隐藏副本→复制透明。

## 高频对比

**四类对象**

| 名称 | 判定 | 典型陷阱 |
| --- | --- | --- |
| DB | 有组织、长期保存和共享的数据集合 | 与 DBMS 混为一谈 |
| DBMS | 定义、操纵、运行控制、存储组织与维护的核心系统软件 | 把 Navicat / DBeaver 当 DBMS |
| DBS | DB + DBMS + 应用 + 人员 + 运行环境 | 缩写成“数据库文件” |
| DBA | 负责规划、授权、安全、备份恢复与运行维护的角色 | 与 DBMS 功能混答 |

**三个阶段**

| 维度 | 人工管理 | 文件系统 | 数据库系统 |
| --- | --- | --- | --- |
| 谁管理数据 | 程序员在程序中安排 | 文件系统管文件，应用解释内容与联系 | DBMS 统一管理数据及其联系 |
| 长期保存 | 典型情况下不保存 | 可以保存 | 可以有组织地长期保存 |
| 共享与冗余 | 很弱、易重复准备 | 文件可复用，跨应用跨格式共享困难 | 共享提高、冗余相对减少 |
| 主要变化 | 程序与数据依赖强 | 冗余、易不一致、数据孤立 | 提高共享、独立性与统一控制 |

**模式与独立性**

| 对象 | 回答什么 | 变化示例 |
| --- | --- | --- |
| 外模式 | 某类用户看到的数据 | 给学生、辅导员各建视图 |
| 概念模式 | 全库逻辑结构与约束 | 新增实体、关系或全局约束 |
| 内模式 | 数据怎样存储和访问 | 创建聚簇索引、调整文件组织 |
| 外模式/概念模式映像 | 逻辑数据独立性 | 概念模式改、用户视图尽量不动 |
| 概念模式/内模式映像 | 物理数据独立性 | 内模式改、概念模式与应用尽量不动 |

**四个容易混的数据库名词**

| 名称 | 先问什么 | 不等于什么 |
| --- | --- | --- |
| 分布式数据库 | 数据跨节点怎样组织仍像一个整体使用 | 不等于“计算一定更快” |
| 并行数据库 | 多个处理资源怎样协同完成一项任务 | 不等于数据一定跨异地 |
| 数据仓库 | 怎样保存整合好的历史分析数据 | 不等于日常交易库 |
| 数据挖掘 | 怎样从数据中发现模式、规则或异常 | 不等于存放数据的数据库 |

## 最容易丢分的地方

- **把“不保存”扩大化**：它只是主教材对人工管理阶段典型处理方式的概括；判题抓“没有专门软件统一管理、数据面向某个程序”。
- **用“底层有文件”否定数据库系统**：核心边界是应用各自围绕孤立文件，还是由 DBMS 统一组织关联数据并提供共享与控制。
- **把 DBMS 当成客户端工具**：Navicat、DBeaver 只是连接与查询界面；关掉客户端，数据库服务器仍由 DBMS 管理。
- **三要素与模型类型串答**：层次、网状、关系是模型类型；三要素永远答结构、操作、约束。
- **建索引被判成概念模式**：索引改变的是存储与访问方式，属内模式；“对表操作”不改变这一判断。
- **两级映像被当成“程序永不用改”**：映像只是隔离变化；业务语义或用户实际需要的字段变化时，外模式和应用仍可能调整。
- **分布式与并行混掉**：一个是数据跨地点统一管理，一个是任务并行计算；出现多个节点不一定选分布式。
- **数据仓库与数据挖掘当同义词**：仓库可以分布式部署，挖掘也读仓库数据，这是实现组合关系，不是定义替代。
