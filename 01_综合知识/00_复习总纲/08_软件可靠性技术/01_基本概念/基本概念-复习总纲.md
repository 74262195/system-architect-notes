## 题干关键词 → 第一反应

| 题干看到什么 | 第一反应 |
| --- | --- |
| 规定条件、规定时间、完成规定功能、不失效 | 软件可靠性，四要素缺一不可 |
| 不失效概率、可靠度、`R(t)` | 可靠度；先确认时间口径 |
| 给出已失效概率 `F(t)` | `R(t)=1-F(t)` |
| 平均能运行多久才失效 | MTTF |
| 可修复系统相邻故障之间的平均间隔 | MTBF |
| 平均多久恢复、恢复时间、MTTR | 视角已转向可用性 |
| 自然时间 / 运行时间 / CPU 执行时间 | 先统一口径，不同口径不能直接比 |
| 失效严重等级、目标值、验收条件、成本与工期 | 可靠性目标：先分级，再定量 |
| 「连续运行很久没出错，所以可靠」 | 缺条件与时间，不能直接判为可靠 |

## 核心做题动作与必要公式

**动作 1：四要素闭合检查。** 题干只说「要可靠、不失效」时，回头找软件对象、运行条件、时间区间、规定功能；缺一项就不能直接下结论。

**动作 2：会写并会读 `R(t)`。** `R(t)` 表示规定条件下运行到时间 $t$ 仍未失效的概率。若 $F(t)$ 表示到 $t$ 前已失效的概率，则

\[
R(t)=1-F(t)
\]

读作「可靠度等于 1 减去累计失效概率」；$t$ 用与试验一致的时间单位（小时、天等）。适用条件：同一软件对象、同一运行条件、同一时间口径。代入检查：同条件观察 100 次「连续运行 10 小时」，8 次在 10 小时内失效，则 $F(10\text{小时})=0.08$，$R(10\text{小时})=0.92$；验算失效比例与未失效比例相加为 1。这只是样本估计，不代表真实环境可靠度恰好是 0.92。

**动作 3：三个 M 只认口径，不背等式。** MTTF 看「平均能运行多久才发生失效」，关注少发生失效本身；MTBF 看「可修复系统相邻两次故障之间的平均间隔」，是间隔口径，不机械等同 MTTF；MTTR 看「发生故障后平均多久恢复」，描述恢复快慢，已进入可用性视角。题干问「服务可用比例」时不要停在可靠性，回 [[可靠性与可用性]] 处理。

> [!warning] 本模块不引入的其他公式
> 若题干把可靠性指标和工期**三点估算**混在一起，那是 [[10_网络计划与关键路径]] 的口径；本章卡片没有该公式，按那张卡执行，不要凭记忆补。

## 高频对比

| 概念对 | 核心区分 | 考试问法 / 陷阱 |
| --- | --- | --- |
| 可靠性 vs 可用性 | 可靠性问「这段时间尽量不失效」；可用性还问「想用时是否可用、多久恢复」 | 出现 MTTR、恢复时间、可用比例就别只答可靠性 |
| MTTF vs MTBF vs MTTR | MTTF 看「到失效为止」；MTBF 看「可修复系统相邻故障间隔」；MTTR 看「恢复快慢」 | 「平均多久才失效」→ MTTF；「相邻间隔」→ MTBF；「多久恢复」→ MTTR |
| $R(t)$ vs $F(t)$ | $R$ 是仍不失效的概率，$F$ 是累计已失效的概率 | 两者相加必须为 1，否则口径不一致 |
| 可靠性目标 vs「越可靠越好」 | 目标要按失效严重程度分级、量化，并与成本、工期平衡 | 低概率高后果的失效不能因「低频」被忽略 |

## 最容易丢分的地方

- 把「连续半年没崩」当成可靠：这类表述没有规定条件、时间区间和功能范围，未覆盖的路径仍可能被新条件触发。
- 把 MTTR 当成可靠性指标：它主要说明恢复快慢；「少发生失效」才是可靠性本身。
- 时间口径混算：自然时间、运行时间、CPU 执行时间不是一个基准，两组数据必须先统一再比较。
- 把 $R(t)$ 读成时间：它是概率，取值 0～1；检查失效比例与未失效比例是否凑成 1。
- 只设一个总可靠度、不做严重程度分级：教材引入失效严重程度类，正是要求按后果分别设目标。
