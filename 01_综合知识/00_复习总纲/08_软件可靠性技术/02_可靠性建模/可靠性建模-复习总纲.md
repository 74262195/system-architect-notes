# 可靠性建模 · 复习总纲

> **用法**：预计 5 分钟（2 张卡，考试优先级都是 P2）。先闭卷做末尾自测，卡住再点原子卡。本页只做复习索引，不是新的事实源；与卡片冲突时以卡片为准。

## 大纲边界与优先级

本模块对应大纲 8.2，只有两个考点：**为什么需要可靠性建模**、**十类可靠性模型认到什么程度**。

- 两张卡都是 P2（[[04_可靠性建模：为什么不能只数缺陷]] 仅在阶段归属类干扰项中出现，[[05_可靠性模型分类：十类模型到底记到什么程度]] 大纲要求识别但无直接真题），**放第二轮**，第一轮不必投入。

## 30 秒主线

[[04_可靠性建模：为什么不能只数缺陷]] 说明缺陷数不等于失效概率，需要「假设 + 失效数据 → 估计与预测」 → [[05_可靠性模型分类：十类模型到底记到什么程度]] 把十类压成四组识别地图。

## 题干关键词 → 第一反应

| 题干看到什么 | 第一反应 |
| --- | --- |
| 根据测试失效数据估计或预测软件可靠性 | 可靠性模型 |
| 两个系统缺陷数相同，可靠性是否相同 | 不能直接判同，要看缺陷路径与使用方式 |
| 模型比较、模型选择 | 先找「假设 + 需要的数据 + 期望输出」 |
| 预先播入已知错误再估计残留错误 | 种子法 |
| 单位时间累计失效数、泊松 | NHPP（非齐次泊松过程） |
| 状态转移、用已有知识更新判断 | 马尔可夫过程 / 贝叶斯分析 |
| 输入出现概率决定哪些缺陷更易触发 | 输入域分类 |

## 核心做题动作与必要公式

**动作 1：模型比较题先看三件事，再看名字。** 依次问：模型假设是什么、需要什么数据、希望输出什么。这三件事决定模型能不能用；名字只用来排除明显不匹配的选项。

**动作 2：不要用缺陷数代替失效概率。** 缺陷藏在几乎走不到的页面，和藏在每笔交易都执行的支付路径，造成失效的机会完全不同；可靠性还受软件结构与复杂度、输入与运行环境、用户实际使用功能与频率、测试排错过程中失效行为变化的影响。

**动作 3：模型是近似，不是真值。** 模型建立的是「已观察到失效数据 + 对软件/使用过程的假设 → 当前可靠性估计 + 未来失效行为预测」。若假设与真实过程不符（例如模型假定「发现缺陷立即修复」，项目却把低严重度缺陷全部延期），算得再精确也可能只是「精确地算错」。实用模型通常要求：假设有依据、足够简单、能算出有用指标、对未来的映射较好、能在一定范围应用。

**动作 4：十类只到「见名知动作」。** 教材十类为种子法、失效率类、曲线拟合类、可靠性增长、程序结构分析、输入域分类、执行路径分析、NHPP、马尔可夫过程、贝叶斯分析。本模块不保留任何公式。

> [!warning] 本模块不引入的公式
> 本模块与三点估算无关；若题干出现工期乐观/最可能/悲观三值，按 [[10_网络计划与关键路径]] 的口径处理，不要在这里套可靠性模型。

## 高频对比

| 概念对 | 核心区分 | 考试问法 / 陷阱 |
| --- | --- | --- |
| 缺陷数 vs 失效概率 | 缺陷数是静态计数；失效概率还取决于缺陷所在路径、输入环境与使用频率 | 「两个软件都 10 个缺陷，可靠性相同吗」→ 不能直接判同 |
| 模型假设 vs 计算精度 | 假设不符，精度再高也无效；假设是选模型的第一道门 | 模型比较题先答假设适用性，别直接比公式复杂度 |
| 四组模型思路 | 数错误/失效数量（种子法、失效率、曲线拟合、可靠性增长）；看程序结构与执行路径；看输入域概率；用随机过程/先验信息（NHPP、马尔可夫、贝叶斯） | 按手头数据与问题挑组，而不是「名字高级就选」 |
| 种子法 vs NHPP | 种子法人为准入已知错误，再看抓到多少来估计残留；NHPP 把随时间发生/累计的失效看成随机计数过程 | 独特动作词：「播种错误」→ 种子法；「泊松、累计失效数」→ NHPP |

## 最容易丢分的地方

- 把「缺陷数」当成可靠性结论。缺陷数只是输入之一，不能单独决定失效概率。
- 默认模型输出就是软件真实世界的完整复制。模型是近似，假设不适用时输出不可信。
- 模型比较题先背名字、比公式复杂度，却不检查假设是否需要的数据现实中能拿到。
- 以为十类模型都要会推导。本章只要求按独特动作词识别思路，不要求公式。
