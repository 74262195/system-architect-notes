# 可靠性评价 · 复习总纲

> **用法**：预计 5 分钟（1 张卡，P1）。先闭卷做末尾自测，卡住再点原子卡。本页只做复习索引，不是新的事实源；与卡片冲突时以卡片为准。

## 大纲边界与优先级

本模块对应大纲 8.6，只有一个考点：**怎样从失效数据判断可靠性是否达到目标**，也是全章闭环的收口。

- 唯一卡片 [[15_可靠性评价：怎样从失效数据判断是否达到目标]] 是 P1（2010 综合知识考过可靠性评价，大纲将 9.6 列为独立节点），第一轮要能答出「评价做什么 + 模型怎么选 + 零失效为什么不是 1」。
- 大纲只要求「用模型和统计方法评估当前、预测未来、与目标比较」；本模块不引入具体统计检验公式。

## 30 秒主线

最后一问不是「测完了吗」，而是「能下什么结论」 → 检查数据质量 → 选择适用模型 → 评估当前并预测未来 → 与可靠性目标比较并决策（发布 / 继续测试 / 停止测试 / 还差多少时间资源）。

## 题干关键词 → 第一反应

| 题干看到什么 | 第一反应 |
| --- | --- |
| 模型选择、失效数据、是否达标 / 停止测试 / 允许发布 | 可靠性评价 |
| 测了一周记录到 3 次失败，能否发布 | 单看数字不能决定，要结合模型、数据质量与目标 |
| 「没有失效，所以可靠度为 1」 | 判错，只能说这批样本未观察到失效 |
| 如何选择可靠性模型 | 先看假设适用性，而不是选最复杂的 |
| 时间、失效、严重程度定义不统一 | 数据质量问题，会直接把评价带偏 |
| 「架构方案有哪些风险/敏感点/权衡点」 | 07 章架构评价，不是本模块 |
| 高可靠系统的保守结论 | 需结合统计假设和置信水平 |

## 核心做题动作与必要公式

**动作 1：先复述评价要回答的五个问题。** 当前可靠性大约是多少；是否达到事先设定的目标；是否满足发布或停止测试的条件；如果还没达到，大概还需要多少时间/资源；未来一段时间可靠性会怎样变化。只会数「测到几个故障」不算评价。

**动作 2：模型选择按四个角度打分。** 假设适用性（模型前提和当前软件过程是否相符）；预测能力与质量（模型是否成熟、预测表现是否可信）；输出是否满足需求（能否给出当前可靠度、MTTF、目标日期/成本等需要的结果）；使用是否简便（所需数据能否现实收集，计算/工具成本是否可接受）。

**动作 3：数据质量和模型一样重要。** 统一「时间、失效、严重程度」等定义，持续收集并保证完整准确，比盲目选择复杂模型更重要；不准确的数据会直接把评价带偏。

**动作 4：「零失效」只能保守表述。** 有限次测试恰好没出现失效，只能说「在这批样本中没有观察到失效」。只要没有穷尽所有可能输入、状态和运行时间，就不能推出软件永远不失效，更不能写可靠度 1.0；高可靠系统往往还要结合统计假设和置信水平做保守估计。本模块不保留公式。

## 高频对比

| 概念对 | 核心区分 | 考试问法 / 陷阱 |
| --- | --- | --- |
| 可靠性评价 vs 07 章架构评价 | 07 章用 ATAM 等看架构方案能否支持质量属性、风险/敏感点/权衡点；本模块是失效数据经可靠性模型后的定量评估与预测 | 问「架构风险点」答 07 章口径，别答失效数据 |
| 零失效 vs 可靠度 1.0 | 零失效只表示本批样本未观察到失效；可靠度 1.0 需要穷尽所有输入、状态和运行时间 | 看到「没失效所以可靠度为 1」先判错 |
| 数据质量 vs 模型复杂度 | 定义统一、持续完整收集是前提；数据不准时复杂模型只会把结论带偏 | 评价效果差先查数据，不要只换更复杂的模型 |
| 评估当前 vs 预测未来 | 评估用失效数据判断当前位置；预测推断未来一段时间的可靠性变化 | 问「未来会怎样」要答预测，不能只答当前水平 |

## 最容易丢分的地方

- 把评价等同于「数故障个数」。评价要检查数据是否可信，再结合适用模型和统计分析估计当前表现并判断是否达标。
- 认为测试期间没有失效就等于可靠度 1.0。未观察到失效不等于不会失效，样本代表性、模型假设和数据质量都要检查。
- 选最复杂的模型。先看假设适用性，再看预测质量、输出是否满足需求和使用是否简便。
- 忽视数据定义的一致性。时间、失效、严重程度口径不统一时，评价结论不可信。
- 与 07 章架构评价混淆。两者对象和证据链不同：一个看架构方案，一个看失效数据。
