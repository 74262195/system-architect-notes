## 30 秒主线

**现实状态 → 感知 → 通信 → 计算 → 控制 → 执行 → 再感知**，这条环就是 CPS 的重点。

- [[01_CPS是什么：为什么不是设备联网的别名]]：CPS = 计算 + 通信 + 控制深度融合，让信息系统进入物理过程闭环；关键不是“设备联网”，而是“信息处理真正作用回物理对象”。
- [[02_CPS闭环：感知计算控制反馈如何连起来]]：闭环两程——去程是数据流（物理对象→传感→通信→计算），回程是控制流（决策→执行器→物理对象）；Unit → System → SoS 只是规模放大，3C 融合不变。
- [[03_CPS建设与应用：什么时候需要信息直接控制物理世界]]：建设就是把“可感知、能通信、能计算、控制目标明确、执行可动作、反馈能闭合”六类能力接成可靠链。

## 题干关键词 → 第一反应

| 题干信号 | 第一反应 |
|---|---|
| 感知现实、计算判断、发出控制、状态再反馈 | 先找“感知→计算→控制→反馈”闭环 |
| 传感器 + 网络 + 上传，但没人控制设备 | 更像 IoT／监测，不急着选 CPS |
| 自动调整阀门/电机，并读取调整后的新状态 | 控制闭环成立，CPS 特征强 |
| 3C（计算、通信、控制） | 三者缺一都不足以说明 CPS 价值 |
| 只发告警、由人另行处理 | 仍是监测或辅助决策，不是自动控制 |

## 核心识别动作：把 3C 连成闭环

1. 圈动词：采集 / 传输 / 分析 / 决策 / 控制 / 反馈。
2. 看去程：现实状态有没有进入数字系统并被计算。
3. 看回程：判断结果有没有改变现实对象（阀门、电机、设备参数）。
4. 看反馈：动作之后的**新状态**有没有再次进入系统。
5. 下结论：只有前两步 → 监测／IoT；四步成环 → CPS 特征最强。

教材层次：Unit 是能自己感知—计算—通信—控制的基本单元，System 是多个单元联网协同，SoS 是多个相对独立的系统再协作；三层不是孤立名词，而是同一根 3C 主线在放大规模。

## 高频对比

| 对比 | 核心区分 | 典型例子 | 考试陷阱 |
|---|---|---|---|
| CPS vs IoT | IoT 强调连接、感知、数据交换；CPS 强调计算与通信进入**物理控制闭环** | 温度上传看板 vs 自动降温并复测 | 写“传感器+网络”就选 CPS |
| CPS vs 普通监控系统 | 监控卖**可见性**；CPS 卖**控制闭环** | 曲线展示 vs 自动调冷却功率并继续调 | 看到“实时”就选，忽略决策是否作用回物理对象 |
| CPS vs 机器人 | CPS 是信息—物理融合的系统范式；机器人强调**实体执行机构怎样完成任务** | 调控产线参数 vs 机械臂抓取搬运 | 看主语和目标，别看到电机就选机器人 |
| CPS vs 数字孪生 | CPS 重控制闭环；数字孪生重“持续关联的数字对应体 + 仿真优化” | 恒温闭环 vs 风机孪生体预测故障 | 两者可同在一个系统，不是二选一 |

## 最容易丢分的地方

- **把“传感器+网络”当充分条件**：联网只是可能的前提，缺回程就不成立。
- **把“告警联动”当自动控制**：只把消息推给人，人是否操作仍是独立环节。
- **只算一次就宣布闭环完成**：必须读回动作后的真实状态才算反馈。
- **把 Unit / System / SoS 背成三个孤立名词**：它们描述同一根 3C 主线的规模扩展。
- **把 CPS 当产品或协议名**：它是系统能力目标，不绑定某种网络或部署位置。
- **3C 只记得住一个**：价值来自融合，单独通信或单独计算都不够。
