## 大纲边界与优先级

大纲 10.3 要求机器人的**定义与发展、Robot 4.0 核心技术、分类**：不铺机械设计，只做识别与归类。

- 本模块两张卡 `exam_priority` **都是 P2**：[[06_机器人闭环：智能如何变成现实动作]] 的理由是“机器人只在架构情境出现，无技术题”，[[07_Robot4.0：核心技术与分类怎么识别]] 的理由是“仅大纲+教材，全库无题”。所以放**第二轮**，时间紧时至少保住两条识别动作。
- 施工蓝图中 A006、A007 的 `build_level` 都是 P1（建设深度），和 `exam_priority: P2` 不是一回事；本章真题证据薄弱（2009–2018 映射零命中，近年才有零星信号），不要按“高频”投入。
- 边界：机器人导航、模块化、虚拟化等更细的工程实现不在本章；数字孪生的主事实源在 [[10_数字孪生：为什么不是普通数字模型]]、[[11_数字孪生关键技术：怎样监测预测仿真并优化现实对象]]，本模块只把它当“可借用的虚实融合能力”。

## 30 秒主线

**AI 给出判断 → 机器人把判断接进实体闭环：感知 → 决策/规划 → 控制 → 执行 → 再感知。**

- [[06_机器人闭环：智能如何变成现实动作]]：机器人是软硬件结合的实体系统。感知回答“在哪里、周围是什么”，决策回答“现在做什么”，规划把目标变成路线或动作序列，控制算出怎样驱动电机，执行真正改变环境，新状态再被感知。
- [[07_Robot4.0：核心技术与分类怎么识别]]：教材明确列出的五项核心技术是**云—边—端无缝协同计算、持续学习与协同学习、知识图谱、场景自适应、数据安全**；分类先问“按什么分”，再看类别。

## 题干关键词 → 第一反应

| 题干信号 | 第一反应 |
|---|---|
| 传感器、导航、轨迹、控制器、机械臂/驱动器、环境反馈 | 实体闭环“感知→规划→控制→执行” |
| 只有图像识别或分类模型 | 是 AI 能力，还缺执行机构，不等于机器人 |
| 任务在端、边、云之间分配 | 云—边—端无缝协同计算（五项之一） |
| 边运行边改进、多台机器人共享经验 | 持续学习与协同学习 |
| 把环境中的对象、关系、事件组织成可用知识 | 知识图谱 |
| 环境变了、行为随之改变，预测后调整行动 | 场景自适应 |
| 保护图像/位置等数据、控制跨端边云传输 | 数据安全 |
| 人远程操纵；按预设程序运行；示教后重复；随环境变化调整；组合多种控制能力 | 分类轴一：**按控制方式** |
| 工厂焊接；面向服务任务；建筑/农业等特殊作业环境 | 分类轴二：**按应用行业** |

## 核心识别动作：机器人闭环与两条分类轴

1. **先看题目要不要在物理世界执行动作**：只输出一个 AI 结果 → 不是机器人。
2. **拆五环**：感知 → 决策 → 规划 → 控制 → 执行，再看新状态是否回流。
3. **Robot 4.0 题先对照教材五项**，用“任务怎样分配、知识怎样共享、环境变了怎样适应、数据怎样保护”判断，不把相关应用词一律当成教材原列项目。
4. **分类题先找轴**：描述“示教后重复”按控制方式；描述“用于工厂焊接”按应用行业。同一台机器人可以同时在两条轴上各有一个标签。
5. **云机器人只作边界识别**：核心是借助网络获得算力、数据、模型、知识或协同服务，最直接对应“云—边—端协同计算”，现场反应不能一概等云端返回。

## 高频对比

| 对比 | 核心区分 | 典型例子 | 考试陷阱 |
|---|---|---|---|
| AI vs 机器人 | AI 解决“怎样获得智能判断能力”；机器人解决“实体系统怎样感知环境并完成物理动作” | 图片分类模型 vs 移动机器人绕障搬运 | 把两者当同义词；看到算法名就答机器人 |
| 机器人 vs 普通机械自动化设备 | 机器人不必然带高级 AI，机械自动化也可属于机器人系统 | 按固定轨迹焊接的工业机器人 | 以为“是机器人就必须有机器学习模型” |
| 机器人 vs CPS | CPS 强调信息计算与物理过程形成控制闭环的系统范式；机器人强调实体执行机器怎样完成任务 | 产线控制闭环 vs 机械臂抓取 | 看到电机只想到机器人，看到反馈只想到 CPS |
| 控制方式 vs 应用行业 | 两条**不同分类轴**，回答“怎么控制”与“用在哪里” | 示教再现机器人 / 工业机器人 | 把两条轴对立成互斥答案；把技术名当类别 |

## 最容易丢分的地方

- **把 Robot 4.0 当成“第 4 类机器人”的分类编号**：它是能力升级方向，不是分类轴上的类别。
- **把相关技术当教材五项**：导航、模块化、虚拟化、人机交互、数字孪生都可能与机器人有关，但不是“五项核心技术”的替代清单。
- **把技术名当分类类别**：分类题必须先问“按什么分”，导航和数字孪生都不是类别。
- **两条分类轴混着答**：先看题目问哪条轴，再选类别，它们不是互斥答案。
- **题目问“持续与协同学习”时错答“云—边—端协同计算”**：经验在云端共享只说明协同计算存在，分类依据仍是执行中的持续更新与多机器人共同学习。

## 跨模块联系

- 上承 AI：[[人工智能-复习总纲]] 给出学习、识别、推理、决策能力；机器人负责把它接到实体动作上。
- 同源于 CPS：机器人本身就是典型的信息—物理融合对象，与 [[CPS-复习总纲]] 关注点不同但可组合。
- 下启边缘计算：机器人与 CPS 都产生大量现场数据，很多动作不能等数据绕到云端再回来，这正是 [[边缘计算-复习总纲]] 的切入口。
- 与数字孪生：机器人可借用数字孪生做状态监测、仿真验证、维护预测和参数优化，但孪生不替换教材五项中的任何一项。
