## 第 1 关 · 起源：一间装满电子管的屋子（1946）

### 📖 故事
1946 年，美国费城的一间大屋子里，**18000 个电子管**同时发光，机器重 30 吨、耗电 150 千瓦——这就是世界第一台计算机 **ENIAC**。它的"编程"方式是**人工插拔线路板**：算一道弹道题，要工人花几天时间改线路。

冯·诺依曼看不下去了，提出天才想法：**把"程序"也当成数据存进机器里**——这就是"存储程序"原理。从此计算机不需要人改线路，只需要"读程序、执行程序"。

> 💡 **这解释了第一个考点**：计算机为什么由 **运算器、控制器、存储器、输入、输出** 五大部件组成？因为冯·诺依曼就是按"存储程序"的需求设计的分工。

### 📚 线性学习顺序
1. **[[计算机系统组成|计算机系统组成]]** → 五大部件 + 软硬件关系（先读这篇，建立全局图）
2. **[[数据表示与编码-进制转换]] → [[数据表示与编码-原反补移码]] → [[数据表示与编码-定点与浮点]] → [[数据表示与编码-字符编码]]** → 数和字符怎样变成位串

### 🎯 学了能干什么
- 上午题 1-2 分：冯·诺依曼原理、"存储程序"、五大部件组成
- **定位**：这是全章的"地图"——后面每一关都是这张地图的放大镜

## 第 2 关 · 大脑：CPU 的语言与流水线

### 📖 故事
CPU 是计算机的"大脑"，它只认自己的母语——**机器指令**。早期的 CPU（CISC）像一位"万事通老先生"：一条指令能干很多事（比如一条"字符串查找"指令），但代价是硬件里塞满复杂电路。

后来人们发现：**程序里 80% 的时间只用到 20% 的简单指令**。于是 RISC 诞生了——"我只会简单的动作（Load/Store、加减），复杂的活交给编译器组合"。就像**老专家 vs 年轻效率狂**：RISC 指令规整、硬件简单，特别适合流水线。

流水线的故事：一条指令要经过"取指→译码→执行→访存→写回"5 个车间。串行做 = 一条做完下一条才开工（**效率浪费**）；流水线 = 5 个车间同时开工，各自处理不同指令（**像工厂流水线**）。

> 💡 **这解释了**：经典 RISC 的规整指令格式为什么利于取指、译码和流水线；现代 CISC/RISC 已互相借鉴，考试识别经典特征即可。

### 📚 线性学习顺序
1. **[[CPU内部组成-运算器与控制器|CPU 内部组成]]** → 先认识运算器与控制器（部件分工）
2. **[[CPU内部组成-寄存器体系|寄存器体系]]** → PC/IR/MAR/MBR/PSW 职能与归属
3. **[[CPU内部组成-指令执行过程|指令执行过程]]** → 取指→译码→执行三阶段 + PC 按指令长度前进的时机
2. **[[CPU指令集 CISC与RISC|CISC vs RISC]]** → 指令集的"两条路线"
3. **[[指令寻址方式|指令寻址方式]]** → 操作数去哪儿找（立即/直接/间接/变址/基址）
4. **[[指令流水线|指令流水线]]** → 用工厂思维理解 + 背熟 3 个计算式
5. **[[Flynn分类法|Flynn 分类法]]** → 并行体系结构四分类（GPU=SIMD、多核=MIMD）

### 🎯 学了能干什么
- 上午题 2-3 分：RISC 特征、流水线计算（周期/总时间/加速比/吞吐率）
- **定位**：CPU 是"大脑"，指令集是"思维方式"，流水线是"效率革命"；寻址方式是"操作数导航"（送分题）

## 第 3 关 · 记忆：为什么要有四层记忆

### 📖 故事
CPU 太快了（纳秒级），而磁盘太慢（毫秒级）——**差了 100 万倍**。如果把所有数据都放磁盘，CPU 就整天干等；全放寄存器，贵到破产。

于是人类发明了"**记忆金字塔**"：寄存器（大脑）→ Cache（办公桌上的笔记本）→ 主存（办公室的抽屉）→ 外存（家里的仓库）。**越往上越快越贵越小，越往下越慢越便宜越大**。

为什么这么分层真的有用？因为程序有**局部性**：它总是"盯着"一小块地方反复访问（循环 = 时间局部性；挨个读数组 = 空间局部性）。既然访问高度集中，那就把最热的数据放最快的地方——Cache 应运而生。

内存还有个致命问题：**一断电就全忘**（DRAM 靠电容存电荷，还得定期刷新防漏电）。所以数据要落到磁盘上；磁盘怕坏，就搞了 **RAID**——多块盘协同（镜像/校验），坏了还能救。

> 💡 **这解释了**：存储层次 = 用"局部性"换"性价比"；SRAM/DRAM 的差别 = "贵而快 vs 便宜但要充电"；RAID = "数据安全保险"。

### 📚 线性学习顺序
1. **[[存储层次与主存|存储层次与主存]]** → 金字塔 + SRAM/DRAM
2. **[[Cache|Cache]]** → 命中率计算 + 三种映射 + 替换算法
3. **[[外存与RAID|外存与 RAID]]** → 磁盘结构 + RAID 0/1/5/10

### 🎯 学了能干什么
- 上午题 2-3 分：Cache 平均访问时间计算、RAID 容量、存储扩展
- **定位**：理解"速度-价格-容量"三角权衡——这也是整个架构师考试的思维底色

## 第 4 关 · 沟通：CPU 与外设的"快递史"

### 📖 故事
五大部件之间怎么交换数据？靠**总线**——一条"高速公路"：
- **数据总线** = 车道数（决定一次运多少位）
- **地址总线** = 门牌号位数（$N$ 位产生 $2^N$ 个地址，容量还要看编址单位）
- **控制总线** = 红绿灯和交警（读/写/中断信号）

CPU 和外部设备（键盘、磁盘、网卡）之间，则是一部"**从骚扰电话到专业物流**"的进化史：
1. **程序查询**：CPU 死等设备（"好了吗？好了吗？"）——CPU 被锁死 ❌
2. **中断**：设备干完喊一声"好了！"，CPU 再去搬数据——但每次只搬 1 个字，频繁被打断 😩
3. **DMA**：雇了个"搬运工"（DMAC），CPU 说好"从哪搬到哪、搬多少"，搬运工整块搬完才喊一声 ✅
4. **通道**：干脆雇个"物流公司"（小型 I/O 处理器），一批设备全归它管，CPU 彻底解放 🏆

> 💡 **这解释了**：I/O 控制方式的发展 = CPU 从"亲力亲为"到"甩手掌柜"的进化；中断技术 = 设备"主动汇报"的机制。

### 📚 线性学习顺序
1. **[[总线|总线]]** → 三种总线的分工
2. **[[IO控制技术|I/O 控制技术]]** → 查询/中断/DMA/通道四连跳
3. **[[中断技术|中断技术]]** → 中断分类 + 处理过程

### 🎯 学了能干什么
- 上午题 1-2 分：总线方向/宽度、DMA 特征、中断分类
- **定位**：理解"CPU 很贵，别让它等"——效率思维

## 第 5 关 · 大管家：操作系统（⭐重点关）

### 📖 故事
硬件齐了，但程序员要直接操作裸机（搬寄存器、管中断）——太痛苦了！于是**操作系统**诞生，它承包了三件大事：

**第一件：管 CPU（进程）**。CPU 只有一个，程序却很多。操作系统发明了"进程"（运行中的程序），让它们**轮流用 CPU**（分时）。谁先跑？→ 调度算法（FCFS/SJF/时间片…）。大家抢同一份数据？→ **PV 信号量**（P 申请、V 释放）。抢着抢着互相等 → **死锁**！→ 用**银行家算法**提前判断会不会死锁。

**第二件：管内存（存储）**。内存不够装程序？→ **虚拟内存**：程序只装入一部分页就能跑，缺了再调（请求分页），调不过来就把老页换出去（**页面置换**：OPT/FIFO/LRU/Clock）。数据要长久保存？→ **文件系统**：磁盘块怎么管理（**位示图**）、文件怎么组织（顺序/链接/索引）。

**第三件：管设备**。慢速设备怎么伺候快速 CPU？→ 缓冲 + **SPOOLing**（把独占打印机变成共享虚拟设备）；磁盘访问要快 → **磁盘调度**（FCFS/SSTF/SCAN 电梯）。

特殊场景：设备内部的专用计算机常受资源、功耗或可靠性约束；可裸机运行或使用嵌入式 OS，需要截止时间保证时再采用 RTOS。

> 💡 **这解释了**：整个操作系统 = "**CPU 很贵、内存很小、设备很慢**"三个难题的解决方案合集。

### 📚 线性学习顺序（按"难题"分三条线，每条线内部再线性走）
**线 A·管 CPU：**
1. [[操作系统概述|操作系统概述]]（先建全局观：特征+分类）
2. [[进程与线程|进程与线程]]（什么是进程、三态转换）
3. [[进程调度|进程调度算法]]（谁先用 CPU + 周转时间计算）
4. [[信号量与PV操作|信号量与 PV 操作]]（抢资源的锁 🔒⭐计算）
5. [[死锁与银行家算法|死锁与银行家算法]]（互等死锁 + 安全序列⭐计算）

**线 B·管内存：**
6. [[存储管理|存储管理]]（分区→分页→分段 + 地址转换⭐计算）
7. [[虚拟存储与页面置换|虚拟存储与页面置换]]（内存不够怎么办 + 缺页计算）
8. [[文件管理|文件管理]]（数据住哪儿：位示图⭐/索引/目录）

**线 C·管设备 + 特殊系统：**

## 第 6 关 · 联网：从“能传信号”到“能设计一张网络”

### 📖 故事
网络不是从 TCP、IP 突然开始的。最底层的问题是：**信息怎样变成信号、怎样穿过信道**；再往上才是 LAN/WAN 怎么组织、交换机和路由器怎么转发、IP 怎么编址、TCP 怎样可靠传输，最后还要把这些能力变成一张真正可规划、可冗余、可验收的网络。

> 💡 **这解释了**：计算机网络要按五块来学——基本概念 → 通信技术 → 网络技术 → 组网技术 → 网络工程。先有通信能力，再有协议和设备，最后才有工程设计。

### 📚 线性学习顺序
完整主线见 [[计算机网络索引]]，这里先记五块：

1. **基本概念**：[[计算机网络基本概念与功能]] → [[网络性能指标]] → [[非性能性指标]]
2. **通信技术**：[[数据通信与交换技术]] → [[5G]]
3. **网络技术**：[[网络类型与广域网技术]] → [[以太网技术]] → [[无线局域网802.11]] → [[5G网络切片]]
4. **组网技术**：[[网络协议与OSI七层]] → [[交换机]] → [[STP与链路聚合]] → [[网络互联设备]] → [[IP编址与子网划分]] → [[IPv4报文与分片]] → [[IPv6与IPv4过渡]] → [[路由协议与路由选择]] → [[TCP与UDP协议]] → [[应用层常用协议]]
5. **网络工程**：[[网络拓扑、组网与网络工程]]

### 🎯 学了能干什么
- 上午题：分层、通信与复用、LAN/WAN、IPv4/IPv6、交换/路由、TCP/UDP、应用协议、网络工程；

## 第 7 关 · 度量：怎么衡量一台计算机

### 📖 故事
学完前面六关，你已经"会造计算机"了。最后一关是**验收**：这台机器到底好不好？
- **好不好跑** → 性能指标：速率、带宽、吞吐量、时延、RTT、利用率（发送时延看数据量，传播时延看距离）
- **好不好用/好管/好养** → 非性能指标（非功能指标）：费用、质量、标准化、可靠性、可扩展、可维护（可用性 = MTBF/(MTBF+MTTR)）

> 💡 **这解释了**：为什么后面学架构设计时反复强调"**权衡**"——省钱就少冗余（不可靠性↑风险），要可靠性就得加冗余（成本↑）。性能与非性能的平衡，就是架构师的日常。

### 📚 线性学习顺序
1. [[网络性能指标|网络性能指标]]（快不快：时延四组成）
2. [[非性能性指标|非性能性指标]]（好不好：六大指标 + 可用性计算）
3. [[计算机性能指标与Amdahl定律|计算机性能指标与 Amdahl 定律]]（机器本身快不快：MIPS/CPI + 加速比计算）

### 🎯 学了能干什么
- 上午题 1-2 分 + **论文/案例的"万能素材"**（谈权衡、谈可靠性必用）
- **定位**：从"会造"到"会评"——这是通向架构师思维的第一级台阶
