# 信号量与PV操作：一把锁怎么变成两道题

## 痛点：调度管的是"谁上CPU"，可大家抢同一份数据时不打起来吗？

上一篇解决了"CPU 先给谁"。但多个进程同时抢**同一份数据**，比如两个进程一起改同一条银行记录，一个读到一半、另一个又写进去，数据就烂了。

光有调度不够——**同一时刻只允许一个进程进临界区（改数据的那段代码）**，否则就会互相踩踏。操作系统给的办法就是**信号量（Semaphore）配合 PV 操作**：一把"门锁"，进门 P（申请）、出门 V（释放）。

> 痛点一句话：**两个进程同时改同一份数据会踩踏，必须加"锁"；信号量就是这把锁，PV 就是开锁关锁的动作。** 软考这里必出两道计算题（互斥、同步），是本章最大分头之一。

## 定义（讲人话）

- **临界资源**：同一时刻只能一个进程用的资源（打印机、共享数据）。
- **临界区**：访问临界资源的那段代码。
- **信号量 $S$**：操作系统用来表示“资源当前可用情况/等待情况”的一个整数变量。
- **P 操作**：对信号量 $S$ 执行一次“申请资源”操作。
- **V 操作**：对信号量 $S$ 执行一次“释放资源”操作。

### 先把 `P(S)` 这三个字符看懂

`P(S)` 不是“P 乘 S”，也不是在问“$S$ 等不等于 0”。

它表示：

> **当前进程要使用由信号量 $S$ 管理的资源，于是调用一次 P 操作。**

可以拆开理解：

- **P**：操作名，表示“申请/等待”；
- **S**：这个 P 操作要检查和修改的那个信号量；
- **P(S)**：对信号量 $S$ 执行 P 操作。

考试模型里，P 操作内部可以理解成：

```text
P(S):
    S = S - 1
    如果 S < 0:
        把当前进程阻塞
        放入 S 对应的等待队列
```

所以，**真正判断能不能继续进入临界区的，不是进程自己额外写一个 `if (S == 0)`，而是 P 操作本身。**

更准确地说，P、V 属于**原语（原子操作）**：一次 P 操作里的“修改 S + 判断 + 必要时阻塞”必须作为一个不可被其他进程插入打断的整体完成。现实系统具体实现可能由内核、线程库以及硬件原子指令共同完成；软考里按“OS 提供的同步原语”理解即可。

对应地：

```text
V(S):
    S = S + 1
    如果 S <= 0:
        唤醒一个等待进程
```

这里有个关键点：

> **被 V 唤醒的进程，不会重新执行一次 P(S)。**

它之前执行 P 时已经完成了“$S=S-1$”并登记等待，只是因为资源不够被阻塞。V 释放资源后把它唤醒，它会先进入**就绪态**，等再次拿到 CPU 后，**从 P(S) 后面继续执行**。

所以：

- **P(S)**：申请资源，减 1；不够就阻塞；
- **V(S)**：释放资源，加 1；有人等就唤醒一个；
- **唤醒 ≠ 立刻运行**，而是阻塞 → 就绪 → 等调度。

> 记一句：**P 申请并登记等待，V 释放并唤醒；醒来不重 P，接着往下走。**

## 逐个认识：两条主线，两种考法

### 1. 互斥：保护临界区不被两人同时进

目标：同一时刻只允许一个进程用临界资源。

**做法**：信号量初值设为 $1$，把临界区夹在 P、V 之间：

```text
P(S)              ← 申请进入
[临界区：关键代码]
V(S)              ← 释放退出
```

这里最关键的是：**是否进入临界区，由 `P(S)` 这个原语执行后的结果决定。**

例如互斥信号量初值 $S=1$：

- A 执行 P：$1\to0$，进入临界区；
- B 再执行 P：$0\to-1$，B 阻塞；
- A 执行 V：$-1\to0$，唤醒 B；
- B 进入就绪态，等调度后**从 P 后面继续进入临界区，不再重新 P**。

所以经典 PV 的关键是：

> **P：先减再判断；V：先加再判断；被唤醒后接着执行。**

因此在单资源互斥模型里，可以这样读：

| $S$ 的值 | 直观含义 |
| ---: | --- |
| $1$ | 资源空闲，无人占用 |
| $0$ | 资源已被占用，但暂时无人等待 |
| $-1$ | 资源已被占用，另有 1 个进程等待 |
| $-2$ | 资源已被占用，另有 2 个进程等待 |

> 记一句：**进程只负责“调用 P/V”；P/V 原语负责改 S、判断、阻塞或唤醒。**

**怎么认**：题里出现“互斥、临界资源、同一时刻只能一个”，初值 = $1$。

### 2. 同步：不是“谁先拿 CPU”，而是“谁必须等谁”

同步要保证的是：**某个条件没满足，后面的进程就不能继续。**

最简单的例子：A 做完步骤①以后，B 才能做步骤②。设同步信号量 $S=0$：

```text
A：
    做步骤①
    V(S)        ← 完成后发通知

B：
    P(S)        ← 没收到通知就等
    做步骤②
```

即使 B 先拿到 CPU，也会在 `P(S)` 阻塞；A 完成并 `V(S)` 后，B 才能继续。

> **谁等待，谁 P；谁产生条件，谁 V。**

#### 生产者-消费者：先把“缓冲区”看成一个盒子

**缓冲区**就是生产者和消费者之间暂存产品的一块共享区域，可以先理解成一个有 $N$ 个格子的盒子。

- **empty**：还有多少空格，初值 $N$；
- **full**：已经有多少产品，初值 $0$。

生产者：

```text
P(empty)      ← 等空位
放入产品
V(full)       ← 通知：多了一个产品
```

消费者：

```text
P(full)       ← 等产品
取出产品
V(empty)      ← 通知：多了一个空位
```

所以：

> **生产者等空位，制造“有产品”；消费者等产品，制造“有空位”。**

#### 为什么还需要 mutex？

如果缓冲区只有 1 格，确实很容易误以为“既然先生产后消费，就不会同时操作”。

但标准模型通常有 $N$ 个格子。比如现在：

- 已有 5 个产品；
- 还有 5 个空位。

那么生产者**有资格继续放**，消费者也**有资格继续拿**，两边可能同时运行。

而缓冲区内部还有共享数据，例如“当前数量、下一个放哪里、下一个取哪里”。如果双方同时修改这些数据，就可能出错。

所以再加一个互斥信号量：

[
mutex=1
]

完整模板：

```text
生产者：
    P(empty)
    P(mutex)
    放入产品        ← 临界区
    V(mutex)
    V(full)

消费者：
    P(full)
    P(mutex)
    取出产品        ← 临界区
    V(mutex)
    V(empty)
```

三个信号量各管一件事：

| 信号量 | 初值 | 作用 |
| --- | ---: | --- |
| empty | $N$ | 还能不能放 |
| full | $0$ | 还能不能拿 |
| mutex | $1$ | 谁可以修改缓冲区 |

> **empty/full 管同步（资格），mutex 管互斥（同一时刻谁能动共享数据）。**

## 核心机制：S 的取值区间怎么算（必考点）

互斥场景下，$n$ 个进程共享一个资源（都做 P 和 V），信号量最小值会变成负数：

$$S_{\min} = 1 - n,\qquad S_{\max} = 1$$

为什么？一开始 $S=1$。第 1 个进程 $P$ → $0$，第 2 个 $P$ → $-1$ 阻塞，第 3 个 $P$ → $-2$……最多 $n$ 个都来抢，最小到 $-$(n−1) 即 $1-n$。一旦有人 V 又往回涨，最多回到 $+1$。

**完整示例**：$3$ 个进程互斥共享一个资源。

| 进程动作 | S 值 | 说明 |
| --- | --- | --- |
| 初始 | $1$ | 空房一间 |
| P1 执行 P | $0$ | 住进去 |
| P2 执行 P | $-1$ | 排队等 |
| P3 执行 P | $-2$ | 排队等 |
| P1 执行 V | $-1$ | 叫醒一个（P2 进） |
| P2 执行 V | $0$ | P2 用完后再叫醒 P3 |

信号量取值范围：$[-2, 1]$，其中 $-2 = 1-3$，符合 $S_{\min}=1-n$。

**易错点**：

- 单资源互斥信号量初值通常为 $1$；若设为 $0$，第一个执行 $P$ 的进程就会阻塞，并不会“放两个人进去”。
- P 是"先减号再看负不负阻塞"；V 是"先加号再看是否唤醒"。方向别记反。
- 取值范围算最小值时，**是 $1-n$，不是 $-n$**。$-n$ 是忘了初始那 1 个。

## 这个知识与考试的关系

- **选择题**：互斥信号量初值 = $1$；同步用生产者空满配对。
- **计算题**：$n$ 个进程互斥，问 S 的取值范围 → $1-n \le S \le 1$。
- **选择题**：P 后 $S<0$ 阻塞，V 后 $S\le0$ 唤醒——这两个条件是高频陷阱。
- **陷阱**：把同步和互斥混成一个——同步**不锁临界区**，它是"数量控制 + 先后告知"。

## 记忆口诀

> **P 申请减号可能等，V 释放加号可能醒；互斥初值 1，同步空满配对补。**
> **互斥保独占，同步保顺序，PV 夹临界区就是锁。**
