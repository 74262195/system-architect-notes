# 死锁与银行家算法：互相等对方的锁，谁都不让

## 痛点：PV 是锁，可锁多了，大家反而等死了

上一篇 PV 是给临界资源上锁。可你要是拿两把锁（拿 A 还要拿 B），两个进程偏一个拿 A 等 B、一个拿 B 等 A——**谁都拿不到第二把，谁也不放手，就这么永远耗着**。这就是死锁。

> 痛点一句话：**抢资源抢出个互相僵住、谁都动不了的局面。** 软考必考两件事：死锁四条件，以及银行家算法怎么算安全序列。

## 定义（讲人话）

- **死锁** = 一组进程每人占着一份资源，又在等别人占着的资源，谁都不释放，于是永远卡住。
- **银行家算法** = 分配资源前先模拟算一遍：如果这次分配下去会让之后谁都完成不了，就拒绝这次分配。像银行家借出钱前先算"能不能全收回来"。

> 记一句：**死锁是会噎死的互相等待；银行家是"先算后借"，借出去前先看能不能还。**
>
> 类比：四个司机各占一个路口方向，都在等对面让路，谁也走不了 → 死锁；警察提前算"这样下去全会堵死"，会就拦住 → 银行家算法。

## 逐个认识：四条件 + 两类措施

### 死锁的必要条件（四条件缺一不可）

| 条件 | 讲人话 | 考试怎么认 |
| --- | --- | --- |
| **互斥** | 资源一次只能一个人用 | "独占资源" |
| **占有并等待** | 拿着一张牌还想要下一张 | "占着又想要" |
| **不可剥夺** | 我占着的东西不能让别人抢走 | "不让抢" |
| **循环等待** | 你等我、我等你，成一圈 | "环状等" |

注意"必要"两个字：四条件齐**可能死锁**（不是必然），但缺任何一个**肯定不会死锁**。所以题常问"破坏哪一条能预防"。

### 预防 vs 避免：两类策略的分水岭

- **预防**：直接**破坏四条件之一**。例如"一次把所要资源全给你""资源统一编号按序申请"——从规则上让死锁不可能出现。
- **避免**：不破坏条件，而是**每次分配前动态判断**——银行家算法，算完安全才给。

> 区分记：**预防 = 拆掉条件（改规则），避免 = 事前检查（算安全）。**

## 核心机制：银行家算法怎么找安全序列（必考计算）

**思路**：看手里现有资源还能喂哪个进程（"还需 ≤ 现有"），喂完它归还，池子变大，再喂下一个……直到全部喂完就是安全序列；喂到喂不动就是不安全。

**判据**：

$$\text{还需资源} \le \text{现有可分配资源}$$

**完整示例**：单一资源，系统总数 12。

| 进程 | 已分配 | 还需 | 说明 |
| --- | --- | --- | --- |
| P0 | 5 | 3 | |
| P1 | 2 | 4 | |
| P2 | 2 | 3 | |

现有可分配 = 总数 − 已分配之和 = $12 - (5+2+2) = 3$。

**第 1 步**：谁“还需 $\le 3$”？P0、P2 都可选。选 P0，假设它完成后释放自己已占有的 $5$ 个资源：

$$Work=3+5=8$$

**第 2 步**：此时 P1 还需 $4\le 8$，完成后释放已占有的 $2$ 个资源：

$$Work=8+2=10$$

**第 3 步**：P2 还需 $3\le 10$，完成后：

$$Work=10+2=12$$

全部喂完 → **安全序列 P0 → P1 → P2**。

**易错点**：

- **先说哪个序号**：必须每次选"还需 ≤ 现有"的，别见谁喂谁。
- 安全性检查是“假设进程能够完成”，完成后把它原先占有的资源归还：$Work=Work+Allocation$。不要在 Work 中再减 Need。
- 如果某一步谁都喂不动 = **不安全**，这次分配要拒绝。

## 这个知识与考试的关系

- **选择题**：死锁四条件，缺一不成立。
- **选择题**：预防=破坏条件，避免=银行家（动态）。
- **计算题**：给分配表问安全序列或是否安全 → 按"喂最少、归还放大池子"走。
- **陷阱**：把"预防"和"避免"说成同一个 ❌，它们是拆条件 vs 动态判断。

## 记忆口诀

> **死锁四条件缺一不立：互斥、占等、不可夺、循环；银行家先从最饿的喂，喂完还池子，喂不动就是不安全。**
