# 指令寻址方式：CPU 去哪找要用的数据

## 痛点：一个数，CPU 该怎么拿到手？

指令要算数，就得有数据。而数据不在 CPU 里——它在内存、在寄存器、或者干脆就写在指令里。问题是：**这条指令里的"操作数"，到底藏在哪？CPU 要怎么找到它？**

想象你想找一本资料，有几种找法：

- **直接贴身带着**：资料就在你口袋里（省事，拿起来就用）
- **告诉别人精确地址**：报出"书架第三层第五本书"（直接去拿）
- **先去查个目录再去找**：先翻登记册找到"资料在仓库A"，再凭这个地址去拿（多绕一道）
- **按编号计算位置**：资料在"第N号柜"，N由某个数算出来（灵活可变）

指令寻址方式，就是定义 CPU 用上面哪种方法拿操作数。它要解决的核心问题：**怎么让 CPU 又快又准地拿到指令里需要的数据，不同场景选哪种省事。** 考试里这是送分题——记住每种方式"操作数藏哪、怎么拿"就行。

> 记一句：**寻址方式 = CPU 找操作数的"路线图"，有贴身带、有报地址、有查目录、有算位置。**（考试重点：操作数在指令里/在内存/在寄存器）

> [!warning] 别和存储器访问方式混了
> 本篇的“立即 / 直接 / 间接 / 寄存器 / 变址”是在回答：**CPU 指令怎么找到操作数？**
>
> [[存储器访问方式]]里的“随机 / 顺序 / 直接 / 相联”是在回答：**存储设备怎么访问数据？**
>
> 两套概念里都有“直接”，但完全不是一回事。

## 定义（讲人话）

寻址方式指：一条指令中"操作数"在哪儿、CPU 根据指令里的什么信息去把它取出来。核心是区分**操作数直接给，还是给地址让 CPU 去取**。

## 逐种认识（含"怎么认"）

| 寻址方式      | 操作数在哪        | 怎么拿                 | 怎么认           | 特点             |
| --------- | ------------ | ------------------- | ------------- | -------------- |
| **立即寻址**  | 直接写在指令里      | 指令里取用，最快            | 题里说"操作数就在指令中" | 快，但数写死在指令里，不灵活 |
| **直接寻址**  | 在内存某地址       | 指令给出地址，CPU 去取       | 指令里是"地址"      | 能找到内存数据，但地址要访存 |
| **间接寻址**  | 在内存，地址还要再拐一道 | 指令给"存地址的地址"，先取地址再取数 | 题里说"地址的地址"    | 灵活，慢（多次访存）     |
| **寄存器寻址** | 在 CPU 的寄存器里  | 直接读寄存器，最快之一         | 指令里是"寄存器名"    | 快，但寄存器就那几个     |
| **变址寻址**  | 在内存，地址=基址+变址 | 用基址加变址算出地址          | 题里说"基址+变址"    | 适合数组/循环访问      |
|           |              |                     |               |                |

## 一个关键区分（送分陷阱）

**直接寻址 vs 间接寻址**——最常考：

- **直接**：指令里就是"数据所在地址"，CPU 直接去那个地址拿。一次指明位置。
- **间接**：指令里是"存着地址的那个地址"，CPU 先去拿地址、再去拿数据。绕了一道。

> 用一句话记：**直接"一口咬到数"，间接"先取地址再去取数"多绕一步。** 题里出现"地址的地址""间接"→ 间接寻址。

## 这个知识与考试的关系

- **送分题**：问"哪种操作数直接在指令中"→ 立即寻址；"操作数在寄存器"→ 寄存器寻址。
- **送分陷阱**：把"间接寻址"说成操作数直接给（那是立即寻址）❌。
- **记忆对口**："地址的地址"→间接；"指令中直接给数"→立即；"算出来的位置"→变址。

## 记忆口诀

> **口袋立即带随身，报址直接去取，查目录间接绕一道，寄存器最快在门口。**
