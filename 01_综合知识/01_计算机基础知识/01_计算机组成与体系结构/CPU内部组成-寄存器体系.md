# 寄存器体系：CPU 的“临时文件夹”和“收发室”

## 痛点：为什么要有这么多寄存器？

CPU 算数很快，但它要**频繁和很慢的主存打交道**。每次从主存搬一个数，CPU 都要干等很久——这就像让一个写字飞快的人，每次蘸一下墨水都要跑到仓库去拿。

寄存器就是解决办法：**在 CPU 内部放一批“随手就能拿”的超快小存储**，把正在用的指令、地址、数据、状态放身边，避免每次都跑主存。

但是问题来了：寄存器那么多，**谁装地址？谁装数据？谁记状态？搞混就全乱套了。** 于是程序员按职责给它们分了工——这就是寄存器体系要解决的核心问题：**给 CPU 内部的临时存储定好规矩，让每个寄存器各司其职。**

> 记一句：**寄存器 = CPU 眼面前的“临时小格子”，按用途分工，不乱放。**

## 定义（讲人话）

寄存器是 CPU 内部的高速暂存单元，按用途分两大类：

- **运算用寄存器**：管「算」——暂存数据、结果、状态（ACC、PSW）
- **接口用寄存器**：管「CPU 和主存通信」——一个负责报地址、一个负责传数据（MAR、MBR）
- **控制用寄存器**：管「流程」——记下一条在哪、当前在干嘛（PC、IR）

## 逐个认识（含一句“怎么认”）

| 寄存器     | 装什么                          | 怎么认                 |
| ------- | ---------------------------- | ------------------- |
| **MAR** | 主存单元的**地址**，走地址总线，单向（CPU→主存） | 题里说“地址”、“去哪” → MAR  |
| **MBR** | 数据/指令，走数据总线，双向（主存↔CPU）       | 题里说“数据”、“双向” → MBR  |
| **PC**  | **下一条**指令的地址，取指时自动+1         | 题里说“下一条指令地址” → PC   |
| **IR**  | **当前**这条指令                   | 题里说“当前指令” → IR      |
| **ACC** | 运算的中间结果                      | 题里说“暂存运算结果” → ACC   |
| **PSW** | C进位/V溢出/Z零/N负 状态             | 题里说“条件转移判断依据” → PSW |

> **最容易混淆的一对**：MAR vs MBR。
> 用一句话记——**MAR 是“报门牌”（只送地址，单向出去），MBR 是“传货物”（只搬数据，可以往返）。**
> 题里若说“MAR 双向”或“MBR 装地址”，直接判错。

## 这个知识与考试的关系

- 问功能归属：“以下哪个存的是地址” → MAR；“哪个存的是当前指令” → IR。
- 问总线/方向：“MAR 走什么总线、单双向” → 地址总线、单向。
- **经典陷阱**：把 MAR 说成双向 ❌；把 MBR 说成放地址 ❌；把 PSW 说成通用寄存器 ❌；把 PC 说成存当前指令 ❌（应为 IR）。

## 记忆口诀

> **PC 指下条，IR 抓当前；MAR 地址单向去，MBR 数据双向来；PSW 只记状态不算数。**
