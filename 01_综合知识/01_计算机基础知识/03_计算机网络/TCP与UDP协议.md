# TCP 与 UDP：可靠快递和即时广播的取舍

> [!important] 一句话结论
> TCP 面向连接、可靠、有序并提供流量/拥塞控制；UDP 无连接、开销小、尽力而为，考试高频是两者对比、三次握手、四次挥手和典型应用。

## 痛点：IP 送到了“网络”，却不保证送到“程序”

IP 只负责把分组尽力送到目标主机，可能丢失、重复、乱序，也不知道目标主机上的哪一个程序接收。文件传输需要可靠有序，实时语音则更在意及时，宁可丢一个片段也不愿等待重传。

传输层因此提供两种不同风格：TCP 像需要签收的可靠快递，UDP 像不等待回执的即时投递。应用根据业务目标选择，而不是简单地说哪个“更高级”。

先抓住 4 个问题：

1. IP 已经找到主机，传输层怎样继续找到具体进程？
2. TCP 为什么能做到可靠、有序？
3. 三次握手和四次挥手到底在确认什么？
4. 流量控制和拥塞控制分别在“保护谁”？

## 定义：两种传输服务

| 对比项 | TCP | UDP |
| --- | --- | --- |
| 连接 | 面向连接 | 无连接 |
| 可靠性 | 确认、序号、重传、校验 | 不保证可靠、不保证顺序 |
| 数据边界 | 字节流，没有消息边界 | 保留数据报边界 |
| 控制能力 | 流量控制、拥塞控制 | 协议本身控制较少 |
| 开销与时延 | 首部和状态较多，通常更重 | 首部小，通常更轻、更快 |
| 典型场景 | Web、文件、邮件传输 | DNS 查询、实时音视频、在线游戏 |

**核心区分**：TCP 解决“可靠、有序地传完”，UDP 更适合“及时发出、由应用自己承担取舍”；速度不是 UDP 的唯一标签，可靠性、边界和控制机制才是本质。

### IP 找主机，端口找进程

假设服务器 IP 是 `203.0.113.10`，Web 服务监听端口 `443`：

> **IP 地址解决“去这台主机”，端口号解决“到主机后交给哪个进程/服务”。**

所以传输层不是重复做 IP 的工作，而是在主机之间已经可达的基础上，再完成**进程到进程**的通信。

## 核心机制：TCP 怎样建立连接

TCP 三次握手不是为了“走形式”，而是为了**同步双方的初始序号，并让双方确认建立连接所需的信息已经双向到达**。

```mermaid
sequenceDiagram
  participant C as 客户端
  participant S as 服务器
  C->>S: SYN，客户端请求建立连接
  S->>C: SYN+ACK，同意并确认客户端序号
  C->>S: ACK，确认服务器序号
  Note over C,S: 连接建立，可以传输数据
```

为什么不是两次：服务器发出的 SYN+ACK 也需要得到确认。第三次 ACK 到达后，服务器才知道自己的 SYN/初始序号信息也已经被客户端收到。题目若问“连接建立完成”，通常以第三次 ACK 到达为判断点。

## 核心机制：可靠传输与连接释放

TCP 用序号标识字节，用确认号表示“下一个期待的字节”，通过校验、确认和重传处理丢失；滑动窗口让发送端在未逐个等待确认的情况下连续发送多个字节。

例如发送端发出一段数据，接收端确认“下一个期待的是 1501”，说明此前连续数据已经收到；如果某段迟迟没有被确认，发送端会根据协议机制进行重传。即使分组在 IP 网络中乱序到达，TCP 也可以利用序号在接收侧恢复正确的字节顺序。

### 流量控制和拥塞控制：都在“限速”，保护对象不同

| 机制 | 它怕谁撑不住 | 主要依据 |
| --- | --- | --- |
| **流量控制** | 接收端来不及接收、缓冲区被撑满 | 接收端通告的窗口 |
| **拥塞控制** | 网络中间链路/路由器过载 | 丢包、时延、拥塞反馈等网络状态 |

> **流量控制看对端，拥塞控制看网络。**

发送端真正能发多少，往往同时受接收窗口和拥塞窗口等限制。

TCP 连接是全双工的，双方都可能还有数据要发送，因此关闭通常需要四次挥手：一方 FIN、一方 ACK；另一方数据发送完后再 FIN，原一方再 ACK。FIN 和 ACK 常分开发送，所以通常是四次而不是三次。

```mermaid
sequenceDiagram
  participant A as 主动关闭方
  participant B as 被动关闭方
  A->>B: FIN，请求关闭一个方向
  B->>A: ACK，确认收到
  B->>A: FIN，B也发送完毕
  A->>B: ACK，确认关闭
```

## 这个知识与考试的关系

- 三次握手顺序：`SYN` → `SYN+ACK` → `ACK`。
- 四次挥手顺序：`FIN` → `ACK` → `FIN` → `ACK`。
- TCP 的可靠性来自序号、确认、重传等机制，不是来自 IP。
- 流量控制主要防止接收端缓冲区被撑满；拥塞控制主要应对网络整体拥塞，二者不要混为一谈。
- 常见端口不是绝对绑定：HTTP 常用 $80$、HTTPS 常用 $443$、DNS 常用 $53$，题干若指定自定义端口应以题干为准。

## 记忆口诀

**TCP 三握手建关系，四挥手拆两边；UDP 不握手，快慢由业务定。**
