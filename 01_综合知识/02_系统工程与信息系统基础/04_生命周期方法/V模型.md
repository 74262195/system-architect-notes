# V模型（V-Model）

> **软考定位**：瀑布的“升级版”，核心是 **“测试和开发对着干”** ——把测试活动提前到设计阶段，强调质量管控。

---

## 一、一句话定义

**V模型** 是瀑布模型的变种，将 **“开发阶段”** 和 **“测试阶段”** 一一对应，形成“V”字形结构。

> **核心思想**：**“左边写代码，右边测代码；左边画什么图，右边就测什么图。”**

---

## 二、V 字形结构

| 左侧（开发） | 右侧（测试） | 对应关系 |
| :--- | :--- | :--- |
| 需求分析 | 验收测试 | 用户需求对不对？ |
| 概要设计 | 系统测试 | 整体功能符不符合设计？ |
| 详细设计 | 集成测试 | 模块之间衔接对不对？ |
| 编码 | 单元测试 | 每一行代码对不对？ |

---

## 三、核心特点

| 特点 | 大白话 |
| :--- | :--- |
| **测试前置** | 不是等代码写完了再测，而是**设计阶段就开始规划测试** |
| **验证与确认（V&V）** | 左边是“验证”（做对了没有），右边是“确认”（做的东西对不对） |
| **质量驱动** | 比瀑布更**重视质量**，适合高可靠性要求的场景 |

---

## 四、适用场景

| ✅ 适合 | ❌ 不适合 |
| :--- | :--- |
| 对**质量和可靠性要求极高**（如航天、医疗、金融） | 需求变化频繁、需要快速迭代的项目 |
| 需求明确、技术方案成熟 | 探索性、创新型项目 |
| 大型、长期、团队庞大 | 小团队、创业型项目 |

---

## 五、瀑布 vs V模型（考场必考对比！）

| 对比维度 | **瀑布模型** | **V模型** |
| :--- | :--- | :--- |
| **测试时机** | 编码完成后才测试 | 从设计阶段就开始规划测试 |
| **核心关注** | **过程管理**（按阶段走） | **质量管控**（测试与开发对应） |
| **用户参与** | 开始和结束参与 | 同样，但更强调验收测试的严谨性 |
| **产出物** | 文档、代码 | 文档 + **详细的测试计划** |

---

## 六、一句话总结

> **瀑布只管“做出来”，V模型保证“做对”。** 质量要求越高，V模型越适合。
