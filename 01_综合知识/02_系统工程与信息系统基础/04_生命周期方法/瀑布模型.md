# 瀑布模型（Waterfall Model）

> **软考定位**：最经典的模型，常作为“正统”代表与其他模型对比。简单，但容易在“适用场景”上丢分。

---

## 一、一句话定义

**瀑布模型** 由 **Winston Royce** 于 1970 年提出，将软件开发过程分为 **线性顺序** 的若干阶段，上一阶段完成后才能进入下一阶段。

> **核心思想**：**“一步一个脚印，绝不回头。”**

---

## 二、阶段流程

> 需求分析 → 设计 → 编码 → 测试 → 部署 → 维护

| 阶段 | 核心任务 |
| :--- | :--- |
| **需求分析** | 搞清楚“做什么” |
| **设计** | 规划“怎么做” |
| **编码** | 写代码实现 |
| **测试** | 验证是否正确 |
| **部署** | 上线交付 |
| **维护** | 运行保障 |

---

## 三、优缺点

| 优点 | 缺点 |
| :--- | :--- |
| 1. 阶段清晰，易于管理和分工 | 1. **怕变化**——需求变更代价极大 |
| 2. 强调文档，有利于团队协作 | 2. 用户只能在**最后**看到成果，风险高 |
| 3. 每个阶段都有明确的交付物 | 3. **不适合复杂/长期项目**（需求大概率会变） |

---

## 四、适用场景（必考！）

| ✅ 适合 | ❌ 不适合 |
| :--- | :--- |
| 需求**明确、稳定、变化少** | 需求**不明确或变化频繁** |
| 技术方案成熟、团队经验丰富 | 新技术探索性项目 |
| 短期项目或规模较小的项目 | 大型复杂、周期长的项目 |
| 对文档要求严格的**政府/银行**项目 | 互联网快速迭代产品 |

---

## 五、考场避坑

| 错误说法 | 正解 |
| :--- | :--- |
| “瀑布模型可以随意回溯到上一阶段” | ❌ 瀑布是**线性**的，回退代价极大 |
| “瀑布模型适合需求不明确的项目” | ❌ 需求不明确应该用**原型法或迭代** |
| “瀑布模型重视用户参与” | ❌ 用户只在**开始（需求）和结束（验收）** 参与 |

---

## 六、一句话总结

> **需求不变的“老实人”项目用瀑布，需求天天变的“折腾”项目别用它。**
