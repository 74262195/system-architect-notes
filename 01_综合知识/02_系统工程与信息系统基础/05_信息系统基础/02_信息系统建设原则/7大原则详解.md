# 信息系统建设原则 7 大原则详解

## 1. 高层管理人员介入（一把手原则）—— 重中之重！
- **大白话**：老大必须亲自下场，给钱、给人、拍板、协调跨部门矛盾。
- **典型考题**：“老板觉得是IT部门的事，不参与。” → **违背一把手原则**

## 2. 用户参与开发
- **大白话**：业务部门的人必须全程参与，不能扔给IT就不管了。
- **典型考题**：“程序员闭门造车，用户只在验收时出现。” → **违背用户参与**

## 3. 自顶向下规划
- **大白话**：先看公司全局战略，再拆解到各个部门子系统。
- **典型考题**：“财务部自己搞一套、销售部自己搞一套，数据对不上。” → **违背自顶向下**，导致 **信息孤岛**

## 4. 工程化原则
- **大白话**：写文档、走标准流程，拒绝“作坊式”开发。
- **典型考题**：“系统只有源代码，没有任何设计文档。” → **违背工程化**

## 5. 创新性原则
- **大白话**：不只是把纸质流程电子化，要利用IT技术优化业务。
- **典型考题**：“只是模拟手工，效率没提升。” → **违背创新性**

## 6. 整体性原则
- **大白话**：各模块数据统一、功能完整，不能缺胳膊少腿。
- **典型考题**：“生产系统和销售系统数据不一致。” → **违背整体性**

## 7. 经济性原则
- **大白话**：花最少的钱办最多的事，追求性价比（但不是砍核心功能！）。
- **典型考题**：“盲目追求大而全，预算超支。” → **违背经济性**

> **⚠️ 避坑**：经济性原则 ≠ 偷工减料！是在保证核心需求的前提下控制成本。
