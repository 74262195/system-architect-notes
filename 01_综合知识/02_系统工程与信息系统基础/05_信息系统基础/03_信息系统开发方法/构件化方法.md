# 构件化开发方法（Component-Based Development）

> **软考定位**：关键词 **“构件/组件、复用、组装”**，代表“搭积木”式的开发方式。

---

## 一、一句话定义

构件化开发方法基于 **可复用的构件（Component）** 来构建系统，就像用现成的积木块搭建建筑一样。

> **大白话**：**“去构件超市买现成的功能模块，然后像拼积木一样拼成系统。”**

---

## 二、构件的四种获取方式（必考！）

| 方式 | 说明 | 场景 |
| :--- | :--- | :--- |
| **从现有构件中获得** | 公司内部已有可复用的构件 | 历史项目积累 |
| **通过遗留工程提取** | 从旧系统中抽取可复用的部分 | 系统升级改造 |
| **从市场购买** | 采购第三方商业构件 | 标准功能（如支付、报表） |
| **开发新的构件** | 市场上没有合适构件时自行开发 | 特有业务功能 |

---

## 三、构件检索方式（必考！）

| 方式 | 说明 |
| :--- | :--- |
| **关键字检索** | 按名称、功能描述等关键词搜索 |
| **刻面检索法** | 按多个维度（分类属性）进行组合检索 |
| **超文本检索法** | 通过链接关系，从相似构件跳到目标构件 |

---

## 四、构件化 vs 面向对象（考场对比！）

| 对比维度 | **构件化开发** | **面向对象开发** |
| :--- | :--- | :--- |
| **粒度** | **粗粒度**（构件 > 类） | 细粒度（类） |
| **复用级别** | **二进制级复用**（直接使用） | 源代码级复用（需继承/引用） |
| **部署方式** | **独立部署** | 打包在应用中 |
| **依赖关系** | 通过**标准化接口**交互 | 通过**方法调用**交互 |
| **适用场景** | 大型复杂系统、高复用性 | 一般复杂系统 |

---

## 五、构件化 vs 面向服务（考场对比！）

| 对比维度     | **构件化开发**  | **面向服务方法**         |
| :------- | :--------- | :----------------- |
| **通信方式** | 进程内调用（同进程） | 网络调用（跨进程/跨机器）      |
| **耦合度**  | 较低         | **松散耦合**           |
| **技术栈**  | 通常同一语言/平台  | **异构平台**（不同语言可互操作） |
| **适用范围** | 单体/局部系统    | **分布式/跨系统**        |

---

## 六、适用场景

| ✅ 适合 | ❌ 不适合 |
| :--- | :--- |
| 大型复杂系统、需要**高复用性** | 简单小规模系统（用构件成本高） |
| 有**成熟的构件市场**或内部构件库 | 构件市场上找不到合适的构件 |
| 需要**快速交付**的标准化功能开发 | 对**运行效率**要求极高（构件可能有多余功能） |
