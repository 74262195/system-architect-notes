# TPS（事务处理系统）

> **定位**：企业信息化的 **“地基”** ，没有它，上面的系统全是空中楼阁。
> **层级**：操作层（一线员工）

---

## 一、一句话定义

专门处理 **日常重复性事务** 的系统，把每一笔原始交易记录下来。

> **大白话**：**“记流水账的会计”**。只记录“发生了什么”，不分析“意味着什么”。

---

## 二、典型场景

| 场景 | 说明 |
| :--- | :--- |
| 超市收银 | POS机扫条形码，记录“某时某刻卖了一瓶可乐” |
| 银行存取款 | ATM机记录“某账户存入1000元” |
| 员工打卡 | 钉钉记录“某人几点几分上班” |
| 电商下单 | 后台记录“某用户下了一笔订单” |
| 酒店预订 | 系统记录“某房号被预订了今晚” |

---

## 三、核心特征

| 特征 | 大白话 |
| :--- | :--- |
| **数据量极大** | 每天成千上万笔，甚至百万级 |
| **逻辑极简单** | 只是“记下来”，不做复杂计算 |
| **重复性极高** | 每天做同样的事，几乎不变 |
| **实时性要求高** | 不能丢单、不能漏记、要快 |
| **准确性要求高** | 一分钱都不能错 |

---

## 四、TPS 的输出

TPS 的输出是 **原始数据（交易记录/日志）** ，这些数据是 **MIS 和 DSS 的原料**。

> **数据流向**：TPS（记录流水） → MIS（生成报表） → DSS（做预测）

---

## 五、TPS vs MIS（考场对比）

| 对比维度 | **TPS** | **MIS** |
| :--- | :--- | :--- |
| **做什么** | 记录原始数据 | 对数据进行汇总统计 |
| **服务对象** | 一线操作员 | 中层管理者 |
| **产出物** | 交易记录（流水） | 统计报表 |
| **逻辑复杂度** | 极简 | 中等 |
