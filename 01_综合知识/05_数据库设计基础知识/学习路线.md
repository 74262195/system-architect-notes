# 数据库设计基础知识学习路线

## 先回答：为什么会需要数据库

如果每个业务程序都把数据放在自己的文件里，同一份“用户、订单、库存”会被重复保存，规则也容易各自实现，结果就是**重复、难共享、难保证一致、难统一恢复和维护**。

所以这一章不是从范式符号开始，而是从一个问题开始：

> **怎样把共享数据交给统一的数据管理系统，再用清晰的数据模型、关系运算和设计方法，让数据既能被正确保存，也能被程序稳定使用？**

整章主线可以压成：

**为什么需要统一管理 → DB / DBMS / DBS 是什么 → 数据怎样建模 → 关系模型怎样表示数据 → 关系代数怎样查数据 → 表设计不好为什么会冗余和异常 → 函数依赖/候选码/范式怎样改进设计 → 怎样从需求落到数据库 → 上线后怎样访问、维护与恢复 → 什么时候考虑 NoSQL。**

P0/P1/P2 只表示学习优先级，不表示某部分可以没有正文。

## 第一段：先建立数据库系统坐标

[[数据库DB-DBMS-DBS]]（P2） → [[数据管理技术三个发展阶段]]（P2） → [[数据模型三要素与分类]]（P2） → [[DBMS核心功能]]（P2） → [[数据库三级模式与两级映像]]（P0） → [[分布式数据库与透明性]]（P1）

先分清：

- **DB**：被统一组织和长期保存的数据集合；
- **DBMS**：负责定义、操作、运行控制、存储组织和维护这些数据的软件；
- **DBS**：数据库系统，包含 DB、DBMS、应用、人员和运行环境，不只是“数据库文件”。

学完这一段，要能回答“数据由谁管、规则由谁执行、为什么应用不必知道磁盘具体怎么放”。

## 第二段：进入关系数据库——先会读表，再会操作表

[[关系模型基本术语与完整性]]（P1） → [[关系代数基础运算]]（P0） → [[连接与自然连接]]（P0）

先把直觉固定：

- 关系≈表；
- 元组≈行；
- 属性≈列；
- 候选码能最小且唯一标识元组，主码只是被选中的一个候选码；
- 外码把一个关系连接到另一个关系的码。

关系代数做题不要先背符号，先翻译题意：

1. **按条件筛记录** → 选择，先想“挑行”；
2. **只保留某些字段** → 投影，先想“挑列”；
3. **把两个关系按相关属性组合** → 连接；
4. **两个相容关系求合并、共同、差异** → 并 / 交 / 差；
5. 出现“满足全部要求” → 再检查除法语义。

## 第三段：为什么要规范化——从异常，而不是从定义背起

[[函数依赖与属性闭包]]（P0） → [[候选码求解]]（P0） → [[范式1NF-2NF-3NF-BCNF]]（P0） → [[多值依赖与4NF]]（P2） → [[无损连接与保持函数依赖]]（P0）

这一段要形成真正的因果链：

**一张表混入多类事实 → 数据重复 → 插入/删除/更新异常 → 用函数依赖描述“谁决定谁” → 用闭包找候选码 → 判断部分依赖/传递依赖 → 逐层判断 1NF / 2NF / 3NF / BCNF → 分解后还要检查无损连接与依赖保持。**

考试第一动作固定为：**先求候选码，再标主属性/非主属性，再逐层检查范式。**

## 第四段：把业务真正设计成数据库

[[数据库设计六阶段]]（P0）先建立总地图：

**需求分析 → 概念结构设计 → 逻辑结构设计 → 物理结构设计 → 实施 → 运行维护**

然后按阶段向下：

[[数据需求分析]]（P1） → [[ER模型与概念结构设计]]（P0） → [[ER图合并与冲突]]（P0） → [[ER图转关系模式]]（P0） → [[逻辑设计与完整性视图]]（P1） → [[反规范化设计]]（P1） → [[物理设计与索引]]（P1） → [[数据库实施与试运行]]（P2） → [[数据库运行维护与备份恢复]]（P1）

阶段题做错时，先判断题目现在是在：**理解业务、画概念模型、形成逻辑关系、决定物理存储，还是已经上线运行维护。**

> [!note] 事务、并发和恢复怎么放
> [[DBMS核心功能]] 已把并发控制、日志和恢复定位为 DBMS 运行管理职责；[[数据库运行维护与备份恢复]] 负责新版第 5 章明确要求的备份/故障恢复。当前稳定契约不把事务隔离级别、锁协议扩成第 5 章主线，因此学习时知道它们是在保护共享数据的一致性即可，不在这里扩成数据库内核课程。

## 第六段：为什么还有 NoSQL

[[NoSQL分类与特点]]（P1） → [[NoSQL体系框架与适用场景]]（P1）

不要把 NoSQL 理解成“关系数据库的升级版”。它是针对不同数据模型、扩展和分布需求的一组方案，选型仍要回到实际需求。
