# 数据库设计基础知识学习路线

## 先建立一条主线

数据库不是从“范式公式”开始的。先理解系统为什么要把数据抽象成模式，再学习关系怎么运算、怎么减少冗余，最后把这些知识用于真正的数据库设计。

## 第一站：数据库怎样把物理存储藏起来

先读 [[数据库三级模式与两级映像]]。

记住三个问题：
- 用户看到什么？→ 外模式；
- 整个数据库逻辑上长什么样？→ 概念模式；
- 数据实际怎样存？→ 内模式。

两级映像的价值是**数据独立性**：底层存储调整，不应逼着所有应用代码跟着改。

## 第二站：表怎样做集合运算

[[关系代数基础运算]] → [[连接与自然连接]]

先掌握“行”和“列”的方向感：
- 选择：挑行；
- 投影：挑列；
- 笛卡尔积：先组合；
- 连接：在组合基础上按条件筛；
- 自然连接：同名属性相等，并去掉重复的同名列。

## 第三站：为什么一张表会越设计越乱

[[函数依赖与属性闭包]] → [[候选码求解]] → [[范式1NF-2NF-3NF-BCNF]] → [[无损连接与保持函数依赖]]

这四张必须连着学：
1. 函数依赖描述属性间的语义约束；
2. 闭包帮助判断一组属性能不能决定全表；
3. 最小的超码才是候选码；
4. 找到码后才有资格判断 2NF/3NF/BCNF；
5. 分表后还要检查能否无损还原、依赖是否仍能方便地约束。

## 第四站：把需求真正变成数据库

[[数据库设计六阶段]] → [[ER模型与概念结构设计]] → [[ER图合并与冲突]] → [[ER图转关系模式]]

阶段感一定要保留：

**需求分析 → 概念设计（E-R）→ 逻辑设计（关系模式）→ 物理设计（存储/索引）→ 实施 → 运行维护**

题目只要出现“与具体 DBMS/硬件无关的企业信息模型”，优先想到概念结构设计；出现索引、存储结构、访问方式，优先想到物理设计。

## 第二轮再补

数据库基础术语、完整性、分布式透明性、反规范化、物理设计、备份恢复、访问接口和 NoSQL 都在大纲内，但不抢占第一轮 P0 时间。按 [[数据库设计基础知识索引]] 的 P1/P2 顺序补。
