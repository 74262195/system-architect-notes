# 数据库设计基础知识学习路线

## 先建立完整主线

数据库不是从“范式公式”开始的。整章要回答六个连续问题：

**谁管理数据 → 怎样描述数据 → 关系怎样运算/约束 → 怎样从需求设计数据库 → 程序怎样访问 → 什么时候考虑 NoSQL。**

P0/P1/P2 只表示学习优先级，不表示某部分可以没有正文。

## 第一段：先知道数据库系统在做什么

[[数据库DB-DBMS-DBS]]（P2） → [[数据管理技术三个发展阶段]]（P2） → [[数据模型三要素与分类]]（P2） → [[DBMS核心功能]]（P2） → [[数据库三级模式与两级映像]]（P0） → [[分布式数据库与透明性]]（P1）

这一段的核心不是背产品名，而是建立坐标：数据由谁管理、为什么逐步统一管理、怎样描述数据、模式层次和分布实现分别处于什么层面。

## 第二段：进入关系数据库的核心

[[关系模型基本术语与完整性]]（P1） → [[关系代数基础运算]]（P0） → [[连接与自然连接]]（P0）

先读懂表里的属性、元组、码和约束，再建立“挑行、挑列、组合、连接”的方向感。

然后进入本章计算/判断主链：

[[函数依赖与属性闭包]]（P0） → [[候选码求解]]（P0） → [[范式1NF-2NF-3NF-BCNF]]（P0） → [[多值依赖与4NF]]（P2） → [[无损连接与保持函数依赖]]（P0）

其中 P0 四个动作必须连起来理解：**依赖 → 闭包 → 候选码 → 范式/分解**。4NF 优先级较低，但正文仍完整保留，用于知道 BCNF 之后为什么还有更高范式。

## 第三段：把业务真正设计成数据库

[[数据库设计六阶段]]（P0）先建立总地图：

**需求分析 → 概念结构设计 → 逻辑结构设计 → 物理结构设计 → 实施 → 运行维护**

然后按阶段向下：

[[数据需求分析]]（P1） → [[ER模型与概念结构设计]]（P0） → [[ER图合并与冲突]]（P0） → [[ER图转关系模式]]（P0） → [[逻辑设计与完整性视图]]（P1） → [[反规范化设计]]（P1） → [[物理设计与索引]]（P1） → [[数据库实施与试运行]]（P2） → [[数据库运行维护与备份恢复]]（P1）

阶段题做错时，回到一个判断：**题目现在是在理解业务、画概念模型、形成逻辑关系，还是已经讨论物理存储/上线运行？**

## 第四段：应用程序怎么访问数据库

[[数据库访问接口总览]]（P2） → [[嵌入式SQL与OCI]]（P2） → [[ODBC与JDBC]]（P2） → [[ORM访问接口]]（P2）

## 第五段：为什么还有 NoSQL

[[NoSQL分类与特点]]（P1） → [[NoSQL体系框架与适用场景]]（P1）

不要把 NoSQL 理解成“关系数据库的升级版”。它是针对不同数据模型、扩展和分布需求的一组方案，选型仍要回到实际需求。

## 核心优先链

时间有限时优先完成 P0：

[[数据库三级模式与两级映像]] → [[关系代数基础运算]] → [[连接与自然连接]] → [[函数依赖与属性闭包]] → [[候选码求解]] → [[范式1NF-2NF-3NF-BCNF]] → [[无损连接与保持函数依赖]] → [[数据库设计六阶段]] → [[ER模型与概念结构设计]] → [[ER图合并与冲突]] → [[ER图转关系模式]]

这条链只表示优先级，不代表 P1/P2 不属于本章。
