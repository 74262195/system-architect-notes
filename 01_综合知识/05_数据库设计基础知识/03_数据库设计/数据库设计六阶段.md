# 数据库设计六阶段

> [!summary] 快速复习卡片
> - **核心结论**：需求分析 → 概念结构设计 → 逻辑结构设计 → 物理结构设计 → 数据库实施 → 运行维护。
> - **做题入口**：E-R 图多半在概念设计；关系模式/规范化在逻辑设计；索引/存储/访问方式在物理设计。

数据库设计不是“画完表就结束”，而是一条从业务到存储的转换链：

| 阶段 | 主要回答什么 | 典型产物/动作 |
| --- | --- | --- |
| 需求分析 | 用户要保存什么、怎样处理 | 数据/处理/系统要求 |
| 概念设计 | 现实世界有哪些实体和联系 | E-R 概念模型 |
| 逻辑设计 | 怎样变成 DBMS 支持的数据模型 | 关系模式、规范化、完整性、视图 |
| 物理设计 | 数据具体怎样存和访问 | 分布、存储结构、索引/访问方式 |
| 实施 | 把设计真正建出来 | DDL、数据装载、应用调试、试运行 |
| 运行维护 | 上线后怎样持续可用 | 性能、备份恢复、重组/重构 |

最容易混淆的是概念与逻辑：**E-R 模型强调与具体 DBMS/硬件无关；把 E-R 转成关系模式后才进入逻辑设计。**

## 真题怎么考

历年“数据库需求与设计”主题多次直接要求判断某动作属于哪个阶段。看到索引不要条件反射到“逻辑设计”：索引通常属于物理设计。

## 自测

> [!question]- 把学生—课程的多对多 E-R 联系转换成选课关系表，主要处于哪一阶段？
> 逻辑结构设计。概念模型已经存在，现在是在转换为关系模型。
