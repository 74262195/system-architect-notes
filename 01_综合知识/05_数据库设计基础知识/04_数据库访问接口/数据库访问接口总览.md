# 数据库访问接口总览

> [!summary] 快速复习卡片
> **作用/定位**：业务程序通常不能让用户直接操作数据库，所以需要程序级接口把高级语言与 DBMS 接起来。
> **核心结论**：大纲重点区分库函数接口（OCI）、嵌入式 SQL、通用接口（ODBC）和 ORM。
> **题干怎么认**：厂商底层函数库→OCI；SQL 写进宿主语言→嵌入式 SQL；异构 DB 统一接口→ODBC；对象与关系表映射→ORM。
> **易错点**：这些接口解决的问题不同，不是同一技术的四个版本。

前面的数据库设计告诉我们“数据怎样组织”。实际应用还要回答：Java/C/C++ 等程序如何连接、查询并更新数据库？

教材把常见方式分成几类：

| 方式 | 核心思路 | 典型特点 |
| --- | --- | --- |
| 库函数级接口 | 直接调用数据库厂商提供的函数库 | 控制细、通常与特定数据库绑定较强 |
| 嵌入式 SQL | 把 SQL 写入宿主程序源代码 | 需要预编译等机制处理 SQL 与宿主语言边界 |
| ODBC 等通用接口 | 通过统一 API + 驱动访问不同 DBMS | 强调异构数据库统一访问 |
| ORM | 把程序对象和关系数据库记录建立映射 | 减少业务代码直接处理关系模型的阻抗 |

这张卡只负责建立坐标。具体区分见 [[嵌入式SQL与OCI]]、[[ODBC与JDBC]]、[[ORM访问接口]]。

## 自测

1. 题目强调“同一应用通过统一接口访问不同厂商数据库”，优先想到哪类技术？

> [!answer]- 第 1 题答案与解析
> **答案**：ODBC 这类通用数据接口标准。
> **解析**：题干关键是统一 API 加驱动来屏蔽不同 DBMS 的访问差异，不是厂商函数库或对象映射。

下一站：若题干出现“预编译器”或 “Oracle 函数调用”，看 [[嵌入式SQL与OCI]]；出现 Java 类和接口，看 [[ODBC与JDBC]]。
