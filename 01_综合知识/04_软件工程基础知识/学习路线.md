# 软件工程基础知识学习路线

## 为什么按这个顺序

软件工程不是一组孤立术语，而是一条完整链：**先决定怎样组织开发，再把需求变成设计和代码，然后验证软件，最后用复用与项目管理控制交付。**

## 先按时间决定学多深

优先级详细依据见 [[软件工程基础知识-复习优先级]]。

- **时间很紧**：先拿下 17 张 P0，再做题。
- **正常第一轮**：完成 P0 + P1，共 37 张。
- **第二轮完整覆盖**：再补 25 张 P2。
- 本章当前没有仅靠旧纲/单个旧题支撑的 P3 卡。

> [!important]
> **优先级 ≠ 学习顺序。** [[软件工程的定位]]、[[面向对象方法]]、[[软件项目管理的范围]] 这类“总入口”可能是 P2，但第一次学习仍要先读，因为它们负责告诉你后面的知识属于哪里。

这条清单是**复习优先级**，不是替代下面的完整学习链。

## 第一轮：先理解整条开发链

### 1. 软件过程：项目准备怎样开发

先读 [[软件工程的定位]]，再比较五类典型思路：

[[瀑布模型]] → [[迭代与增量模型]] → [[螺旋模型]] → [[原型的去留与目标系统]] → [[构件组装模型]]

不要把它们背成同一张特点表，先问：
- 需求是否稳定？
- 是否需要尽早交付一部分能力？
- 风险是否需要反复识别和控制？
- 是否先用原型澄清需求？
- 是否大量依赖已有构件复用？

然后学习两组扩展：
- RUP：[[RUP]] → [[RUP九类工作流]] → [[RUP四加一视图]]
- 敏捷：[[极限编程XP]]、[[Scrum迭代管理]]、[[水晶系列方法]]、[[特征驱动开发FDD]]

最后再读 [[CMMI成熟度等级]]。它回答的是“组织的软件过程怎样持续改进和评估”，**不是另一种生命周期模型**。

第一轮投入上，瀑布/增量/螺旋/CMMI 优先；敏捷的 XP、Scrum、水晶、FDD 都在范围内，但不要因为“敏捷方法整体重要”就把四张细分卡全部当成 P0。

**为什么下一站是需求？** 过程模型决定“怎么组织工作”，但真正开发什么，要靠需求工程确定。

### 2. 需求工程：先把“要什么”说清楚

[[需求层次与非功能需求]] → [[需求开发与需求管理]] → [[需求获取方法]] → [[需求规格与确认验证]] → [[需求变更控制]] → [[需求双向追踪矩阵]]

重点区分两条线：
- 开发需求：获取、分析、规格说明、确认/验证；
- 管理需求：变更控制和双向追踪。

复习时优先抓：**需求开发 vs 需求管理、需求变更、需求追踪**。近年去重题多次直接从这些角度出题。

**为什么下一站是设计？** 需求给出目标，设计负责把目标组织成可实现的软件结构。

### 3. 分析与设计：从问题走向实现结构

先走结构化方法：

[[结构化分析与设计分工]] → [[数据流图DFD]] → [[数据字典]] → [[模块信息隐藏]] → [[模块耦合类型]] / [[模块内聚类型]] → [[结构化详细设计工具]]

再走面向对象方法：

[[面向对象方法]] → [[面向对象分析OOA]] → [[面向对象设计OOD]] → **UML 集中识图** → [[实体类边界类与控制类]] → [[面向对象程序设计OOP]] → [[对象持久化与ORM]]

其中 UML 的唯一主事实源在“计算机软件与语言”知识域。按下面这条小链集中学习：

[[建模语言与UML]] → [[UML类图与基本关系]] → [[UML用例图]] → [[UML序列图与通信图]] → [[UML活动图与状态机图]] → [[UML构件图与部署图]]

> [!note] 为什么把 UML 放在 OOD 后面
> 这是**学习顺序**，不是说 UML 是 OOD 和 OOP 之间一个强制独立开发阶段。实际 OOA、OOD 过程中都可以使用 UML。这里先让你搞懂“分析和设计到底在做什么”，再集中学“这些结果怎样用统一图形表达”，认图会更容易。

补充两类大纲明确方法：[[逆向工程]]、[[形式化方法]]。

最重要的阶段感：

> **OOA 理解问题域 → OOD 设计对象职责/接口/协作 → UML 把分析设计结果统一画出来 → OOP 用代码实现。**

其中 UML 是表达工具，不是额外开发阶段。

复习优先级上先抓 **DFD、内聚、耦合**；OOA/OOD/OOP 整条链要能区分。UML 本身再按题目“到底要表达什么”选图，不要背成 13 个孤立名称。

### 4. 软件测试：不要把不同分类维度混在一起

先学“怎么分类”：
- 是否运行程序：[[静态测试与动态测试]]
- 是否利用内部结构：[[黑盒白盒与灰盒测试]]
- 具体设计技术：[[黑盒用例设计方法]]、[[白盒覆盖的判断]]
- 质量视角：[[验证与确认V&V]]
- 执行方式：[[测试自动化]]

再学“在哪个层次/场景测”：

[[单元测试与集成测试]] → [[系统测试与验收测试]] → [[性能负载与压力测试]] → [[回归测试]] → [[Alpha与Beta测试]] → [[AB测试]]

[[Web链接与表单测试]] 作为教材补充场景阅读，不要把它和黑盒/白盒等基本分类并列背诵。

第一轮优先拿下：**静态/动态、黑白灰盒、白盒覆盖、单元/集成、系统/验收**。V&V、自动化、A/B 等仍在新版大纲内，但先放第二轮，不与核心分类抢时间。

### 5. 净室软件工程

[[净室软件工程]] → [[净室盒子结构]]

先理解它强调缺陷预防和严格过程，不要只背“盒子”名称。当前均为 P2，第二轮再补即可。

### 6. 基于构件的软件工程

[[构件模型与容器]] → [[CBSE开发过程]] → [[构件组装方式]] → [[构件接口适配]]

注意与前面的 [[构件组装模型]] 区分：前者这里讲 CBSE 机制和实现细节，后者是软件过程模型视角。

构件主题整体仍活跃，但子卡优先级不同：构件模型/容器、组装方式、接口适配先学，CBSE 过程细节第二轮补。

### 7. 软件项目管理：把开发活动管住

[[软件项目管理的范围]] → [[工作分解结构WBS]] → [[活动依赖与进度计划]] → [[软件配置管理]] → [[版本控制与基线]] → [[软件质量保证SQA]] → [[软件风险管理]]

这里不要把“项目管理的范围”因为是入口就误判成最高优先级。第一轮重点抓：**进度/依赖、配置管理**；WBS、基线、SQA、风险属于紧随其后的 P1。

## 第二轮：按题干快速定位

- “阶段顺序、需求稳定、增量交付、风险驱动、原型、复用已有构件” → 过程模型。
- “业务/用户/功能/非功能、获取、变更、追踪” → 需求工程。
- “DFD、数据字典、内聚/耦合” → 结构化分析设计。
- “问题域对象、职责/接口、继承多态” → OOA / OOD / OOP，先判断阶段。
- “外部角色能使用系统哪些功能” → 用例图；“类及其关系” → 类图；“谁先调用谁” → 序列图；“对象连接与消息编号” → 通信图；“业务步骤怎么走” → 活动图；“一个对象生命周期怎么变” → 状态机图；“软件拆成哪些构件” → 构件图；“软件跑在哪些结点” → 部署图。
- “从旧代码恢复设计” → 逆向工程；“严格数学语义/证明性质” → 形式化方法。
- “是否运行程序” → 静态/动态；“内部结构” → 黑盒/白盒/灰盒；“把产品做对/做正确产品” → V&V。
- “复用、构件评估、适配、组装” → 构件组装模型或 CBSE，再看题目问过程还是技术细节。
- “WBS、依赖、基线、SQA、风险” → 项目管理。
