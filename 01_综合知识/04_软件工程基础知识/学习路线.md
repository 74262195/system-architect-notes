# 软件工程基础知识学习路线

## 为什么按这个顺序

软件工程不是一组孤立术语，而是一条完整链：**先决定怎样组织开发，再把需求变成设计和代码，然后验证软件，最后用复用与项目管理控制交付。**

## 先按时间决定学多深

优先级详细依据见 [[软件工程基础知识-复习优先级]]。

原有软件工程卡的优先级统计仍是：P0 17 / P1 20 / P2 25。**本轮迁入的 UML 知识组不机械套用这组旧统计**：[[UML总览]] 沿用已核验的 P0，其余 UML 子卡暂为 `待评估`，后续按 Atom 级证据统一校准。

- **时间很紧**：先拿下原有 P0，再把 [[UML总览]] 和典型 UML 图识别一起学完；
- **正常第一轮**：完成 P0 + P1，并走完下面完整学习链；
- **第二轮完整覆盖**：再补 P2 和低信号细节。

> [!important]
> **优先级 ≠ 学习顺序。** [[软件工程的定位]]、[[面向对象方法]]、[[软件项目管理的范围]] 这类“总入口”即使不是最高优先级，第一次学习仍要先读，因为它们负责告诉你后面的知识属于哪里。

## 第一轮：先理解整条开发链

### 1. 软件过程：项目准备怎样开发

先读 [[软件工程的定位]]，再比较五类典型思路：

[[瀑布模型]] → [[迭代与增量模型]] → [[螺旋模型]] → [[原型的去留与目标系统]] → [[构件组装模型]]

不要把它们背成同一张特点表，先问：
- 需求是否稳定？
- 是否需要尽早交付一部分能力？
- 风险是否需要反复识别和控制？
- 是否先用原型澄清需求？
- 是否大量依赖已有构件复用？

然后学习两组扩展：
- RUP：[[RUP]] → [[RUP九类工作流]] → [[RUP四加一视图]]
- 敏捷：[[极限编程XP]]、[[Scrum迭代管理]]、[[水晶系列方法]]、[[特征驱动开发FDD]]

最后再读 [[CMMI成熟度等级]]。它回答的是“组织的软件过程怎样持续改进和评估”，**不是另一种生命周期模型**。

**为什么下一站是需求？** 过程模型决定“怎么组织工作”，但真正开发什么，要靠需求工程确定。

### 2. 需求工程：先把“要什么”说清楚

[[需求层次与非功能需求]] → [[需求开发与需求管理]] → [[需求获取方法]] → [[需求规格与确认验证]] → [[需求变更控制]] → [[需求双向追踪矩阵]]

重点区分两条线：
- 开发需求：获取、分析、规格说明、确认/验证；
- 管理需求：变更控制和双向追踪。

复习时优先抓：**需求开发 vs 需求管理、需求变更、需求追踪**。

**为什么下一站是设计？** 需求给出目标，设计负责把目标组织成可实现的软件结构。

### 3. 分析与设计：从问题走向实现结构

先走结构化方法：

[[结构化分析与设计分工]] → [[数据流图DFD]] → [[数据字典]] → [[模块信息隐藏]] → [[模块耦合类型]] / [[模块内聚类型]] → [[结构化详细设计工具]]

再走面向对象方法：

[[面向对象方法]] → [[面向对象分析OOA]] → [[面向对象设计OOD]] → **UML 集中建模** → [[实体类边界类与控制类]] → [[面向对象程序设计OOP]] → [[对象持久化与ORM]]

#### UML 为什么现在放在这里详细学

官方大纲仍把 UML 放在“计算机语言 → 建模语言”中，因此 `04_计算机软件与语言` 仍保留 [[建模语言与UML]] 作为**考试归属定位卡**。

但第一次学习时，更自然的问题链是：

> **OOA：业务里有什么对象？ → OOD：这些对象怎么设计？ → UML：怎样把分析和设计统一画出来？ → OOP：怎样写成代码？**

所以完整 UML 主事实源现在就在本章 `03_分析与设计`。按下面这条小链学习：

[[UML总览]] → [[UML用例图]] → [[UML类图与基本关系]] → [[UML序列图与通信图]] → [[UML活动图与状态机图]] → [[UML构件图与部署图]]

> [!note]
> 这是**学习顺序**，不是说 UML 是 OOD 和 OOP 之间一个强制独立开发阶段。实际 OOA、OOD 过程中都可以使用 UML。这里先让你理解“分析和设计在做什么”，再集中学“这些结果怎样统一表达”。

最重要的阶段感：

> **OOA 理解问题域 → OOD 设计对象职责/接口/协作 → UML 统一表达分析设计结果 → OOP 编码实现。**

补充两类大纲明确方法：[[逆向工程]]、[[形式化方法]]。

### 4. 软件测试：不要把不同分类维度混在一起

先学“怎么分类”：
- 是否运行程序：[[静态测试与动态测试]]
- 是否利用内部结构：[[黑盒白盒与灰盒测试]]
- 具体设计技术：[[黑盒用例设计方法]]、[[白盒覆盖的判断]]
- 质量视角：[[验证与确认V&V]]
- 执行方式：[[测试自动化]]

再学“在哪个层次/场景测”：

[[单元测试与集成测试]] → [[系统测试与验收测试]] → [[性能负载与压力测试]] → [[回归测试]] → [[Alpha与Beta测试]] → [[AB测试]]

[[Web链接与表单测试]] 作为教材补充场景阅读，不要把它和黑盒/白盒等基本分类并列背诵。

## 第二轮：按题干快速定位

- “阶段顺序、需求稳定、增量交付、风险驱动、原型、复用已有构件” → 过程模型。
- “业务/用户/功能/非功能、获取、变更、追踪” → 需求工程。
- “DFD、数据字典、内聚/耦合” → 结构化分析设计。
- “问题域对象、职责/接口、继承多态” → OOA / OOD / OOP，先判断阶段。
- “外部角色能使用系统哪些功能” → 用例图；“类及其关系” → 类图；“谁先调用谁” → 序列图；“对象连接与消息编号” → 通信图；“业务步骤怎么走” → 活动图；“一个对象生命周期怎么变” → 状态机图；“软件拆成哪些构件” → 构件图；“软件跑在哪些结点” → 部署图。
- “从旧代码恢复设计” → 逆向工程；“严格数学语义/证明性质” → 形式化方法。
- “是否运行程序” → 静态/动态；“内部结构” → 黑盒/白盒/灰盒；“把产品做对/做正确产品” → V&V。
- “复用、构件评估、适配、组装” → 构件组装模型或 CBSE，再看题目问过程还是技术细节。
- “WBS、依赖、基线、SQA、风险” → 项目管理。
