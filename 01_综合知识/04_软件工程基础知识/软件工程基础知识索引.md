# 软件工程基础知识索引

> 本章按“**过程怎么组织 → 需求怎么确定 → 设计怎么落地 → 测试怎么验证 → 构件怎么复用 → 项目怎么管住**”学习。范围以新版考试大纲为边界，教材用于补机制；真题按独立题目标识校准考法与优先级，不以文件/关键词出现次数推导“高频”。

## 优先级怎么读

- **P0**：第一轮优先拿分。
- **P1**：主线必学，正常第一轮与 P0 一起完成。
- **P2**：仍在当前范围内，第二轮补齐；不是“超纲”。
- **P3**：旧纲/历史补充；本章当前没有仅靠旧纲支撑的存量卡。

本章当前：**P0 17 / P1 20 / P2 25 / P3 0**。详细依据见 [[软件工程基础知识-复习优先级]]。

> [!note]
> 优先级不等于学习顺序。例如 [[软件工程的定位]] 标 P2，但仍然应该第一篇读，因为它负责建立整章坐标。

### UML 建模表达（跨章节主事实源）

> [!note]
> 软件工程章负责说明 **OOA/OOD 为什么需要 UML 来表达分析设计结果**；UML 的完整定义、关系和典型图不在这里复制。唯一主事实源位于“计算机软件与语言”。

- [[建模语言与UML]]：先知道 UML 是“软件系统统一画图语言”，不是开发方法；
- [[UML类图与基本关系]]：类、依赖、关联、泛化、实现；
- [[UML用例图]]：系统外部角色与系统能提供什么功能；
- [[UML序列图与通信图]]：对象之间怎样发消息；
- [[UML活动图与状态机图]]：流程怎样走 vs 一个对象怎样换状态；
- [[UML构件图与部署图]]：软件拆成什么 vs 软件部署在哪。

学习顺序可以写成：

> **OOA 理解问题域 → OOD 设计职责/接口/协作 → 集中学习 UML 怎样表达 → OOP 编码实现。**

但 UML 是分析/设计的**表达工具**，不是强制独立的开发阶段。
