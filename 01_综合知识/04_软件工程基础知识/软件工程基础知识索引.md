# 软件工程基础知识索引

## 第一次学习从这里开始

如果你现在是**第一次学软件工程**，不要从 P0 清单跳着读。直接按 [[学习路线]] 顺序走完整主线：

> **软件工程定位 → 过程模型 → 需求工程 → 分析与设计 → UML/OOP → 软件测试 → 净室 → CBSE → 软件项目管理**

每一段都在回答上一段留下的新问题。P0/P1/P2 只用于**复习取舍**，不是第一次学习顺序。

- **零基础主线**：[[学习路线]]

## 优先级怎么读

- **P0**：第一轮优先拿分。
- **P1**：主线必学，正常第一轮与 P0 一起完成。
- **P2**：仍在当前范围内，第二轮补齐；不是“超纲”。
- **P3**：旧纲/历史补充。

历史优先级统计见 [[软件工程基础知识-复习优先级]]；它只用于复习取舍，不代表当前目录文件数或 Atom 数。UML 知识组现已迁入本章作为**教学主事实源**：[[UML总览]] 沿用已核验优先级，其余 UML 子卡保持 `待评估`，待下一轮原子级优先级统一校准，不能把旧的 17/20/25 统计机械套到迁入卡片上。

> [!note]
> 优先级不等于学习顺序。例如 [[软件工程的定位]] 可能不是最高优先级，但仍然应该第一篇读，因为它负责建立整章坐标。

### UML 建模表达（本章完整学习主事实源）

> [!important]
> 官方大纲仍把 UML 列在“计算机语言 → 建模语言”中；那个位置只保留 [[建模语言与UML]] 作为**考试归属定位卡**。为了让学习顺序更自然，完整 UML 正文放在这里：先理解 OOA/OOD 在想什么，再学怎样把分析和设计统一画出来。

推荐按下面顺序：

1. [[UML总览]]：先把“组成、事物、关系、图、视图”放回正确层级；
2. [[UML用例图]]：先站在系统外看“谁来用、系统能做什么”；
3. [[UML类图与基本关系]]：再看系统里面有哪些类、类之间怎么连；
4. [[UML序列图与通信图]]：看对象之间怎样发消息；
5. [[UML活动图与状态机图]]：分清流程怎么走和一个对象怎样换状态；
6. [[UML构件图与部署图]]：看软件拆成什么，以及最后部署在哪。

学习链可以理解成：

> **OOA 理解问题域 → OOD 设计职责/接口/协作 → UML 把分析设计结果统一表达 → OOP 编码实现。**

但 UML 是分析/设计的**表达语言**，不是 OOD 和 OOP 之间强制新增的开发阶段；实际 OOA、OOD 过程中都可以使用 UML。
