# RUP四加一视图：它不是阶段也不是工作流，而是“体系结构怎么表达”

> [!summary]- 快速复习卡片（学完再看）
> **定位**：RUP 的生命周期二维模型是“四阶段 + 九工作流”；4+1 不属于这两个轴。  
> **为什么出现**：RUP 强调“以体系结构为中心”，而不同角色对同一架构关注点不同，所以需要多视图描述。  
> **本卡只负责**：把 4+1 放回 RUP 语境，防止和阶段、工作流混淆。  
> **完整主事实源**：[[04_软件架构视图：为什么同一系统需要多个观察视角]]。  
> **做题第一动作**：题目问 RUP 特点 → 用例驱动 / 体系结构中心 / 迭代增量；题目问某个视图职责 → 转到软件架构 4+1 主源。

上一站 [[RUP九类工作流]] 已经把 RUP 的二维生命周期拆清：

> **四阶段 = 项目时间推进；九工作流 = 团队工作的种类。**

现在再看 4+1。

最重要的一句话：

> **4+1 既不是第五个 RUP 阶段，也不是第十类工作流；它是 RUP“以体系结构为中心”时，用来从多个关注点描述同一套软件架构的方法。**

## 为什么 RUP 需要 4+1

假设还是告警平台。

不同角色会问不同问题：

- 业务人员：系统功能怎样组织？
- 架构师：运行时哪些部分并发、怎样同步？
- 开发人员：代码模块和子系统怎样组织？
- 运维/系统工程人员：软件最终部署到哪些机器或节点？

一张图很难同时把这些问题讲清。

所以 RUP 采用 4+1 多视图模型表达体系结构。

大白话：

> **同一个系统不变，只是换不同角度看。**

## 它和 RUP 的“二维模型”是什么关系

| 问题 | RUP 对应知识 |
| --- | --- |
| 项目现在主要处在哪个时间阶段？ | 初始 / 细化 / 构造 / 移交 |
| 团队当前开展哪一类工程工作？ | 九类核心工作流 |
| 同一套体系结构怎样从不同关注点描述？ | 4+1 多视图 |

因此：

> **阶段 + 工作流 = 生命周期二维模型。**  
> **4+1 = 架构表达。**

这就是本卡存在的主要目的。

## 最容易串层的三个错误

### 错误 1：把 4+1 当成 RUP 第三个生命周期维度

不对。

教材明确把 RUP 生命周期称为二维模型：

> **阶段 + 工作流。**

4+1 属于体系结构描述。

### 错误 2：把“部署工作流”和“物理视图”当成一回事

不对。

- **部署工作流**：团队在做打包、安装、交付、支持等活动；
- **物理视图**：描述软件如何映射到硬件节点。

一个是“做什么工作”，一个是“从什么角度描述架构”。

### 错误 3：把“测试工作流”和“+1 用例/场景”当成一回事

也不对。

测试工作流是工程活动。

+1 场景用于贯穿、说明和验证多个架构视图之间是否一致。

## 考试第一动作

- **初始 / 细化 / 构造 / 移交** → RUP 阶段。
- **需求 / 实现 / 测试 / 配置变更 / 项目管理等** → RUP 工作流。
- **用例驱动 / 体系结构为中心 / 迭代增量** → RUP 特点。
- **逻辑 / 进程 / 开发 / 物理 / 场景分别关注什么** → 进入软件架构 4+1 题，按 [[04_软件架构视图：为什么同一系统需要多个观察视角]] 判断。

## 自测

1. 4+1 是不是和四阶段、九工作流并列，组成 RUP 的第三个生命周期维度？

> [!answer]- 第 1 题答案与解析
> **答案：不是。**
> **解析：**RUP 生命周期是“阶段 + 工作流”的二维模型；4+1 是“以体系结构为中心”时采用的架构多视图表达。

2. “部署工作流”和“物理视图”为什么不是同一个概念？

> [!answer]- 第 2 题答案与解析
> **答案：一个是工程活动，一个是架构视角。**
> **解析：**部署工作流关注打包、安装和交付等活动；物理视图关注软件到硬件节点的映射。

3. 题目问“哪个视图关注并发和同步”，应该在本卡展开推理吗？

> [!answer]- 第 3 题答案与解析
> **答案：转到软件架构主事实源判断。**
> **解析：**本卡只维护 RUP 中的定位；完整 4+1 职责统一由 [[04_软件架构视图：为什么同一系统需要多个观察视角]] 维护。
