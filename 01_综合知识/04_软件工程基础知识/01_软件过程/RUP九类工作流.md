# RUP九类工作流

> [!summary] 快速复习卡片
> - **核心结论**：六类工程工作流加三类支持工作流，共九类；可以跨阶段开展。
> - **做题入口**：把配置与变更管理、项目管理、环境遗漏掉，就把九类误记成六类。

**工作流**是围绕某方面目标组织的相关活动集合。它与 [[RUP]] 的四阶段交叉：初始阶段也可做测试，构造阶段也可能细化需求，只是投入比例不同。

| 工作流 | 负责的成果或作用 |
| --- | --- |
| 业务建模 | 理解组织业务与系统影响 |
| 需求 | 明确功能和用户界面要求 |
| 分析与设计 | 形成实现所需模型 |
| 实现 | 编码、单元测试与集成 |
| 测试 | 验证需求和交互，记录缺陷 |
| 部署 | 打包、安装、培训与支持 |
| 配置与变更管理 | 维护制品的一致性和完整性 |
| 项目管理 | 计划、人员、监控与风险管理 |
| 环境 | 提供开发过程和工具支持 |

例如同一迭代既开发短信通知，又维护版本、更新计划和构建环境。后面三项不是产品功能，但缺少它们会让多人协作失控。

## 考试动作：先分清“阶段”还是“工作种类”

- 题干出现“初始、细化、构造、移交”时，先按 **RUP 四阶段**判断时间推进和阶段目标。
- 题干出现“需求、分析设计、实现、测试、部署、项目管理”等时，先按 **工作流**判断活动种类。
- 看到“某阶段只能做一种工作流”要警惕：工作流可以跨阶段，只是各阶段投入强度不同。

## 自测

> [!question] 自测
> 1. 四阶段与九工作流是什么关系？
>
> > [!answer]- 第 1 题答案与解析
> > **答案**：两个维度：四阶段描述时间和阶段目标，九工作流描述跨阶段的活动种类。
