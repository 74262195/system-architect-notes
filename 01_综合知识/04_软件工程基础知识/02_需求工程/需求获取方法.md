# 需求获取方法

> [!summary] 快速复习卡片
> - **核心结论**：获取需求先明确范围和涉众，再结合面谈、讨论、问卷、观察、原型与头脑风暴。
> - **做题入口**：隐性操作看观察，意见冲突看讨论，统计倾向看问卷，界面不清看原型。

**需求获取**是与涉众交流、观察工作并识别系统必要能力的活动。涉众不只包括最终用户，也包括维护、测试等对系统有诉求的人。

先理解业务和高层目标，界定系统范围；识别用户角色及代表；获取具体需求并梳理业务流程；最后整理规则、约束与验收要求。漏掉运维人员，就可能直到上线才发现系统不支持备份或排障。

| 方法 | 怎样开展 | 主要限制 |
| --- | --- | --- |
| 面谈 | 准备问题、交流、整理并回确认 | 少数人的意见可能不代表全体 |
| 专题讨论 | 多方集中澄清冲突并达成共识 | 需要有效主持 |
| 问卷 | 统一问题收集倾向数据 | 难深入追问含糊答案 |
| 现场观察 | 观看实际工作及异常处理 | 需解释观察到的行为 |
| 原型 | 用样品获得反馈 | 容易被误认为成品 |
| 头脑风暴 | 对新业务发散提出想法 | 想法仍要整理与验证 |

同一项目可组合多种方法，不能按“一种方法最有效”省去后续核实。
