# 数据流图 DFD：需求已经知道了，怎样画清“数据从哪来、被怎么处理、最后到哪去”

> [!summary]- 快速复习卡片（学完再看）
> **定位**：DFD 属于结构化分析，用数据流、加工、数据存储、外部项建立系统的功能/数据流逻辑模型。  
> **四类元素**：外部项、加工、数据流、数据存储。  
> **建立步骤**：明确目标与范围 → 顶层图 → 第一层分解图 → 继续逐层分解 → 检查确认。
> **分层核心**：从顶层开始逐步分解；父图与子图的边界输入输出要保持一致。  
> **第一动作**：先找系统边界，再看“谁提供/接收数据、数据经过什么加工、是否进入存储”。  
> **易错点**：DFD 不描述程序控制顺序；ER 看实体关系，程序流程图看控制流程，SC 看模块调用。

上一站 [[结构化分析与设计分工]] 已经把几个容易混的图放回正确层次：

> **DFD 看数据怎样流动和被加工。**

现在还是告警平台。

已知需求：

> 监控设备上报告警，系统校验并分级，把告警保存下来，再向值班人员发送通知。

如果只写一句“系统处理告警”，仍然看不出：

- 数据从谁那里来；
- 经过什么处理；
- 哪些结果要保存；
- 最后送给谁。

DFD 的直接答案是：

> **把系统看成一组“数据进入 → 被加工 → 存储或继续流出”的逻辑处理关系。**

## DFD 的主角不是“步骤”，而是数据和加工

先看同一个告警场景。

| DFD 元素 | 当前例子 | 它回答什么 |
| --- | --- | --- |
| **外部项** | 监控设备、值班人员 | 数据从系统外哪里来 / 到哪里去 |
| **加工** | 校验告警、分级、生成通知 | 数据发生了什么转换 |
| **数据流** | 原始告警、分级结果、通知内容 | 在对象之间传递什么数据 |
| **数据存储** | 告警记录库 | 数据在哪里被保存 |

例如：

> 监控设备提供“原始告警” → “告警校验”加工 → 合格告警进入“告警分级” → 分级结果写入告警库并形成通知内容。

这里真正要表达的是：

> **数据发生了什么变化。**

不是 CPU 先执行第 1 行还是第 2 行。

## 从一句需求开始，完整建立一次 DFD

**不要先画框，而要先把需求中的系统边界、数据来源、数据去向和数据变化找出来，再按“顶层 → 第一层 → 子图”逐层细化。**

下面继续使用这句教学需求：

> 监控设备上报告警，告警平台校验并分级，把告警保存下来，再向值班人员发送通知。

这不是教材原图，而是依据主教材 PDF 209–210 的建模步骤重构的小型例子。

### 第 1 步：明确目标和系统范围

先回答“这张图把什么算进系统”：

| 要确认的对象 | 本例结论 | 为什么 |
| --- | --- | --- |
| 目标系统 | 告警平台 | 当前要描述它怎样处理告警数据 |
| 外部数据提供者 | 监控设备 | 它提供原始告警，但不属于告警平台内部 |
| 外部数据使用者 | 值班人员 | 他接收通知，也在系统边界之外 |
| 内部加工 | 校验、分级并保存、生成通知 | 都属于告警平台承担的数据转换 |
| 数据存储 | 告警记录库 | 保存平台处理后的告警记录 |

如果边界尚未确定，就不能稳定判断“监控设备”究竟是外部项还是系统内部加工。

### 第 2 步：先画顶层图，只确定系统边界

顶层图先把整个告警平台看成**一个加工**，只画它和外部项交换的数据：

- 监控设备输入“原始告警”；
- 告警平台输出“通知内容”给值班人员。

此时先不要把校验、分级、保存全部塞进来。顶层图的任务是确认：

> **谁在系统外，系统整体接收什么、输出什么。**

### 第 3 步：把顶层加工拆成第一层 DFD

现在才打开“告警平台”这个加工，根据数据发生的变化拆成：

1. **P1 校验告警**：原始告警变成合格告警；
2. **P2 分级并保存**：合格告警形成告警记录并写入 D1；
3. **P3 生成通知**：从 D1 取得待通知告警，形成通知内容。

![[05_画图素材/Excalidraw/原子笔记插图/告警平台DFD建立示例.svg]]

读图时按数据走一遍：

> 监控设备提供原始告警 → P1 校验 → P2 分级并形成告警记录 → D1 保存并提供待通知告警 → P3 生成通知 → 值班人员收到通知内容。

图中箭头名称写的是**数据名**，不是“下一步”“然后”等控制词；加工名称使用“动词 + 名词”，让人看出数据发生了什么变化。

### 第 4 步：只继续分解仍然不够清楚的加工

如果“P1 校验告警”仍然太粗，可以建立 P1 的子图，例如再拆成：

1.1 检查必要字段 → 1.2 校验设备身份 → 1.3 输出合格告警或错误信息。

但不是每个加工都要无限拆分。可以停止的判断是：

- 加工已经能够被清楚命名；
- 输入、处理目的和输出已经明确；
- 继续拆分不会再显著帮助理解需求。

> [!warning] DFD 仍然只描述逻辑功能
> “校验失败走哪个 `if` 分支、循环几次、调用哪个函数”属于详细设计或程序控制逻辑，不应继续塞进 DFD。

### 第 5 步：从外到内检查这张图

先做**父子图平衡检查**：

| 顶层边界数据流 | 第一层是否仍存在 | 结论 |
| --- | --- | --- |
| 原始告警：监控设备 → 告警平台 | 原始告警：监控设备 → P1 | 保留 |
| 通知内容：告警平台 → 值班人员 | 通知内容：P3 → 值班人员 | 保留 |

再检查每个元素：

- P1、P2、P3 都至少有一个输入和一个输出；
- D1 既有 P2 写入的“告警记录”，也有流向 P3 的“待通知告警”；
- 每条数据流至少有一端连接加工；
- 没有把外部项直接连到数据存储；
- 数据流名称、加工名称和需求用语能够对应。

到这里才算真正完成一次 DFD 建立，而不是只记住四种符号。

## 为什么 DFD 不等于程序流程图

这两个都可能有箭头，所以非常容易混。

### DFD 的箭头

表示：

> **数据在谁和谁之间流动。**

例如：

> “原始告警”从设备流向“告警校验”。

### 程序流程图的箭头

表示：

> **控制下一步执行到哪里。**

例如：

> 判断“告警级别是否为 P1”，是则发送短信，否则结束。

所以看到箭头不要马上判断。

先问：

> **箭头上表达的是“数据”，还是“执行控制”？**

- 数据 → DFD；
- 执行顺序 / 判断 / 循环 → [[结构化详细设计工具]]。

## 什么叫父图和子图“平衡”

这是 DFD 最重要的考试规则之一。

假设父图里某个加工：

> 输入：原始告警  
> 输出：通知结果

把这个加工继续拆成子图后：

> **对这个加工边界来说，原来的输入输出不能凭空消失，也不能无依据多出新的对外数据。**

这就是父子图平衡的核心直觉：

> **内部可以拆得更细，但对外承诺的输入输出要保持一致。**

所以：

- 父图有“原始告警”输入，子图不能完全看不到它；
- 父图有“通知结果”输出，子图也不能无故丢失；
- 子图突然新增一个父图从未出现的对外输入，也要警惕。

## DFD 还有哪些基本合理性检查

教材给出几个稳定规则。

### 加工不能凭空产生数据

一个加工至少应有输入，也应有输出。

如果“生成通知”没有任何输入，却能凭空产生通知内容：

> 逻辑不完整。

### 数据存储不能完全与加工脱离

数据存储应通过加工被读取或写入。

例如：

> 外部设备直接把数据画进“告警库”，中间没有任何加工。

按教材 DFD 规则就要警惕。

### 数据流至少要和加工发生关系

DFD 中的数据流不是随便把两个对象连起来。

题目常见错误就是：

> 外部项 ↔ 数据存储直接相连。

此时缺少系统对数据的处理。

## 为什么 DFD 还需要数据字典

DFD 画出一条：

> “告警信息”

但“告警信息”到底包含什么？

可能有人理解成：

> 设备号 + 时间 + 级别

另一个人却以为还有：

> 责任人 + 机房 + 业务系统。

图本身很难把这些定义全部展开。

因此下一站需要：

> **把 DFD 中出现的数据项、数据结构、数据流、存储和加工含义统一定义清楚。**

→ [[数据字典]]

## DFD、ER、SC 一眼怎么分

| 题目主角 | 第一反应 |
| --- | --- |
| 数据从哪里来、经过什么加工、到哪里去 | **DFD** |
| 实体、属性、1:1 / 1:N / M:N | [[概念数据模型与实体联系]] |
| 模块层次、谁调用谁 | SC / 概要设计 |
| 顺序、判断、循环 | [[结构化详细设计工具]] |

考试先找**主角**，不要先看“都有图”就混在一起。

## 考试第一动作

DFD 题建议固定三步：

1. **先定边界**：谁在系统外，谁是内部加工；
2. **再看四元素连接是否合理**：数据必须经加工发生变化；
3. **最后查父子图平衡**：分解后边界输入输出是否一致。

## 自测

1. 拿到一段业务需求后，建立 DFD 的第一步为什么不是直接画加工框？

> [!answer]- 第 1 题答案与解析
> **答案：应先明确建模目标和系统范围。**
> **解析：**只有先确定系统边界，才能判断哪些对象是外部项、哪些活动是系统内部加工，以及系统整体接收和输出什么数据。

2. “监控设备”直接连到“告警记录库”，中间没有任何加工，是否合理？

> [!answer]- 第 2 题答案与解析
> **答案：按教材 DFD 规则不合理。**
> **解析：**外部项与数据存储之间应通过系统加工发生联系，不能把外部项直接画到数据存储。

3. 一个父加工输入 A、输出 B，分解成子图后 B 完全消失，应该优先检查什么？

> [!answer]- 第 3 题答案与解析
> **答案：父子图平衡。**
> **解析：**内部可以细化，但该加工对外的边界输入输出应保持一致。

4. 题目描述“如果 P1 则发短信，否则只记录”，这是 DFD 的主要问题还是详细设计控制逻辑？

> [!answer]- 第 4 题答案与解析
> **答案：更偏详细设计控制逻辑。**
> **解析：**题目主角是条件分支和执行顺序，而不是数据在加工/存储之间怎样流动。

5. DFD 上已经有“告警信息”数据流，为什么还需要数据字典？

> [!answer]- 第 5 题答案与解析
> **答案：DFD 只显示名称和关系，不能完整定义其中字段、含义、范围等细节。**
> **解析：**数据字典负责把这些元素定义清楚，避免不同人员理解不一致。
