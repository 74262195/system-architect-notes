# 结构化详细设计工具

> [!summary] 快速复习卡片
> - **核心结论**：详细设计说明模块内部算法；流程图、NS、PAD、判定表和 PDL 是不同表达工具。
> - **做题入口**：模块调用层次看 SC；模块内部控制过程看详细设计工具；数据流向看 DFD。

概要设计确定模块和接口后，开发者仍要知道每个模块内部怎样运行。**详细设计工具**用图、表或语言表达这些逻辑。

| 工具 | 最该抓住的识别点 |
| --- | --- |
| 程序流程图 | 方框表示处理、菱形表示条件、箭头表示控制流；能描述执行过程，但不擅长描述数据 |
| NS 图 | 盒状嵌套的结构化图；控制不能任意跳转，适合看嵌套与作用域 |
| PAD 图 | 比流程图更直观、结构更清晰；能体现自顶向下的细化过程，也可描绘数据结构 |
| 判定表 | 将各种条件组合与对应动作列成表，适合查条件组合有没有漏项或冲突 |
| PDL | 用结构化伪码说明模块内部算法；外层控制结构确定，内层业务操作可按实际情况灵活写 |

例如告警级别与是否已确认共同决定是否通知，判定表易于检查组合是否遗漏；处理循环则可用结构化伪码。

教材的 PDL 外层控制语法较确定，内层具体操作可按业务灵活描述。它不是必须编译运行的程序语言。结构化程序主要用顺序、选择和循环组合，强调自顶向下、逐步求精和清晰表达。

> [!tip] 一句话选工具
> 问“模块怎样被调用”选 **SC**；问“数据如何流动”选 **DFD**；问“模块内部如何执行”才在本卡的流程图、NS、PAD、判定表、PDL 中判断。

> [!question] 自测
> 1. 选择判定表最主要是为了展示什么？
>
> > [!answer]- 第 1 题答案与解析
> > **答案**：条件组合与动作的对应关系。
> > **解析**：判定表适合把多种条件组合逐列展开，从而检查动作是否遗漏、冲突或不一致；它不是模块调用层次图，也不以描绘控制流为主。
