# 模块耦合类型

> [!summary] 快速复习卡片
> - **核心结论**：耦合描述模块之间的依赖；传普通数据、结构、控制信息、共享数据和侵入内部，依赖逐步加深。
> - **做题入口**：先看模块怎样交换或共享信息，再判类别；不要把模块内部关系当耦合。总原则是**低耦合**。

两个模块都完成任务，并不说明连接方式合理。通知模块只接收告警编号，通常比直接修改告警模块内部变量更容易维护。

**耦合**是模块之间联系的程度。下表按主教材列法保留七种，理解重点是依赖的性质。

| 类型 | 识别方式 |
| --- | --- |
| 非直接耦合 | 无直接关系，由上级模块协调 |
| 数据耦合 | 参数传递简单数据 |
| 标记耦合 | 参数传递记录等数据结构 |
| 控制耦合 | 参数包含控制对方内部逻辑的信息 |
| 通信耦合 | 按本教材口径，共享输入或需整合输出 |
| 公共耦合 | 共同访问全局数据环境 |
| 内容耦合 | 越过正常接口访问内部数据或代码 |

例如传“告警编号”看数据耦合；传整个告警记录看标记耦合；传“执行路径编号”决定内部处理看控制耦合。不能只看参数数量判断。

**教材口径**：不同资料可能列“外部耦合”等不同成员，做题按题干定义，不能把其他版本的分类静默替换进本表。

## 历年怎么考

2019-H2-综合知识-34 直接考模块化设计，解析明确用**内聚和耦合衡量模块独立性，设计原则是高内聚、低耦合**。具体类型题再看“两个模块怎样发生联系”：简单数据、结构、控制信息、公共数据或直接侵入内部，不能只背强弱顺序。

## 自测

> [!question]- 一个模块直接跳入另一个模块内部代码，属于什么耦合？
> 内容耦合，破坏正常模块边界。
