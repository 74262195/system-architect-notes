# 概念数据模型与实体联系

> [!summary] 快速复习卡片
> - **核心结论**：实体是可区分的事物，属性描述特征，联系描述实体间关系；基数取决于业务约束。
> - **做题入口**：先问一个 A 对应几个 B，再反向问一个 B 对应几个 A，确定联系类型。

**概念数据模型**表达业务中有哪些信息和关系，属于数据库设计前期，暂不指定具体表结构和存储方式。常用实体—联系模型表达。

教学例子：设备产生告警。在“一条告警只属于一个设备”的约束下，一个设备可以有多条告警，一个告警只对应一个设备，因此是设备对告警的一对多关系。

| 成分 | 例子 |
| --- | --- |
| 实体 | 一台设备、一条告警 |
| 属性 | 设备编号、告警时间 |
| 联系 | 设备产生告警 |
| 标识 | 区分设备的唯一编号 |

绘制时识别实体集合、列属性、确定联系、确定标识，再标明数量约束。一对一、一对多、多对多必须双向检查；不能只看一个方向就下结论。

例如学生选课的成绩依赖特定学生和特定课程，属于选课联系的信息。概念模型之后才进入逻辑和物理设计，这里不扩写数据库完整章节。

> 1. 知道一个设备可有多条告警，能立刻断定一对多吗？

> > [!answer]- 第 1 题答案与解析
> > **答案**：还要检查每条告警是否只属于一个设备，必须双向确认。
