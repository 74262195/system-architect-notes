## 3. 本轮真实发现与修复

第三轮没有发现新的事实错误，也没有触发 `covered → partial`。发现的问题集中在“正文事实已经够，但学习链尾部不够明确”。

### 3.1 [[瀑布模型]]

- **问题**：定义、机制、优缺点、真题判断均存在，但自测后没有明确解释为什么下一站要进入原型模型。
- **修复**：补 `[[软件工程的定位]] → [[瀑布模型]] → [[原型的去留与目标系统]]` 的知识关系；明确“需求稳定”与“需求说不清”是下一站出现的原因。
- **复查**：六要素闭环完整，`SE-A002` 继续 `covered`。

### 3.2 [[RUP九类工作流]]

- **问题**：九类工作流表已有，但“RUP 四阶段”和“九工作流”做题时怎样先分维度不够显式，且缺少收口到 CMMI 的桥梁。
- **修复**：补“阶段 vs 工作种类”考试动作；补 `[[RUP四加一视图]] → [[RUP九类工作流]] → [[CMMI成熟度等级]]`。
- **复查**：`SE-A008` 的阶段/工作流边界更适合直接做选择题，继续 `covered`。

### 3.3 [[需求开发与需求管理]]

- **问题**：开发/管理边界和真题入口已经清楚，但模块入口缺少与上一知识组、下一张需求获取卡的显式关系。
- **修复**：补 `[[CMMI成熟度等级]] → [[需求开发与需求管理]] → [[需求获取方法]]`，把“组织过程能力”自然落到“具体工程活动”。
- **复查**：`SE-A012` 继续 `covered`。

### 3.4 [[静态测试与动态测试]]

- **问题**：“是否运行被测程序”判断动作已经正确，但正文结束后没有把读者带到另一条测试分类轴。
- **修复**：补“是否运行被测程序 → [[黑盒白盒与灰盒测试]] 的内部结构信息维度”的收口，明确两个分类轴不能混用。
