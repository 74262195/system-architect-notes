# 信息系统与软件工程术语映射

> [!info] 承接与定位
> 架构题之外，英语段落经常把“需求→设计→实现”的流程换成英文。这里的目标不是再学软件工程，而是先认出它属于哪个阶段、哪类产物。

> [!summary]- 快速复习卡片（20～40 秒）
> - `requirements`：需求；`functional/nonfunctional` 先分功能与非功能。
> - `specification`：规格说明；`design`：设计；`implementation`：实现。
> - `use case / DFD`：看到后优先回到需求分析/建模语境。
> - `cohesion/coupling`：内聚/耦合，方向通常是高内聚、低耦合。

## 一道具体英文问题

> Functional requirements describe what the system should do, whereas nonfunctional requirements constrain qualities or operating conditions.

题眼怎么抓？

- `what the system should do` → 功能需求。
- `whereas` → 前后对照。
- `qualities or operating conditions` → 非功能需求。

## 最小术语路由表

| 英文 | 中文定位 | 题干信号 | 易混点 |
|---|---|---|---|
| requirement | 需求 | should / must / need | design decision |
| functional requirement | 功能需求 | what the system does | nonfunctional requirement |
| nonfunctional requirement | 非功能需求 | performance/security/constraint | functional requirement |
| requirements analysis | 需求分析 | analyze / model user needs | design |
| specification | 规格说明 | detailed description | implementation |
| use case | 用例 | actor / interaction / functional need | class |
| DFD / data flow diagram | 数据流图 | process / data store / flow | flowchart |
| cohesion | 内聚 | responsibilities inside a module | coupling |
| coupling | 耦合 | dependency between modules | cohesion |
| reconstruction | 重构/重建语境 | extract / view / recover architecture | greenfield design |

## 考试第一动作

先找**阶段词**：analysis、design、implementation、testing、maintenance。阶段锁定后，再看名词是 requirement、model、specification 还是 artifact，选项会立刻缩小。

## 易混边界

- `design` 不是“开发全过程”，不要看到系统建设就都选 design。
- `process` 可以表示过程，也可表示处理；在 DFD 语境里常指加工/处理。
- `artifact` 在软件工程语境常指制品/工件，不是日常英语的“人工制品”那种直译重点。
