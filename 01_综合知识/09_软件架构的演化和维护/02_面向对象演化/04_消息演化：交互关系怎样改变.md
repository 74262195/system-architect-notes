# 消息演化：交互关系怎样改变

> [!summary]- 快速复习卡片（学完再看）
> **核心结论**：消息演化是顺序图演化的核心，重点有 AM、DM、SMO、OM、CMM 五类。
> **题干信号 → 第一反应**：增删消息、交换顺序、反转发送方向、改变发送/接收对象 → 判断对应操作。
> **第一动作**：改消息后检查它是否触犯现有约束。
> **易错边界**：消息变化不一定破坏架构；真正危险的是变化与约束冲突。

## 为什么消息比对象更直接影响行为

消息带着源对象、目标对象和时序信息。对象之间“谁先调用谁、谁把信息发给谁”一变，系统行为就变了。

教材给出五类核心操作：

| 操作 | 含义 | 典型场景 |
| --- | --- | --- |
| AM | Add Message，新增消息 | 新增一次交互 |
| DM | Delete Message，删除消息 | 移除一次交互 |
| SMO | Swap Message Order，交换消息顺序 | 改变两个行为的先后 |
| OM | Overturn Message，反转消息方向 | 原发送方与接收方角色互换 |
| CMM | Change Message Module，改变消息关联对象 | 让消息改由另一个对象发送或接收 |

## 改了消息，为什么还要看约束

可以分三种情况理解：

1. 变化与约束无关 → 通常不破坏正确性；
2. 与约束有关但仍满足约束 → 仍可能是正确演化；
3. 与约束有关且违背约束 → 演化结果不正确。

所以“发生消息变化”本身不是错误；**没有验证约束**才是风险。

## 考试动作

看到“交换两个调用的先后”优先 SMO；“改变发送和接收方向”优先 OM；“消息还在，但换了交互对象”优先 CMM。若问是否正确，继续检查约束，不要凭操作类型直接判断。

## 自测

1. 一条消息仍然存在，但原来由 A 发给 B，现在改为由 C 发给 B；这属于哪类消息演化？为什么不能只凭操作名称判断演化正确？

> [!answer]- 第 1 题答案与解析
> **答案**：属于 CMM（Change Message Module）；还必须检查变化后的交互是否仍满足约束。
> **解析**：消息存在但关联对象改变就是 CMM。消息增删、换序或换向本身不必然错误，违背约束才会使演化不正确。
