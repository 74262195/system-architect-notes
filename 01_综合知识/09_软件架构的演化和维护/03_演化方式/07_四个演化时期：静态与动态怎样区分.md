# 四个演化时期：静态与动态怎样区分

> [!summary]- 快速复习卡片（学完再看）
> **核心结论**：四个时期依次是设计时、运行前、有限制运行时、运行时；前两类属于静态演化，后两类属于动态演化。
> **题干信号 → 第一反应**：编译前＝设计时；编译后执行前＝运行前；运行中进入预设安全条件＝有限制运行时；运行中直接改结构＝运行时。
> **第一动作**：先判断系统是否正在运行，再判断变化条件是不是设计时预先规定。
> **易错边界**：动态演化不等于“完全无约束地热改”；有限制运行时演化恰恰要求满足预设安全条件。

## 一张时间轴先锁定位置

同样是增加一个支付校验组件：开发时改设计、编译后上线前调整配置，以及线上运行时切换组件，面对的风险不同。先问“系统此刻运行了吗”，再问“运行中切换是否预先规定了安全条件”，四个时期才有具体位置。

```mermaid
flowchart LR
    A[设计时演化<br/>编译前] --> B[运行前演化<br/>编译后、执行前]
    B --> C[有限制运行时演化<br/>运行中且满足预设安全条件]
    C --> D[运行时演化<br/>运行中按需求调整结构]
```

## 四类分别是什么

| 时期 | 系统状态 | 要点 |
| --- | --- | --- |
| 设计时演化 | 架构模型/代码编译前 | 改设计、模型和实现方案 |
| 运行前演化 | 已编译但尚未执行 | 不必处理运行状态，但要能增删组件等 |
| 有限制运行时演化 | 正在运行 | 设计阶段已经规定可演化条件，进入“安全”状态后执行预定操作 |
| 运行时演化 | 正在运行 | 因当前架构不满足要求而动态增删/替换组件、改变拓扑等，最难 |

教材的分类关系可以直接记成：

- **静态演化** = 设计时 + 运行前；
- **动态演化** = 有限制运行时 + 运行时。

## “是否停机”怎么用

静态演化的典型特征是修改期间系统不运行；动态演化的价值就是面对长期运行或停机代价极高的系统，在运行过程中完成结构调整。但实际动态操作仍需保证一致性、状态安全和原子性，不是随便热改。

## 考试动作

题干出现“编译以后、程序尚未执行” → 运行前演化；“预先规定演化条件，进入安全模式” → 有限制运行时；“航空/金融等不能停机，运行中替换组件” → 动态/运行时演化。

## 自测

1. 程序已编译但尚未执行，此时替换一个组件；它属于哪个演化时期和哪一大类？

> [!answer]- 第 1 题答案与解析
> **答案**：运行前演化，属于静态演化。
> **解析**：四时期中，设计时和运行前归入静态演化；有限制运行时和运行时归入动态演化。先看系统是否运行，是最快判断入口。
