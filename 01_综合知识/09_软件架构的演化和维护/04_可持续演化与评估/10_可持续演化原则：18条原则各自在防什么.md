# 可持续演化原则：18条原则各自在防什么

> [!summary]- 快速复习卡片（学完再看）
> **核心结论**：18 条原则不是一串口号，本质是在防三类失控：交付失控、结构失控、适应/质量失控。
> **题干信号 → 第一反应**：成本/进度/风险 → 可控；局部修改/波及/复杂度 → 结构健康；新技术/环境/标准/质量/需求 → 可持续适应。
> **第一动作**：先看题干“在防什么失控”，再对应原则名。
> **易错边界**：演化成功不只看“功能能跑”，还要看成本、结构、原则、质量和未来适应能力。

## 先分三组，避免硬背 18 个孤立名词

假设订单服务每加一条促销规则，就要同时改网页、库存和结算三个模块；几轮之后，团队既不知道波及范围，也不敢替换底层平台。18 条原则要解决的正是这类长期演化失控问题：让变化尽量局部、影响可预测、结构质量不因一次次修改而退化。

### A. 防止“项目交付失控”

| 原则 | 它在防什么 |
| --- | --- |
| 1 演化成本控制 | 演化贵到还不如重做 |
| 2 进度可控 | 变更无限拖期 |
| 3 风险可控 | 经济、时间、人力、技术、环境风险失控 |
| 7 目标一致 | 每轮局部优化最后偏离总体目标 |

### B. 防止“结构越改越坏”

| 原则 | 它在防什么 |
| --- | --- |
| 4 主体维持 | 核心行为剧烈摇摆、系统失去稳定主体 |
| 5 系统总体结构优化 | 局部变好但整体布局恶化 |
| 6 平滑演化 | 相邻版本变化过猛、更新速率失控 |
| 8 模块独立演化/修改局部化 | 改一个模块必须改半个系统 |
| 9 影响可控 | 波及范围不可预测 |
| 10 复杂性可控 | 架构越来越难理解、测试和维护 |
| 11 有利于重构 | 演化后反而更难整理结构 |
| 12 有利于重用 | 内聚下降、耦合升高，资产难复用 |
| 13 设计原则遵从性 | 演化破坏已经验证有效的设计原则 |

### C. 防止“未来适应与质量失控”

| 原则 | 它在防什么 |
| --- | --- |
| 14 适应新技术/技术独立性 | 对某一技术平台锁死 |
| 15 环境适应性 | 换硬件/软件环境就无法使用 |
| 16 标准依从性 | 演化偏离国际/国家/行业/企业标准 |
| 17 质量向好 | 功能变了，但关键质量属性明显恶化 |
| 18 适应新需求 | 当前改完后反而更难接下一轮需求 |

## 最值得建立的因果链

“修改局部化”解决的是**尽量少波及**；“影响可控”强调**即使有波及也要可预测**；“复杂性可控”关注多轮演化后结构是否仍能理解和维护。这三个很容易混淆。

07 章的质量属性提供“要守住什么”的目标；这里的 18 条原则提供“演化过程中怎样不把目标和结构改坏”的护栏。

## 考试动作

题干出现“修改一个模块导致大量其他模块被迫修改” → 先联想到模块独立演化/影响可控；“绑定特定平台” → 技术独立性；“演化后性能或可靠性下降” → 质量向好原则被破坏；“成本接近重开发” → 演化成本控制失败。

## 自测

1. 修改一个模块总会牵动许多无关模块，且团队无法预估波及范围。优先违反了哪两类原则？

> [!answer]- 第 1 题答案与解析
> **答案**：模块独立演化/修改局部化，以及影响可控。
> **解析**：前者要求修改尽量局部，后者要求即使存在影响也能预测和控制；它们都属于防止结构越改越坏的护栏。
