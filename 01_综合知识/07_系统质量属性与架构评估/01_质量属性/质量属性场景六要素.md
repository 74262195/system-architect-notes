# 质量属性场景六要素：怎么把“系统要快”变成能验收的要求

> [!summary]- 快速复习卡片
> **作用/定位**：把“快、稳、安全、好改”这种模糊愿望改写成可分析、可测试、可度量的场景。
> **核心结论**：六要素是刺激源、刺激、环境、制品、响应、响应度量。
> **题干怎么认**：问“谁触发、发生什么、当时什么状态、作用到谁、系统怎么做、做到什么程度”。
> **易错点**：响应是“做什么”，响应度量是“做到什么程度”；环境不是制品。

## 先把“系统要快”说成一个能验收的要求

促销时很多用户同时查询订单，业务方只说“系统要快”，开发团队却不知道要测什么：多少人同时查询算高峰？查询多久返回才算达标？如果没有这些条件，测试结果也无法回答系统是否满足业务要求。质量属性场景就是把模糊愿望改成参与者、事件、环境、对象、系统响应和验收尺度都清楚的描述。

例如：“促销高峰时，大量在线用户集中查询订单，订单查询服务处理请求并返回结果，95% 的请求在 2 秒内完成。”下面再把这句话拆成六个问题。

## 六个问题

| 人话问题 | 教材术语 | 在问什么 |
| --- | --- | --- |
| 谁触发？ | 刺激源 Source | 谁产生事件 |
| 发生什么？ | 刺激 Stimulus | 到达系统的事件 |
| 当时什么情况？ | 环境 Environment | 正常、过载、部署时等 |
| 影响谁？ | 制品 Artifact | 系统或某部分 |
| 系统怎么处理？ | 响应 Response | 采取什么动作 |
| 做到什么程度？ | 响应度量 Measurement | 用什么标准验收 |

> **谁发起 → 发生什么 → 什么环境 → 打到哪里 → 系统怎么做 → 做到什么程度。**

## 示例

| 六要素 | 订单查询 |
| --- | --- |
| 刺激源 | 大量在线用户 |
| 刺激 | 集中发起查询 |
| 环境 | 促销高峰、高负载 |
| 制品 | 订单查询服务 |
| 响应 | 处理并返回订单信息 |
| 响应度量 | P95 响应时间不超过 2 秒 |

## 历年考法落点

质量属性场景题常把六个元素打散放进一句需求中，让你判断某一段属于什么。第一步永远先分三组：**谁/什么事、当时/作用对象、做什么/做到多好**。

## 三组最容易混

- 刺激源 vs 刺激：谁干的 vs 发生了什么。
- 环境 vs 制品：当时什么状态 vs 事件作用到谁。
- 响应 vs 响应度量：做什么 vs 做到什么程度。

## 自测

1. “促销高峰”为什么通常是环境？

> [!answer]- 第 1 题答案与解析
> 它描述刺激发生时系统所处的运行条件，而不是谁发起动作。

2. “攻击者尝试读取数据”里谁是刺激源？

> [!answer]- 第 2 题答案与解析
> 攻击者是刺激源；“尝试读取数据”是刺激。

3. “30 秒内恢复”中的 30 秒属于什么？

> [!answer]- 第 3 题答案与解析
> 是响应度量，规定恢复这项响应要达到的可验证时间目标。
