# ATAM：为什么架构评估不能只追求一个质量属性

> [!summary] 快速复习卡片
> **作用/定位**：在多个质量属性之间分析架构决策，识别风险、敏感点和权衡点。
> **核心结论**：ATAM 重点不是给架构打总分，而是找“哪些质量场景最重要、哪些决策最敏感、哪里需要折中”。
> **题干怎么认**：多质量属性、敏感点、权衡点、效用树、风险/非风险。
> **易错点**：ATAM 比 SAAM 更强调多属性权衡；CBAM 则继续加入经济成本收益。

ATAM 经典关注性能、安全性、可修改性和可用性等质量目标之间的竞争关系。

## 主线怎么理解

1. 收集业务驱动因素和质量场景；
2. 描述架构与关键决策；
3. 对场景进行优先级排序；
4. 分析关键架构决策对质量属性的影响；
5. 找出敏感点、权衡点、风险与需要进一步验证的假设。

## SAAM vs ATAM

| | SAAM | ATAM |
| --- | --- | --- |
| 经典重点 | 可修改性 | 多质量属性权衡 |
| 核心技术 | 场景 | 场景 + 属性分析 + 权衡 |
| 题眼 | 场景交互 | 敏感点、权衡、多属性、效用树 |

## 历年考法落点

ATAM 题最常从“敏感点/权衡点”“效用树”“多质量属性”识别，不需要先背一大串活动编号。先判断题目是不是在**分析架构决策如何同时影响多个质量目标**。
