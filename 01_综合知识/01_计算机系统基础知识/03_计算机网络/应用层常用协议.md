# 应用层常用协议：看到业务需求先想到哪个协议

> [!summary] 快速复习卡片
> **作用/定位**：把“域名、地址配置、网页、文件、邮件、远程管理”等业务动作映射到应用层协议。
> **核心结论**：DNS 查域名，DHCP 发网络配置，HTTP/HTTPS 访问 Web，FTP 传文件，SMTP 发邮件，POP3/IMAP 收邮件，SSH 安全远程登录。
> **经典题型怎么做 / 题干怎么认**：先根据**功能**选协议，再用默认端口校验：DNS 53、DHCP 67/68、HTTP 80、HTTPS 443、FTP 21、SSH 22、SMTP 25、POP3 110、SNMP 161/162。
> **易错点 / 考试重点**：端口是默认约定，不是协议定义；SMTP 负责发，POP3/IMAP 负责收；DNS 常用 UDP 但必要时也可用 TCP。

## 为什么传输层之后还需要应用层

TCP/UDP 只能把数据交给主机上的通信端点，不能规定“怎样查域名、怎样请求网页、怎样发送邮件”。应用层协议继续约定这些业务消息的含义与交互规则。

## 高频映射表

| 功能 | 协议 | 常用端口 | 题眼 |
| --- | --- | ---: | --- |
| 域名解析 | DNS | 53 | 域名 ↔ IP |
| 自动分配网络配置 | DHCP | 67/68 | IP、掩码、网关、DNS |
| Web | HTTP | 80 | 网页请求/响应 |
| 加密 Web | HTTPS | 443 | HTTP + TLS |
| 文件传输 | FTP | 21（控制） | 上传、下载 |
| 安全远程登录 | SSH | 22 | 加密远程管理 |
| 明文远程终端 | Telnet | 23 | 明文登录 |
| 发送/转发邮件 | SMTP | 25 等 | 发邮件 |
| 接收邮件 | POP3 | 110 | 下载式收信 |
| 网络管理 | SNMP | 161/162 | 监控、管理、通知 |

第一轮不需要背所有冷门端口；优先掌握表里的稳定映射。

## 两条流程最值得理解

### DHCP：DORA

Discover → Offer → Request → ACK

- Discover：客户端寻找 DHCP 服务器；
- Offer：服务器给出地址方案；
- Request：客户端请求采用；
- ACK：服务器确认租约生效。

### 打开网页

1. DNS 先把域名解析成 IP；
2. 网络层把数据送向服务器；
3. 传输层建立/提供端到端传输；
4. HTTPS 场景再通过 TLS 建立加密保护；
5. HTTP 交换真正的 Web 请求和响应。

> **DNS 是“找到服务器”，HTTP 是“找到以后谈业务”。**

## 易混点

- SMTP 是发信，不是收信；
- POP3/IMAP 都用于收信，IMAP 更强调服务器端同步管理；
- ping 主要使用 ICMP，不是 TCP/UDP 应用层协议；
- ARP 解决同一链路上的 IP 到 MAC 映射，不要因为它常和 DNS 一起出现就把两者混为一层。

## 一句话总结

**先按功能认协议，再用端口核对；不要反过来只背一串数字。**
