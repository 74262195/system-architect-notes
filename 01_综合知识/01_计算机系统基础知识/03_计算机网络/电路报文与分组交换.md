# 电路、报文、分组交换：中间网络到底是“先占路、整件搬、还是拆小包”

## 先定位：前面解决“信号怎么走”，现在解决“经过多个中间节点时怎么转”

当发送端和接收端不直接相连，数据需要经过多个网络节点。

这时经典有三种交换思路。

## 电路交换：先建立专用通路

通信前先建立端到端资源通路，通信期间持续占用，结束后释放。

```mermaid
flowchart LR
    A["建立通路"] --> B["持续传输"]
    B --> C["释放通路"]
```

特点：

- 建立后通信过程稳定；
- 没数据时预留资源也可能闲置。

## 报文交换：整份报文收完再转

中间节点先完整接收整个报文，再存储并转发。

报文很大时：

- 缓冲需求大；
- 等完整报文收齐后才能继续转，时延可能较大。

## 分组交换：拆成小包共享网络

把大数据拆成多个较小分组，分组在网络中逐跳存储转发。

```mermaid
flowchart LR
    A["大数据"] --> B["拆成分组"]
    B --> C["共享链路逐跳转发"]
    C --> D["到达目的端后按协议处理"]
```

现代互联网主要建立在分组交换思想上。

## 三者一眼区分

> **电路先占路，报文整件走，分组拆小包。**

## 和网络时延怎么接

交换方式决定数据怎样经过节点，但“到底慢在发送、传播、排队还是处理”属于 [[网络性能指标]]。

不要在交换卡里重复背一套时延公式。
