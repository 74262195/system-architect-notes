# 非性能性指标：网络不只要快，还要长期可用、可扩展、可维护

> [!summary] 快速复习卡片
> **作用/定位**：补充“性能之外”的网络评价维度，连接后续系统质量属性和可靠性知识。
> **核心结论**：常见关注费用、可靠性、可扩展性、可升级性、易管理性、可维护性和标准化。
> **经典题型怎么做 / 题干怎么认**：预算/TCO → 费用；少故障 → 可靠性；用户/站点增长 → 可扩展；好定位好修复 → 可维护；统一配置监控 → 易管理。
> **易错点 / 考试重点**：P3，网络章只做识别；MTBF/MTTR 与可用性计算不要在这里重复重学，后续放到可靠性/质量属性主线统一掌握。

## 为什么快还不够

一个网络即使带宽很高，如果经常故障、无法扩容、难以监控维护或成本无法承受，也不是好的工程方案。

| 指标 | 人话 |
| --- | --- |
| 费用 | 建设和长期运行成本是否可承受 |
| 可靠性 | 是否能较长时间稳定工作 |
| 可扩展性 | 用户、站点、带宽增长后能否扩容 |
| 可升级性 | 技术演进时能否平滑升级 |
| 易管理性 | 配置、监控、告警是否方便统一管理 |
| 可维护性 | 故障是否容易定位、修复和恢复 |
| 标准化 | 是否方便与其他标准系统互联 |

## 和后续质量属性的关系

这里站在“网络建设”角度认识这些词即可。可靠性、可用性、MTBF/MTTR 等会在后续系统质量属性和软件可靠性章节中成为更完整的主问题，避免在网络章重复背一套。

如果网络题单独给出 MTBF 和 MTTR 要求计算可用性，再调用后续统一掌握的方法即可。

## 一句话总结

**网络好不好不只看速度，还要看建不建得起、稳不稳定、扩不扩得开、坏了好不好修。**
