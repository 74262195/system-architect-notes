# 端口与进程通信：数据到达主机后怎样交给正确程序

## 先定位：IP 只负责找到主机

一台服务器可以同时运行 Web、DNS、数据库和 SSH 服务。IP 地址把分组送到目标主机，但主机还要知道：

> **这份数据应该交给哪个通信端点。**

TCP 和 UDP 使用 **16 位端口号**标识主机内的通信端点。端口属于传输层概念，不是网卡上的物理插孔。

## IP、端口和协议分别负责什么

| 标识 | 回答的问题 |
| --- | --- |
| IP 地址 | 数据送到哪台主机 |
| TCP 或 UDP | 交给哪一种传输协议处理 |
| 端口号 | 在该协议内交给哪个通信端点 |

例如目标是 203.0.113.10 的 TCP 443 端口，表示送到这台主机后，由 TCP 交给监听 443 的端点。

同一台主机可以同时有 TCP 53 和 UDP 53，因为传输协议不同；不同主机也都可以使用 443，因为端口号不是全网唯一编号。

## Socket 是什么

**Socket（套接字）**是应用使用网络通信能力的操作系统接口和通信端点抽象。应用创建 socket、绑定本地地址和端口，服务器再监听连接或接收数据。

不要把 socket 简化成“端口的英文名”：

- 端口只是标识通信端点的一个数字；
- socket 还包含协议、地址、状态和收发缓冲等上下文。

## 一条 TCP 连接怎样被区分

一条 TCP 连接通常可用以下 5 项区分：

| 项目 | 示例 |
| --- | --- |
| 传输协议 | TCP |
| 源 IP | 198.51.100.20 |
| 源端口 | 53000 |
| 目的 IP | 203.0.113.10 |
| 目的端口 | 443 |

因此许多客户端都能同时访问同一服务器的 443：它们的源 IP 或临时源端口不同，连接仍可区分。

## 端口范围怎么认

| 范围 | 常见称呼 | 用途直觉 |
| --- | --- | --- |
| 0～1023 | 熟知端口 | HTTP 80、HTTPS 443、DNS 53 等约定服务 |
| 1024～49151 | 注册端口 | 由应用或厂商登记使用 |
| 49152～65535 | 动态/私有端口 | 常作为客户端临时源端口 |

具体系统的临时端口范围可以配置，考试按标准分类识别即可。

## 易错点

- 端口号能修改，不能仅凭端口绝对断定应用协议；
- 服务器的“监听 socket”和连接建立后的“已连接 socket”不是同一个状态；
- UDP 没有 TCP 连接，但仍用 IP、协议和端口完成复用与分用。

## 一句话记住

> **IP 找主机，协议选 TCP/UDP，端口找通信端点；socket 是应用实际使用的网络通信接口与端点抽象。**
