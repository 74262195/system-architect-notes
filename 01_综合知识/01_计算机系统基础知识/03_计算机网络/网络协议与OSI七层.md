# 网络协议与 OSI 七层：网络通信的七道工序

> [!important] 一句话结论
> 上午题常考“协议/设备属于哪一层”、七层顺序和封装过程；先记住“物链网传会表应”，再用数据单元和典型协议定位。

## 痛点：为什么网络要分层

两台电脑要通信，难点不只是把电信号送过去：应用要表达业务，数据要可靠到达，路上要经过多个网络，还要解决不同厂商网卡和线路的差异。如果所有功能写在一个巨大协议里，任何一处升级都会牵动全局。

分层就是把“寄快递”拆成几道相对独立的工序：应用准备内容，传输层负责端到端交付，网络层负责跨网络找路，链路层负责一跳一跳地装帧，物理层负责真正发信号。某一层更换技术，只要上下层接口不变，其他层就不必重写。

这篇真正要回答 4 个问题：

1. 七层分别负责什么？
2. 同一份数据往下走时，每层具体加了什么？
3. MAC、IP、端口分别在解决哪一级“送给谁”？
4. OSI 和 TCP/IP 为什么不是同一个模型？

## 定义：OSI 是网络的分工表

OSI（Open Systems Interconnection）是 ISO 提出的七层参考模型。它不是一套必须照着部署的具体协议，而是帮助人们划分网络功能、描述协议位置和排查故障的共同语言。

可以把每一层想成快递链条中的一个岗位：上层提出服务需求，下层提供运输能力；发送端从上到下逐层封装，接收端从下到上逐层解封装。

## 七层怎么认：从“物”一路到“应”

| 层次 | 主要任务 | 典型协议或技术 | 数据单元/识别线索 |
| --- | --- | --- | --- |
| 应用层 | 为用户应用提供网络服务 | HTTP、FTP、DNS、SMTP | 报文；网页、邮件、域名 |
| 表示层 | 处理格式、编码、压缩、加密 | JPEG、ASCII；TLS 常被联系到此层 | 数据格式；编码、加密、压缩 |
| 会话层 | 建立、管理、终止会话 | RPC、NetBIOS 等 | 会话；对话管理、断点恢复 |
| 传输层 | 端到端传输、可靠性、流量控制、复用 | TCP、UDP | 段/用户数据报；端口 |
| 网络层 | 逻辑寻址、路由和分组转发 | IP、ICMP、路由协议 | 包/分组；IP 地址、路由器 |
| 数据链路层 | 成帧、MAC 寻址、差错检测、介质访问 | Ethernet、802.11、PPP | 帧；MAC 地址、交换机 |
| 物理层 | 在介质上传输原始比特 | 双绞线、光纤、无线电信号 | 比特；接口、电平、速率 |

从上到下记作“应表会传网链物”；从下到上记作“物链网传会表应”。软考更常用后一个顺序。

这里先有了“岗位”，还要知道一份数据如何经过这些岗位，才不会把“层次”背成孤立的名词。

## 核心机制：封装、传输与解封装

发送端的应用数据向下交给每一层。每层通常会在上层数据外面增加自己的首部，形成新的数据单元：传输层增加 TCP/UDP 首部，网络层增加 IP 首部，链路层再增加帧首部和尾部。

```mermaid
flowchart LR
  A([应用数据]) --> B([TCP/UDP 段<br/>加端口])
  B --> C([IP 分组<br/>加 IP])
  C --> D([链路帧<br/>加 MAC/FCS])
  D --> E([比特信号])
```

接收端做相反动作：**比特 → 帧 → IP 分组 → TCP/UDP 数据 → 应用数据**，逐层检查并去掉本层控制信息。

网络层的 IP 地址通常用于端到端的逻辑寻址；链路层的 MAC 地址只负责当前这一跳。报文经过路由器时，链路层帧会被拆掉并重新封装，IP 分组通常继续向前转发。

### MAC、IP、端口：三个“送给谁”不要混

假设浏览器访问远端 Web 服务：

| 标识 | 它回答的问题 | 作用范围 |
| --- | --- | --- |
| **MAC 地址** | 当前这一跳把帧交给哪块网卡/下一跳？ | 当前链路 |
| **IP 地址** | 整个跨网通信最终去哪个主机/网络？ | 端到端逻辑寻址 |
| **端口号** | 到达主机后交给哪个进程/服务？ | 主机内的传输层复用 |

> **MAC 找这一跳，IP 找目标主机，端口找目标进程。**

经过路由器时，通常会重新生成下一跳所需的二层 MAC 头；源/目的 IP 通常保持端到端语义（NAT 等场景另论），而端口用于把数据交给正确应用。

## 易混对比：OSI 与 TCP/IP

| 对比项 | OSI 参考模型 | TCP/IP 模型 |
| --- | --- | --- |
| 层数 | 七层 | 常见教材表述为四层或五层 |
| 定位 | 理论参考模型、分层更细 | 互联网实际协议体系 |
| 表示层、会话层 | 单独列出 | 通常并入应用层 |
| 典型协议 | 不等于具体协议集合 | IP、TCP、UDP、HTTP 等 |
| 考试关键词 | “七层模型”“ISO” | “互联网协议体系”“实际使用” |

**核心区分**：OSI 是“怎么分工”的参考框架，TCP/IP 是“互联网实际使用的协议家族”；不要把两者当成同一个模型。

## 这个知识与考试的关系

- 看到“MAC、帧、交换机、CSMA/CD”，优先定位数据链路层。
- 看到“IP、路由、分组、TTL”，优先定位网络层。
- 看到“端口、可靠传输、三次握手、滑动窗口”，优先定位传输层。
- 看到“HTTP、DNS、FTP、SMTP”，优先定位应用层。
- 看到“光纤、双绞线、接口、电平、比特流”，优先定位物理层。
- 陷阱是把交换机和路由器混为一谈：二层交换机主要依据 MAC 转发，路由器依据 IP 做跨网络转发。

## 记忆口诀

**物链网传会表应，越往上越像应用，越往下越接近线路。**
