# 网络协议与 OSI 七层：一份数据怎样经过七层分工

## 先定位：OSI 是参考模型，不是一个具体协议

网络通信同时要处理业务格式、端到端传输、跨网寻址、局部成帧和物理信号。OSI（Open Systems Interconnection）把这些功能分成七层，方便描述职责、替换技术和排查问题。

它是**功能分层参考模型**，不是现实网络必须逐层部署的单一协议。互联网实际更常按 TCP/IP 协议体系工作。

## 七层分别解决什么

| 层次 | 主要任务 | 典型识别词 |
| --- | --- | --- |
| 应用层 | 为应用提供网络服务 | HTTP、DNS、FTP、SMTP |
| 表示层 | 数据格式转换、编码、压缩、加密表示 | 格式、编码、压缩 |
| 会话层 | 建立、管理和恢复对话 | 会话、检查点、对话控制 |
| 传输层 | 端到端进程通信、可靠性和流量控制 | TCP、UDP、端口、段 |
| 网络层 | 逻辑寻址、路由与分组转发 | IP、路由器、分组 |
| 数据链路层 | 成帧、MAC 寻址、差错检测、介质访问 | 以太网、帧、交换机 |
| 物理层 | 在介质上传输比特信号 | 电平、接口、光纤、比特 |

从下到上可记“物、链、网、传、会、表、应”，但口诀只负责顺序，不能替代每层职责。

> [!warning] TLS 不要机械塞进表示层
> “加密”是表示层的功能描述之一，但现实中的 TLS 位于应用协议与传输服务之间，不能因为它提供加密就断言“TLS 就是 OSI 表示层协议”。考试若要求协议分层，以题目采用的模型和教材口径判断。

## 发送端如何封装

应用数据向下交付时，各层加入完成本层职责所需的控制信息：

~~~mermaid
flowchart LR
    A["应用数据"] --> B["TCP/UDP 段<br/>端口"]
    B --> C["IP 分组<br/>IP 地址"]
    C --> D["链路帧<br/>MAC/FCS"]
    D --> E["比特信号"]
~~~

接收端按相反方向解封装：从比特恢复帧，检查并取出 IP 分组，再交给 TCP/UDP 和目标应用。

路由器每经过一跳，通常会拆除当前链路的帧头，再为下一条链路重新封装；IP 分组保持端到端寻址语义，但 TTL 等字段会变化，NAT 等场景另论。

## MAC、IP、端口解决的不是同一层地址

| 标识 | 回答的问题 | 作用范围 |
| --- | --- | --- |
| MAC 地址 | 当前链路把帧交给哪个接口或下一跳 | 一跳 |
| IP 地址 | 跨网络最终送到哪个主机/网络 | 端到端逻辑寻址 |
| 端口号 | 到达主机后交给哪个通信端点 | 主机内传输层 |

> **MAC 找下一跳，IP 找目标主机，端口找通信端点。**

## OSI 与 TCP/IP 怎么对应

| OSI | TCP/IP 常见四层表示 |
| --- | --- |
| 应用层、表示层、会话层 | 应用层 |
| 传输层 | 传输层 |
| 网络层 | 网际层 |
| 数据链路层、物理层 | 网络接口层 |

TCP/IP 也常被教材画成五层模型，把物理层和链路层分开。题目说“四层”或“五层”时先识别采用的口径，不要认为其中一个必然错误。

## 考试怎么认

- 比特、电平、接口 → 物理层；
- 帧、MAC、交换机 → 数据链路层；
- IP、路由、TTL → 网络层；
- TCP/UDP、端口、窗口 → 传输层；
- HTTP、DNS、SMTP → 应用层。

## 一句话记住

> **分层把复杂通信拆成职责；发送端逐层封装，接收端逐层解封装，MAC、IP、端口分别负责一跳、主机和通信端点。**
