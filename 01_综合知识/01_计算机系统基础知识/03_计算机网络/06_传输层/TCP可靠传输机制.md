# TCP 可靠传输：IP 会丢包，TCP 为什么还能交付有序字节流

> [!summary] 快速复习卡片
> **作用/定位**：解释 TCP 怎样在底层可能丢包、乱序的情况下，向应用提供可靠、有序字节流。
> **核心结论**：序号定位字节位置，校验和发现损坏，ACK 确认连续收到的数据，超时/重复 ACK 暴露丢失，重传补齐缺口，滑动窗口提高效率。
> **经典题型怎么做 / 题干怎么认**：`ACK=N` → “下一字节期望 N”，也就是 N 之前连续数据已确认；中间缺一段却收到后续数据 → 确认号通常停在缺口处，等待重传补齐。
> **易错点 / 考试重点**：TCP 序号按**字节**编号，不是“第几个包”；校验和只能检测差错，不能单独完成可靠传输；SACK 等实现扩展不作为第一轮重点。

## 可靠性是一条闭环

TCP 的可靠不是“网络从不出错”，而是通信两端能发现问题并恢复：

**编号 → 检查 → 确认 → 发现缺口 → 重传 → 按序交付。**

| 机制 | 作用 |
| --- | --- |
| 序号 | 标记字节流位置 |
| 校验和 | 检测传输损坏 |
| ACK | 告诉发送端下一步期望的字节 |
| 重传 | 把丢失数据重新发送 |
| 滑动窗口 | 允许多段数据同时在途，提高效率 |

## 用一个 ACK 看懂累计确认

发送端发送字节 `1001～1500`，接收端连续收到后返回：

`ACK=1501`

它不是说“1501 已经收到”，而是：

> **1001～1500 已连续收到，下一步请从 1501 开始。**

如果中间一段丢失，而后面的数据先到，经典累计确认模型会继续报告缺口起点。发送端可能因超时或多个重复 ACK 触发重传。

## 滑动窗口解决什么

如果每发一段都停下来等 ACK，往返时延稍大时链路会大量空闲。滑动窗口允许发送方在许可范围内保留多份未确认数据；ACK 返回后，窗口向前移动，新的数据获得发送资格。

> **窗口主要提高效率；序号、ACK 和重传保证可靠。**

## 一句话总结

**序号定位，ACK 推进，丢了重传，窗口让多份数据可以同时在路上。**
