# 端口：IP 找到主机后，数据怎样交给正确应用

> [!summary] 快速复习卡片
> **作用/定位**：承接 TCP/UDP，解释同一台主机上多个网络程序怎样被区分。
> **核心结论**：端口号是传输层的逻辑标识，不是物理插孔；IP 找主机，TCP/UDP 端口继续定位主机上的具体网络服务/通信端点。
> **经典题型怎么做 / 题干怎么认**：DNS 53、HTTP 80、HTTPS 443、SMTP 25 等题目，本质是在考“应用协议 ↔ 默认端口”的映射。
> **易错点 / 考试重点**：TCP 53 和 UDP 53 属于不同传输协议下的端口；默认端口是约定，服务实际可以改到其他端口。

## 先直接回答：为什么有 IP 和 TCP/UDP 还不够

上一站 [[TCP与UDP对比]] 已经知道：TCP 和 UDP 决定应用使用哪一种传输服务。

但一台服务器可以同时运行：

- Web 服务；
- DNS 服务；
- 邮件服务；
- SSH 远程登录服务。

IP 地址只能告诉网络“**是哪台主机**”，却不能告诉操作系统“**交给这台主机上的哪一个网络程序**”。

所以传输层还要使用**端口号**区分不同服务/通信端点。

可以压成三层定位：

| 标识 | 回答的问题 |
| --- | --- |
| IP 地址 | 数据要到哪台主机 |
| TCP / UDP | 使用哪种传输层服务 |
| 端口号 | 到主机后交给哪个网络服务/通信端点 |

例如 `203.0.113.10:443/TCP`：

- `203.0.113.10` 找到主机；
- TCP 说明使用 TCP 传输；
- 443 把数据交给这台主机上监听该端口的服务。

## 端口号学到哪里

TCP 和 UDP 都使用 16 位端口号空间，数值范围 0～65535。

0～1023 常称熟知端口，但本章不背完整分类表。真正高价值的是**常用应用协议的默认端口映射**，统一放到下一站。

还要注意：

> **“443 默认用于 HTTPS”是约定，不代表 443 在任何机器上都一定运行 HTTPS，也不代表 HTTPS 永远不能改端口。**

## 为什么下一站是应用层协议

现在网络已经能把数据：

**送到目标主机 → 选择 TCP/UDP → 交给具体端口。**

下一步就自然来到最靠近用户业务的一层：

> 浏览网页、解析域名、自动分配地址、传文件、发邮件分别使用什么应用协议？

## 一句话总结

**IP 找主机，TCP/UDP 决定传输方式，端口再找主机上的具体服务。**
