# TCP 与 UDP：传输层为什么提供两种服务风格

> [!summary] 快速复习卡片
> **作用/定位**：网络层把数据送到目标主机后，传输层再决定应用需要哪一种端到端传输服务。
> **核心结论**：TCP 面向连接，提供可靠、有序的字节流；UDP 无连接，以数据报为单位发送，协议本身不提供 TCP 同等级别的可靠、有序保证。
> **经典题型怎么做 / 题干怎么认**：可靠、按序、连接、字节流 → TCP；无连接、数据报、控制机制简单 → UDP。
> **易错点 / 考试重点**：“UDP 更快”不是定义；TCP 不保留应用消息边界，UDP 保留数据报边界；某应用常用 TCP/UDP 不等于永远只能使用它。

## 先直接回答：为什么不只设计一种传输协议

上一站 [[IPv6与IPv4过渡]] 把网络层问题收口了：无论 IPv4 还是 IPv6，目标都是把网络层数据送到目标主机。

但是不同应用对“怎样送”要求不一样。

例如：

- 文件传输更关心**内容完整、顺序正确**；
- 实时音视频或简单查询有时更关心**控制开销小、应用自己决定怎么处理丢失或时效**。

如果所有应用都强制使用同样复杂的可靠控制，灵活性会变差；如果所有应用都只提供最简单的数据报，又会让需要可靠性的应用自己重复造机制。

所以传输层提供两种典型服务风格：

> **TCP 偏“帮应用把可靠、有序这些事做好”；UDP 偏“提供更简单的数据报传输，更多控制交给应用自己决定”。**

## 核心对比

| 对比项 | TCP | UDP |
| --- | --- | --- |
| 连接 | 面向连接 | 无连接 |
| 可靠性 | 提供可靠、有序传输 | 尽力而为，不保证可靠有序 |
| 数据形式 | 字节流 | 数据报 |
| 消息边界 | 不保留应用写入边界 | 保留一个个数据报边界 |
| 协议控制 | 确认、重传、流量控制等机制较多 | 控制机制较简单 |

### “字节流”和“数据报”怎么理解

- **TCP 字节流**：应用连续写入的数据在传输层被看成一串连续字节，不保证接收端按你每次 `write` 的边界原样分块得到；
- **UDP 数据报**：每次发送形成一个独立数据报，接收时仍保留这个数据报边界。

考试通常只要求认这个服务差异，不进入 socket 编程。

## 应用场景怎么判断

- 文件、需要完整有序到达的业务 → 优先想到 TCP；
- 简单查询、实时业务等希望传输层控制更轻 → 常见 UDP；
- DNS 常见 UDP，也能在特定场景使用 TCP，所以不要把“应用名 = 唯一传输协议”背死。

当前边界只到服务差异，不再单独扩展三次握手、四次挥手、窗口和拥塞算法。

## 为什么下一站是“端口”

现在知道 TCP/UDP 决定“**用什么传输服务**”，但同一台目标主机上可能同时运行多个网络程序。

IP 只找到主机，TCP/UDP 还需要一个标识告诉系统：

> **这份数据最终应该交给主机上的哪一个服务/通信端点？**

这个标识就是端口号。

## 一句话总结

**TCP = 连接 + 可靠有序字节流；UDP = 无连接 + 数据报 + 较简单的传输层控制。**
