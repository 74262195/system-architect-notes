# TCP 与 UDP：传输层为什么提供两种服务风格

> [!summary] 快速复习卡片
> **作用/定位**：IP 把数据送到目标主机后，传输层还要决定应用需要哪种端到端传输服务。
> **核心结论**：TCP 面向连接，提供可靠、有序的字节流；UDP 无连接，以数据报为单位发送，协议本身不提供 TCP 同等级别的可靠、有序保证。
> **经典题型怎么做 / 题干怎么认**：可靠、按序、连接、字节流 → TCP；无连接、数据报、协议开销小 → UDP。
> **易错点 / 考试重点**：“UDP 更快”不是定义；TCP 不保留应用写入消息边界，UDP 保留一个个数据报边界；某应用常用 TCP/UDP 不等于只能使用它。

## 核心对比

| 对比项 | TCP | UDP |
| --- | --- | --- |
| 连接 | 面向连接 | 无连接 |
| 可靠性 | 提供可靠、有序传输 | 尽力而为，不保证可靠有序 |
| 数据形式 | 字节流 | 数据报 |
| 消息边界 | 不保留应用写入边界 | 保留数据报边界 |
| 协议控制 | 确认、重传、流量控制等机制较多 | 协议头和控制机制较简单 |

## 怎么选

- 文件传输、要求完整有序到达 → 优先想到 TCP；
- 简单查询、实时业务等希望减少传输层额外控制 → 常见 UDP；
- DNS 常见 UDP，也可在特定情况下使用 TCP，因此不要把“应用名 = 唯一传输协议”背死。

当前考试边界只要求理解服务差异，不再单独扩展握手、挥手、窗口算法。

## 一句话总结

**TCP = 连接 + 可靠有序字节流；UDP = 无连接 + 数据报 + 轻量控制。**
