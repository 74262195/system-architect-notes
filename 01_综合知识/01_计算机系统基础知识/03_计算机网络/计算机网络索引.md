## 一、先建立整章坐标：一份数据到底经历什么

第一次学网络，先不要把它看成几十个互不相关的协议。抓住一份业务数据从发送端到接收端的主链：

**应用要通信 → TCP/UDP 用端口找到进程 → IP 决定跨网络去哪里 → ARP 找到当前链路要交付的 MAC → 交换机按 MAC 转发帧 → 以太网/WLAN 把比特送过链路。**

这条链给后面所有知识一个位置：

- **协议与分层**：先回答“每一类问题应该由谁负责”；
- **数据通信**：回答“比特怎样真正经过信道”；
- **二层**：回答“同一链路/局域网里帧怎样送过去”；
- **IP 与路由**：回答“目标不在本地时怎样跨网络”；
- **传输层**：回答“到了目标主机后交给哪个进程”；
- **应用层**：回答“具体业务协议怎样使用网络”；
- **无线/组网工程**：最后把协议知识落到真实网络建设。

## C. 然后进入局域网：一帧怎样在二层交付

## D. 再跨出局域网：IP、ARP 和路由怎样配合

[[IPv4地址结构与特殊地址]]
→ [[子网掩码与CIDR]]
→ [[子网划分与地址范围计算]]

这一段必须形成一个稳定判断：

- **IP**：最终要去哪个主机/网络；
- **路由表**：下一跳往哪里走；
- **ARP**：当前 IPv4 链路这一跳对应哪个 MAC；
- **MAC**：这一跳的链路帧交给谁。

## E. 到了目标主机：怎样找到具体应用

[[TCP与UDP对比]]
→ [[端口与进程通信]]

→ [[FTP文件传输]]
→ [[电子邮件协议]]

这一段回答：

**传输服务选 TCP 还是 UDP → 到达主机后交给哪个进程 → 常见应用协议分别做什么 → 主机怎样获得网络参数 → 域名怎样变成 IP → Web/文件/邮件业务怎样落地。**

其中配置顺序重点记：**DHCP 先让主机获得 IP、掩码、网关、DNS 等参数；DNS 再负责域名 → IP。**

# 七、P3 旁支与减负边界

第一次学习时间紧时，下面这些**不改变主线**：

- [[非性能性指标]]：最低识别；
- [[RARP反向地址解析]]：历史识别，MAC → IP；
- [[5G关键通信技术最低识别]]：OFDM、Massive MIMO、毫米波等只认名称与大致作用；
- SONET/SDH、DDN、帧中继、ATM：只在 [[网络类型与广域网技术]] 做旧 WAN 技术最低识别。

明确不扩展：

- CRC：本章只在 [[以太网技术]] 的 FCS 建联系；算法回校验码主线；
- NAT：当前不建立独立主线卡；
- TCP：不把三次握手、四次挥手、TIME_WAIT、拥塞算法扩成当前独立复习任务；
- OSPF/BGP：不进入 LSA、状态机、路径属性和厂商配置；
- 5G：不背完整网元、帧结构和射频工程参数。

如果拿不准某项该学到什么程度，回到 [[计算机网络-知识点边界]]。
