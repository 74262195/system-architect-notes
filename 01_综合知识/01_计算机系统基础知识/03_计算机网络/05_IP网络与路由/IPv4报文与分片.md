# IPv4 报文与分片：路选好了，下一条链路却装不下怎么办

> [!summary] 快速复习卡片
> **作用/定位**：路由表决定“往哪走”，本卡只看 IPv4 数据报真正转发时会遇到的两个约束：**太大**和**绕圈**。
> **太大**：数据报超过下一跳 MTU，允许分片时可拆小；DF=1 时不能分片，只能丢弃并可由 ICMP 反馈。
> **分片题眼**：每片都要有自己的 IP 首部；Fragment Offset 以 **8B** 为单位；MF=0 表示最后一片。
> **TTL**：每经过一次路由转发都会减少，耗尽就丢弃，防止数据报在路由环里无限循环。
> **减负**：不背完整 IPv4 首部位图；会认 MTU、DF/MF、片偏移和 TTL 即可。

## 先看真正的问题：路由器已经知道下一跳，但包可能还是发不出去

上一站 [[自治系统与IGP-BGP]] 已经解决了“路由信息从哪里来”。
假设路由器也已经查好路由表，决定下一跳走接口 A。

现在出现一个新问题：

> **这个 IPv4 数据报有 4000B，而接口 A 所在链路一次最多只能承载 1500B 的 IP 数据报。怎么办？**

这里“链路一次最多能承载多大的网络层数据报”就是 **MTU（最大传输单元）**。

所以路由选对，只代表**方向对了**；还要满足下一条链路的尺寸限制。

## 允许分片时：把一个大数据报拆成几个能继续走的小数据报

IPv4 在允许分片时，可以把大数据报拆成多个分片。

每个分片都要独立经过后续路由器，所以：

- 每片都有自己的 IPv4 首部；
- 同一原始数据报的分片带有共同的 Identification，用来帮助目的端识别它们属于同一份数据；
- **MF** 表示后面是否还有分片；
- **Fragment Offset** 表示本片数据在原始数据中的位置，单位是 **8B**；
- 最终通常由**目的主机**重组，不是每经过一个路由器就拆了再拼。

考试遇到分片计算，只抓一个动作顺序：

1. 先用 `MTU - 本片IP首部长度`，得到一片最多能装多少数据；
2. 非最后一片的数据长度要取 8B 的整数倍；
3. 下一片的片偏移 = 这片数据在原始数据区的起点 ÷ 8；
4. 最后一片 `MF=0`。

> [!example] 最小例子
> MTU 为 1500B，IP 首部为 20B，那么一片最多装 1480B 数据。
> 第二片如果从原始数据区第 1480B 开始，片偏移就是 `1480 ÷ 8 = 185`。

这已经够应付基础分片题，不需要继续背整张 IPv4 首部位图。

## 如果禁止分片：装不下就不能硬塞

IPv4 首部里的 **DF（Don't Fragment）** 用来表示“不要分片”。

因此：

- 数据报不超过 MTU → 正常转发；
- 超过 MTU 且允许分片 → 可以拆小；
- 超过 MTU 且 `DF=1` → 路由器不能擅自切片，只能丢弃，并可通过 ICMP 返回相应错误信息。

这里先记结果即可，下一站专门解释 ICMP 是怎样把这种网络层失败反馈回去的。

## 另一个约束：方向错了，包不能永远绕圈

假设错误路由形成：

`R1 → R2 → R3 → R1 → ...`

即使每条链路都装得下，这个数据报也不能无限转发。

因此 IPv4 首部还有 **TTL（Time To Live）**。学习和做题时把它理解成“还允许经过多少次路由转发”即可：

- 路由器转发时 TTL 减少；
- TTL 耗尽，数据报被丢弃；
- 通常会产生 ICMP Time Exceeded，告诉源主机“包死在半路了”。

所以 TTL 解决的不是可靠传输，而是：

> **路由异常时给数据报设置一个终点，避免无限循环。**

## 一句话收口

**路由表解决“往哪走”；MTU 决定“这一跳装不装得下”；允许时 IPv4 可以分片，DF=1 时不能分；TTL 则防止数据报因为路由环一直转下去。**
