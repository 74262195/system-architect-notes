# IPv4 报文与分片：大报文遇到更小 MTU 怎么办

> [!summary] 快速复习卡片
> **作用/定位**：在已经知道 IP 怎样跨网络选路后，处理分组经过不同链路时的“长度限制”和“环路寿命”问题。
> **核心结论**：同一原始报文的分片标识相同；DF=1 禁止分片；MF=1 表示后面还有分片；片偏移以 **8 字节**为单位；TTL 用于限制分组可继续经过的路由跳数。
> **经典题型怎么做 / 题干怎么认**：先看总长度是否超过 MTU、DF 是否允许 → 每片数据容量先用 MTU 扣 IP 首部 → 非末片数据按 8B 对齐 → 片偏移用“本片数据起点 ÷ 8”。
> **易错点 / 考试重点**：MTU 包含 IP 首部；总长度也包含首部；片偏移不是“第几片”。

## 先直接回答：为什么已经能路由，还会遇到“报文太大”

上一站 [[自治系统与IGP-BGP]] 已经把“怎样找到跨网络路径”讲到考试需要的深度。

但一条端到端路径会经过很多不同链路，而不同链路允许承载的最大网络层报文大小可能不同。这个最大承载限制通常用 **MTU（最大传输单元）**描述。

假设一个 IPv4 数据报有 4000B，但下一段链路的 MTU 只有 1500B：

> **方向虽然找对了，但这么大的报文不能原样通过这条链路。**

在经典 IPv4 机制中，如果允许分片，就可以把它拆成多个较小分片，到最终目的主机再重组。

## 分片只抓四个字段

| 字段 | 人话 |
| --- | --- |
| Identification | 哪些分片来自同一个原始报文 |
| DF | 能不能分片；1 表示禁止 |
| MF | 后面还有没有分片；末片为 0 |
| 片偏移 | 当前片数据在原数据中的起始位置，单位 8B |

另外还有一个稳定字段 **TTL**：每经过路由器通常会减少，减到 0 时分组被丢弃，用来防止路由异常时分组在网络中无限循环。

## 计算例子：4000B 报文经过 1500B MTU

假设 IPv4 首部 20B：

1. 原数据区：`4000 - 20 = 3980B`；
2. 每个最大分片能装的数据：`1500 - 20 = 1480B`；
3. 前两片各装 1480B，最后剩 1020B；
4. 三片数据在原数据中的起点分别为 0、1480、2960；
5. 片偏移分别是 0、185、370，因为偏移单位是 8B；
6. 前两片 MF=1，最后一片 MF=0。

| 分片 | 数据长度 | 总长度 | 片偏移 | MF |
| --- | ---: | ---: | ---: | ---: |
| 1 | 1480B | 1500B | 0 | 1 |
| 2 | 1480B | 1500B | 185 | 1 |
| 3 | 1020B | 1040B | 370 | 0 |

> **先算每片能装多少数据，再算这一片从原数据哪里开始。**

## 为什么下一站是 ICMP

到这里 IP 已经能完成寻址、路由和分片等“尽力转发”工作，但它并不保证一定成功。

如果目标不可达、TTL 减到 0，或者网络层需要反馈某些状态，发送方怎样知道发生了什么？

这就是 ICMP 提供的网络层控制/差错反馈能力。

## 一句话总结

**IPv4 分片是为不同链路 MTU 适配报文大小；算容量先扣首部，算偏移再除 8；TTL 防止分组无限转发。**
