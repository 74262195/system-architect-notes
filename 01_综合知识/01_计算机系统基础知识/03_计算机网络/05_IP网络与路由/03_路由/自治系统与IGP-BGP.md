# 自治系统与 IGP/BGP：路由表里的路，到底是谁告诉路由器的

## 先接上上一站

上一站 [[路由表与最长前缀匹配]] 已经解决了一个问题：

> **数据包到了路由器以后，路由器查路由表，再用最长前缀匹配（LPM）选出该走哪一条。**

但这里马上会冒出一个新问题：

> **路由表里的这些“路”，一开始是从哪里来的？**

有些路由可以直接连接得到，有些可以由管理员手工写成静态路由。

可是 Internet 太大了，不可能让管理员把全世界的路一条条手工写进每台路由器。

所以路由器还需要通过**路由协议**互相交换信息，自动学习“哪些网络可以从哪里到达”。

问题又来了：Internet 上有无数运营商、企业和路由器，难道所有路由器都放在一起，用同一种方式互相学习吗？

**也不行。**

于是才有了这一篇的三个概念：**AS、IGP、BGP**。

---

## 1. 先别背 AS，把 Internet 想成很多个“大院子”

假设有两家运营商：

```text
Internet

┌────────── A 运营商管理的网络 ──────────┐
│                                        │
│   R1 ───── R2 ───── R3                 │
│                       │                │
└───────────────────────│────────────────┘
                        │
                        │ 与外部网络连接
                        │
┌───────────────────────│────────────────┐
│                       │                │
│   R4 ───── R5 ───── R6                 │
│                                        │
└────────── B 运营商管理的网络 ──────────┘
```

A 运营商自己的路由器怎么配置、内部走哪条链路、出口怎么管理，主要由 A 自己决定。

B 运营商也一样。

所以 Internet 并不是“全世界所有路由器由一个人统一管理”，而是由很多个**各自管理自己路由网络的区域**连接起来。

这样的一个路由管理区域，就可以先理解成一个 **自治系统**。

专业名称是：

> **AS（Autonomous System，自治系统）**：由同一管理体系控制、采用协调路由策略的一组网络和路由器。

“自治”说的不是“它和 Internet 隔离了”，而是：

> **这个区域内部的路由怎么管理，主要由它自己决定。**

每个 AS 可以有自己的编号，叫 **ASN（Autonomous System Number）**。

这里先不用研究 ASN 怎么编码，只要知道它相当于 AS 在域间路由中的编号即可。

> [!important]
> **AS 不是一种协议，也不等于一个局域网。**
> 它说的是“谁统一管理这一组网络”。一个 AS 里面可以有很多路由器、很多网段，甚至跨越很大的地理范围。

---

## 2. 一旦把 Internet 分成很多 AS，找路就自然变成两个问题

现在假设：

- 你的数据在 **AS 100**；
- 目标网络在 **AS 200**。

那么找路其实分成了两层：

```text
AS 100                                   AS 200

主机 ── R1 ── R2 ── 出口R3  =====  入口R4 ── R5 ── 目标
       └──── AS 内部怎么走 ────┘       └── AS 内部怎么走 ──┘
                         ↑
                  两个 AS 之间怎么走
```

你可以把它类比成从一个大型园区去另一个大型园区：

1. **先在自己园区里找到出口；**
2. **再决定从这个园区怎样到另一个园区；**
3. **进入对方园区以后，再走对方内部的路。**

因此网络中的路由协议也分出了两种任务：

> **AS 内部找路 → IGP**  
> **AS 之间交换路由 → BGP**

这就是 IGP 和 BGP 最重要的定位。

---

## 3. IGP：解决“自己这个 AS 里面怎么走”

先看 AS 100 内部：

```text
AS 100

        R2
       /  \
主机──R1   R4──出口
       \  /
        R3
```

R1 想到出口 R4，可能经过 R2，也可能经过 R3。

这些路由器需要互相交流内部网络信息，算出 AS 内部应该怎么走。

负责这种工作的协议统称为：

> **IGP（Interior Gateway Protocol，内部网关协议）**

大白话就是：

> **IGP 管“自己家里面的路”。**

常见 IGP 有：

- **OSPF**
- **RIP**
- **IS-IS**

这里有一个很容易弄错的地方：

> **IGP 是一类协议的总称，不是某一个具体协议。**

就像“水果”是一个类别，“苹果、香蕉”才是具体东西。

同样：

```text
IGP
├── OSPF
├── RIP
└── IS-IS
```

所以如果题目问：

> OSPF 属于哪一类路由协议？

答案就是：**IGP**。

---

## 4. BGP：解决“我要去别的 AS，该往哪个方向走”

现在继续往外走。

AS 100 想访问 AS 300，外面可能不止一条路：

```text
                 AS 200
                /      \
AS 100  ───────          ───────  AS 300
                \      /
                 AS 400
```

AS 100 就需要知道：

- 从 AS 200 这边能不能到 AS 300？
- 从 AS 400 这边能不能到？
- 自己最终愿意选择哪条外部路径？

这就是 **BGP** 主要解决的问题。

> **BGP（Border Gateway Protocol，边界网关协议）**：主要用于不同自治系统之间交换网络可达信息和路径信息。

大白话就是：

> **IGP 管自己家里的路，BGP 管不同“家”之间的路。**

例如 AS 200 可以告诉 AS 100：

> “要去某个目标网段，可以经过我。”

AS 100 收到多个这样的外部路由以后，再结合 BGP 的属性和自己的路由策略决定采用哪一条。

---

## 5. BGP 为什么不能简单理解成“谁近就走谁”

这是 BGP 和普通“找最短路”思维最容易混淆的地方。

假设去目标 AS 有两条路径：

```text
路径 A：AS100 → AS200 → AS300

路径 B：AS100 → AS400 → AS500 → AS300
```

你可能第一反应是：

> “A 经过的 AS 少，那肯定永远选 A。”

不能这样判断。

因为不同 AS 属于不同组织，选择外部路径时不仅考虑路径本身，还可能考虑自己的**路由策略**。

比如某个运营商可能更愿意把流量交给某个合作网络，而不愿意走另一条路径。

所以现阶段只需要记住：

> **BGP 不是简单的“全球最短路算法”，它会结合路径属性和策略选路。**

BGP 有一个很常见的属性叫 **AS_PATH**，它会记录一条域间路由经过了哪些 AS。

例如：

```text
AS_PATH：200 300 400
```

可以先理解为：

> “去这个目标网络，路上会经过 AS200、AS300、AS400。”

它还可以帮助发现 AS 级别的路由环路：如果一个 AS 发现路径里已经出现了自己的 ASN，就知道这条路又绕回自己了。

## 6. IGP、BGP 和“路由表 + LPM”到底是什么关系

这一段是这篇最重要的连接点。

上一站讲的是：

> **路由表已经在那里了，数据包来了以后，LPM 负责从里面选哪一条。**

这一站讲的是：

> **路由表中的很多动态路由信息，是怎样被路由器学习到的。**

可以把整个过程拆成两阶段：

```text
第一阶段：先学路

IGP / BGP / 静态配置 / 直连网络
              ↓
        形成可用路由信息
              ↓
           路由表

第二阶段：真正来了一个数据包

        数据包的目的 IP
              ↓
           查路由表
              ↓
       最长前缀匹配 LPM
              ↓
      选出应该使用的表项
              ↓
            转发
```

所以不要把它们混成一件事：

> **IGP / BGP 主要回答“路由器怎样学到路”。**  
> **LPM 回答“数据包来了以后，在已有路由表中选哪一条”。**

注意这里说“很多动态路由”是因为路由表里的路并不全来自 IGP/BGP，还可能来自**直连路由、静态路由**等来源。

---

## 7. 把整个过程真正走一遍

现在假设：

```text
主机A
  │
  │        AS 100                         AS 200
  │
  └── R1 ── R2 ── 边界R3  =====  边界R4 ── R5 ── 主机B
       └──── IGP ────┘         BGP        └── IGP ──┘
```

主机 A 要访问 AS 200 中的主机 B。

在数据包真正发送以前，各台路由器已经通过路由协议学习过路由：

**在 AS 100 内部**，IGP 帮助内部路由器知道怎样到达各内部网络以及相关出口。

**AS 100 和 AS 200 之间**，BGP 用来交换外部网络的可达信息，让边界路由器知道哪些目标前缀可以从哪个外部方向到达。

**数据包真正来到 R1、R2、R3 等路由器时**，这些路由器并不是临时再运行一次 IGP/BGP 给这个包“算路”。

它们做的仍然是上一站学过的事情：

> **看目的 IP → 查已有路由信息 → 做最长前缀匹配 → 选表项 → 转发。**

这时你就能把两篇笔记接起来了：

```text
IGP / BGP
   │
   │ 学习、传播路由信息
   ↓
路由表 / 转发表
   │
   │ 数据包到来
   ↓
LPM 选择匹配表项
   │
   ↓
逐跳转发
```

## 8. 几个最容易混淆的地方

### AS 是不是一个公司？

不一定。

一个组织可能管理一个或多个 AS，所以不能死记成“一个公司 = 一个 AS”。

入门阶段把 AS 理解成**一个统一管理路由策略的区域**最合适。

### AS 是不是一个局域网？

不是。

局域网主要描述网络覆盖和二层连接范围；AS 描述的是**路由管理边界**。一个 AS 可以包含很多局域网和很多三层网络。

### IGP 是不是一种协议？

不是。

IGP 是类别名，OSPF、RIP、IS-IS 才是具体协议。

### BGP 是不是只可能出现在两个 AS 之间？

入门和软考基础判断先记：**BGP 主要解决 AS 之间的路由问题。**

真实网络中还有 **iBGP**，会在同一个 AS 内部的 BGP 路由器之间传播 BGP 路由；这并不改变 BGP 作为 Internet 域间路由核心协议的定位。当前阶段不需要展开 iBGP 的机制。

### BGP 是不是选物理距离最短的路线？

不是。

BGP 会结合路径属性和策略选路，不能把它理解成单纯比较地理距离或链路长度。

## 快速复习卡片

> [!summary]
> **AS**：先把 Internet 按“谁统一管理路由”分成一个个自治系统。  
> **IGP**：解决一个 AS **内部**怎么找路；OSPF、RIP、IS-IS 都属于 IGP。  
> **BGP**：主要解决不同 AS **之间**怎么交换外部网络的可达信息、选择域间路径。  
> **LPM**：数据包真正到来后，从已有路由表中选择**最长、最具体的匹配前缀**。  
>
> 最重要的关系：**IGP/BGP 负责“学路”，LPM 负责“用已有路由表给这个包选路”。**

### 考试看到这些词怎么判断

- “自治系统内部路由” → **IGP**
- “OSPF / RIP / IS-IS 属于什么” → **IGP**
- “不同 AS 之间交换路由” → **BGP**
- “记录经过哪些自治系统” → **AS_PATH**
- “BGP 一定选择物理距离最短的路线” → **错误**
- “AS 就是一个局域网” → **错误**
- “数据包到路由器后从多条匹配前缀中选最具体的一条” → **LPM**

## 一句话把这一篇串起来

**Internet 先按路由管理关系分成很多 AS；每个 AS 内部主要用 IGP 学内部路由，不同 AS 之间主要用 BGP 交换外部路由；这些信息进入路由体系后，数据包真正到达路由器时再靠路由表和 LPM 完成逐跳转发。**
