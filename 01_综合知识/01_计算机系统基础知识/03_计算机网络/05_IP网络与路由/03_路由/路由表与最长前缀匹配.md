# 路由表与最长前缀匹配：网关收到分组以后，怎么知道下一步该往哪边走

> [!summary] 快速复习卡片
> **作用/定位**：ARP 已把分组交给默认网关，路由表接着回答“网关应该从哪个出口继续转发”。
> **固定动作**：看目的 IP → 找出所有匹配路由 → 选择**前缀最长**的一条 → 按下一跳或出口继续转发。
> **最长前缀为什么优先**：前缀越长，表示的地址范围越小、越具体。
> **默认路由**：`0.0.0.0/0` 什么都能匹配，但最不具体，所以只在没有更具体路由时兜底。
> **易错点**：路由器不是按源 IP 选择目标路由；“最长”指前缀位数最长，不是路由表文字最长。

## 继续上一站：A 已经把帧交给网关，网关接下来怎么办

上一站 [[ARP地址解析]] 中：

- 主机 A 是 `192.168.10.70/27`；
- 跨网段目标 C 是 `192.168.10.100`；
- A 已经判断 C 不在本地子网。

于是 A：

1. IP 目的地址仍然写目标 C，也就是 `192.168.10.100`；
2. 当前以太网帧的目的 MAC 写默认网关的 MAC；
3. 帧先到路由器 R1。

现在 R1 把二层帧拆开，看到里面 IP 分组的目的地址。

它面临的问题不是“这个帧的 MAC 是谁”了，而是：

> **这个远程 IP 下一步应该从哪个方向继续走？**

这就是路由表存在的原因。

## 路由表可以先理解成一张“目标范围 → 下一步”的地图

假设 R1 的路由表里有：

| 目标网络 | 下一步 |
| --- | --- |
| `192.168.0.0/16` | 交给出口 1 |
| `192.168.10.96/27` | 交给出口 2 |
| `0.0.0.0/0` | 交给默认出口 3 |

每一条并不是在列“一台主机”，而是在说：

> **如果目的 IP 落在这个网络范围里，就优先往这个方向走。**

这正是前面学“IP 地址里为什么有网络前缀”的实际用途。

## 为什么一个目的 IP 会同时匹配很多条

现在 R1 看到的目的 IP 仍然是：

`192.168.10.100`

它同时属于：

- `192.168.0.0/16`；
- `192.168.10.96/27`；
- `0.0.0.0/0`。

三个范围都“包含”它。

那到底选谁？

如果随便选，路由器的行为就不稳定。

所以有一条最核心的规则：

> **选最长前缀匹配。**

这里 `/27` 比 `/16` 长，因此 `192.168.10.96/27` 描述得更具体，R1 选择出口 2。

你可以把它想成地址导航：

- `/16`：只知道目标在一个较大的区域；
- `/27`：已经缩小到 `.96～.127` 这个具体地址块。

多个地址范围都包含目标时，当然优先用**最具体的那条指路信息**。

## `/0` 为什么什么都能匹配，却反而最后用

`0.0.0.0/0` 的前缀长度是 0。

它没有要求任何前缀位必须相同，所以所有 IPv4 地址都能落进去。

这使它非常适合作为：

> **默认路由 / 最后兜底。**

在当前例子中，虽然默认路由也能匹配 `192.168.10.100`，但已经有更具体的 `/27`，所以不会选择 `/0`。只有更具体的路由都不匹配时，默认路由才负责兜底。

所以不要因为 `/0` “什么都匹配”就最先选它。最长前缀规则恰好保证了它通常最后才生效。

## 查到下一跳以后，路由器还要重新做二层交付

路由表决定的是：

> **下一步逻辑上往哪里走。**

但真正从某个以太网接口发出去时，仍然要重新封装新的链路层帧。

所以跨网络的一跳可以串成：

```mermaid
flowchart LR
    A[收到IP分组] --> B[查看目的IP]
    B --> C[查路由表<br/>最长前缀匹配]
    C --> D[确定下一跳/出口]
    D --> E[重新封装当前链路帧]
```

这也再次说明：

- IP 负责跨网络方向；
- MAC 负责每一跳真正落地的链路交付。

## 路由表里的路由从哪里来

现在先只认三种来源：

- **直连路由**：这个网络直接连接在路由器接口上；
- **静态路由**：管理员手工告诉路由器；
- **动态路由**：路由器通过路由协议自动学习。

这一篇只讲“表怎么用”。

下一篇才回答：为什么互联网规模这么大，动态路由还要按管理边界分成内部和外部两类。

## 这一篇解决了什么，还剩什么没解决

现在 R1 已经会：

> 看目的 IP → 找匹配前缀 → 选最长前缀 → 确定下一跳。

但路由表不是凭空出现的。

一个公司内部可以自己维护路由，可整个 Internet 横跨运营商、企业、学校，各自不属于同一个管理员。

新的问题是：

> **这么多不同组织，动态路由信息应该怎么分范围交换？**

这就是下一站 [[自治系统与IGP-BGP]]。

## 一句话总结

**路由表是“目标网络范围 → 下一步”的地图；一个目的 IP 同时匹配多条时，选最长前缀，也就是最具体的那一条；`/0` 只做兜底。**
