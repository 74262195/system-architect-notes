# 路由表与最长前缀匹配：网关收到分组以后，怎么知道下一步该往哪边走

> [!summary] 快速复习卡片
> - **作用/定位**：ARP 已把分组交给默认网关，路由/转发表接着回答“这个目的 IP 下一跳往哪里走”。
> - **转发时固定动作**：看目的 IP → 在**已经生效、可用于转发**的路由中找匹配前缀 → 选择前缀最长的一条 → 得到下一跳/出口。
> - **最长前缀为什么优先**：前缀越长，覆盖的地址范围越小、越具体。
> - **默认路由**：`0.0.0.0/0` 匹配所有 IPv4 地址，但最不具体，只在没有更具体前缀时兜底。
> - **重要边界**：最长前缀匹配（LPM）解决的是**转发阶段“不同前缀谁更具体”**；同一前缀若从多个路由来源学到，先由控制平面的协议偏好/度量等规则决定哪些路由成为有效路由，这不是 LPM 的下一步比较。
> - **易错点**：不是按源 IP 选路；“最长”是网络前缀位数最长，不是字符串最长、metric 最大/最小。

## 唯一主问题

> **路由器已经收到一个目的 IP 分组时，怎样从已有的有效路由中确定下一跳，而且为什么“最长前缀匹配”不能和动态路由协议自己的选路规则混为一谈？**

## 继续上一站：A 已经把帧交给网关，网关接下来怎么办

上一站 [[ARP地址解析]] 中，主机发现目标不在本地网段，于是：

1. IP 目的地址仍是最终目标；
2. 当前以太网帧的目的 MAC 写默认网关 MAC；
3. 帧到达路由器。

路由器拆掉当前二层头后，面对的是 IP 目的地址。此时它要回答：

> **这个目的 IP 下一跳从哪个接口、往哪个下一跳继续？**

这就是路由表/转发表的作用。

## 路由表先理解成“目标网络范围 → 下一步”的地图

假设 R1 已经有这些**生效路由**：

| 目标网络 | 下一步 |
| --- | --- |
| `192.168.0.0/16` | 出口 1 |
| `192.168.10.96/27` | 出口 2 |
| `0.0.0.0/0` | 默认出口 3 |

目的地址是 `192.168.10.100`。

它同时落在 `/16`、`/27` 和 `/0` 三个范围中。转发不能随便挑，而要选：

> **最长前缀匹配（Longest Prefix Match, LPM）：所有匹配项中，前缀位数最长者优先。**

所以这里选 `/27`。直觉上：

- `/16` 描述一个更大的区域；
- `/27` 已把地址缩到更小、更具体的范围；
- `/0` 什么都能覆盖，因此只是兜底。

## 最关键的第二轮边界：LPM 不是“所有选路规则的总称”

这里容易把两件事混起来。

### 场景 A：不同前缀都能匹配目的 IP

比如：

- `10.0.0.0/8`
- `10.1.0.0/16`
- `10.1.2.0/24`

目的地址 `10.1.2.9` 同时匹配三条。

这是**转发阶段**的问题，直接选 `/24`。

### 场景 B：同一个前缀从多个来源学到

例如对同一个 `10.1.2.0/24`，路由器可能同时得到几种不同说法：

- 静态路由说：去 `10.1.2.0/24` 走 R2；
- OSPF 说：去 `10.1.2.0/24` 走 R3；
- BGP 说：去 `10.1.2.0/24` 走 R4。

三条路由的目标网段完全一样，都是 `/24`，所以这里 **LPM 根本分不出谁更优先**。

大白话理解整个过程：

1. **先收集方案**：路由器先知道“去这个网段有哪几种走法”。
2. **再选一个方案**：按照路由来源的优先级、协议自己的规则等，选出真正要采用的那条。
3. **把结果放进实际转发用的表**：以后转发数据包时直接查这个结果，不需要每来一个包都重新让 OSPF、BGP 比一次。
4. **真的有数据包来了，再做 LPM**：根据这个数据包的目的 IP，在已经选好的有效路由中，找所有能匹配的网络，再选前缀最长的那条。

最简单地记：

> **前 3 步是在“建表”，第 4 步是在“用表”。**
>
> **静态路由、OSPF、BGP 谁被采用，是建表时解决；LPM 是数据包真正到来后，查表转发时解决。**

```mermaid
flowchart LR
    A[收集多种路由方案] --> B[选出有效路由]
    B --> C[放进转发表]
    C --> D[真实数据包到来]
    D --> E[按目的IP做LPM]
    E --> F[得到下一跳/出口]
```

所以要分清：

> **前面先决定“表里放什么”；真正转发数据包时，LPM 再决定“这个目的 IP 用表里的哪一条”。**

不同厂商对“管理距离/路由优先级”的名称和数值可能不同，因此不要把某个厂商的数值顺序背成 IP 层通用协议标准。

## 查到下一跳以后，为什么还要重新做二层交付

因为**路由表只告诉路由器“这个 IP 包下一步该交给谁”**，但要真的从当前网口发出去，还得用当前这段链路的二层帧来发送。

假设路径是 A → R1 → R2 → B。

A 把数据交给 R1 时，这一段以太网帧的目的 MAC 是 **R1 的 MAC**。R1 收到后，这个二层帧的任务就结束了。R1 去掉旧的二层头，查看里面的目的 IP，查路由表发现下一跳是 R2。

这时 R1 **不能继续使用原来的二层帧**，因为原来的目的 MAC 是 R1 自己，不是 R2。于是 R1 必须为 **R1 → R2 这一段链路**重新封装一个新的二层帧：新的目的 MAC 改成 R2 的 MAC；如果还不知道 R2 的 MAC，就先通过 ARP 查询。

最简单地记：

> **路由查表负责决定“下一站是谁”；二层封装负责把 IP 包真正送过“当前这一段链路”。**
>
> **每经过一个路由器，上一段的二层头就结束使命，下一段要重新封装新的二层头。**
>
> **IP 目的地址通常还是最终目标 B（不讨论 NAT）；MAC 目的地址会随着每一跳改成当前下一跳的 MAC。**

## 路由从哪里来

当前只需认三类：

- **直连路由**：接口所在网络；
- **静态路由**：管理员配置；
- **动态路由**：由路由协议学习。

本卡只解决“有效路由如何被数据平面使用”。动态路由为什么还要区分 AS 内部与 AS 之间，放到下一站。

## 考试怎么识别

看到题干：

- “多个网络前缀都包含目的地址” → 想 **最长前缀匹配**；
- “`0.0.0.0/0`” → 想 **默认兜底**；
- “同一目标前缀由不同路由协议学习” → 这是**控制平面候选路由选择**，不要机械回答 LPM；
- “已经给出转发表，问某目的 IP 从哪个接口出” → 只对匹配项比较前缀长度。

## 自测

1. 目的 `172.16.1.9` 同时匹配 `172.16.0.0/16`、`172.16.1.0/24` 和 `0.0.0.0/0`，转发选哪条？

> [!answer]- 第 1 题答案与解析
> **答案**：选择 `172.16.1.0/24`。
> **解析**：三条路由都匹配目的地址；`/24` 前缀最长、覆盖范围最小，因此在已生效路由中最具体。

2. 同一个 `172.16.1.0/24` 同时由 OSPF 和 BGP 学到，是否直接靠 LPM 决定哪个协议获胜？

> [!answer]- 第 2 题答案与解析
> **答案**：不是。
> **解析**：两条候选具有相同前缀长度，先由控制平面的协议偏好、策略或协议自身规则选出有效路由；LPM 用于转发阶段比较不同长度的匹配前缀。

3. 为什么默认路由能匹配所有 IPv4 地址却通常最后才用？

> [!answer]- 第 3 题答案与解析
> **答案**：因为默认路由前缀长度为 0，匹配范围最大、具体程度最低。
> **解析**：只要有更具体且匹配的有效路由，它的前缀就比 `/0` 长，会优先选中；没有更具体匹配项时才由默认路由兜底。

## 一句话总结

**先让控制平面决定哪些候选路由成为有效路由；真正转发时，再对目的 IP 的有效匹配项做最长前缀匹配，选最具体的下一跳。**
