# IPv6 与 IPv4 过渡：IPv4 地址不够以后，新旧网络怎样共存

> [!summary] 快速复习卡片
> **作用/定位**：IPv4 网络层主线的收口，认识更大的 IPv6 地址空间，以及 IPv4/IPv6 共存阶段的三类互通思路。
> **核心结论**：IPv6 地址 128 位；常见目的地址类型有单播、组播、任播；过渡重点认 **双协议栈、隧道、协议转换**。
> **经典题型怎么做 / 题干怎么认**：设备自己同时懂 IPv4/IPv6 → 双栈；两端懂 IPv6、中间只有 IPv4 → 隧道；一端只懂 IPv4、一端只懂 IPv6 → 协议转换。
> **易错点 / 考试重点**：任播不是发给全部成员，而是路由到一组接口中的一个合适成员；NAT-PT 按教材识别，不当成现代唯一方案。

## 先直接回答：为什么还要 IPv6

上一站 [[ICMP与Ping]] 已经把 IPv4 的基本网络层主线闭环了。

IPv4 地址只有 32 位。随着联网设备数量不断增加，地址空间越来越紧张，因此需要更大的网络层地址体系。

IPv6 把地址长度扩展到 **128 位**，核心目的之一就是提供远大于 IPv4 的地址空间，同时重新设计了一些网络层机制。

本章不要求深入 IPv6 首部，只需要认识地址特点和“新旧协议怎样共存”。

## IPv6 地址先抓三件事

1. **128 位**；
2. 常写成 8 组十六进制数；
3. 连续的全 0 组可以用 `::` 压缩，但同一个地址中通常只能写一次 `::`，否则无法判断究竟省略了多少组。

目的地址类型最低识别：

| 类型 | 人话 |
| --- | --- |
| 单播 | 发给一个接口 |
| 组播 | 发给一组接口 |
| 任播 | 发给一组接口中的一个合适成员 |

IPv6 不沿用 IPv4 的广播方式，很多对应场景采用组播。

## 为什么 IPv6 出现了，IPv4 不能马上全部消失

现实网络里大量设备、应用和基础设施长期只支持 IPv4，不可能某一天同时切换到 IPv6。

所以会存在很长的新旧协议共存期，需要三类过渡思路。

### 双协议栈
设备自己同时运行 IPv4 和 IPv6，按对端和网络情况选择。

> **双栈 = 自己两种都会。**

### 隧道
两端支持某种协议，但中间网络暂时不支持，于是把内层数据“套进”中间网络能转发的外层报文，穿过中间网络后再拆开。

> **隧道 = 套壳穿过去。**

### 协议转换
通信两端只理解不同 IP 版本，需要中间设备在两种协议表示之间做转换。

> **转换 = 中间翻译。**

## 为什么下一站进入 TCP 与 UDP

到这里，网络层已经解决“**数据怎样找到目标主机并跨网络到达**”。

但是同一台主机上同时可能运行浏览器、DNS 服务、邮件程序等很多进程。数据到达主机后，还要继续解决：

> **应该用什么传输服务，并最终交给哪个程序？**

这就是传输层 TCP/UDP 和端口要解决的问题。

## 一句话总结

**IPv6 用 128 位扩大地址空间；新旧网络共存时，双栈是“两种都会”，隧道是“套壳穿过”，转换是“中间翻译”。**
