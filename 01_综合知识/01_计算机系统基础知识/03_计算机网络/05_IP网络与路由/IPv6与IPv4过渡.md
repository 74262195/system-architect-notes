# IPv6 与 IPv4 过渡：IPv4 地址不够，为什么不能直接全部换成 IPv6

> [!summary] 快速复习卡片
> **核心变化**：IPv4 地址 32 位；IPv6 地址 128 位，地址空间大得多。
> **地址类型最低识别**：单播 = 一个目标；组播 = 一组目标；任播 = 一组候选里选一个合适目标；IPv6 不沿用 IPv4 的广播方式。
> **双协议栈**：设备自己同时支持 IPv4 和 IPv6。
> **隧道**：两端懂 IPv6，中间旧网络只懂 IPv4，把 IPv6 包“套壳”穿过去。
> **协议转换**：通信两端分别只懂不同版本，需要中间做翻译。

## 先看现实问题：新协议可以设计出来，旧网络却不可能同时消失

上一站 [[ICMP与Ping]] 已经把 IPv4 的基本转发和诊断机制收口了。

IPv4 能正常工作，但它的地址只有 **32 位**。随着联网设备和网络规模不断扩大，地址空间成为长期限制。

于是 IPv6 把地址扩展到 **128 位**。

到这里并不难。真正麻烦的是：

> **全球已经有海量 IPv4 主机、路由器和业务系统，它们不可能在同一分钟全部升级。**

所以 IPv6 的考试重点之一，不只是“地址更长”，而是**新旧网络怎样共存**。

## 三种过渡方式，其实对应三种不同场景

### 场景一：设备自己两种协议都会

一台主机既支持 IPv4，也支持 IPv6。

访问 IPv4 目标时说 IPv4，访问 IPv6 目标时说 IPv6。

这就是 **双协议栈**。

大白话：

> **自己会两种语言。**

### 场景二：两端都懂 IPv6，中间旧网络只懂 IPv4

两边都是 IPv6 网络，但中间还有一段 IPv4 基础设施暂时改不了。

这时可以把 IPv6 数据包封装进中间网络能转发的外层报文，穿过旧网后再拆出来。

这就是 **隧道**。

大白话：

> **两端会新语言，中间听不懂，就先套一层它看得懂的外壳。**

### 场景三：一端只懂 IPv4，另一端只懂 IPv6

这时光“套壳”没用，因为终端本身就听不懂对方的协议。

需要中间设备做协议之间的转换。

这就是 **协议转换**。

大白话：

> **两边语言不同，中间要翻译。**

## 做题只按场景选，不背一串名字

| 题目描述 | 第一反应 |
| --- | --- |
| 同一设备同时支持 IPv4、IPv6 | 双协议栈 |
| 两端 IPv6，中间只能走 IPv4 | 隧道 |
| 一端只 IPv4，另一端只 IPv6 | 协议转换 |

教材出现 NAT-PT 等具体术语时按教材语境识别即可，不把某一个历史方案背成“所有 IPv4/IPv6 互通的唯一方法”。

## 到这里，网络层阶段正式结束

从 IP 地址、子网、ARP、路由，到 MTU/TTL、ICMP，再到 IPv6，我们一直在解决：

> **怎样把数据跨网络送到正确的目标主机。**

现在这个主问题已经够用了。

但目标主机上可能同时跑着 Web、DNS、邮件、数据库等很多程序。IP 只能找到**主机**，还不知道应用希望使用怎样的传输方式。

这就是传输层要接手的问题。

## 一句话收口

**IPv6 用 128 位地址扩展地址空间；IPv4 不会瞬间消失，所以双栈解决“自己两种都会”，隧道解决“中间旧网不懂”，协议转换解决“两端协议不同”。**
