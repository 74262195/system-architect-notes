# ARP 地址解析：知道目标 IP 后，当前这一跳的 MAC 从哪里来

> [!summary] 快速复习卡片
> **作用/定位**：把网络层的 IP 地址落到当前以太网链路，找到这一跳真正要写进帧里的目的 MAC。
> **核心结论**：同网段通信时解析目标主机 MAC；跨网段通信时解析的是**默认网关/下一跳接口的 MAC**，而 IP 目的地址仍保持远程目标。
> **经典题型怎么做 / 题干怎么认**：IP 已知但不知道二层地址、ARP 请求/应答、ARP 缓存 → ARP。
> **易错点 / 考试重点**：DNS 是域名 → IP；ARP 是当前 IPv4 链路 IP → MAC；交换机未知单播泛洪也不是“ARP 泛洪”。

## 先直接回答：为什么有 IP 还不够

上一站 [[子网划分与地址范围计算]] 已经能判断“目标是不是和自己在同一个子网”。

但真正通过以太网发送时，IP 分组还要放进一个二层帧。帧必须写**目的 MAC**，所以主机还要知道：

> **当前这一跳，帧到底交给哪个网卡接口？**

ARP（地址解析协议）就是在 IPv4 局域网里把“当前链路要找的 IP”解析成 MAC 地址。

## 同网段时解析谁

A 要访问同一子网里的 B：

1. A 已知 B 的 IP；
2. A 通过 ARP 获得 B 的 MAC；
3. 发送帧时，目的 MAC 写 B 的 MAC；
4. IP 目的地址写 B 的 IP。

此时二层目标和三层目标都是 B，只是使用的地址类型不同。

## 跨网段时为什么不是解析远程服务器 MAC

A 要访问另一个网络里的服务器 C。

A 根据前缀判断 C 不在本地子网，于是不会尝试直接在当前局域网找 C 的 MAC，而是先把分组交给**默认网关**。

因此：

1. IP 目的地址仍然是远程服务器 C；
2. 当前帧要交给本地网关；
3. ARP 查询的是**默认网关接口的 MAC**。

先用图抓住“IP 看最终目标，MAC 看当前一跳”：

```mermaid
flowchart LR
  A["主机 A"] -->|"第 1 跳帧：目的 MAC = 网关 MAC<br/>IP 目的 = 服务器 C"| R["路由器 / 默认网关"]
  R -->|"重新封装下一跳帧：MAC 会改变<br/>IP 目的仍 = 服务器 C"| C["远程服务器 C"]
```

所以跨网段时，路由器会把收到的链路帧拆掉，再按下一条链路重新封装新的帧：

> **IP 目的地址表示最终要到哪里；链路层 MAC 地址表示这一跳先交给谁。**

这也是为什么你不能把“IP 找主机”和“MAC 找网卡”理解成两套互相替代的地址：它们工作的范围不同。

## 和 DNS 的区别

| 协议 | 解决的问题 |
| --- | --- |
| DNS | 域名 → IP |
| ARP | 当前 IPv4 链路 IP → MAC |

DNS 是后面的应用层协议；这里只提前做一句区别，避免“都是解析”就混在一起。

## 为什么下一站是路由表

ARP 已经说明：跨网段时第一跳先交给默认网关。

但网关/路由器收到这个 IP 分组后，还有更核心的问题：

> **目标 IP 可能匹配很多网络范围，路由器到底从哪个出口继续转？下一跳选谁？**

这就是路由表与最长前缀匹配。

## 一句话总结

**ARP 负责把当前这一跳的 IP 目标解析成 MAC；同网段找目标主机，跨网段先找默认网关。最终 IP 目标通常保持，逐跳 MAC 会随下一跳改变。**
