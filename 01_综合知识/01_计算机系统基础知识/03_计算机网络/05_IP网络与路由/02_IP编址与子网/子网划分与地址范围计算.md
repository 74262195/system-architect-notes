# 子网划分与地址范围计算：拿到 `192.168.10.70/27` 后，到底应该算什么

> [!summary] 快速复习卡片
> **作用/定位**：上一站用 `/27` 画出了网络边界，这一站要算出边界里面具体有哪些地址。
> **为什么需要**：不知道目标属于哪个子网，主机就不知道应该直接发送，还是交给默认网关。
> **一句大白话**：先找到 IP 所在的地址块，块头代表整个网络，块尾代表广播，中间通常才能分给普通主机。
> **经典题型怎么做**：算块大小 → 找 IP 落在哪一块 → 取块头和块尾 → 写出常规主机范围。
> **本题答案**：`192.168.10.70/27` 所在块为 `.64～.95`，常规主机范围为 `.65～.94`。
> **下一站**：判断目标在本地以后，还要用 ARP 找到当前这一跳的 MAC 地址。

## 继续上一站：我们已经知道了什么

上一站 [[子网掩码与CIDR]] 已经解释过：

> `/27` 表示 IPv4 地址的前 27 位是网络前缀，剩余 5 位可以变化。

5 个二进制位一共有 32 种不同组合，所以 `/27` 的每个地址块包含 **32 个地址**。

上一站解决的是：

> **每个地址块有多大？**

这一站继续解决：

> **给定的 IP 究竟落在哪个地址块？块里的地址分别有什么用途？**

## 为什么不能把附近的地址随便分给电脑

假设公司的一台电脑配置为：

`192.168.10.70/27`

你不能只看到 `.70`，然后在它附近随便挑一个地址分给其他电脑。至少要先知道：

1. `.70` 属于哪个子网；
2. 这个子网从哪里开始、到哪里结束；
3. 哪些地址承担特殊作用；
4. 目标地址是否和 `.70` 在同一个子网。

否则可能把网络地址或广播地址误分给普通主机，也无法正确判断数据应该直接发送还是交给网关。

## 第一步：找到所有可能的块头

每个 `/27` 地址块有 32 个地址，因此第四段按照 32 递增：

| 地址块 | 第四段范围 |
| --- | --- |
| 第 1 块 | 0～31 |
| 第 2 块 | 32～63 |
| 第 3 块 | 64～95 |
| 第 4 块 | 96～127 |
| 第 5 块 | 128～159 |
| 第 6 块 | 160～191 |
| 第 7 块 | 192～223 |
| 第 8 块 | 224～255 |

题目中的第四段是 70。70 在 64 和 95 之间，所以 `192.168.10.70/27` 属于：

`192.168.10.64～192.168.10.95`

这一地址块。

> [!tip] 零基础判断方法
> 从 0 开始不断加块大小 32：`0、32、64、96……`。
> 70 在块头 64 和下一个块头 96 之间，所以它属于从 64 开始的地址块。

## 第二步：为什么块头是网络地址

当前地址块的第一个地址是：

`192.168.10.64`

它不是用来表示某一台普通电脑，而是用来表示：

> **`192.168.10.64/27` 这一整个网络。**

因此，在常规 IPv4 子网题中，`192.168.10.64` 是**网络地址**。

可以把它理解成“小区名称”，而不是某一户的门牌号。

## 第三步：为什么块尾是广播地址

当前地址块的最后一个地址是：

`192.168.10.95`

在传统 IPv4 子网语境中，它表示：

> **向这个子网里的所有主机发送。**

因此，`192.168.10.95` 是这个子网的**广播地址**，通常也不能直接分给某一台普通主机。

## 第四步：写出普通主机范围

已经知道：

- 块头 `.64` 是网络地址；
- 块尾 `.95` 是广播地址。

那么两者中间就是常规可用主机范围：

`192.168.10.65～192.168.10.94`

完整答案如下：

| 要求 | 结果 |
| --- | --- |
| 所属网络 | `192.168.10.64/27` |
| 网络地址 | `192.168.10.64` |
| 第一可用主机地址 | `192.168.10.65` |
| 最后一可用主机地址 | `192.168.10.94` |
| 广播地址 | `192.168.10.95` |
| 地址总数 | 32 |
| 常规可用主机地址数 | 30 |

32 个总地址减去网络地址和广播地址，常规可用主机地址数就是 30。

> [!warning] 使用边界
> “总地址数减 2”是传统软考 IPv4 子网题的常用规则。`/31`、`/32` 等特殊使用场景不在本卡展开，不能把“减 2”当成没有条件的现实世界绝对规律。

## 为什么计算结果会影响真正的通信

现在让 `192.168.10.70/27` 分别访问三个目标：

- `192.168.10.90`；
- `192.168.10.95`；
- `192.168.10.100`。

主机自己的地址块是 `.64～.95`。

### 目标是 `192.168.10.90`

`.90` 位于 `.64～.95`，而且不是块头或块尾，因此它是同一子网内的普通主机地址。

主机接下来需要寻找 `.90` 对应的 MAC 地址，然后在本地链路上发送。

### 目标是 `192.168.10.95`

`.95` 虽然位于当前地址块内，但它是广播地址，不代表某一台普通主机。

### 目标是 `192.168.10.100`

`.100` 已经进入下一个地址块 `.96～.127`，因此它不属于当前子网。

主机不会在本地直接寻找 `.100` 的 MAC，而是先把帧交给默认网关。

这就是子网计算在整条网络主线中的真正作用：

> **它不只是为了算数字，而是在帮助主机决定“本地直接交付”还是“先交给网关”。**

## 考试时固定做这五步

遇到 `IP/前缀` 地址范围题时：

1. 用 32 减去前缀长度，得到剩余主机位数；
2. 根据主机位数算出每块地址总数；
3. 按块大小找到 IP 所在的地址块；
4. 块头作为网络地址，块尾作为广播地址；
5. 写出两者中间的常规主机范围。

对于 `192.168.10.70/27`：

1. 32 位减去 27 位，还剩 5 位；
2. 5 位可以组成 32 个地址，所以每块大小为 32；
3. 70 落在 64～95；
4. 块头是 64，块尾是 95；
5. 常规主机范围就是 65～94。

## 容易犯的错误

| 错误 | 为什么错 |
| --- | --- |
| 把 `.70` 当成网络地址 | 题目给出的 IP 不一定正好位于块头 |
| 把 `.64～.95` 全部分给主机 | `.64` 和 `.95` 在常规题中有特殊用途 |
| 看到 `/27` 就说有 27 台主机 | 27 是网络前缀位数，不是主机数量 |
| 不看前缀，只比较前三段 | 前三段相同不保证一定属于同一子网 |
| 只背“减 2” | 必须先确认总地址数和题目语境 |

## 这一站解决了什么

现在我们已经能够回答：

- 某个 IP 属于哪个子网；
- 该子网从哪里开始、到哪里结束；
- 哪些是常规主机地址；
- 目标 IP 是本地地址还是其他子网的地址。

但是主机还不能马上发送以太网帧。

因为以太网帧需要填写目的 MAC 地址，而我们现在只知道 IP 地址。

## 下一站为什么是 ARP

如果目标在同一子网，主机需要找到：

> 目标主机 IP 对应的 MAC。

如果目标不在同一子网，主机需要找到：

> 默认网关 IP 对应的 MAC。

因此下一站进入 [[ARP地址解析]]：

> **子网计算决定“应该找谁”，ARP 负责把这个人的 IP 换成当前链路真正需要的 MAC。**

## 一句话总结

**子网范围计算就是先找到 IP 所在的地址块：块头是网络地址，块尾是广播地址，中间通常是主机地址；算完以后才能决定直接找目标，还是先找网关。**

## 自测

1. `192.168.10.110/27` 属于哪个地址块？

> [!answer]- 第 1 题答案与解析
> **答案**：`192.168.10.96～192.168.10.127`。
> **解析**：`/27` 每块 32 个地址；第四段按 32 递增，110 落在 96 与 128 之间，所以块头是 96、块尾是 127。

2. 它的网络地址和广播地址分别是什么？

> [!answer]- 第 2 题答案与解析
> **答案**：网络地址为 `192.168.10.96`，广播地址为 `192.168.10.127`。
> **解析**：常规 IPv4 子网题中，地址块的第一个地址表示网络，最后一个地址用于广播。

3. `192.168.10.125` 是否是该子网的常规主机地址？

> [!answer]- 第 3 题答案与解析
> **答案**：是。
> **解析**：125 位于 96～127 之间，且不是网络地址 96 或广播地址 127，因此属于常规主机范围 97～126。

4. `192.168.10.130` 与它是否属于同一子网？

> [!answer]- 第 4 题答案与解析
> **答案**：不是。
> **解析**：130 已落入下一个 `/27` 地址块 128～159，不属于 96～127。

5. 如果不属于同一子网，下一步应该先寻找谁的 MAC？

> [!answer]- 第 5 题答案与解析
> **答案**：默认网关本地接口的 MAC。
> **解析**：跨子网通信先把以太网帧交给本地默认网关；最终目标 IP 仍是 `192.168.10.130`，但当前一跳 MAC 指向网关。
