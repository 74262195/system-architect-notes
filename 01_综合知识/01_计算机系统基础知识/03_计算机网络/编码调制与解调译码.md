# 编码、调制、解调、译码：发送端和接收端到底各做什么

## 先定位：信道只会承载信号，不会理解“原始信息”

[[数据通信基本模型与信道]] 里，发信机负责把信息加工成信号。

发送端主干可以先记成：

```mermaid
flowchart LR
    A["原始信息"] --> B["编码"]
    B --> C["调制"]
    C --> D["适合信道传播的信号"]
```

接收端反过来：

```mermaid
flowchart LR
    A["收到信号"] --> B["解调"]
    B --> C["译码"]
    C --> D["还原信息"]
```

## 编码是在干什么

编码把信息按照规定规则映射成适合后续处理的数字表示或码型。

不同上下文里“编码”可能进一步分信源编码、信道编码、线路编码等。

零基础先抓：

> **编码负责按规则重新表示信息。**

## 调制是在干什么

调制把信息映射到适合物理信道传播的载波/信号参数上。

例如无线通信里不能把“0、1 这两个字符”直接扔进空气，需要通过电磁信号的变化表达它们。

## 解调和译码是什么关系

- 解调：从接收到的物理信号中恢复出编码后的信息；
- 译码：再按编码规则恢复原始信息。

所以二者在主干上与发送端相反。

## 一句话记住

> **发送端：信息 → 编码 → 调制 → 信号；接收端：信号 → 解调 → 译码 → 信息。**
