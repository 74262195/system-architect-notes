# 以太网技术：传统共享网络为什么要先听再发

> [!summary] 快速复习卡片
> **作用/定位**：有线局域网的数据链路层基础，理解以太网帧和传统共享介质的 CSMA/CD。
> **核心结论**：CSMA/CD = 发送前监听、空闲再发、发送中检测碰撞、碰撞后随机退避重传；现代交换式全双工以太网通常不再靠它处理碰撞。
> **经典题型怎么做 / 题干怎么认**：共享式有线、边发边听、碰撞检测、退避 → CSMA/CD；帧、MAC、FCS → 以太网数据链路层。
> **易错点 / 考试重点**：无线 802.11 用 CSMA/CA，不套 CD；经典以太网帧长 `64～1518B` 只做第二轮识别，带 802.1Q 标签时常见最大 `1522B`。

## CSMA/CD 怎么动作

1. 有数据先监听；
2. 信道忙就继续等；
3. 空闲后开始发送；
4. 发送过程中继续检测；
5. 若碰撞，停止发送并随机退避；
6. 等待后重新从“监听”开始。

> **“CD”是 Collision Detection，检测碰撞；“CA”是 Collision Avoidance，尽量避免碰撞。**

## 以太网帧只记高价值字段

| 字段 | 作用 |
| --- | --- |
| 目的 MAC | 帧发给谁 |
| 源 MAC | 帧从谁来 |
| 类型/长度 | 标识上层或数据长度 |
| 数据 | 承载 IP 分组等 |
| FCS | CRC 差错检测 |

FCS 能检测帧传输差错，但不等于协议会自动完成可靠重传。

## 为什么最小帧长和碰撞有关

传统共享式网络中，帧太短时，发送端可能已经把整帧发完，远处产生的碰撞才返回，于是发送端来不及检测。因此经典以太网设置最小帧长。

当前只需理解这个因果，不展开物理时隙推导。

## 一句话总结

**有线共享式以太网用 CD：先听、再发、边发边检测；无线 802.11 则主要用 CA。**
