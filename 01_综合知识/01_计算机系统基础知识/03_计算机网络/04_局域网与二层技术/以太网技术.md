# 以太网技术：传统共享式局域网为什么要“先听再发”

> [!summary] 快速复习卡片
> **作用/定位**：进入最典型的有线局域网技术，认识以太网帧、MAC 和传统共享介质上的 CSMA/CD。
> **核心结论**：传统共享式以太网使用 CSMA/CD：发送前监听、空闲再发、发送中检测碰撞、碰撞后随机退避；现代交换式全双工以太网通常不再靠它处理碰撞。
> **经典题型怎么做 / 题干怎么认**：共享式有线、边发边听、碰撞检测、退避 → CSMA/CD；帧、MAC、FCS → 以太网数据链路层。
> **易错点 / 考试重点**：无线 802.11 主要用 CSMA/CA；经典以太网最小帧长 64B，数据字段通常最多 1500B。

## 先定位：以太网在前面的分层地图里属于哪里

上一站 [[OSI与TCP-IP协议体系对比]] 已经建立了分层地图：TCP/IP 的网络接口层大体承接 OSI 的数据链路层和物理层职责。

现在开始把抽象层次落到真实局域网。以太网（Ethernet）就是最常见的**有线局域网技术**之一。它关心的是：

- 局域网里的数据怎样组织成**帧**；
- 帧里怎样写源 MAC、目的 MAC；
- 多台设备共享同一介质时，怎样避免大家同时发送造成混乱。

所以这一张先建立“局域网里的帧和 MAC”，下一张再看交换机怎样利用 MAC 把帧定向送到正确端口。

## 为什么传统共享式以太网会发生碰撞

早期多个主机可能共享同一段传输介质。如果两台主机差不多同时发送，它们的信号会互相干扰，这就叫**碰撞**。

因此经典共享式以太网使用 CSMA/CD：

1. 有数据先监听；
2. 信道忙就等待；
3. 空闲后开始发送；
4. 发送过程中继续检测；
5. 若发现碰撞，停止本次发送；
6. 随机等待后重新尝试。

可以压成：

> **先听，空闲再发；边发边听，撞了退避。**

现代交换式全双工网络中，每个交换端口通常形成独立链路，不再像早期共享介质那样发生同类碰撞，因此 CSMA/CD 更多作为经典原理和考试识别点。

## 以太网帧只记高价值字段

| 字段 | 作用 |
| --- | --- |
| 目的 MAC | 当前链路上要交给谁 |
| 源 MAC | 帧从哪个接口/设备来 |
| 类型/长度 | 标识承载的数据类型或长度语境 |
| 数据 | 承载 IP 分组等上层数据 |
| FCS | 检查帧在传输中是否发生差错 |

FCS 中使用 CRC 做差错检测。**CRC 算法本身回校验码主线学习**，这里不重复计算，只记“FCS 用于检错”。

## 为什么经典以太网规定最小帧长

在共享介质里，如果帧太短，发送端可能已经发送完，远处的碰撞才传播回来；这样发送端就来不及在发送期间发现碰撞。

因此经典以太网规定最小帧长 64B，使发送端有机会在发送过程中检测到最远处传播回来的碰撞。

当前理解这个因果即可，不展开时隙和网线长度推导。

## 为什么下一站是交换机

传统共享式网络的问题很直观：很多设备共用介质，容易碰撞，而且数据缺少精确的端口转发能力。

交换机进一步读取以太网帧中的 MAC 地址，把局域网从“大家共用一段介质”变成“可以按端口定向转发”的结构。

## 一句话总结

**以太网用帧和 MAC 组织局域网通信；传统共享介质用 CSMA/CD 处理碰撞，现代交换式全双工网络通常不再依赖它。**
