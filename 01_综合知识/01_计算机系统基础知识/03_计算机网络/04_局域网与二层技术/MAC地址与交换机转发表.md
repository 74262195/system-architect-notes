# MAC 地址与交换机转发表：交换机为什么知道帧该从哪个端口出去

> [!summary] 快速复习卡片
> **作用/定位**：承接交换机的“按 MAC 定向转发”，具体解释 MAC 表怎样学习和查询。
> **核心结论**：交换机从收到帧的**源 MAC**学习“MAC → 入端口”；转发时查询**目的 MAC**。已知目的定向转发，未知目的泛洪。
> **经典题型怎么做 / 题干怎么认**：给端口和帧序列 → 每一帧都先写“源 MAC → 入端口”，再查目的 MAC，最后决定转发/过滤/泛洪。
> **易错点 / 考试重点**：学习源 MAC，不是目的 MAC；未知单播泛洪不等于 ARP；MAC 表通常会随时间老化更新。

## 先直接回答：交换机凭什么知道某个 MAC 在哪个端口

上一站 [[交换机]] 只说到：交换机可以利用 MAC 地址表做定向转发。

但交换机刚启动时，这张表并不是天生就知道所有主机位置。它主要靠**观察收到帧的源 MAC**逐步学习。

原因很简单：

> 一个帧既然是从端口 1 进来的，而且源 MAC 是 A，那么交换机至少可以推断：**A 目前可以从端口 1 找到。**

于是形成表项：`A → 端口1`。

## 收到一帧时固定按两个动作想

### 第一步：学源 MAC

读取源 MAC，记录：

> **源 MAC → 当前入端口**

### 第二步：查目的 MAC

| 目的 MAC 状态 | 动作 |
| --- | --- |
| 表中已知，且在其他端口 | 只向对应端口转发 |
| 表中已知，且就是入端口 | 过滤，不向其他端口发 |
| 表中未知 | 除入端口外泛洪 |
| 广播地址 | 除入端口外泛洪 |

## 最小例子

MAC 表一开始为空，A 接端口 1，B 接端口 3。

A → B：

1. 先学 `A → 1`；
2. 查不到 B；
3. 除端口 1 外泛洪。

随后 B → A：

1. 先学 `B → 3`；
2. 已经知道 A 在端口 1；
3. 只向端口 1 转发。

这就是交换机转发表题最稳定的解题动作。

## MAC 和 IP 在这里不要混

- **MAC**解决当前链路这一跳怎样交付帧；
- **IP**解决跨网络逻辑寻址，下一站开始进入 IP 主线。

所以 MAC 表记录的是“MAC → 交换端口”，不是“IP → 交换端口”。

## 为什么主下一站直接进入 IPv4

学到这里，局域网内部已经有了一条完整链：

**以太网帧 → MAC 地址 → 交换机学习和转发。**

它解决的是“**当前局域网里怎么把帧送到对方**”。但互联网不能只靠一个局域网：如果目标主机在另一个网络，MAC 地址本身不能告诉路由器“最终应该跨哪些网络去哪里”。

于是网络继续发展出**IP 逻辑寻址**，用来标识跨网络的目的地。

VLAN、STP 和链路聚合仍然要学，但它们是在“把局域网做大、做隔离、做冗余”时出现的二层扩展问题，不再抢主线的下一站。

## 一句话总结

**交换机转发表就是“MAC → 端口”；收到帧先学源，再查目的。MAC 解决当前链路，跨网络还要继续靠 IP。**
