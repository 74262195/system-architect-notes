# MAC 地址与交换机转发表：交换机为什么知道帧该从哪个端口出去

> [!summary] 快速复习卡片
> **作用/定位**：解释二层交换机如何把“MAC 地址”映射到“交换端口”。
> **核心结论**：交换机从收到帧的**源 MAC**学习表项；转发时查询**目的 MAC**。已知目的定向转发，未知目的泛洪。
> **经典题型怎么做 / 题干怎么认**：给端口和帧序列 → 每一帧都先写“源 MAC → 入端口”，再查目的 MAC。
> **易错点 / 考试重点**：学习源 MAC，不是目的 MAC；未知单播泛洪不等于“做 ARP”；MAC 表是动态学习的，通常会老化。

## MAC 地址解决什么问题

IP 地址解决跨网络的逻辑寻址；到了某一条具体局域网链路，还需要用 MAC 地址把帧交给这一跳的目标接口。

所以可以记：

- **IP**：最终要去哪个网络/主机；
- **MAC**：当前这一跳把帧交给谁。

## 交换机收到一帧的固定动作

1. 读取源 MAC；
2. 记录“源 MAC → 入端口”；
3. 查询目的 MAC；
4. 决定转发：

| 目的 MAC 状态 | 动作 |
| --- | --- |
| 表中已知，且在其他端口 | 只向对应端口转发 |
| 表中已知，且就是入端口 | 过滤，不向其他端口发 |
| 表中未知 | 除入端口外泛洪 |
| 广播地址 | 除入端口外泛洪 |

## 最小例子

表为空：A 接端口 1，B 接端口 3。

A → B：
- 学习 `A → 1`；
- B 未知；
- 泛洪。

随后 B → A：
- 学习 `B → 3`；
- A 已知在端口 1；
- 只发端口 1。

## 一句话总结

**交换机的表是“MAC → 端口”；收到帧先学源，再查目的。**
