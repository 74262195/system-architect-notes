# STP 与链路聚合：多接几根线为什么既能提高冗余，也可能造成环路

> [!summary] 快速复习卡片
> **作用/定位**：承接 VLAN 后的二层网络，分别解决“冗余链路形成环路”和“多条链路怎样合并使用”两个问题。
> **核心结论**：STP 保留物理冗余，但逻辑上阻塞部分路径形成无环结构；链路聚合把多条物理链路组成一个逻辑链路，提高整体带宽和冗余。
> **经典题型怎么做 / 题干怎么认**：广播风暴、二层环路、生成树、阻塞冗余端口 → STP；端口捆绑、多链路组成逻辑接口、带宽+冗余 → 链路聚合。
> **易错点 / 考试重点**：P2，先掌握“防环 vs 合链”；不展开 BPDU 手算和厂商配置；单条流也不一定获得所有聚合链路带宽之和。

## 先直接回答：为什么“多接备用线”会出问题

上一站 [[VLAN与广播域]] 解决了广播范围划分，但真实网络还要考虑链路故障。

最直接的办法是：两台交换机之间不要只接一条线，再接备用线。这样主链路断了还有第二条路。

问题是：二层广播帧没有像 IP 分组那样的逐跳寿命限制。如果多条交换链路形成环路，广播帧或未知目的帧可能被交换机不断泛洪，在环里反复转发，最终形成**广播风暴**并造成 MAC 表不稳定。

所以“有冗余”与“不能成环”必须同时解决。

## 先看图：STP 为什么要“物理有环、逻辑无环”

假设三台交换机为了冗余互相都有链路：

```mermaid
flowchart LR
  A[交换机 A] --- B[交换机 B]
  B --- C[交换机 C]
  C -.->|STP 暂时阻塞这条冗余路径| A
```

物理线并没有拔掉，但 STP 让其中一条冗余路径在正常状态下不参与普通二层转发，于是逻辑转发结构不再形成闭环。

如果当前主路径故障，STP 再重新计算，让备用路径恢复参与转发。

## STP：物理上留备用，逻辑上先去掉环

STP（生成树协议）的核心思想是：

> **线可以都接着，但正常状态下只让一部分链路参与转发，使逻辑拓扑不形成二层环路。**

你只需要理解大致动作：

1. 选一个参考根；
2. 计算优选路径；
3. 让必要端口转发；
4. 让会形成环路的冗余端口暂时不转发；
5. 主路径故障后重新计算，让备用路径接替。

根桥、根端口、指定端口只做最低识别，不在这里展开选举计算。

## 链路聚合：多条线当成一条逻辑链路

另一类需求不是“选一条主路、一条备路”，而是希望多条兼容链路共同承担流量。

可以把物理关系先画成这样：

```mermaid
flowchart LR
  A[交换机 A] ==>|成员链路 1| B[交换机 B]
  A ==>|成员链路 2| B
  A ==>|成员链路 3| B
```

对上层和设备逻辑来说，这几条兼容成员链路可以作为**一个聚合后的逻辑链路/逻辑接口**使用，而不是三条互相独立、任意形成二层环路的普通链路。

链路聚合的效果包括：

- 不同流量可以分布到不同成员链路；
- 某一条成员链路故障时，其余成员仍能继续承担通信；
- 单个流通常保持在某一成员链路，避免数据乱序。

因此“总带宽增加”主要体现为**多流并行能力提升**，不是保证一个单连接速度等于所有链路简单相加。

## STP 和链路聚合不要混

- **STP**：核心问题是“有冗余，但不能形成二层转发环”；
- **链路聚合**：核心问题是“多条兼容链路怎样作为一个逻辑链路使用”。

## 为什么下一站开始学 IPv4

到这里，局域网二层主线已经收口：

**以太网帧 → 交换机 → MAC 转发表 → VLAN 广播域 → 二层冗余。**

但这些机制主要解决“**当前局域网/当前链路怎么交付**”。如果目标主机在另一个网络，就必须再有一种跨网络的逻辑地址，让路由器知道最终往哪里送。

这就是 IP 地址要解决的问题。

## 一句话总结

**STP 是“保留备用但逻辑防环”，链路聚合是“多条物理链路合成一个逻辑链路”。**
