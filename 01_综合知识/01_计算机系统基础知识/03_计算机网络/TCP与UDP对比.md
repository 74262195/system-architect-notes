# TCP 与 UDP：传输层为什么要提供两种完全不同的服务风格

## 先定位：IP 找到主机以后，还没有解决“怎样把数据交给应用”

网络层 IP 的目标是把分组尽力送到目标主机。

应用之间通信还要考虑：

- 要不要先建立连接；
- 丢了要不要重传；
- 乱序要不要恢复；
- 要不要保留一条一条消息的边界；
- 为可靠性愿意付出多少开销。

因此传输层提供 TCP 和 UDP 两种不同服务。

## 核心对比

| 对比项 | TCP | UDP |
| --- | --- | --- |
| 连接 | 面向连接 | 无连接 |
| 可靠性 | 提供可靠、有序字节流 | 尽力而为，不保证交付和顺序 |
| 数据边界 | 字节流，不保留应用消息边界 | 保留数据报边界 |
| 状态与开销 | 维护连接状态，机制较多 | 首部和协议状态更轻 |
| 控制 | 流量控制、拥塞控制等 | 协议本身不提供同等机制 |

## “UDP 更快”为什么不是定义

UDP 通常协议开销更小，也不用 TCP 连接管理和可靠重传机制。

但实际业务快慢还受：

- 网络状况；
- 应用设计；
- 丢包后的应用处理；
- 加密与协议栈等因素影响。

所以考试判断更稳的是：

> **TCP 重点是可靠、有序、连接；UDP 重点是无连接、轻量、数据报。**

## 典型场景怎么理解

- 文件、需要完整可靠传输的数据：常使用 TCP 类可靠传输；
- DNS 查询、实时音视频等场景：常能看到 UDP，但具体协议并非永远固定使用 UDP。

不要把“某应用 = 永远只能某传输协议”绝对化。
