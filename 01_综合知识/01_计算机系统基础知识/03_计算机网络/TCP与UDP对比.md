# TCP 与 UDP：传输层为什么提供两种服务风格

> [!summary] 快速复习卡片
> **作用/定位**：IP 把数据送到目标主机后，传输层决定应用需要“可靠连接”还是“轻量数据报”服务。
> **核心结论**：TCP 面向连接，提供可靠、有序的字节流；UDP 无连接，按数据报发送，不提供 TCP 同等级别的可靠、有序保证。
> **经典题型怎么做 / 题干怎么认**：可靠、按序、连接、字节流 → TCP；无连接、轻量、数据报、实时性优先 → UDP。
> **易错点 / 考试重点**：“UDP 更快”不是定义；TCP 不保留应用消息边界，UDP 保留数据报边界；某应用常用 UDP/TCP 不等于永远只能用它。

## 先定位：IP 找到主机，还没有决定怎样服务应用

网络层 IP 提供跨网络的尽力转发。应用之间通信还要考虑：

- 要不要建立连接；
- 丢失后要不要恢复；
- 乱序后要不要重排；
- 是否保留一条消息一条消息的边界；
- 愿意为可靠性付出多少协议开销。

于是传输层提供 TCP 和 UDP 两种主要服务风格。

## 核心对比

| 对比项 | TCP | UDP |
| --- | --- | --- |
| 连接 | 面向连接 | 无连接 |
| 可靠性 | 可靠、有序 | 尽力而为 |
| 数据形式 | 字节流 | 数据报 |
| 消息边界 | 不保留应用写入边界 | 保留数据报边界 |
| 控制机制 | 有确认、重传、流量/拥塞控制等 | 协议本身更轻量 |

## 题目怎么选

- 文件或必须完整到达的数据 → 优先想到 TCP；
- 实时音视频、简单查询等强调低额外开销的场景 → 常见 UDP；
- DNS 常见 UDP，也可以在特定场景使用 TCP，所以不要把“应用名 = 唯一传输协议”背死。

后面的 [[TCP三次握手]]、[[TCP可靠传输机制]]、[[TCP流量控制与拥塞控制]]、[[TCP四次挥手]] 都是在解释 TCP 为什么能提供上表里的服务，它们当前统一作为第二轮机制细节学习。

## 一句话总结

**先问业务要不要可靠、有序、面向连接：要就优先 TCP；要轻量数据报服务就看 UDP。**
