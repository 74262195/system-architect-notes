# 电子邮件协议：为什么发信和收信要用不同协议

> [!summary] 快速复习卡片
> **作用/定位**：应用层邮件业务的核心辨析，区分发送/转发邮件与读取邮箱使用的协议。
> **核心结论**：SMTP 负责发送/服务器间转发邮件；POP3 与 IMAP 用于用户读取/管理邮件；三者都属于应用层。
> **经典题型怎么做 / 题干怎么认**：发邮件、邮件服务器转发 → SMTP；传统下载式收信 → POP3；服务器端同步管理 → IMAP。
> **易错点 / 考试重点**：SMTP 不是收信协议；优先记 SMTP 25、POP3 110，IMAP 主要记功能即可。

## 先直接回答：为什么不能一个协议把“发”和“收”全做掉

上一站 [[FTP文件传输]] 让你看到：应用层协议通常围绕具体业务动作设计。

邮件业务内部也至少有两个不同动作：

1. **把新邮件送出去，并在邮件服务器之间转发**；
2. **用户打开邮箱，读取和管理已经到达服务器的邮件**。

这两个动作的工作方式不同，因此经典邮件体系使用不同协议分工。

## SMTP：负责把邮件送出去

可以把发送链条简化成：

`发件客户端 → SMTP → 发件服务器 → SMTP → 收件服务器`

所以题干出现“发送邮件、邮件服务器之间转发”，优先想到 **SMTP**。

常见默认端口识别：25。

## POP3 / IMAP：负责用户读取邮件

当邮件已经到收件人的邮件服务器后，用户再通过收信协议访问邮箱：

- **POP3**：传统上更强调把邮件取到本地；
- **IMAP**：更强调邮件保留在服务器上，并在多设备之间同步状态和管理。

考试只需做到“SMTP 发、POP3/IMAP 收”，不进入邮件头、MIME 或服务器部署。

## 为什么下一站离开应用层去看 WLAN

到这里应用层主线已经完成：

**DHCP 配置 → DNS 找地址 → HTTP/HTTPS Web → FTP 文件 → 邮件收发。**

接下来回到“大纲中独立要求的网络技术”：无线局域网。它和前面的有线以太网形成一个重要对比：**共享介质访问时为什么一个用碰撞检测，一个更强调碰撞避免。**

## 一句话总结

**SMTP 管发和转发，POP3/IMAP 管收；先判断题目问的是“发”还是“收”。**
