# DNS 域名解析：浏览器为什么要先把域名变成服务器 IP

> [!summary] 快速复习卡片
> **作用/定位**：承接 DHCP 获得的网络配置，把便于人记忆的域名解析成网络层真正用于寻址的 IP 地址。
> **核心结论**：DNS 属于应用层，常用端口 53；它解决“域名 → IP”，不负责 IP → MAC。
> **经典题型怎么做 / 题干怎么认**：域名解析、主机名查询、53 → DNS。
> **易错点 / 考试重点**：DNS 与 ARP 不同：DNS 找服务器 IP，ARP 找当前链路需要的 MAC。

## 先直接回答：为什么浏览器不能直接拿域名去路由

上一站 [[DHCP自动地址配置]] 已经让主机拿到了 IP、默认网关、DNS 服务器等网络参数。

用户更喜欢输入 `www.example.com` 这样的名字，但前面学过，网络层路由真正依据的是 **IP 地址**。

因此访问网站前必须先完成：

> **人类容易记的域名 → 网络能寻址的 IP 地址。**

这个转换就是 DNS（域名系统）的核心作用。

## 打开网站时 DNS 在哪一步

可以先用一条最小链理解：

1. 用户输入域名；
2. DNS 查询得到对应服务器 IP；
3. 网络层根据这个 IP 找到服务器；
4. 传输层连接到相应服务端口；
5. HTTP/HTTPS 才开始真正交换 Web 数据。

所以：

> **DNS 是“先找到服务器在哪里”，HTTP/HTTPS 是“找到以后交换什么 Web 业务”。**

## 为什么 DNS 和 ARP 容易混

它们都像“把一个标识换成另一个标识”，但所在层次完全不同：

| 机制 | 输入 | 输出 | 主要语境 |
| --- | --- | --- | --- |
| DNS | 域名 | IP | 应用层名称解析 |
| ARP | 当前链路 IPv4 地址 | MAC | 二层实际交付 |

考试看到“域名/主机名”就优先想 DNS；看到“IP 已知，要找 MAC”才想 ARP。

## 为什么下一站是 HTTP/HTTPS

DNS 只负责找到服务器 IP，并不规定浏览器和服务器怎样请求网页、返回页面数据。

服务器找到以后，Web 业务本身还需要一套应用协议，这就是 HTTP/HTTPS。

## 一句话总结

**DNS 只回答一个核心问题：这个域名对应哪个 IP；找到 IP 以后，Web 业务再交给 HTTP/HTTPS。**
