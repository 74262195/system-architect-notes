# 应用层协议功能与端口识别：看到业务动作先想到哪个协议

> [!summary] 快速复习卡片
> **作用/定位**：承接端口，把“自动获取配置、查域名、浏览网页、传文件、收发邮件、远程登录”等业务动作映射到应用层协议。
> **核心结论**：DHCP 发网络配置；DNS 查域名；HTTP/HTTPS 访问 Web；FTP 传文件；SMTP 发邮件；POP3/IMAP 收邮件；Telnet/SSH 远程登录；NFS 提供网络文件服务；SNMP 做网络管理。
> **经典题型怎么做 / 题干怎么认**：先看题目描述的**业务动作**，选协议；再看“所在层次”和默认端口校验答案。2024 分层题要求能认出 NFS、Telnet、FTP、SMTP 都属于应用层。
> **易错点 / 考试重点**：SMTP 是发，POP3/IMAP 是收；DNS 是域名→IP；IP/ICMP 属于网络层，TCP/UDP 属于传输层。

## 先直接回答：为什么到了应用层会突然出现这么多协议

上一站 [[端口与进程通信]] 已经解决“数据到主机以后交给哪个网络服务”。

但是不同服务做的事情完全不同：

- 新电脑刚接入网络，要自动拿到 IP、网关和 DNS；
- 浏览器只有域名，要先查到服务器 IP；
- 找到服务器以后，要按 Web 规则请求网页；
- 传文件、发邮件、远程登录又各有不同业务动作。

所以应用层不会只有一个万能协议，而是：

> **不同业务各自使用适合自己的应用协议。**

考试最常见的考法不是问协议内部报文，而是给一个业务动作，让你判断“该想到哪个协议、它在哪一层、常见端口是什么”。

## 第一轮必须会认的映射

| 业务动作 | 协议 | 常见端口/备注 |
| --- | --- | --- |
| 自动获得 IP/网关/DNS 等配置 | DHCP | 67/68 |
| 域名解析 | DNS | 53 |
| Web | HTTP | 80 |
| 加密 Web | HTTPS | 443 |
| 文件传输 | FTP | 21（控制） |
| 网络文件服务 | NFS | **记功能和应用层即可** |
| 安全远程登录 | SSH | 22 |
| 明文远程终端 | Telnet | 23 |
| 发邮件 | SMTP | 25 |
| 收邮件 | POP3 | 110 |
| 收邮件/服务器同步 | IMAP | 143 |
| 网络管理 | SNMP | 161/162 |

> 第一轮先做到“业务动作 → 协议”。端口只记稳定高频映射，不背整张端口表。

## 一个更自然的应用层使用顺序

假设一台新电脑接入网络并打开网页：

1. **DHCP**：先获得 IP、子网掩码、网关、DNS 等配置；
2. **DNS**：把网站域名解析成服务器 IP；
3. 网络层和传输层把数据送到对应主机/端口；
4. **HTTP/HTTPS**：真正交换 Web 请求和响应。

这个小链条不仅用于理解，第一次完整学习时也按这个顺序继续展开具体协议，再补 FTP 和电子邮件。

## 教材明确但当前低频：最低识别

- **NFS**：网络文件服务，属于应用层；2024 分层题出现过，必须会认。
- **NNTP**：网络新闻传输协议，应用层；当前只保留名称和功能，不背端口/流程。

## 为什么完整路线先进入 DHCP，而主线可以直接去 WLAN

到这里，基础互联网的主通信链已经闭环：

**局域网用 MAC/交换机完成当前链路交付 → IP/路由完成跨网络寻址与转发 → TCP/UDP 和端口把数据交给目标应用 → 应用协议完成具体业务。**

所以如果只是抓网络发展的主线，可以继续看网络形态怎样从有线扩展到 [[无线局域网802.11]]。

但第一次完整学习还要把应用层的几个稳定考点逐个补完：

**[[DHCP自动地址配置]] → [[DNS域名解析]] → [[HTTP与HTTPS]] → [[FTP文件传输]] → [[电子邮件协议]]**，然后再进入 WLAN。

## 一句话总结

**应用层按业务分协议：DHCP 发配置，DNS 查名字，HTTP 谈 Web，FTP 传文件，SMTP 发信，POP3/IMAP 收信；基础互联网通信链到这里已经闭环。**
