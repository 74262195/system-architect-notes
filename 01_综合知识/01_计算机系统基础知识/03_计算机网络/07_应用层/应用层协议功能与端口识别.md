# 应用层协议功能与端口识别：程序已经找到了，双方还要约定“怎么说话”

> [!summary] 快速复习卡片
> **先认业务再认协议**：自动拿配置 → DHCP；域名找 IP → DNS；网页 → HTTP/HTTPS；文件 → FTP；发邮件 → SMTP；收邮件 → POP3/IMAP。
> **高价值默认端口**：DHCP 67/68、DNS 53、HTTP 80、HTTPS 443、FTP 控制 21、SMTP 25、POP3 110、IMAP 143。
> **其他识别项**：SSH 22 = 安全远程登录；Telnet 23 = 明文远程终端；SNMP 161/162 = 网络管理；NFS = 网络文件服务。
> **分层边界**：这些属于应用层；TCP/UDP 是传输层，IP/ICMP 是网络层。
> **做题顺序**：先看题目在做什么业务，再用协议名、层次和默认端口互相验证。

## 先看问题：找到正确程序，不代表双方已经知道数据是什么意思

上一站 [[端口与进程通信]] 已经能把数据送到正确的服务。

但两个程序还必须约定：

> **这段数据是在请求网页、查询域名、发邮件，还是传文件？请求和响应应该按什么规则组织？**

这种“具体业务怎样通信”的规则，就是**应用层协议**。

因此应用层协议很多，不是因为网络体系混乱，而是因为业务本来就不同。

## 用一台刚联网的电脑串起最常见协议

你把一台新电脑接入网络，随后打开网页、下载文件、收发邮件：

1. **先获得 IP、掩码、网关、DNS 等配置** → DHCP；
2. 输入域名，需要先得到服务器 IP → DNS；
3. 请求网页 → HTTP；需要 TLS 保护时常见为 HTTPS；
4. 题目明确是传统文件传输 → FTP；
5. 发送或服务器间转发邮件 → SMTP；
6. 用户读取邮箱 → POP3 / IMAP。

这就是第一次学习真正要抓住的主线。

## 做题时按“业务动作”识别

| 题干动作 | 协议 | 常见默认端口 |
| --- | --- | --- |
| 自动获得网络配置 | DHCP | UDP 67/68 |
| 域名 → IP | DNS | 53 |
| Web 请求/响应 | HTTP | TCP 80 |
| TLS 保护的 Web | HTTPS | TCP 443 |
| 传统文件传输 | FTP | TCP 21（控制） |
| 发送/转发邮件 | SMTP | TCP 25 |
| 收取邮件 | POP3 | TCP 110 |
| 邮箱同步管理 | IMAP | TCP 143 |
| 安全远程登录 | SSH | TCP 22 |
| 明文远程终端 | Telnet | TCP 23 |
| 网络管理 | SNMP | UDP 161/162 |
| 网络文件服务 | NFS | 先记功能和应用层定位 |

端口是**默认约定**，不是绝对不能修改的硬编码。

题目如果只问“属于哪一层”，直接抓应用层；如果问具体业务，再按上表的动作匹配。

## 为什么总览页不继续讲每个协议的完整过程

这张卡的主问题只有一个：

> **看到一种网络业务，应该先想到哪个应用层协议？**

所以这里不再把 DHCP 四步、DNS 递归/迭代、HTTP 安全机制、FTP 双连接、邮件收发流程全部重讲一遍。

真正需要理解机制的协议，后面各自有原子卡。

这样复习时先拿到一张清晰的“业务 → 协议”地图，再按主线逐个进入即可。

## 一句话收口

**应用层协议规定具体业务怎样说话：先看题目在做什么，再匹配 DHCP、DNS、HTTP/HTTPS、FTP、SMTP、POP3/IMAP 等协议，最后用层次和默认端口验证。**
