# 应用层协议功能与端口识别：数据已经能送到程序，为什么还会有这么多协议

> [!summary] 快速复习卡片
> **先按业务动作认协议**：自动拿网络配置 → DHCP；域名找 IP → DNS；浏览网页 → HTTP/HTTPS；传文件 → FTP；发邮件 → SMTP；收邮件 → POP3/IMAP；远程登录 → SSH/Telnet；网络管理 → SNMP；网络文件服务 → NFS。
> **第一轮先认“做什么”再记端口**：DHCP 67/68，DNS 53，HTTP 80，HTTPS 443，FTP 控制 21，SSH 22，Telnet 23，SMTP 25，POP3 110，IMAP 143，SNMP 161/162。
> **分层边界**：这些是应用层协议；TCP/UDP 是传输层，IP/ICMP 是网络层。

## 传输层已经把数据交给正确程序，为什么还没结束

上一站 [[端口与进程通信]] 已经解决：

> **IP 找主机，TCP/UDP 决定怎么传，端口号把数据交给正确服务。**

但“交给正确程序”只是把快递送到了窗口。

窗口里的两个程序还必须约定：

- 这一段数据表示“请求网页”还是“发邮件”？
- 请求和响应应该按什么格式组织？
- 谁先说、谁后说？
- 哪些字段表示地址、状态、文件名或邮件内容？

这些**业务语义和交互规则**就是应用层协议负责的事。

所以应用层会有很多协议，不是因为网络设计得乱，而是因为业务本来就不同。

## 用一台刚开机的笔记本把常见协议串起来

假设你带着一台新笔记本连接公司网络，随后打开网页、下载文件、查看邮件。

整个过程会自然碰到不同应用协议。

### 第一步：电脑刚接入，连自己的 IP 都不知道

它需要自动拿到：

- IP 地址；
- 子网掩码；
- 默认网关；
- DNS 服务器地址。

这时用 **DHCP**。

### 第二步：你输入的是域名，不是服务器 IP

浏览器里输入 `www.example.com`。

IP 层真正需要的是 IP 地址，所以先用 **DNS** 把域名解析成 IP。

### 第三步：已经找到 Web 服务器，开始请求页面

浏览器和服务器要约定怎样发送请求、返回页面和资源。

这时用 **HTTP**；需要 TLS 安全保护时就是 **HTTPS**。

### 第四步：业务明确是传统文件传输

如果题目明确出现 FTP 文件上传/下载、控制连接等语境，就想到 **FTP**。

### 第五步：你开始收发邮件

邮件内部又分两种动作：

- 发出去、服务器之间转发 → **SMTP**；
- 用户读取邮箱 → **POP3 / IMAP**。

所以不要把 SMTP 背成“电子邮件协议 = 什么都做”。

## 其他稳定识别项也按“动作”记

| 业务动作 | 协议 | 常见默认端口/边界 |
| --- | --- | --- |
| 自动获得 IP、网关、DNS 等 | DHCP | UDP 67/68 |
| 域名 → IP | DNS | 53，常见 UDP，也可用 TCP |
| Web 请求/响应 | HTTP | TCP 80 |
| 受 TLS 保护的 Web | HTTPS | TCP 443 |
| 传统文件传输 | FTP | TCP 21 为常见控制端口 |
| 安全远程登录 | SSH | TCP 22 |
| 明文远程终端 | Telnet | TCP 23 |
| 发送/转发邮件 | SMTP | TCP 25 |
| 传统收取邮件 | POP3 | TCP 110 |
| 服务器端邮箱同步管理 | IMAP | TCP 143 |
| 网络管理 | SNMP | UDP 161/162 |
| 网络文件服务 | NFS | 当前先记功能和应用层定位 |

端口是**默认约定**，不是现实中绝对不能改的硬编码。

## 为什么先看业务动作，再看端口数字

考试常故意把：

- 协议名；
- 所在层次；
- 默认端口；
- 业务功能

交叉来问。

如果只背数字，很容易混。

更稳的顺序是：

> **题目到底在做什么业务 → 应该是哪种协议 → 再用层次和端口验证。**

例如：

- “自动获得网关和 DNS” → 先想到 DHCP，再核对 67/68；
- “域名解析” → DNS，再核对 53；
- “服务器之间发送邮件” → SMTP，再核对 25。

## NFS、Telnet 为什么还保留

它们不一定需要像 HTTP/DNS 那样展开完整机制，但仍可能作为“哪一个属于应用层”“哪个协议做什么”的识别项出现。

所以当前减负策略是：

- **高价值主线协议**：理解为什么存在和基本动作；
- **低频识别协议**：只保留功能、层次和必要默认端口，不扩成工程专题。

## 这一张总览解决了什么，还剩什么没解决

现在已经知道应用层不是一堆随机缩写，而是不同业务动作各自有协议。

下一步不继续背整张表，而是回到那台**刚接入网络的新电脑**：

> 它连 IP、网关、DNS 都没有，第一份正常网络配置到底是怎么自动拿到的？

这就是下一站 [[DHCP自动地址配置]]。

## 一句话总结

**应用层协议是在规定“具体业务怎么说话”：DHCP 发配置，DNS 找 IP，HTTP/HTTPS 做 Web，FTP 传文件，SMTP 发邮件，POP3/IMAP 收邮件。先认业务动作，再记端口。**
