# FTP 文件传输：为什么还需要一个专门传文件的应用协议

> [!summary] 快速复习卡片
> **作用/定位**：应用层常见文件传输协议，题目明确出现“FTP、文件上传/下载、控制端口 21”时要能快速识别。
> **核心结论**：FTP 属于应用层；常见控制连接端口 21；当前只掌握用途和协议识别，不进入主动/被动模式工程细节。
> **经典题型怎么做 / 题干怎么认**：文件传输、上传下载、21 → FTP。
> **易错点 / 考试重点**：浏览器也能通过 HTTP 下载文件，但“HTTP 能传文件”不等于 HTTP 和 FTP 是同一个协议。

## 先直接回答：HTTP 也能下载文件，为什么考试还单独学 FTP

上一站 [[HTTP与HTTPS]] 已经知道 HTTP 主要围绕 Web 请求和响应。

现实中“传一个文件”当然不只 FTP 一种方式，但 FTP 的协议目标本身就是**在客户端和服务器之间进行文件传输和文件操作**，因此它长期作为应用层协议识别项出现。

考试看到：

- FTP；
- 文件上传/下载；
- 控制连接端口 21；

就先定位为**应用层文件传输协议**。

## 学到哪里就够

只保留：

- FTP 的用途：文件传输；
- 所在层次：应用层；
- 常见控制端口：21。

不进入：

- 主动/被动模式的端口协商；
- 数据连接细节；
- FTP 服务器配置。

这些内容对当前系统架构设计师网络基础性价比低。

## 为什么下一站是电子邮件协议

HTTP/HTTPS 和 FTP 已经覆盖 Web 与文件业务。

下一类稳定应用协议题是邮件：同样是应用层，但“发邮件”和“收邮件”不是同一个协议，最容易出现 SMTP/POP3/IMAP 混淆。

## 一句话总结

**FTP = 应用层文件传输协议；考试先认“文件上传/下载 + 控制端口21”，不学工程配置。**
