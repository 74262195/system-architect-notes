# 非性能性指标：网络不只要快，还要建得起、稳得住、扩得开

> [!summary]- 快速复习卡片（学完再看）
> **作用/定位**：作为 [[网络性能指标]] 的 P3 可选补充，把“评价一张网络”的非速度维度补完整。
> **核心结论**：教材列出的非性能指标包括 **费用、质量、标准化、可靠性、可扩展性、可升级性、易管理性、可维护性**。
> **经典题型怎么做 / 题干怎么认**：预算 → 费用；整体稳定与构建质量 → 质量；互操作 → 标准化；故障少 → 可靠性；规模增长 → 可扩展；版本/能力演进 → 可升级；配置监控方便 → 易管理；故障容易定位修复 → 可维护。
> **易错点 / 考试重点**：本卡只识别网络建设语境，不在这里重复学习可用性公式、MTBF、MTTR；也不要把这些评价指标和 [[网络QoS-IntServ与DiffServ|QoS 的差异化服务机制]] 混成一回事。

## 为什么性能指标之后还会有这一张

上一站回答的是：

- 快不快；
- 实际传多少；
- 延迟多大；
- 网络忙不忙。

但假设有两张网络速度一样：

- A 很贵，而且坏了很难修；
- B 成本更低，还容易扩容和维护。

显然不能说两张网络“同样好”。所以**性能只是网络评价的一部分**。

## 一张表够用

| 指标 | 人话 |
| --- | --- |
| 费用 | 建设和运行成本是否可承受 |
| 质量 | 网络构件和整体构建质量是否足够好 |
| 标准化 | 是否遵循通用标准、便于互操作 |
| 可靠性 | 是否能稳定工作、少故障 |
| 可扩展性 | 用户、站点、容量增长后能否扩容 |
| 可升级性 | 技术和性能演进时能否升级 |
| 易管理性 | 配置、监控和运维是否方便 |
| 可维护性 | 故障是否容易定位、修复和恢复 |

## 和 QoS 是什么关系

两者都在回答“网络好不好”，但角度不同：

- **性能/非性能指标**：用于评价网络本身，例如吞吐量、时延、可靠性、可扩展性；
- **QoS**：是一类让不同业务获得不同服务待遇的机制，例如根据业务类别区别调度和转发。

因此旧题出现 IntServ、DiffServ、DSCP 时，不要在这张指标表里硬找，转到 [[网络QoS-IntServ与DiffServ]]。

## 为什么它不再挡住主线

这张卡属于教材范围，但当前优先级是 P3。第一次时间充足时可以在性能指标后顺手扫一遍；时间紧时直接从 [[网络性能指标]] 进入 [[以太网技术]]。

它只负责补齐“网络好不好不只看速度”这个认识，不再承担把学习路线带去其他专题的职责。

## 边界在哪里

网络章回答的是“评价一张网络还要看哪些方面”。后续质量属性、可靠性章节会系统学习可用性、故障恢复等内容；这些计算不在本卡重复展开。

## 一句话总结

**网络好不好不只看快不快，还要看成本、质量、标准、可靠、扩展、升级、管理和维护。**
