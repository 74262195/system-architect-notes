# IntServ 与 DiffServ：网络怎样给不同业务提供不同服务质量

> [!summary]- 快速复习卡片（学完再看）
> **QoS**：不是“让网络永远更快”，而是让不同业务获得不同的带宽、时延、抖动或丢包处理待遇。
> **IntServ**：偏向按流提供服务；历史题要求识别三类服务：保证质量、负载受控、尽力而为。
> **DiffServ**：先给 IP 分组打服务类别标记，再让路由器按标记采用不同转发行为。
> **IPv4 题眼**：历史教材/真题常写“服务类型字段”；现代术语通常对应 DS 字段中的 DSCP。
> **易错点**：IntServ 的三类服务里没有“突发式服务”；DiffServ 也不是看源 IP 来决定 DS 码点。

## 为什么网络需要 QoS

普通 IP 转发可以把分组尽力送到目的地，但不同业务对网络的要求并不一样。

例如：

- 文件下载更在意最终完整；
- 实时语音更在意时延和抖动；
- 普通网页通常可以接受尽力而为服务。

所以网络需要一种办法表达：

> **哪些流量需要更明确的服务保证，哪些流量按普通方式转发即可。**

这类能力统称为 QoS（Quality of Service，服务质量）。

## IntServ：把“这条业务流需要什么服务”说清楚

IntServ（Integrated Services，集成服务）可以先理解为：

> **针对具体业务流表达服务需求，并由网络按相应服务类型处理。**

软考历史题最需要识别的是三种服务：

| 服务类型 | 人话理解 |
| --- | --- |
| 保证质量服务 | 对带宽、时延、抖动、丢包等提供较明确的定量保证 |
| 负载受控服务 | 目标是让业务获得类似网络不拥塞时的服务体验 |
| 尽力而为服务 | 普通 Internet 服务，不承诺明确 QoS 保证 |

所以看到“突发式服务是否属于 IntServ 三类服务”时，应判断：**不属于这三类。**

## DiffServ：不逐条讲业务，而是先给分组打类别标签

DiffServ（Differentiated Services，区分服务）的思路不同：

1. 先根据业务的 QoS 需求给 IP 分组分类；
2. 在 IP 首部中写入相应的服务类别标记；
3. 网络中的路由器根据这个标记采用不同的排队、调度或转发待遇。

历史 IPv4 题常把这个位置称为**服务类型（ToS）字段**。现代 IPv4 首部中对应区域通常称为 **DS 字段**，其中使用 **DSCP（Differentiated Services Code Point）** 表示区分服务码点。

因此做旧题时看到：

> “DiffServ 根据 IPv4 首部哪个字段设置 DS 码点？”

第一反应应是：

> **服务类型 / DS 字段这一位置，而不是 TTL、分片偏移或源地址。**

## IntServ 和 DiffServ 最小区别

| 判断点 | IntServ | DiffServ |
| --- | --- | --- |
| 直觉 | 更强调具体业务流的服务需求 | 更强调给分组分类打标 |
| 历史题重点 | 三类服务名称 | IPv4 服务类型/DS 字段、DSCP |
| 当前复习深度 | 会识别三类服务即可 | 会识别“打标 → 按标记处理”即可 |

## 一句话收口

**IntServ 重点是“这条业务流需要什么服务”，DiffServ 重点是“先给分组标类别，再按类别区别处理”。**

> [!question] 自测 1
> “保证质量、负载受控、尽力而为、突发式”四项中，哪一项不属于历史题所列 IntServ 三类服务？

> > [!answer]- 第 1 题答案与解析
> > **答案**：突发式服务。
> > **解析**：历史题要求识别的三类是保证质量、负载受控和尽力而为。

> > [!question] 自测 2
> > DiffServ 在 IPv4 历史题中，通常通过哪个首部区域写入 DS 码点来区分流量类别？

> > [!answer]- 第 2 题答案与解析
> > **答案**：服务类型/DS 字段对应区域。
> > **解析**：DSCP 用于表达区分服务类别；不是源地址、TTL 或分片偏移字段。
