# Cache 映射方式：主存块进 Cache 到底能坐哪里

## 先定位：映射是在回答“主存里的这一块，进 Cache 后放哪一行”

[[Cache]] 的容量远小于主存，所以不可能让每个主存块都拥有一个永久固定的 Cache 空间。CPU 访问主存块时，硬件必须先有一套规则决定：

> **这个主存块允许进入哪些 Cache 行？**

这套“主存块 → Cache 位置”的对应规则就是 **Cache 映射**。直接映射、全相联、组相联不是三种存储器，而是三种**放置规则**。

本卡只解决“放哪里”；当允许的位置都满了以后“踢谁出去”，才是下一站 [[Cache-替换算法]]。


## Cache 很小，位置怎么分

当一个主存块要进入 Cache，核心问题不是“要不要缓存”，而是**它允许放到哪些 Cache 行**。

| 映射 | 能放哪里 | 优点 | 代价 |
| --- | --- | --- | --- |
| **直接映射** | 固定唯一位置 | 硬件简单、查找快 | 冲突多 |
| **全相联** | 任意位置 | 冲突最少、最灵活 | 比较硬件复杂 |
| **组相联** | 固定组，组内任意 | 在冲突与复杂度间折中 | 需要组内比较 |

### 直觉

- 直接映射：每个人只有固定座位。
- 全相联：哪里空坐哪里。
- 组相联：先分班，再在班里自由坐。

组相联不是“第三种完全无关的办法”，而是直接映射与全相联之间的折中。

## 考试怎么认

- “只能映射到固定位置” → 直接映射。
- “可以放任意行” → 全相联。
- “先确定组，组内任选” → 组相联。

## 一句话记住

> **直接固定、全相联自由、组相联先定组再自由。**

## 自测

1. 为什么直接映射容易冲突？
2. 全相联为什么硬件代价高？
3. 组相联折中了哪两个矛盾？
