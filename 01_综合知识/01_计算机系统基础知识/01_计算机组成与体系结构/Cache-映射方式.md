# Cache 映射方式：主存块进入 Cache 时到底能坐哪里

## 先定位：映射决定候选位置，替换决定候选满后踢谁

Cache 按“块/行”保存主存数据的副本。CPU 给出地址后，硬件必须快速回答：

1. 这个地址属于哪个主存块？
2. 这个块允许放在哪个 Cache 行或组？
3. 候选位置中的标签是否匹配？

因此一个典型 Cache 地址可理解成：

| 地址部分 | 作用 |
| --- | --- |
| 块内偏移 | 在命中的数据块中选择具体字节/字 |
| 行号或组号 | 快速定位允许查找的 Cache 范围 |
| 标记 Tag | 判断候选行保存的是不是目标主存块 |

## 三种映射怎样查找

### 直接映射

每个主存块只能映射到唯一 Cache 行：

> Cache 行号 = 主存块号 mod Cache 行数

硬件定位该行后比较 Tag；匹配且有效位为 1 才命中。它速度快、硬件简单，但多个常用主存块若映射到同一行，会反复互相替换，形成冲突不命中。

### 全相联映射

主存块可以放任意 Cache 行。查询时需要把目标 Tag 与所有有效行并行比较；放置灵活、冲突少，但比较硬件和功耗成本高。

### 组相联映射

Cache 先分成若干组，主存块只能进入固定组，但可放在组内任意一路：

> 组号 = 主存块号 mod 组数

N 路组相联表示每组有 N 行。查询时只并行比较该组内 N 个 Tag，是直接映射与全相联之间的折中。

## 用 8 行 Cache 走一个例子

假设 Cache 有 8 行，主存块 3、11、19 被反复访问。

- 直接映射：3 mod 8、11 mod 8、19 mod 8 都等于 3，三个块只能争第 3 行。
- 若改成 2 路组相联：8 行分为 4 组，每组 2 行；三个块仍落入第 3 组，但组内能同时容纳其中两个。
- 全相联：三个块可分别放在任意空行，基本不产生这类固定位置冲突。

~~~mermaid
flowchart LR
    A[CPU地址] --> B[拆出组号与Tag]
    B --> C[定位候选组]
    C --> D{组内Tag匹配?}
    D -- 是 --> E[命中并按偏移取数据]
    D -- 否 --> F[访问下级存储并装入]
~~~

## 与替换算法的边界

- 直接映射只有唯一位置，新块到来时直接覆盖对应行，不需要在多个候选中选择。
- 全相联或组相联的候选位置全满后，才由 [[Cache-替换算法]] 选择牺牲块。

## 考试怎么认

- 固定唯一行 → 直接映射。
- 任意 Cache 行 → 全相联。
- 固定组、组内任选 → 组相联。
- 题目要求计算行号/组号时，先统一主存块号、Cache 行数和组数，不要把字节地址直接拿去取模。
