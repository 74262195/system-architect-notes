# I/O 控制技术：CPU 怎么伺候又慢又多的外设

## 先定位：I/O 接口解决“怎么接”，I/O 控制技术解决“数据搬运时 CPU 要管多少”

上一站 [[IO接口|I/O 接口]] 已经建立了 CPU 与外设之间的翻译和缓冲层，让速度、格式和控制方式不同的设备能够接入系统。

但“接上了”还不等于“传数据效率高”。当键盘、磁盘、网卡真的要和内存交换数据时，还要决定：

> **CPU 是一直盯着设备、收到通知再处理，还是把整块搬运工作交给专门硬件？**

因此程序查询、中断、DMA、通道是在比较 **CPU 参与 I/O 数据传输的程度**。这就是为什么它们会紧跟在 I/O 接口之后。


## 痛点：CPU 很贵，却要整天等慢外设

CPU 快得像闪电，而外设（键盘、打印机、硬盘、网卡）又慢又磨蹭。如果 CPU 每次都自己亲自盯着外设干活，那就等于让一个年薪百万的工程师整天站在打印机旁边等它吐纸——**CPU 大量宝贵时间被浪费在干等上**。

那么问题来了：怎么让 CPU 既能把数据交给外设，又不用天天干等？这就是 I/O 控制方式演进的核心推动力——**CPU 从"亲力亲为"一步步变成"甩手掌柜"，让出时间做更有用的事。**

> 记一句：**I/O 控制的发展史，就是 CPU 从"凡事自己盯"到"统统甩手"的甩手掌柜进化史。**

## 定义（讲人话）

I/O 控制方式：CPU 与外部设备之间传输数据时，CPU 以什么方式参与、干预到什么程度。核心是**CPU 出多少力、等多少时间**的取舍。

## 四种方式逐个认识（按 CPU 的"劳累程度"从重到轻）

这是重点，四种方式是"进化史"，越往后 CPU 越省心：

| 方式       | CPU 怎么干活                                  | 特点                     | 怎么认                |
| -------- | ----------------------------------------- | ---------------------- | ------------------ |
| **程序查询** | CPU 死等设备，反复问"好了吗？好了吗？"                    | CPU 被锁死干等，最笨           | 题里说"CPU 循环查询/轮询等待" |
| **中断**   | 设备干完主动喊一声"好了"，CPU 再去搬                     | 不用死等，但每次只搬一点，频繁打断      | 题里说"设备发出中断请求"      |
| **DMA**  | 请个“搬运工”（DMAC），CPU 初始化地址、方向和长度，DMAC 直接在主存与设备间成块传输 | CPU 不逐字搬运，但仍参与初始化、总线协调和完成处理 | 题里说“DMA 控制器整块搬” |
| **通道**   | 干脆请个"物流公司"（专用 I/O 处理器），一批设备全归它管           | CPU 彻底解放，只管吩咐          | 题里说"通道/专用I/O处理器"   |

**关键区分（最常考）：**
- **程序查询**：CPU 全程**死等**，CPU 利用率最低。
- **中断**：CPU **不用死等**（可去干别的），但每次传送量小，频繁被打断。
- **DMA**：CPU 不参与逐字节搬运；DMAC 可能通过周期窃取等方式取得总线，传输完成后通常用中断通知 CPU。

> 一句话记四种方式的"劳累度"：**程序查询"CPU 全程盯"，中断"打断去办"，DMA"交底撒手，搬运工整块搬"，通道"请个物流公司全托管"。** 越往后 CPU 越闲、效率越高。

## 这个知识与考试的关系

- **选择题**：问"哪种方式 CPU 不用干等"→ 中断/DMA/通道（不是程序查询）；问"批量传输、CPU 干预最少"→ DMA。
- **经典陷阱**：把"程序查询"说成 CPU 高效（错，它最浪费时间）；把中断说成"整块搬完才通知"（那是 DMA，中断是频繁小量）。
- **考点**：I/O 方式的演变本质 = CPU 从"亲力亲为"到"甩手掌柜"，记住这条主线就串起来了。

## 记忆口诀

> **程序查询死等烦，中断打断去办，DMA 交底撒手搬运工整块搬，通道请个物流全托管——越往后 CPU 越闲。**
