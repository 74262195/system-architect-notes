# 共享内存与消息传递：多个处理器怎么交换结果

> [!summary] 快速复习卡片
> **共享内存**：多个处理单元访问共同地址空间，通过共享数据协作  
> **为什么要同步**：共同可见不代表修改顺序安全，并发写可能产生竞争  
> **消息传递**：各处理单元有相对独立内存，通过发送/接收显式交换数据  
> **适用直觉**：共享内存常见于多核/共享地址空间；消息传递更适合分布式和集群  
> **硬件层别混淆**：片内总线/片内互连是数据真正经过的硬件通路；共享内存/消息传递是通信方式  
> **不要混淆**：Flynn 分类看指令流/数据流；这里看处理单元之间怎么通信  
> **考试重点**：共享内存 → 同步；消息传递 → 显式通信


## 先定位：Flynn 分类完“怎么算”，这里开始讲“怎么交流”

上一站 [[Flynn分类法]] 是从**指令流和数据流**的角度给并行计算机分类，例如 SIMD、MIMD。它回答的是：

> **这些处理单元在执行什么样的指令和数据？**

但即使已经知道一个系统属于 MIMD，还没回答另一个问题：多个处理器算到一半，彼此需要对方的结果时，**数据怎么交过去？**

这就是本卡的主题：**并行计算的通信方式**。

- **Flynn 分类**：看“怎么并行计算”。
- **共享内存 / 消息传递**：看“并行单元怎么交换数据”。

因此它们不是同一套分类。一个 MIMD 系统既可以采用共享内存，也可以采用消息传递。

---

## 不是已经有片内总线了吗？

有。多个 CPU 核心之间确实需要靠**片内总线或其他片内互连**搬运数据。

但这里讲的是两个不同层次：

> **片内总线 / 片内互连：解决“数据从哪条硬件通路走”。**

> **共享内存 / 消息传递：解决“多个计算单元用什么方式交流”。**

所以它们不是二选一。

~~~mermaid
flowchart TD
    A[多个核心一起计算] --> B[需要交换结果]
    B --> C{采用什么通信方式}
    C --> D[共享内存]
    C --> E[消息传递]
    D --> F[底层真正传输数据]
    E --> F
    F --> G[片内总线 / Ring / Mesh / NoC / 网络]
~~~

例如 Core 0 算出一个结果，Core 1 要使用它：

- 从**通信模型**看：Core 0 写入共享地址空间，Core 1 再读取，这是**共享内存**。
- 从**硬件实现**看：这个数据仍然要经过 Cache、片内互连、内存控制器等硬件路径传过去。

因此：

> **共享内存讲“共享什么、怎么协作”，片内总线讲“数据实际怎么走”。**

现代多核处理器内部也不一定真是一根传统“总线”，还可能使用 Ring、Mesh、NoC 等片内互连。软考阶段统一理解成“核心之间的硬件传输通路”即可。

## 多个核心一起算，结果怎么交给别人

并行计算不只是“多个人同时干活”。A 算出的中间结果，B 往往还要继续使用。真正的问题变成：**处理单元之间怎么通信？**

## 共享内存：大家看同一块白板

多个处理器共享一个地址空间。一个处理器把结果写入共享内存，另一个处理器直接读取。

~~~mermaid
flowchart LR
    P1[处理器 1] <--> M[共享内存]
    P2[处理器 2] <--> M
~~~

优点是编程模型直观；代价是多个处理器同时访问和修改共享数据时，需要同步、锁以及缓存一致性等机制。

### 为什么共享内存需要同步

“共享”只解决了**大家都能看到同一份数据**，并没有规定大家修改它的先后顺序。

假设共享变量 `count = 10`，两个线程都要做 `count = count + 1`。这个看起来像一步的动作，实际通常至少包含：读旧值 → 加 1 → 写回。

如果两个线程都先读到 10，它们都算出 11，再分别写回，最终可能仍然只有 11，而不是预期的 12。

所以只要多个执行单元可能并发修改同一份可变数据，就需要锁、信号量、原子操作等同步手段来约束关键操作的顺序。

> **共享内存解决“数据放在共同哪里”，同步解决“大家什么时候能动这份数据”。**

## 消息传递：各自有本子，需要时寄消息

各处理单元拥有相对独立的内存，需要通过发送/接收方式显式交换数据。

这里同样不要和硬件通路混淆：

> **消息传递规定“发送/接收”这种通信方式；真正的消息仍然要依靠片内互连或网络传过去。**

### 为什么消息传递特别适合集群

集群通常由多台独立计算机组成。每台机器都有自己的物理内存，A 机器不能像访问自己 RAM 一样，直接用普通内存地址读取 B 机器的 RAM。

但机器之间本来就通过网络互连，因此最自然的协作方式是：

> **把任务、数据或计算结果封装成消息，通过互连网络发送给另一台机器。**

所以消息传递并不是“比共享内存更高级”，而是特别适合**物理内存彼此独立**的节点。常见的分布式/集群并行通常采用这种思路。

~~~mermaid
flowchart LR
    A[节点 A 私有内存] -->|发送消息| B[互连或网络]
    B -->|接收消息| C[节点 B 私有内存]
~~~

| 对比 | 共享内存 | 消息传递 |
| --- | --- | --- |
| 地址空间 | 共享 | 各自独立 |
| 数据交换 | 读写共同内存 | 显式发送/接收 |
| 典型问题 | 同步、锁、一致性 | 通信延迟、消息组织 |
| 常见场景 | 多核/多处理器共享内存系统 | 集群、分布式并行 |
| 与底层互连关系 | 最终仍要靠硬件互连传输 | 最终仍要靠硬件互连或网络传输 |

2023 年回忆资料中出现过“并行计算通信方式，共享内存和消息传递”的近年信号。

## 一句话记住

> **共享内存和消息传递讲“怎么交流”，片内总线/片内互连讲“数据怎么走”。**

> **共享内存是在同一块白板上协作，消息传递是各写各的本子、需要时互相发消息。**
