# Cache 替换算法：位置满了，新块进来该踢谁

## 先定位：替换算法不是决定“放哪里”，而是决定“满了踢谁”

上一站 [[Cache-映射方式]] 已经决定一个主存块**可以放到哪些 Cache 行**。如果候选位置还有空位，直接放进去即可。

只有当候选位置已经满了、又有新块需要进入时，才出现新的问题：

> **旧块里选谁离开，给新块腾位置？**

这就是 Cache 替换算法。LRU、LFU、FIFO、OPT 都是在回答同一个“牺牲谁”的问题，和映射规则是前后两个层次。


## 只有“可选位置”都满了才需要替换

直接映射的位置是固定的，不存在“从多个候选里选谁”的问题；全相联或组相联中的候选位置都满了，才需要替换策略。

| 算法 | 判定依据 | 题眼 |
| --- | --- | --- |
| **LRU** | 最久没有被访问 | “最近最少使用” |
| **LFU** | 累计使用次数最少 | “使用次数最少” |
| **FIFO** | 最早进入 | “先进先出” |
| **OPT** | 未来最长时间不会使用 | 理论最优、现实不可预知 |

最容易混的是 LRU 和 LFU：

- LRU 看**时间距离**。
- LFU 看**累计次数**。

## LRU 实际怎么更新

假设组内有 A、B、C，最近性从新到旧为：

A（最新）→ B → C（最旧）

如果访问 B，B 立刻变成最新，顺序更新为：

B → A → C

下一次需要替换时，优先淘汰 C。

## 一句话记住

> **LRU 看多久没碰，LFU 看一共碰几次，FIFO 看谁先来，OPT 看未来但现实看不到。**

2. 为什么 OPT 只能作为理论基准？
