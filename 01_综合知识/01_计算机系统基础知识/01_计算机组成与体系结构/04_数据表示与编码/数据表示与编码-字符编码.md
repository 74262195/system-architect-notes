# 字符编码：字符编号与实际字节为什么不是一回事

## 先定位：数值编码表示“数是多少”，字符编码表示“符号是谁”

计算机存储的仍是二进制。要保存字母、汉字或符号，必须先约定：

1. 每个字符对应什么编号；
2. 这个编号怎样编码成一个或多个字节。

把“字符编号”和“存储字节”分开，是理解 ASCII、Unicode 和 UTF-8 的关键。

## ASCII：编号和单字节表示几乎重合

ASCII 使用 7 位编码 128 个字符，包括英文字母、数字、标点和控制字符。实际存储常占一个字节，最高位为 0。

例如字符 A 的 ASCII 码为十六进制 41。ASCII 不能覆盖大量非拉丁文字。

## Unicode 与 UTF-8：码点不是字节序列

- **Unicode** 为字符分配码点，例如 A 是 U+0041，“中”是 U+4E2D。
- **UTF-8** 是 Unicode 的一种编码形式，把码点转换成 1～4 个字节。
- UTF-16、UTF-32 也是 Unicode 编码形式，不能把 Unicode 等同于 UTF-8。

| 字符 | Unicode 码点 | UTF-8 字节 |
| --- | --- | --- |
| A | U+0041 | 41 |
| 中 | U+4E2D | E4 B8 AD |

UTF-8 与 ASCII 在前 128 个字符上兼容：ASCII 字符的 UTF-8 表示仍是原来的单字节值。

~~~mermaid
flowchart LR
    A[抽象字符] --> B[Unicode码点]
    B --> C[选择UTF-8等编码]
    C --> D[得到实际字节序列]
    D --> E[存储或传输]
~~~

## 为什么会出现乱码

发送方按一种编码生成字节，接收方却按另一种编码解释时，同一串字节会被还原成错误字符，甚至被判为非法序列。因此协议和文件不仅要传字节，还应明确字符编码。

> **补充理解：** GB 2312、GBK 等是面向中文的传统编码体系，与 Unicode/UTF-8 不是同一套编号规则。做题若给出具体编码范围或字节规则，以题干为准。

## 考试怎么认

- ASCII → 7 位、128 个字符。
- Unicode → 统一字符码点体系。
- UTF-8 → Unicode 的变长字节编码，1～4 字节并兼容 ASCII。
- “一个 Unicode 字符固定等于两个字节”是错误的绝对说法。
