# Cache 命中率与平均访问时间：命中一次到底省了多少时间

## CPU 先翻桌面，没找到才去仓库

CPU 取数据时先查 Cache。命中就直接拿到；未命中才去更慢的主存。于是一次访问到底花多久，不取决于“Cache 有多快”这一项，而取决于**命中率和题目采用的时间口径**。

- 命中率：$h$
- Cache 访问时间：$T_c$
- 主存访问时间：$T_m$

### 口径一：命中与未命中是两个完整分支

若题目把 $T_m$ 直接视为一次未命中的总访问时间：

$$T=hT_c+(1-h)T_m$$

### 口径二：每次都先查 Cache

若题目明确“先查 Cache，未命中后再访问主存”：

$$T=T_c+(1-h)T_m$$

这两式不能混用，关键是看题目里的 $T_m$ 是否已经包含前面的 Cache 查询时间。

## 例子

$T_c=10ns$，$T_m=100ns$，$h=0.9$。若采用第一种口径：

$$T=0.9\times10+0.1\times100=19ns$$

命中率越高，平均访问时间越接近 Cache 的速度。

## 一个常考性质：对程序员透明

普通程序按统一地址访问数据，是否命中、从哪一级 Cache 取、替换哪一块通常由硬件自动处理，因此 Cache 对普通程序员通常是透明的。2009 年真题考过这一点。

## 一句话记住

> **平均时间先看题目口径；命中率越高越接近 Cache，Cache 是否命中通常由硬件自动处理。**

## 自测

1. 两种平均访问时间公式为什么不同？
2. 命中率从 90% 提高到 99%，平均时间为什么会显著下降？
3. “Cache 对程序员透明”是什么意思？
