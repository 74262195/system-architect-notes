# 中断技术：CPU 不轮询，设备怎样在需要时通知它

## 先定位：中断是 I/O 控制与异常处理的共同入口

[[IO控制技术]] 要解决 CPU 与慢速外设怎样协作。轮询让 CPU 反复查询设备状态；中断方式则让 CPU 先执行别的程序，事件发生时再转去处理。异常和程序主动陷入内核也会借用相近的控制转移机制，但来源与语义不同。

> [!important] 一句话结论
> 中断的价值不是“绝对最快”，而是让 CPU 不必忙等，并能及时处理突发事件。

## 参与者与关键状态

- **中断源**：外设、定时器等提出请求；异常则由当前指令执行触发。
- **CPU**：判断能否响应，保存返回所需状态并转移控制。
- **中断控制器/向量表**：完成请求汇聚、优先级判断或服务程序入口定位，具体实现因体系结构而异。
- **中断服务程序 ISR**：保存必要现场、处理事件、确认或清除中断源，然后返回。
- **屏蔽与优先级状态**：决定请求现在能否被接受，以及多个请求先处理谁。

## 完整过程：从请求到返回

~~~mermaid
flowchart LR
    A[设备请求] --> B[判断响应]
    B --> C[保存断点]
    C --> D[执行服务程序]
    D --> E[恢复并返回]
~~~

1. 设备完成 I/O 或发生事件，置位状态并发出中断请求。
2. CPU 通常在当前指令结束后的中断检查点，结合总允许位、屏蔽位和优先级判断是否响应。
3. CPU 保存返回地址和必要处理器状态；这部分常称**断点**。具体保存位置由体系结构规定，经典软考口径常答“栈”。
4. CPU 通过中断向量或体系结构规定的入口进入服务程序；服务程序再按约定保存通用寄存器等**现场**。
5. ISR 识别并处理事件，读取/写入设备状态，并确认或清除中断源。若未清除，返回后可能再次触发。
6. ISR 恢复现场，执行专用的中断返回指令，恢复先前状态并从断点继续。

> [!warning] 断点不等于全部现场
> 断点主要保证“回到哪里”；现场还包括寄存器、状态字等运行上下文。硬件保存哪些、软件再保存哪些，取决于体系结构和调用约定。

## 分类：先看触发来源与同步性

| 事件 | 来源与时机 | 典型例子 | 答题口径 |
| --- | --- | --- | --- |
| 外部中断 | CPU 外部、通常与当前指令异步 | I/O 完成、时钟 | 外中断/硬件中断 |
| 异常 | 当前指令执行导致、通常同步 | 除零、非法指令、缺页 | 内部异常 |
| 程序主动陷入 | 程序执行专用指令 | 系统调用、trap | 软件触发的异常/陷入 |

“内中断、软中断”的命名在教材和体系结构中并不完全统一。做题时先按题干定义；解释机制时优先使用“外部中断—同步异常—主动陷入”这组不易混淆的表述。

## 屏蔽、优先级与嵌套

- **屏蔽**回答“现在接不接”：不可屏蔽中断通常用于必须立即关注的严重事件；可屏蔽中断可被暂缓。
- **优先级**回答“多个请求先接谁”，由硬件、中断控制器配置和软件策略共同决定。
- **嵌套**表示处理低优先级中断时允许更高优先级请求打断。它能降低高优先级事件延迟，但会增加现场保存和栈空间压力。

## 考试视角与证据边界

- 题干说“对突发事件快速响应、CPU 不反复查询”时，优先想到中断 I/O。
- 题干问“断点信息一般保存在哪里”，经典软考答案是**栈**；这不是所有体系结构的普遍硬件定律。
- 仓库中的 2009 标准化题可支持上述经典口径，但其元数据标为“真题解析资料（来源待核验）”，不写成已核验官方原题。
- 2026 上半年公开回忆题只作为趋势信号，不能据此推断固定题型或必考结论。
