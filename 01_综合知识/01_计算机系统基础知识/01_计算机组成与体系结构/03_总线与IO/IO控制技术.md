# I/O 控制技术：数据传输时 CPU 到底参与多少

## 先定位：接口负责连接，控制方式负责组织传输

[[IO接口|I/O 接口]] 提供数据、状态和控制寄存器，解决 CPU 与设备怎样通信。I/O 控制方式进一步决定：设备未就绪时 CPU 是否等待、数据由谁逐次搬运、一次能管理多少设备和任务。

## 四种方式完整对比

| 方式 | 等待设备期间 | 数据主要由谁搬 | CPU 主要动作 | 题眼 |
| --- | --- | --- | --- | --- |
| 程序查询 | CPU 反复轮询 | CPU 指令 | 查询状态并逐次读写 | 忙等、轮询 |
| 中断驱动 | CPU 可执行别的程序 | CPU/中断服务程序参与 | 启动 I/O，事件到来后响应中断 | 突发事件、无需轮询 |
| DMA | CPU 可执行别的程序 | DMA 控制器在设备与主存间成块传送 | 初始化地址、方向和计数，处理完成通知 | 成块、直接存储器访问 |
| 通道 | CPU 可执行别的程序 | 通道按通道程序组织 I/O | 发出任务，通道管理多步操作和设备 | 专用 I/O 处理器、通道程序 |

CPU 参与程度总体下降，但不能简单写成“越往后一定越快”；设备速度、传输规模、硬件成本、总线竞争和中断开销都会影响实际性能。

## 四种方式各走一遍

### 程序查询

CPU 发出命令后循环读取状态寄存器；设备未就绪就继续查询，准备好后 CPU 再通过接口寄存器搬运数据。实现简单，但忙等占用 CPU。

### 中断驱动

CPU 启动设备后继续运行其他程序；设备就绪或完成时请求中断；CPU 保存断点并进入服务程序处理数据或状态，清除中断源后返回。一次中断传多少数据由设备和系统设计决定，不能一概说“只能搬一点”。

### DMA

~~~mermaid
flowchart LR
    A[CPU设置地址方向计数] --> B[DMA请求总线]
    B --> C[设备与主存成块传输]
    C --> D[更新地址和计数]
    D --> E{计数结束?}
    E -- 否 --> B
    E -- 是 --> F[中断通知CPU]
~~~

DMA 控制器可能采用周期窃取等方式取得总线。CPU 不逐字节执行搬运指令，但仍负责初始化、资源协调和完成处理。

### 通道

CPU 提交通道程序或 I/O 任务；通道独立解释并执行多步 I/O 控制，管理一个或多个设备，结束或异常时再通知 CPU。通道比 DMA 具备更强的 I/O 任务组织能力，但硬件和系统复杂度也更高。

## 考试怎么认

- “CPU 循环检查状态” → 程序查询。
- “设备完成后主动通知、适合突发事件” → 中断。
- “设备与主存成块传输、DMAC、周期窃取” → DMA。
- “通道程序、专用 I/O 处理器、管理多个设备” → 通道。
- 若四种方式同时比较 CPU 干预程度，通道通常少于 DMA；若选项只在程序查询、中断、DMA 中比较批量传输，则 DMA 更合适。
