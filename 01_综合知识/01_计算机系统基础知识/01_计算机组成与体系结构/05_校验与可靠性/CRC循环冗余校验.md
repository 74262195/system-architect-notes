# CRC：校验码到底怎么算

> [!summary] 快速复习卡片
> **作用**：强检错，主要不能纠错  
> **计算主线**：原数据补 0 → 模 2 除以生成多项式对应二进制 → 余数就是 CRC  
> **补几个 0**：除数有 n 位，就补 n-1 个 0  
> **模 2 除法**：把普通减法换成 XOR，不借位、不进位  
> **接收端判断**：同一除数再除；余数为 0 表示未检测到错误，非 0 表示检测到错误  
> **考试重点**：会判断补零位数、会求余数、知道 CRC 主要负责检错


## 先定位：CRC 是干什么的

上一站 [[奇偶校验]] 解决的是：数据传输或存储后，怎样发现某些比特被改错了。

CRC（循环冗余校验）也是一种**检错方法**，只是比简单奇偶校验更强。

它的基本思路可以先理解成：

> 发送端根据原始数据算出几位“校验尾巴”，跟着原数据一起发送；接收端再按相同规则检查一次。

CRC 这一题真正要学会的是：**这个“校验尾巴”怎么计算。**

---

## 生成多项式是什么

CRC 题目一般会给一个**生成多项式**。它不是考试时自己算出来的，而是双方事先约定好的计算规则。

例如题目给：

**G(x) = x³ + x + 1**

做题时把它转换成二进制：

| 位置 | x³ | x² | x¹ | x⁰ |
| --- | --- | --- | --- | --- |
| 是否出现 | 有 | 没有 | 有 | 有 |
| 二进制 | 1 | 0 | 1 | 1 |

所以：

**x³ + x + 1 → 1011**

后面计算 CRC 时，就把 **1011 当作除数**。

---

## CRC 怎么算：先记最简单的过程

以原始数据 **10110**、题目给出的生成多项式二进制 **1101** 为例。

`1101` 有 4 位，因此需要 3 位 CRC。原始数据后先补 3 个 0：

**10110 → 10110000**

然后直接做：

> **10110000 ÷ 1101，按照 CRC 的模 2 除法计算，得到余数 101。**

所以：

**CRC 校验码 = 101**

最终发送的数据为：

**10110 + 101 = 10110101**

先把这一条主线记住即可：

> **原数据补 0 → 除以生成多项式对应的二进制数 → 得到的余数就是 CRC。**

不需要把计算过程理解成“找 1”“消 1”或反复截取几位。

---

## 模 2 除法和普通除法有什么不同

上面的“除”不是普通二进制除法，而是 **模 2 除法**。

你只需要知道一个区别：

> **普通除法过程中使用减法；CRC 的模 2 除法把减法换成 XOR（异或）。**

XOR 的规则是：

| 两位数字 | XOR 结果 |
| --- | --- |
| 0 和 0 | 0 |
| 0 和 1 | 1 |
| 1 和 0 | 1 |
| 1 和 1 | 0 |

也就是：**相同得 0，不同得 1，而且没有借位和进位。**

### 手算时真正怎么往下除

考试手算可以记成：

> **看当前最高位：是 1 就和除数 XOR；是 0 就不 XOR。然后丢掉最高位，从原来补 0 后的数据中再拉下一位下来。一直做到没有下一位可拉，最后留下的 n-1 位就是 CRC。**

例如原始数据是 `1001`，生成码是 `1011`：

1. `1011` 有 4 位，所以先在 `1001` 后补 3 个 0，得到 `1001000`。
2. 先看前 4 位 `1001`，最高位是 1，所以和 `1011` XOR，得到 `0010`。
3. 从后面的原数据中拉下一位 `0`，当前变成 `0100`。最高位是 0，这一步不和 `1011` XOR，直接继续拉下一位。
4. 拉下一位后得到 `1000`，最高位是 1，再和 `1011` XOR，得到 `0011`。
5. 再拉最后一位 `0`，得到 `0110`。已经没有下一位可拉，保留最后 3 位，所以 CRC 是 `110`。

最终发送的数据是：**`1001 110` → `1001110`**。

> [!warning] 最容易错
> “首位为 0 就在后面自己补一个 0”这种说法不准确。**只能拉原来数据中还没处理的下一位；数据已经全部拉完时就停止。**

---

## 为什么补 3 个 0

这里不需要先研究复杂的多项式理论。

做题直接记规则：

> **生成多项式对应的二进制数有 n 位，CRC 就有 n-1 位，因此原始数据先补 n-1 个 0。**

本题除数是 `1101`，一共 4 位：

- CRC 有 3 位；
- 原数据后补 3 个 0；
- 最终得到 3 位余数 `101`。

因此：

**10110 → 补 000 → 10110000 → 除以 1101 → 余数 101。**

---

## 接收端怎么检查

发送端最终发送：

**10110101**

接收端拿到以后，仍然用双方约定的 `1101` 做模 2 除法。

- 余数为 `000`：没有检测到错误。
- 余数不为 `000`：检测到数据发生了错误。

CRC 的主要作用是**发现错误**，不能判断具体哪一位错了，也不能像 [[海明码]] 那样直接纠正某些错误。

---

## 软考做题时怎么记

看到 CRC 计算题，先抓住这一条：

> **原数据补 0 → 用补 0 后的完整数据除以生成多项式对应的二进制数 → 余数就是 CRC。**

例如：

> **10110 → 10110000 → 10110000 ÷ 1101 → 余数 101 → CRC = 101**

额外注意两点：

- 补几个 0：生成多项式二进制位数减 1。
- CRC 的“除法”是模 2 除法，过程中用 XOR，不是普通减法。

## 自测

1. 如果生成多项式对应二进制是 `10011`，原始数据后要补几个 0？
2. `10110000` 模 2 除以 `1101`，本例得到的余数是多少？
3. CRC 校验结果非 0，能否判断具体哪一位出错？
