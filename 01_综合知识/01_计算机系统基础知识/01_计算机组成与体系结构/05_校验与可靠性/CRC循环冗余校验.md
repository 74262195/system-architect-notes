# CRC：校验码到底怎么算

## 先定位：CRC 是干什么的

上一站 [[奇偶校验]] 解决的是：数据传输或存储后，怎样发现某些比特被改错了。

CRC（循环冗余校验）也是一种**检错方法**，只是比简单奇偶校验更强。

它的基本思路可以先理解成：

> 发送端根据原始数据算出几位“校验尾巴”，跟着原数据一起发送；接收端再按相同规则检查一次。

CRC 这一题真正要学会的是：**这个“校验尾巴”怎么计算。**

---

## 生成多项式到底是什么

CRC 题目一般会给一个**生成多项式**，它不是考试时自己发明出来的，而是双方事先约定好的计算规则。

例如题目给：

**G(x) = x³ + x + 1**

不要被“多项式”吓到。做题时只要从 x³ 一直看到 x⁰：

| 位置 | x³ | x² | x¹ | x⁰ |
| --- | --- | --- | --- | --- |
| 是否出现 | 有 | 没有 | 有 | 有 |
| 写成二进制 | 1 | 0 | 1 | 1 |

所以：

**x³ + x + 1 → 1011**

接下来计算 CRC 时，就把 **1011 当作除数**。

---

## CRC 计算先记住 4 步

以原始数据 **10110**、生成多项式二进制 **1101** 为例。

1. 看生成多项式最高次数，确定要补几个 0。
2. 在原始数据后补 0。
3. 用生成多项式做“模 2 除法”。
4. 最后剩下的余数，就是 CRC 校验码。

这里 `1101` 有 4 位，对应最高次数为 3，所以 CRC 有 **3 位**，原始数据后面先补 **3 个 0**：

**10110 → 10110000**

现在真正开始计算。

---

## 模 2 除法到底是什么

它长得像普通除法，但有一个关键区别：

**这里不做普通减法，而是做 XOR（异或）。**

你只需要记住：

| 两位数字 | XOR 结果 |
| --- | --- |
| 0 和 0 | 0 |
| 0 和 1 | 1 |
| 1 和 0 | 1 |
| 1 和 1 | 0 |

也就是：

> **相同得 0，不同得 1。**

而且没有借位，也没有进位。

---

## 完整手算：10110000 ÷ 1101

除数 `1101` 有 4 位，所以每次先看当前的 **4 位**。

### 第 1 步：取前 4 位 1011

当前是：

**1011**

最高位是 1，可以和除数 `1101` 做 XOR：

**1011 XOR 1101 = 0110**

最左边的 0 已经处理完，不再管它。保留后面的 `110`，再从原数据中拉下一位 `0`：

**110 → 拉下 0 → 1100**

### 第 2 步：计算 1100

**1100 XOR 1101 = 0001**

保留后 3 位 `001`，再拉下下一位 `0`：

**001 → 拉下 0 → 0010**

### 第 3 步：当前最高位是 0

现在得到 `0010`。

因为最高位是 **0**，这一步不能拿 `1101` 去除。

可以把它理解为：

**0010 XOR 0000 = 0010**

然后继续往下移动一位，保留后三位 `010`，拉下最后一个 `0`：

**010 → 拉下 0 → 0100**

### 第 4 步：已经没有下一位了

现在剩下 `0100`，最高位仍然是 0，因此不再和 `1101` 做 XOR。

CRC 只需要 3 位，所以取最后 3 位：

**100**

等等——如果按上面这种“窗口口述法”很容易在拉位时错位，所以考试手算更推荐下面的连续消元法。

---

## 更稳的算法：从左往右消掉每一个 1

还是计算：

**10110000 ÷ 1101**

从左往右看，只要当前位置是 1，就把 `1101` 对齐到这里做 XOR。

### 第一次消元

原数：`10110000`

把 `1101` 对齐最左边 4 位：

`1011 XOR 1101 = 0110`

整个数变成：

**01100000**

### 第二次消元

最左边已经是 0，继续往右找第一个 1。

现在从第 2 位开始的 4 位是 `1100`：

`1100 XOR 1101 = 0001`

整个数变成：

**00001000**

### 第三次消元

继续往右找 1。

现在这个 1 已经靠近末尾，能对齐的 4 位是 `1000`：

`1000 XOR 1101 = 0101`

整个数变成：

**00000101**

前面的位都已经消掉了，最后只剩 3 位：

**101**

所以 CRC 校验码就是：

**101**

最终发送的数据是：

**原始数据 10110 + CRC 101 = 10110101**

> 做题时推荐记“从左往右消 1”。看到 1，就让除数的最高位和它对齐，然后 XOR；看到 0 就跳过去。这样比机械模仿普通竖式除法更不容易错。

---

## 为什么一开始要补 3 个 0

生成多项式 `1101` 有 4 位，因此最高次数是 3。

这意味着最终 CRC 校验码需要 **3 位**。

所以发送端先在原始数据后面空出 3 个位置：

**10110 000**

经过计算得到余数 `101` 后，再把这 3 个 0 换成 `101`：

**10110 101**

所以可以直接记：

> **生成多项式有 n 位 → CRC 有 n-1 位 → 原始数据先补 n-1 个 0。**

---

## 接收端怎么检查

发送端最终发送：

**10110101**

接收端拿到以后，仍然用双方约定的 `1101` 做同样的模 2 除法。

- 最终余数是 `000`：没有检测到错误。
- 最终余数不是 `000`：检测到数据发生了错误。

注意：CRC 的主要作用是**发现错误**，不是告诉你具体哪一位错了，也不能像 [[海明码]] 那样直接纠正某些错误。

---

## 软考做题时只记这一套

看到 CRC 计算题：

**生成多项式转二进制 → 看最高次数 → 原数据补 0 → 从左向右用 XOR 消 1 → 最后几位余数就是 CRC。**

最容易错的地方有三个：补 0 的数量是生成多项式位数减 1；模 2 除法用 XOR，不是普通减法；最终取的余数位数也等于生成多项式位数减 1。

## 自测

1. `G(x)=x⁴+x+1` 转成二进制是多少？CRC 应有几位？
2. 模 2 运算中，`1011 XOR 1101` 等于多少？
3. 如果生成多项式是 `10011`，原始数据后面先补几个 0？
4. CRC 校验结果非 0，能够判断具体哪一位出错吗？
