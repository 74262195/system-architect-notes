# CPU 指令集：CISC 与 RISC 两条路线

## 痛点：CPU 该说复杂话，还是简单话？

CPU 干活靠的就是指令——一条指令就是一句"命令"，比如"把这两个数加起来"。问题是：**一条指令应该多复杂？**

想象两个厨师：

- **一位万事通老师傅**：一张菜谱上千道菜，每道菜都精心设计（"红烧肉""佛跳墙"都有专门做法），点啥会啥，但他记菜谱累、厨房设备贵。
- **一位只会简单活的快手**：菜谱只有几十道基础做法（切、炒、炖），复杂的菜靠"几道简单活组合"完成，他记的少、设备简单，但同一道复杂菜要组合很多步。

CISC 和 RISC 就是 CPU 的这两条路线。它们要解决的核心问题：**指令集设计成"复杂全能"还是"精简基础"，哪个更能让程序跑得快、硬件不贵？**

> 记一句：**CISC = 复杂的老师傅（指令大而全），RISC = 精简的快手（指令少而基础）。**

## 定义（讲人话）

- **CISC（复杂指令集计算机）**：指令又多又复杂，一条指令能完成很复杂的操作（如一条"字符串查找"）。硬件复杂，指令长短不一。
- **RISC（精简指令集计算机）**：经典设计强调少而规整的指令、较少寻址方式、Load/Store 和**较多通用寄存器**，复杂操作由多条指令组合；常见固定长度，也可能提供压缩指令编码。

## 为什么会提出 RISC？——一个关键观察

工程师发现一个规律：**程序里 80% 的时间，只用到 20% 的简单指令。**

也就是说，CISC 花大力气设计的一堆"复杂指令"，实际很少被用到；反而是那些简单指令在拼命跑。既然如此——不如把硬件做得简单（只支持简单指令、更快），复杂的操作靠编译器把多条简单指令拼出来。这正是 RISC 的诞生逻辑。

## 指令定长的巨大好处：喂给流水线

经典 RISC 指令通常**长度较固定、格式规整**，有利于取指、译码和流水线实现。现代 CISC 处理器会把复杂指令译成内部微操作，现代 RISC 也可能有扩展与压缩指令，两类架构在工程实现上已经互相借鉴。

> 这也是为什么 RISC 更适合流水线——**流水线的节奏由最慢的一段决定，CISC 指令长短不一会让流水线频繁等齐。**

## 这个知识与考试的关系

常考对比表，直接对照背：

| 对比项 | CISC | RISC |
| --- | --- | --- |
| 指令数量 | 多、复杂 | 少、基础 |
| 指令长度 | 常见变长 | 经典特征是较固定、格式规整 |
| 流水线实现 | 译码通常更复杂 | 经典设计更便于流水线 |
| 寻址方式 | 通常较丰富 | 经典模型中较少 |
| 寄存器 | 依具体实现 | 经典设计倾向更多通用寄存器以减少访存 |
| 控制实现 | 复杂指令常与微程序控制联系 | 规整指令常与硬布线控制联系 |
| 硬件复杂度 | 控制与译码较复杂 | 控制相对规整，但现代实现也可很复杂 |
| 代表 | 复杂指令集（x86 系） | ARM / RISC-V |

- **经典陷阱**：把"指令等长/流水线高效"说成 CISC 的特点 ❌（那是 RISC 的）
- **考点**：问"哪种指令定长→选 RISC"；问"流水线更高效→选 RISC"；问“更多寄存器、减少访存”也常指向 RISC。
- **控制器实现不要硬背成绝对规律**：经典考试常把 RISC 与硬布线、CISC 与微程序联系，真正机制见 [[硬布线控制与微程序控制]]。

## 记忆口诀

> **CISC 复杂、常见变长；RISC 规整、Load/Store、利于流水。记的是经典特征，不是给现代处理器判绝对输赢。**
