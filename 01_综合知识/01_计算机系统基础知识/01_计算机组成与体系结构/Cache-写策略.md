# Cache 写策略：CPU 改了数据，Cache 和主存怎样重新一致

## 先定位：先分“写命中”和“写未命中”

CPU 写地址时有两个连续问题：

1. 目标块已经在 Cache 中，什么时候更新主存？
2. 目标块不在 Cache 中，要不要先把它调入 Cache？

第一问对应写直达/写回，第二问对应写分配/不写分配。只记前一组会漏掉写未命中机制。

## 写命中：主存什么时候更新

| 策略 | 动作 | 优点 | 代价 |
| --- | --- | --- | --- |
| 写直达 Write Through | 同时更新 Cache 与下级存储 | 下级副本较新，控制直观 | 写流量较大，常需写缓冲 |
| 写回 Write Back | 先只更新 Cache 并置脏位 | 合并多次写，减少下级流量 | 替换脏块前必须回写，控制更复杂 |

写回过程不是简单“淘汰时丢掉旧块”：

~~~mermaid
flowchart LR
    A[选择牺牲行] --> B{脏位为1?}
    B -- 是 --> C[先回写主存]
    B -- 否 --> D[无需回写]
    C --> E[装入新块]
    D --> E
~~~

## 写未命中：要不要把块调入 Cache

| 策略 | 动作 | 常见搭配倾向 |
| --- | --- | --- |
| 写分配 Write Allocate | 先从下级存储装入该块，再在 Cache 中写 | 常与写回搭配 |
| 不写分配 No Write Allocate | 不装入 Cache，直接把本次写送往下级 | 常与写直达搭配 |

这些只是常见组合，不是不可改变的硬规则，具体取决于处理器设计和工作负载。

## 一次写操作怎么判断

1. 查找目标块并比较 Tag。
2. 命中：按写直达或写回策略修改。
3. 未命中：按写分配或不写分配决定是否装块。
4. 若装入位置需要替换，先检查旧块脏位。
5. 完成写入并更新有效位、脏位和替换状态。

## 易错点

- **Cache 与主存一致**不等于**多核 Cache 一致性**；后者还要处理多个核心各自缓存副本之间的关系。
- 写回减少主存写流量，但断电前尚未回写的数据只存在于 Cache，因此系统还需要相应可靠性设计。
- 写直达不是“没有 Cache”，数据仍可同时写入 Cache。
