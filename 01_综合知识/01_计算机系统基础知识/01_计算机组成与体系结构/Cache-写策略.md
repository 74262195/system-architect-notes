# Cache 写策略：Cache 改了，主存什么时候跟着改

## 先定位：写策略解决的是“Cache 和主存有两份数据，修改后怎样保持一致”

Cache 保存的是主存数据的高速副本。读数据时只要找到正确副本即可；但 CPU **修改**了 Cache 中的数据后，就会出现两份内容不一致的问题：Cache 已经是新值，主存可能还是旧值。

所以写策略并不是另一种替换算法，而是在回答：

> **CPU 写入数据时，主存应该立刻一起更新，还是先只改 Cache，等以后再写回？**

这就是写直达（Write Through）和写回（Write Back）的由来，也是 Cache 专题“命中 → 放置 → 替换 → 写入一致性”的最后一环。


## 读命中容易，写命中更麻烦

CPU 修改了 Cache 里的副本后，主存里的旧值怎么办？核心只有两条路线。

### 写直达（Write Through）

每次写 Cache 的同时也写主存。

- 一致性直观。
- 每次写都要碰主存，写流量更大。

### 写回（Write Back）

先只修改 Cache，并记录该块已变“脏”；等它被替换时再回写主存。

- 写性能更好。
- 需要脏位和更复杂的一致性管理。

| 对比 | 写直达 | 写回 |
| --- | --- | --- |
| 何时写主存 | 每次写 | 替换等时机 |
| 写流量 | 大 | 小 |
| 控制复杂度 | 低 | 高 |
| 关键词 | 同时写 | 脏块/脏位 |

## 一句话记住

> **写直达每次两边一起写；写回先欠着，淘汰脏块时再还给主存。**

## 自测

1. 写回为什么需要“脏位”？
2. 哪种策略主存写流量更大？
3. “写回更快”为什么不等于“实现更简单”？
