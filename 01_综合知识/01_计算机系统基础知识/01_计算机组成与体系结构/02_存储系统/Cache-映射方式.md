# Cache 映射方式：CPU 拿着地址，到底怎么在 Cache 里找到数据

## 先纠正一个很容易产生的误解

Cache 映射**不是**：

> 已经确定 Cache 命中了，然后再去 Cache 里找数据。

真实顺序刚好相反：

> **CPU 先拿着内存地址去 Cache 里找 → 根据地址缩小查找范围 → 比较标记 → 确认是自己要的数据后，才叫 Cache 命中。**

所以 Cache 映射真正解决的问题是：

> **主存里的某一块数据，进入 Cache 后允许放在哪里？CPU 下次再访问它时，应该先去 Cache 的哪里找？**

上一站 [[Cache-命中率与平均访问时间]] 讨论的是“命中以后能省多少时间”。

这一站开始回答更具体的问题：

> **CPU 怎么知道自己到底有没有命中？**

---

## 先把 Cache 想成一排快递柜

主存非常大，Cache 很小。

可以把：

- **主存**想成一个巨大的仓库；
- **Cache**想成 CPU 旁边的一排快递柜；
- 主存中的数据不是一个字节一个字节搬过来，而是通常**一次搬一小块**；
- Cache 中保存这一小块数据的位置，通常称为一个 **Cache 行**。

CPU 要数据时，不可能把所有 Cache 行一个个翻一遍。

所以 CPU 手里的地址除了告诉它“我要哪个数据”，还要帮助硬件完成三件事：

1. **先去 Cache 的哪里找；**
2. **看看那里放的是不是我要的那一块；**
3. **确认是以后，再从这一块里拿出具体位置的数据。**

这就是下面三个概念出现的原因。

---

## 行号 / 组号、Tag、块内偏移分别是干什么的

先不要管二进制位数，只记它们的职责。

| 地址中的信息 | 人话理解 | 作用 |
| --- | --- | --- |
| **行号 / 组号** | 去哪个快递柜或哪一排柜子找 | **先缩小查找范围** |
| **Tag（标记）** | 柜子里这份快递的“身份证” | **判断是不是我要的那一块** |
| **块内偏移** | 快递箱里具体拿第几个东西 | **命中后取出块里的具体数据** |

最重要的是顺序：

> **行号 / 组号负责“去哪找” → Tag 负责“是不是它” → 块内偏移负责“拿哪一个”。**

### 为什么光有行号还不够？

因为主存比 Cache 大得多。

假设 Cache 只有 8 个位置，但主存有成千上万个数据块。

那么不可能做到：

> 主存第 3 块永远放 Cache 第 3 行，主存第 11 块就有 Cache 第 11 行。

因为 Cache 根本没有那么多行。

因此，**不同的主存块可能会被安排到同一个 Cache 行或同一组里。**

这时 CPU 到了目标位置以后，还必须继续看 Tag：

- Tag 对得上 → 这里确实是我要的主存块 → **命中**
- Tag 对不上 → 虽然位置找对了，但里面现在放的是别的主存块 → **未命中**

---

## 块内偏移为什么要等到命中以后再看

因为 Cache 通常一次搬的是“一整块”，不是只搬 CPU 当前要的一个字节。

比如某个 Cache 行里现在保存了一小块连续数据：

| 块内位置 | 数据 |
| --- | --- |
| 第 0 个位置 | A |
| 第 1 个位置 | B |
| 第 2 个位置 | C |
| 第 3 个位置 | D |

CPU 先通过行号 / 组号和 Tag 确认：

> “对，就是这一整块。”

然后块内偏移再告诉 CPU：

> “我要这一块里的第 2 个位置。”

最后才拿到 C。

所以：

> **块内偏移不是用来判断是否命中的，而是在已经命中的块里选择具体数据。**

---

## CPU 实际查 Cache 的顺序

~~~mermaid
flowchart LR
    A[CPU 发出一个内存地址] --> B[根据地址定位 Cache 行或组]
    B --> C[读取候选位置中的 Tag]
    C --> D{Tag 是否匹配}
    D -- 是 --> E[Cache 命中]
    E --> F[根据块内偏移取出具体数据]
    D -- 否 --> G[Cache 未命中]
    G --> H[去主存等下级存储取数据]
~~~

你可以把它压缩成一句话：

> **先定位 → 再验身份 → 确认命中 → 最后取块里的具体数据。**

# 那“映射方式”到底改变了什么？

前面的查找逻辑都一样。

三种 Cache 映射方式真正不同的只有一个问题：

> **一个主存块，允许放到 Cache 的哪些位置？**

这会直接影响 CPU 第一步“去哪里找”。

---

## 直接映射：每个主存块只有一个固定位置

直接映射最严格。

可以理解成：

> **每一份快递都事先规定好了唯一的柜门。**

比如 Cache 有 8 行。

某几个不同的主存块，经过硬件规则后，都可能被规定只能使用 **Cache 第 3 行**。

于是会发生：

- 主存块 A 来了 → 放第 3 行；
- 主存块 B 也只能放第 3 行 → 把 A 换掉；
- CPU 又访问 A → 第 3 行已经是 B → 未命中；
- A 再装回来，又把 B 换掉。

这就是直接映射最典型的问题：

> **明明 Cache 其他地方可能还有空位，但这两个主存块因为都只能去同一个位置，还是会互相打架。**

### CPU 怎么找？

非常简单：

1. 地址直接告诉 CPU 去哪个 Cache 行；
2. CPU 只查这一行；
3. 比较这一行的 Tag；
4. Tag 一样才命中。

所以直接映射：

> **找得最快、硬件简单，但容易出现固定位置冲突。**

---

## 全相联映射：主存块可以放 Cache 的任何位置

全相联最自由。

相当于：

> **快递来了，只要哪个柜子空，就可以放哪个柜子。**

这样就不会出现：

> “明明旁边有空柜子，但因为你只能用第 3 个柜子，所以必须把别人赶出去。”

好处是空间利用灵活。

但是 CPU 下次再来找时就麻烦了：

> “它上次到底放哪儿了？”

因为没有固定行号可以直接定位，所以硬件需要同时检查很多 Cache 行的 Tag，寻找哪个 Tag 与目标匹配。

因此全相联：

> **放得最自由，冲突少，但查找硬件更复杂。**

---

## 组相联映射：先规定一组，组里面随便坐

组相联就是直接映射和全相联之间的折中。

它先把 Cache 分成几组。

例如：

- 第 0 组：有 2 行
- 第 1 组：有 2 行
- 第 2 组：有 2 行
- 第 3 组：有 2 行

一个主存块会被规定：

> **你只能去第 3 组，但是第 3 组里的两个位置你可以任选。**

这就是所谓的 **2 路组相联**：

> 一个组里有 2 个 Cache 行，所以同一组里可以同时容纳 2 个符合条件的主存块。

CPU 查找时：

1. 地址先告诉 CPU 去哪个组；
2. CPU 只检查这个组；
3. 比较组内几个 Cache 行的 Tag；
4. 找到匹配的那个就算命中。

因此组相联可以理解成：

> **直接映射：只能坐指定座位。**  
> **全相联：全场随便坐。**  
> **组相联：只能进指定区域，但区域里随便坐。**

---

## 把三种方式放到同一个场景里看

假设 Cache 有 8 行，现在有 3 个经常访问的主存块 A、B、C。

### 直接映射

硬件规则恰好让 A、B、C 都只能去第 3 行。

结果：

> 三个人抢一个座位，来一个换一个。

冲突最大。

### 2 路组相联

8 行被分成 4 组，每组有 2 行。

A、B、C 都属于第 3 组。

现在第 3 组有两个座位：

> A 和 B 可以同时坐下，C 来时才需要考虑换掉谁。

比直接映射缓和很多。

### 全相联

A、B、C 可以去整个 Cache 的任意空位。

> 只要还有空位置，它们基本不用互相赶走。

但 CPU 查找时需要检查更大的范围。

---

## 映射和“替换算法”不是一回事

这两个知识点很容易连在一起后混掉。

**映射方式**解决的是：

> **这个主存块允许去哪里？**

**替换算法**解决的是：

> **允许去的位置都满了，现在应该踢掉谁？**

例如 2 路组相联中，一个主存块只能进入第 3 组。

如果第 3 组两个位置都满了，新数据又必须进入第 3 组，这时才需要 [[Cache-替换算法]] 决定：

> 留谁，换掉谁？

---

## 考试看到这些词怎么认

| 题目描述 | 对应映射 |
| --- | --- |
| 一个主存块只能去唯一一个 Cache 行 | **直接映射** |
| 一个主存块可以放到任意 Cache 行 | **全相联映射** |
| 一个主存块只能进入固定组，但组内位置任选 | **组相联映射** |

如果题目出现 **Tag、行号/组号、块内偏移**，先不要急着算二进制。

先在脑子里翻译：

> **去哪找 → 是不是它 → 拿哪一个。**

等这个动作顺序理解以后，再做地址位数题会容易很多。

---

## 一句话记住

> **Cache 映射不是“命中以后怎么找”，而是 CPU 拿着地址先决定去哪里找，再用 Tag 判断是否命中；真正命中以后，才用块内偏移取出这一块里的具体数据。**

三种映射方式只是在改变：

> **一个主存块到底允许放在 Cache 的哪些位置。**
