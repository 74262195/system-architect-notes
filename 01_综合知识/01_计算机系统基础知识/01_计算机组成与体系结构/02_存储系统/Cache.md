# Cache：高速缓存专题入口

## 先定位：Cache 到底是什么，放在存储体系哪里

在 [[存储层次与局部性]] 中已经知道：CPU 很快，主存相对慢，如果 CPU 每次都直接等主存，处理器会浪费大量时间。

**Cache（高速缓存）** 就是放在 **CPU 与主存之间** 的一小块高速存储，用来暂时保存 CPU 最近或很可能马上还会访问的数据和指令。

它不是另一块“长期保存文件的硬盘”，也不是用来替代主存的大容量内存。它承担的是：

> **用少量更快的存储，尽量挡住 CPU 对慢速主存的大量访问。**

前面的“局部性”解释了为什么热点数据值得缓存；接下来这个专题才继续拆成“命中了能省多少 → 主存块放哪里 → 满了换谁 → 写入时主存什么时候更新”。


Cache 的主问题只有一句话：

> **CPU 比主存快得多，怎样用一小块更快的存储降低平均访问时间？**

这个问题继续分成四个可独立出题的机制，因此不再全部塞在一张正文里：

1. [[Cache-命中率与平均访问时间]]：命中率、两种时间口径、对程序员透明。
2. [[Cache-映射方式]]：直接、全相联、组相联。
3. [[Cache-替换算法]]：LRU、LFU、FIFO、OPT。
4. [[Cache-写策略]]：写直达与写回。

> [!tip] 学习顺序
> 先算“命中是否真的带来收益”，再看“放哪里 → 满了踢谁 → 写入时何时同步主存”。
