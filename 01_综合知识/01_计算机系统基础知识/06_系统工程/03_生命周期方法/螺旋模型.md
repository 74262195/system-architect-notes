# 螺旋模型（Spiral Model）

> **软考定位**：**“瀑布 + 迭代 + 风险分析”** 三合一，关键词 **“风险驱动”** 。看到“风险”两个字，第一时间想到它。

---

## 一、一句话定义

**螺旋模型** 由 **Barry Boehm** 于 1988 年提出，是一种 **风险驱动** 的生命周期模型，将系统的每次迭代都分为四个象限（目标 → 风险 → 开发 → 计划），像螺旋一样一圈一圈向外扩展。

> **核心思想**：**“每一步都想清楚风险再走，走一步看三步。”**

---

## 二、螺旋结构四象限

| 象限 | 任务 | 大白话 |
| :--- | :--- | :--- |
| **第1象限** | **目标设定** | 这一轮要达到什么目标？有哪些约束？ |
| **第2象限** | **风险分析** | 有哪些风险？怎么应对？（**最重要！**） |
| **第3象限** | **开发与测试** | 做出本轮的原型并验证 |
| **第4象限** | **计划下一轮** | 下轮要做什么？怎么规划？ |

---

## 三、核心特点

| 特点 | 大白话 |
| :--- | :--- |
| **风险驱动** | 每走一步先评估“这样做会不会出事” |
| **循环迭代** | 每一圈都生成一个新版本，逐步完善 |
| **结合原型** | 每轮都会构建原型用于风险验证 |
| **严格要求** | 适合**高风险、大规模、长周期**项目 |

---

## 四、适用场景

| ✅ 适合 | ❌ 不适合 |
| :--- | :--- |
| **高风险**项目（如航天、核电、军工） | 低风险、简单项目（用瀑布就够了） |
| 大规模、长周期的复杂项目 | 小团队、快速迭代的互联网项目 |
| 需求不确定但必须保证安全性的项目 | 预算有限、无法承担频繁风险分析的项目 |

---

## 五、螺旋 vs 其他模型（考场对比）

| 对比维度 | **螺旋模型** | **瀑布模型** | **迭代模型** |
| :--- | :--- | :--- | :--- |
| **核心驱动** | **风险** | 文档 | 反馈 |
| **是否包含风险分析** | ✅ 每轮都做 | ❌ 基本不做 | ⚠️ 可选 |
| **灵活性** | 中等（有结构但能调整） | 低（非常僵化） | 高 |
| **适用场景** | 高风险、超大规模 | 需求稳定、小规模 | 需求可变、中等规模 |

---

## 六、一句话总结

> **“高风险项目用螺旋，风险越低越不用它。”** 看到题干有“风险分析”“风险驱动”，立刻锁定螺旋模型。
