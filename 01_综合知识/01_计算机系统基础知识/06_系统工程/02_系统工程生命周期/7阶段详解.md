# 系统工程生命周期：一个系统从想法到退出，到底经历哪 7 个阶段

## 先定位：为什么学完“方法”又开始讲“生命周期”

前面的霍尔、切克兰德、并行工程、综合集成法回答的是：

> **面对复杂系统问题，可以用什么方法思考和组织工作？**

生命周期换了一个问题：

> **一个系统从最早的想法开始，到最后停止使用，时间上会经历哪些阶段？**

教材给出 7 个一般生命周期阶段。

## 七个阶段分别在干什么

| 阶段 | 教材核心目标 | 先用人话记 |
| --- | --- | --- |
| 探索性研究 | 识别利益攸关者需求，探索创意和技术 | 有什么需求和可能性？ |
| 概念 | 细化需求，探索可行概念和候选解决方案 | 大体要做成什么？ |
| 开发 | 细化系统需求，构建并验证/确认系统 | 把方案真正做出来 |
| 生产 | 生产系统并检验、验证 | 把系统形成可交付产品 |
| 使用 | 运行系统以满足用户需求 | 真正在环境里提供服务 |
| 保障 | 提供持续的系统能力 | 维护、支持，让它继续可用 |
| 退役 | 存储、归档或退出系统 | 有序结束和退出 |

记忆顺序：

> **探 → 概 → 开 → 生 → 使 → 保 → 退**

## 最容易混的三组

### 探索性研究 vs 概念

探索性研究更早，重点是识别需求、探索创意和技术。

概念阶段是在这些探索基础上继续细化需求，并形成有希望实现的解决概念。

### 使用 vs 保障

- **使用**：系统本身正在提供预期服务；
- **保障**：为了让它持续具有这种能力而做维护、支持和改进。

两者在现实中可以同时存在，不是“先把使用阶段完全结束，再进入保障”。

### 退役不是临时想起来的

教材特别强调退出计划可以在较早阶段就被考虑。系统工程看的是全生命周期，不应该等系统坏到不能用时才第一次考虑怎么退出。

## 为什么这 7 个阶段不能和霍尔时间维混

[[霍尔三维结构]] 的时间维也有 7 项：

规划 → 拟订方案 → 研制 → 生产 → 安装 → 运行 → 更新。

名字和生命周期七阶段并不相同，因为它们属于**两套不同框架**。下一篇专门比较。

## 一句话记住

> **生命周期七阶段回答“系统一生走到哪一段”；方法论回答“面对系统问题怎么组织和分析”。**

## 自测

1. 探索性研究和概念阶段的先后关系是什么？

> [!answer]- 第 1 题答案与解析
> **答案**：先探索性研究，后概念阶段。
> **解析**：前者识别利益攸关者需求并探索创意、技术；后者在此基础上细化需求和候选解决方案。

2. 使用阶段和保障阶段为什么可能同时发生？

> [!answer]- 第 2 题答案与解析
> **答案**：系统提供服务时，仍需维护、支持和改进以保持持续能力。
> **解析**：保障不是使用结束后的单独阶段，而是支撑系统持续可用的活动。

3. “规划、拟订方案、研制”属于本卡七阶段吗？

> [!answer]- 第 3 题答案与解析
> **答案**：不属于，它们属于霍尔三维结构的时间维。
> **解析**：系统生命周期使用“探索性研究、概念、开发、生产、使用、保障、退役”这组名称。
