# 位示图：文件系统怎样知道“哪个磁盘块还空着”

> [!summary] 快速复习卡片
> **作用/定位**：文件系统位示图用 1 个 bit 对应 1 个磁盘物理块，解决“哪些盘块空闲、哪些已占用”。
> **核心结论**：题目问位示图大小时，先算磁盘一共有多少物理块；一个块对应 1 bit，再按题目要求换成“位、Byte、字”等单位。
> **2020真题抓手**：300GB 磁盘、4MB 物理块 → 76,800 个块 → 需要 76,800 bit；字长 32 bit → **2,400 个字**。
> **块号定位题**：若问某块对应位示图哪里，再用“商定位第几个字/单元，余数定位单元内第几位”。这里定位的是**记录该磁盘块占用状态的 bit**，不是文件数据本身的位置。
> **易错点**：先确认编号从 0 还是 1 开始、0/1 谁代表空闲；本卡管磁盘块，[[页框位图]] 管物理内存页框。

## 先定位：知道一个文件怎么占块以后，还要知道哪些块可以分配

[[文件物理结构与分配方式]] 和 [[文件多级索引]] 都在研究：

> **已经属于某个文件的数据块怎样被找到。**

创建新文件或文件增长时，系统还要解决：

> **整个磁盘还有哪些物理块没有被占用？**

这叫空闲空间管理。

## 位示图是什么

位示图（Bitmap）给每个物理块安排一个二进制位。

例如约定：

- 0 = 空闲；
- 1 = 已占用。

那么某个位的状态就能表示对应物理块能不能分配。

## 先分清：块号、字长、字号、字内位号

位示图本质是一长串 0 和 1。每一个 bit 只负责记录**一个磁盘物理块是否空闲/已占用**。

为了方便处理，题目常把这些 bit 按“字”分组。例如：

- **块号**：磁盘物理块本身的编号，例如“磁盘块 36”。
- **字长**：一个字里有多少个 bit。例如字长为 16 位，就是每 16 个 bit 分成一组；因此一个字能记录 16 个磁盘块的占用状态。
- **字号**：位示图按字长分组后，第几个字。
- **字内位号**：这个字内部的第几个 bit。

> [!important] 最关键的区别
> **磁盘块 36** 是真正存放数据的磁盘块；位示图中的“某字某位”只是一个 0/1 标志，用来记录“磁盘块 36 现在是否被占用”。

## 为什么要用“块号 ÷ 字长”求商和余数

假设：

- 一个字 = 16 bit；
- 要查询的磁盘块号 = 36；
- 块号、字号、字内位号都从 0 开始编号。

那么位示图中的分组关系是：

| 位示图中的字 | 负责记录哪些磁盘块的状态 |
|---|---|
| 第 0 个字 | 块 0～15 |
| 第 1 个字 | 块 16～31 |
| 第 2 个字 | 块 32～47 |

现在计算：

> **36 ÷ 16 = 2 余 4**

这里的 `36 ÷ 16` **不是在计算“块 36 的数据存在哪里”**，而是在计算：

> **位示图中的哪一个 bit，负责记录磁盘块 36 是否被占用？**

计算结果这样解释：

- **商 2 → 字号 2**：负责记录块 36 状态的 bit 在位示图的第 2 个字里；
- **余数 4 → 字内位号 4**：具体是第 2 个字中的第 4 位。

对应关系就是：

```text
第 2 个字负责块 32～47

bit 0  → 块 32
bit 1  → 块 33
bit 2  → 块 34
bit 3  → 块 35
bit 4  → 块 36  ← 这一位记录块 36 是否占用
bit 5  → 块 37
...
bit 15 → 块 47
```

所以正确结论是：

> **磁盘块 36 的数据仍然在磁盘块 36。位示图第 2 个字的第 4 位，只负责记录磁盘块 36 当前是空闲还是已占用。**

### 做题时只记这一条

从 0 开始编号时：

> **块号 ÷ 每字位数 → 商找“第几个字”，余数找“字内第几位”。**

也就是说：

> **商和余数的作用，是定位“位示图中的状态位”，不是定位文件数据本身。**

如果题目从 1 开始编号，则必须按题目的编号规则调整，不能直接套从 0 开始的结果。

## 还有哪些经典空闲管理方法

主教材还提到：

- 空闲区表：记录连续空闲区的起始块和长度；
- 空闲块链：把空闲块链接起来；
- 成组链接：把空闲块进一步分组组织。

但计算题最常见的是位示图的编号转换。

## 一句话记住

> **文件索引回答“我的数据在哪”；位示图回答“还有哪里没被别人占”。**
