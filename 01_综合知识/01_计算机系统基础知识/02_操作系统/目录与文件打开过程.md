# 目录与文件打开：路径怎样变成可读写的句柄

> [!summary] 快速复习卡片
> **作用/定位**：目录负责把路径中的名字逐级解析到文件控制信息；“打开文件”则把磁盘上的文件信息变成进程可使用的打开状态。
> **核心结论**：典型过程是沿路径查目录项 → 找到对应 FCB/inode → 检查权限等条件 → 建立/引用打开文件表项 → 给进程返回文件描述符或句柄。
> **经典题型怎么做 / 题干怎么认**：看到“路径解析”先想目录项和 inode；看到“open 后反复 read/write 为什么不用每次重新查路径”时，想到打开文件表与进程句柄。
> **易错点 / 考试重点**：文件描述符/句柄不是文件内容，也不是 inode 本身，而是进程访问已打开文件的入口。

## 先定位：目录解决按名定位，open 建立本次访问状态

路径名是人和程序使用的名字；read/write 通常不每次重新解析路径，而是使用 open 返回的文件描述符或句柄。不同操作系统的数据结构名称不同，下面描述共同机制。

## 完整打开与读取过程

~~~mermaid
flowchart LR
    A[解析路径] --> B[查目录项]
    B --> C[取元数据]
    C --> D[建立打开记录]
    D --> E[返回句柄]
~~~

1. 从根目录或当前目录开始，逐段解析路径，并检查沿途目录的搜索权限。
2. 在目录中查找名字，得到 FCB、inode 号或等价文件标识。
3. 读取元数据，检查目标类型、打开模式与访问权限。
4. 建立或复用系统级打开文件记录；为本进程建立描述符/句柄表项。
5. read/write 通过句柄找到打开记录，使用当前偏移和块映射访问数据。
6. 操作推进偏移；close 减少引用，必要时刷新数据并释放运行时记录。

## 哪些状态属于哪里

| 信息 | 典型归属 | 原因 |
| --- | --- | --- |
| 文件名 | 目录项 | 一个文件可有多个名字 |
| 权限、大小、块地址 | FCB/inode 等元数据 | 描述持久文件对象 |
| 打开模式、当前偏移 | 打开文件记录/句柄相关状态 | 描述一次打开实例 |
| 进程可用编号 | 进程的描述符表 | 每个进程命名自己的打开对象 |

> [!warning] 当前偏移不总是“文件自身唯一属性”
> 同一文件可被多次打开，每次打开可能有独立偏移；复制描述符或特定共享方式又可能共享同一打开记录。做题按题干的表项层次判断。

## 考试怎么认

- 路径解析失败：先看目录项或权限，不要直接归因于数据块。
- open 成功但 read 失败：还可能是打开模式、偏移、介质错误等。
- 文件名、inode、文件描述符分别属于命名、持久元数据、进程运行时引用三个层次。
