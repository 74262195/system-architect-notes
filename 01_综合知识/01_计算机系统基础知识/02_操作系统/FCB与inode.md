# FCB 与 inode：它们记录文件，不记录进程

> [!summary] 快速复习卡片
> **作用/定位**：FCB 和 inode 都用于保存文件的管理信息，让文件系统知道“这个文件是谁、有什么属性、数据放在哪里”。
> **核心结论**：进程状态保存在 **PCB**；文件说明信息保存在 **FCB 或同类元数据结构**。inode 是类 Unix 文件系统中的具体设计，通常不保存文件名。
> **题干怎么认**：进程状态/现场 → PCB；文件属性和存储位置 → FCB；类 Unix、文件名与元数据分离 → 目录项 + inode。
> **易错点 / 考试重点**：FCB 不是磁盘数据块，inode 也不是文件名；它们保存的是管理文件和定位数据块所需的信息。

## 先纠正最容易混的地方：你记得的是 PCB

**PCB（Process Control Block，进程控制块）**记录进程状态；**FCB（File Control Block，文件控制块）**记录文件信息。两者只是在名称上相似。

| 对比 | PCB | FCB |
| --- | --- | --- |
| 管理对象 | 进程 | 文件 |
| 典型内容 | 进程状态、寄存器现场、调度与内存信息 | 文件类型、大小、权限、时间和存储位置等 |
| 生命周期 | 随进程创建，进程结束后撤销 | 随文件存在，进程退出后文件仍然存在 |
| 主要位置 | 内核管理的内存结构 | 文件系统持久保存，使用时可把相关信息装入内存 |

> [!tip] 一眼区分
> **P = Process，PCB 管进程；F = File，FCB 管文件。**

PCB 中可以记录进程打开了哪些文件，但这不意味着文件信息存放在 PCB 中。PCB 只是通过文件描述符等运行时结构，间接引用文件对应的 FCB/inode。

## 为什么文件不能只保存内容

主教材把一个文件区分为**文件体**和**文件说明**：

- **文件体**：文件真正的数据，例如文档文字、图片内容或程序代码；
- **文件说明**：操作系统管理文件所需的信息，例如文件类型、长度、权限、时间和存储位置。

如果磁盘只保存文件体，操作系统就不知道：

- 这串数据属于哪个文件；
- 文件有多大、谁能访问；
- 文件的数据分散在哪些磁盘块中。

因此，文件系统必须为每个文件保存一份管理记录。操作系统教材通常把这种记录称为 **FCB**。

> [!important] FCB 的定位
> FCB 不保存文件的正文内容，而是保存“怎样识别、管理并找到这个文件”的信息。真正的文件内容仍然保存在磁盘数据块中。

## FCB 通常记录什么

| 信息类别 | 典型内容 | 解决的问题 |
| --- | --- | --- |
| 标识信息 | 文件内部标识，部分模型也包含文件名 | 这是哪个文件 |
| 属性信息 | 类型、大小、所有者、时间 | 文件是什么状态 |
| 保护信息 | 读、写、执行等权限 | 谁可以怎样访问 |
| 位置或索引信息 | 起始块、块指针、索引入口等 | 文件内容放在哪里 |

FCB 是通用名称，具体字段和保存方式取决于文件系统。有的教材模型把目录项本身看作 FCB 或让它包含完整文件说明；有的系统则把“文件名”和“文件元数据”拆开保存。

## inode 与 FCB 到底是什么关系

**inode（索引节点）**是类 Unix 文件系统中保存文件元数据和数据块定位信息的一种具体结构。

| 对比 | FCB | inode |
| --- | --- | --- |
| 所在层次 | 通用文件管理概念 | 类 Unix 文件系统的具体设计 |
| 主要作用 | 描述并管理一个文件 | 保存文件元数据并定位数据块 |
| 是否保存文件名 | 取决于教材模型或文件系统实现 | 通常不保存 |
| 怎样按名找到它 | 取决于目录组织方式 | 目录项保存“文件名 → inode 号” |

因此，在软考学习中可以把 inode 理解为：

> **类 Unix 文件系统实现 FCB 核心职责的一种方式。**

但不能把二者说成所有系统中完全相同的结构。FCB 是通用概念，inode 带有明确的 Unix/Linux 实现语境。

## 类 Unix 系统怎样从文件名找到内容

假设目录中有文件 `report.txt`：

```mermaid
flowchart LR
    A["文件名"] --> B["目录项"]
    B --> C["inode 号"]
    C --> D["inode"]
    D -->|"块指针或索引"| E["磁盘数据块"]
```

完整过程是：

1. 目录项记录 `report.txt` 对应哪个 inode 号；
2. 文件系统根据 inode 号找到对应 inode；
3. inode 提供文件类型、大小、权限等属性；
4. inode 中的块指针或索引入口帮助文件系统找到磁盘数据块；
5. 文件系统从数据块中读取真正的文件内容。

这里三种信息不能混：

| 信息 | 保存在哪里 |
| --- | --- |
| 文件名 `report.txt` | 目录项 |
| 文件属性和块定位信息 | inode |
| 文件真正内容 | 磁盘数据块 |

具体的直接地址、一级间接地址和二级间接地址怎样寻找数据块，在 [[文件多级索引]] 中单独学习。

## 没有进程访问时，inode 还存在吗

存在。文件属于文件系统，不属于某个正在运行的进程。即使没有程序打开它，目录项、inode 和数据块仍然保存在文件系统中。

当进程打开文件后，只是建立了一条运行时引用：

```mermaid
flowchart LR
    A["进程文件描述符"] --> B["打开文件记录"]
    B --> C["FCB 或 inode"]
    C --> D["磁盘数据块"]
```

- **FCB/inode**描述长期存在的文件；
- **打开文件记录**描述这一次打开，例如当前读取位置和打开方式；
- **文件描述符**是进程访问这次打开记录时使用的编号。

因此，当前读取位置通常不应理解为文件唯一的永久属性：同一个文件可以被多次打开，每次打开可以拥有不同的读取位置。详细过程见 [[目录与文件打开过程]]。

> [!note] 补充理解：为什么 inode 通常不保存文件名
> 文件名属于目录中的命名关系，而 inode 表示文件对象本身。多个目录项可以指向同一个 inode，这就是硬链接能够存在的基础。理解这层关系即可，硬链接不是本卡的主线。

## 考试怎么认

- “进程存在的标志、保存运行现场、进程状态” → **PCB**。
- “操作系统为管理文件而设置的数据结构” → **FCB**。
- “类 Unix、索引节点、文件名通常不在其中” → **inode**。
- “文件名与 inode 号的对应关系” → **目录项**。
- “文件真正的数据” → **磁盘数据块**。
- “当前读取位置、打开方式” → **打开文件记录**，不要直接归给 inode。

> [!warning] 常见错误
> 1. 把 FCB 记成记录进程状态——记录进程状态的是 PCB。  
> 2. 把 inode 记成文件名——文件名通常在目录项中。  
> 3. 把 inode 记成文件内容——inode 保存元数据和定位信息，内容在数据块中。  
> 4. 把文件逻辑块到磁盘物理块的映射归给进程页表——页表管理虚拟页到内存页框；文件块映射由 FCB/inode 及其分配结构管理。

## 一句话记住

> **PCB 管进程；FCB 管文件；inode 是类 Unix 文件系统中保存文件元数据和块定位信息的具体结构；文件名通常在目录项，内容在数据块。**

## 自测

1. 记录进程状态的是 PCB 还是 FCB？
2. 类 Unix 系统中，文件名通常记录在目录项还是 inode 中？
3. inode 保存文件内容本身吗？如果不保存，它怎样帮助找到内容？
4. 没有任何进程打开文件时，inode 是否仍然存在？

### 答案

1. PCB；FCB 记录文件管理信息。
2. 目录项；目录项把文件名关联到 inode 号。
3. 不保存。inode 通过块指针或索引入口帮助文件系统定位磁盘数据块。
4. 存在。inode 属于持久文件系统，不依赖某个进程是否正在运行。
