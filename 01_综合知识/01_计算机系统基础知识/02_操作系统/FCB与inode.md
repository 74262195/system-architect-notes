# FCB 与 inode：怎样找到文件的数据块

> [!summary] 快速复习卡片
> **FCB**：操作系统为管理文件而设置的文件说明信息。
> **inode**：类 Unix 文件系统中承担 FCB 核心职责的具体结构。
> **核心链路**：文件名 → 父目录项 → inode 号 → inode → 磁盘数据块。
> **职责边界**：文件名通常在目录项中；属性和块定位信息在 inode 中；正文在数据块中。
> **易错点**：inode 不保存文件正文；进程页表也不负责文件逻辑块到磁盘块的映射。

## 先抓住 FCB

文件不仅要保存正文，还要保存大小、权限以及正文位于哪些磁盘块等管理信息。这些文件说明信息统称为 **FCB（文件控制块）**。

**PCB 管进程，FCB 管文件**；名称相似，但不是同一种结构。

FCB 是一个通用概念，具体字段由文件系统决定，通常包括：

- 文件属性：类型、大小、权限、时间等；
- 文件定位信息：起始块、块指针或索引入口等。

真正的文件内容不在 FCB 中，而在磁盘数据块中。

## inode 与 FCB 的关系

| 概念 | 重点 |
| --- | --- |
| FCB | 文件管理记录的通用概念，具体形式因文件系统而异 |
| inode | 类 Unix 文件系统中的具体元数据结构，承担 FCB 的核心职责 |
| 目录项 | 保存文件名，并把文件名关联到 inode 号 |
| 数据块 | 保存文件的真正内容 |

inode 通常保存文件类型、大小、权限、时间，以及定位文件数据块所需的**块指针或索引入口**；它通常不保存文件名。

因此不要机械地说“inode 就等于所有系统中的 FCB”。更准确的理解是：

> **FCB 是通用概念，inode 是类 Unix 文件系统实现这类文件管理信息的一种具体结构。**

## 从文件名到文件内容

假设父目录中有文件 `report.txt`：

```mermaid
flowchart LR
    A["文件名"] --> B["父目录项"]
    B --> C["inode 号"]
    C --> D["inode"]
    D -->|"块指针或索引"| E["磁盘数据块"]
```

以 inode 号 105 为例，查找过程如下：

1. 创建文件时，文件系统分配一个 inode，例如 **inode 105**。
2. 父目录的数据中写入目录项：`report.txt → 105`。
3. 查找 `report.txt` 时，文件系统读取父目录项，得到 inode 号 105。
4. 文件系统根据编号，到 inode 表中找到 **inode 105**。
5. inode 105 给出文件属性，以及数据块的块号或索引入口。
6. 文件系统据此读取相应磁盘数据块，得到文件正文。

所以，**inode 号与 inode 的关系类似“编号与编号对应的记录”**：inode 号不是磁盘正文地址，而是文件系统用来定位 inode 表中相应 inode 的编号。

## inode 中到底有没有数据块

inode 一般**不保存文件实际内容**，但它保存“怎样找到内容”的信息：

- **直接指针**：inode 直接记录某个数据块的物理块号；
- **间接指针**：inode 记录一个索引块的块号，索引块再记录多个数据块号；
- 文件较大时，还可以使用二级、三级间接索引。

详细寻址过程见 [[文件多级索引]]。

> [!example] 例子
> 若 inode 105 的直接指针记录了块号 800、801，那么文件系统会到磁盘块 800、801 读取文件内容。  
> 因此 inode 保存的是**数据块号**，数据块才保存**实际字节**。

## 各类信息保存在哪里

| 信息 | 保存位置 |
| --- | --- |
| 文件名 `report.txt` | 父目录的目录项 |
| `report.txt → inode 105` | 父目录的目录项 |
| inode 105 的具体记录 | inode 表 |
| inode 号是否已被占用 | inode 位图 |
| 文件类型、大小、权限 | inode |
| 数据块号或索引入口 | inode |
| 文件真正内容 | 磁盘数据块 |

## 考试重点

- 操作系统为管理文件而设置的数据结构：**FCB**。
- 类 Unix 中保存文件元数据和块定位信息：**inode**。
- 文件名与 inode 号的对应关系：**目录项**。
- 文件正文：**磁盘数据块**。
- inode 中的块指针保存数据块号，或指向保存更多块号的索引块。
- 文件逻辑块到磁盘物理块的映射由 FCB、inode 或文件分配结构管理，**不是进程页表**；页表管理的是虚拟页到物理页框的映射。

## 一句话记住

> **目录项用文件名找到 inode 号，inode 用块指针找到数据块，数据块保存文件正文。**

## 自测

1. 已知文件名，类 Unix 文件系统先到哪里查 inode 号？
2. inode 中保存文件正文，还是保存定位正文的信息？
3. inode 号、inode、数据块三者分别是什么？

### 答案

1. 到父目录的目录项中查找。
2. 保存文件属性和定位正文的信息；正文位于数据块中。
3. inode 号是编号；inode 是该编号对应的元数据记录；数据块保存文件正文。
