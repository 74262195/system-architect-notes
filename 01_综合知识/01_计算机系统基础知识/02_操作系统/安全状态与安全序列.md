# 安全状态：银行家算法为什么不是直接判断“现在有没有死锁”

## 先定位：死锁避免要比“已经死锁”更早一步

如果系统等到真正死锁以后才处理，代价可能很大。

死锁避免想提前判断：

> **当前资源分配以后，未来是否还至少存在一种让所有进程都能完成的顺序？**

这种“存在可行退路”的状态叫安全状态。

## 什么叫安全序列

假设存在一个顺序：

> P2 → P1 → P3

并且按这个顺序模拟时：

1. 当前剩余资源足够让 P2 完成；
2. P2 完成后释放自己占有的资源；
3. 资源变多，又能让 P1 完成；
4. P1 释放资源后，再能让 P3 完成。

那么这个顺序就是一个：

> **安全序列。**

只要至少存在一个安全序列，当前状态就是安全状态。

## 安全状态不要求真实调度必须照这个顺序

安全性分析只是在证明：

> **至少有一条所有人都能走完的路。**

实际 CPU 调度不必严格按照这个安全序列执行。

## 不安全是不是已经死锁

不是。

| 状态 | 含义 |
| --- | --- |
| 安全 | 至少存在一个安全序列 |
| 不安全 | 找不到可保证所有进程完成的安全序列 |
| 死锁 | 已经形成无法自行解除的资源等待 |

所以：

> **不安全 ≠ 已经死锁，但进入不安全状态以后存在走向死锁的风险。**

## 一句话记住

> **安全状态看“还有没有至少一条全员能完成的退路”，不是看“现在有没有人正在等”。**
