# PCB：操作系统靠什么记住“这个进程现在运行到哪了”

## 先定位：有了进程，OS 还需要一份管理档案

[[程序与进程]] 已经说明：进程是程序的一次动态执行。

但 OS 要同时管理很多进程，就必须回答：

- 它是谁？
- 当前是什么状态？
- 上次执行到哪里？
- 占用了哪些资源？
- 调度时有哪些信息要参考？

于是每个进程都需要一份管理记录。

## PCB 是什么

**PCB（Process Control Block，进程控制块）**是操作系统用来描述和管理一个进程的核心数据结构。

可以把它理解成：

> **OS 给每个进程建立的“管理档案”。**

里面通常会记录几类信息：

- 进程标识，如 PID；
- 当前进程状态；
- CPU 现场，如程序计数器和寄存器信息；
- 调度相关信息；
- 内存、文件、I/O 等资源管理信息。

## PCB 和 PID 不要混

- **PID**：进程编号，回答“它是谁”；
- **PCB**：整个管理档案，PID 只是其中的一项。

就像：

> 身份证号 ≠ 整份人事档案。

## 为什么进程切换离不开 PCB

假设进程 A 正在运行，时间片到了，OS 要切换到 B。

OS 必须先：

1. 保存 A 当前 CPU 现场；
2. 更新 A 的状态；
3. 找到 B 的 PCB；
4. 恢复 B 之前保存的 CPU 现场；
5. 让 B 继续运行。

因此：

> **没有保存运行现场，就做不到“停下来以后还能从原来的地方继续”。**

## 一句话记住

> **PCB 是 OS 管进程的档案；PID 只是档案里的编号。进程切换靠 PCB 保存和恢复现场。**
