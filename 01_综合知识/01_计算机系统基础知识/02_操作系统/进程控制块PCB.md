# PCB：操作系统怎样暂停并继续一个进程

> [!summary] 快速复习卡片
> **作用/定位**：PCB 是操作系统记录和管理一个进程所需信息的数据结构，可理解为进程的“管理档案”。
> **核心结论**：进程切换时，操作系统会把关键运行现场保存到 PCB，并从另一个进程的 PCB 恢复现场。
> **题干怎么认**：看到“进程存在的标志、保存状态、调度信息、现场保护与恢复”，优先想到 PCB。
> **易错点 / 考试重点**：PCB 不是“断点”本身；断点/返回位置等运行现场只是 PCB 中需要保存的一部分信息。

## 先定位：PCB 是进程存在与受管理的依据

操作系统同时管理多个进程，需要知道它是谁、处于什么状态、下次从哪里继续以及占用了哪些资源。**PCB（Process Control Block，进程控制块）**就是描述和管理进程的核心数据结构；PID 只是其中的标识信息。

## PCB 通常记录什么

| 信息类别 | 典型内容 | 用途 |
| --- | --- | --- |
| 标识 | PID、父子关系、用户标识 | 区分与授权 |
| 处理器状态 | 程序计数器 PC、通用寄存器、栈指针 SP、状态字等 | 恢复执行 |
| 调度状态 | 就绪/运行/阻塞、优先级、队列指针 | 调度与状态转换 |
| 内存信息 | 地址空间、页表或段表引用 | 恢复内存视图 |
| 资源与 I/O | 打开文件、设备、记账信息 | 管理占用和回收 |

> [!important] 栈和栈指针不是一回事
> **栈（stack）是一块内存区域**，用于保存函数调用、局部变量、返回地址等；**SP（Stack Pointer，栈指针）是 CPU 寄存器**，记录当前栈顶位置。进程切换时，PCB 保存的是 **SP 等寄存器上下文**，不是把整个进程栈复制进 PCB。

字段名称和归属随操作系统实现而异，考试通常考类别和作用，不必死背某一系统的结构体字段。

## 一次上下文切换怎样用到 PCB

~~~mermaid
flowchart LR
    A[保存A上下文] --> B[更新A状态]
    B --> C[选择B]
    C --> D[恢复B上下文]
    D --> E[B继续运行]
~~~

触发原因可能是时间片到、进程阻塞、更高优先级进程就绪等。切换时内核保存 A 的必要 CPU 上下文并更新 PCB，调度器选择 B，再依据 B 的 PCB 恢复其上下文。

> [!warning] 中断处理不必然等于进程切换
> 中断会发生控制转移并保存现场，但处理完可能仍返回原进程；只有调度决策选择了另一个进程，才发生进程上下文切换。

## 考试怎么认

- PID 回答“是谁”，PCB 回答“OS 怎样全面管理它”。
- “保存/恢复执行现场、调度队列、进程状态” → PCB。
- **看到“栈”时要分清：栈是内存，SP 是寄存器；PCB 保存的是 SP 等上下文。**
- PCB 是内核管理结构，不是进程普通用户代码可以任意修改的数据。
