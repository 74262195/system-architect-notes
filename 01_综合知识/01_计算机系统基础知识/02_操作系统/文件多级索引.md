# 文件多级索引：一级、二级“间接”在哪里

> [!summary] 快速复习卡片
> **作用/定位**：多级索引用索引块继续保存“数据块地址”，让有限的 inode 指针能管理更大的文件。
> **核心结论**：一个索引块可放的地址数 = 索引块大小 ÷ 每个地址项大小；一级间接覆盖 1 份这个数量，二级间接再乘一层。
> **经典题型怎么做**：先算“一个索引块有多少地址项” → 再按**直接块范围 → 一级间接范围 → 二级间接范围**划逻辑块号；问最大容量时再把可定位的数据块总数乘数据块大小。
> **易错点 / 考试重点**：一级间接指针→索引块→数据块；二级间接指针→一级索引块→二级索引块→数据块。先判断题目问“块号落哪一级”还是“总容量”，不要混着算。

## 先定位：这是索引分配解决大文件寻址的方法

元数据中的地址项有限。直接地址直接给出数据块号；间接地址先指向一个索引块，再由索引块保存更多块号。层级越深，容量越大，但首次访问需要读取更多索引块。

## 三种地址怎样走

~~~mermaid
flowchart TD
    A[文件逻辑块号] --> B{落在哪个区间}
    B -->|直接区| C[数据块]
    B -->|一级间接区| D[一级索引块]
    D --> C
    B -->|二级间接区| E[一级索引块]
    E --> F[二级索引块]
    F --> C
~~~

- **直接地址**：地址项就是数据块号。
- **一级间接**：地址项指向一个索引块，索引块的每项再指向数据块。
- **二级间接**：第一层索引项指向第二层索引块，第二层项再指向数据块。

## 容量怎么算（只记做题动作）

先算一个索引块能放多少个地址项。例如索引块和数据块都为 4KB，每个地址项占 4B，则：

> 4KB ÷ 4B = 1024 个地址项。

- 一个一级间接地址最多覆盖 1024 个数据块；
- 一个二级间接地址先指向 1024 个一级索引块，每个一级索引块再指向 1024 个数据块，所以可覆盖 1024 × 1024 个数据块；
- 如果 inode 还有 d 个直接地址，总覆盖量就是直接地址、一级间接和二级间接三部分相加；题目问容量时，再用数据块总数乘每个数据块的大小。


## 块号边界题怎么做

1. 先确认题目从 0 还是从 1 编号。
2. 先扣除直接地址覆盖的块数。
3. 再判断落入一级还是二级间接区。
4. 进入某层后，用整除求索引项、取模求层内偏移。

> [!warning] 最常见错误
> 索引块本身保存的是“地址项”，不是文件数据；题目问可存多少数据时，不要把索引块当成数据块重复计入。若题目另给指针层数或索引块也占文件空间，按题干口径计算。

## 用题目给的索引节点实际定位逻辑块

教材题给出 8 个 inode 地址项：`iaddr[0]～iaddr[5]` 是 6 个直接地址，`iaddr[6]` 是一级间接，`iaddr[7]` 是二级间接；索引块和数据块均为 4KB，每个地址项为 4B。因此每个索引块可放 `4KB÷4B=1024` 个地址项。下面按逻辑块号从 0 开始：

| 逻辑块号 | 先扣掉的范围 | 落点与索引位置 | 应采用的地址项 |
| ---: | --- | --- | --- |
| 6 | 直接区是 0～5，共 6 块；`6−6=0` | 一级间接区第 0 项 | `iaddr[6]` 指向的索引块第 0 项 |
| 520 | 扣 6 个直接块，`520−6=514` | 一级间接区第 514 项；该区覆盖 6～1029 | `iaddr[6]` 指向的索引块第 514 项 |
| 1030 | 扣 6 个直接块和 1024 个一级间接块，`1030−6−1024=0` | 二级间接区偏移 0：外层第 0 项、内层第 0 项 | `iaddr[7]` 指向的二级结构第 0 项，再进入其指向的索引块第 0 项 |

所以题给的 6、520、1030 分别走**直接、一级间接、二级间接**。边界的通用做法是：先比较逻辑块号是否小于直接块数；否则减去直接块数。若剩余量小于一级容量，就落在一级；否则再减去一级容量，在二级区把偏移 `q` 拆为外层索引 `q÷1024` 与内层索引 `q mod 1024`。这里 1030 的二级偏移为 0，因此两层索引都取 0。

题目还问最大文件长度时，先数**数据块**：`6+1024+1024²=1,049,606` 块；再乘每块 4KB，得到 `4,198,424KB`。索引块用于寻址，不再作为文件数据块加进这个长度。

## 代价与适用性

小文件多用直接地址，访问路径短；文件变大才进入间接层。多级索引避免预留巨大的连续空间，但索引块占空间，冷缓存时也会增加 I/O 次数。
