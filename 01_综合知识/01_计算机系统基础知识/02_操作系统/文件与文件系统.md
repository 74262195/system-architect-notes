# 文件与文件系统：从文件名到磁盘块，中间有哪些层

> [!summary] 快速复习卡片
> **作用/定位**：文件系统负责把用户看到的“文件名/路径”一路映射到真正保存数据的磁盘块。
> **核心结论**：考试先分三层：**目录项管名字 → FCB/inode 管文件属性和块定位信息 → 数据块保存真正内容**。
> **经典题型怎么认**：问“名字在哪”→目录项；问“权限/大小/块指针在哪”→FCB/inode；问“数据怎么落盘”→连续/链接/索引分配。
> **易错点 / 考试重点**：逻辑结构是“用户怎样看文件内容”，物理结构是“磁盘块怎样摆”，两者不是一回事。

## 先定位：文件系统负责持久化与按名访问

虚拟存储把运行中的虚拟页映射到内存/外存；文件系统把长期保存的数据组织成文件，并提供命名、目录、访问控制和空间分配。二者都使用块，但解决的问题不同。

## 文件与文件系统分别是什么

- **文件**：具有名字的一组相关信息，是用户看到的逻辑存储单位。
- **文件系统**：操作系统管理文件、目录和存储空间的一组数据结构与规则，并通过 create、open、read、write、close 等接口提供服务。

## 一次读取怎样贯穿各层

> [!important] 先区分两个阶段
> 用户说“读取 `/docs/a.txt`”，操作系统实际上先要**打开文件**，再根据返回的文件描述符执行**读取**。路径解析主要发生在打开阶段；文件已经打开后，后续读取通常不再从路径名重新查起。

### 阶段一：根据路径打开文件

```mermaid
flowchart LR
    A["路径名"] --> B["逐级查目录"]
    B --> C["找到 FCB 或 inode"]
    C --> D["返回文件描述符"]
```

以 `/docs/a.txt` 为例：

1. 操作系统从根目录开始，先找到 `docs` 目录，再在其中查找 `a.txt`。
2. 目录项负责把名字关联到文件的元数据对象：一般模型中是 FCB；类 Unix 系统通常是 inode 号。
3. 操作系统读取 FCB/inode，检查权限，并取得文件大小和数据块定位信息。
4. 打开成功后，为本次打开建立运行时记录，向进程返回文件描述符，例如 `fd=3`。

文件描述符不是磁盘地址，而是进程后续访问这个已打开文件时使用的代号。

### 阶段二：根据文件描述符读取数据

```mermaid
flowchart LR
    A["文件描述符"] --> B["当前读取位置"]
    B --> C["文件逻辑块"]
    C --> D["磁盘物理块"]
    D --> E["缓存或进程内存"]
```

进程执行 `read(fd=3)` 后：

1. 操作系统根据 `fd=3` 找到本次打开文件的运行时记录，其中包含当前读取位置。
2. 根据当前读取位置，确定要访问文件内部的哪个**逻辑块**。
3. FCB/inode 中的数据块定位信息，以及连续、链接或索引等分配结构，把文件逻辑块映射到磁盘物理块。
4. 如果目标数据已经在操作系统缓存中，直接从缓存读取；否则先从磁盘物理块读入缓存。
5. 把需要的数据复制到进程的内存缓冲区，并推进本次打开文件的读取位置。

> [!example] 走一个具体例子
> 假设每个数据块为 4 KiB，当前要读取文件的第 5000 字节。前 4096 字节属于逻辑块 0，因此第 5000 字节位于逻辑块 1。若分配结构记录“逻辑块 1 → 磁盘物理块 9007”，文件系统最终读取的就是物理块 9007 中对应位置的数据。

完整的定位链可以记成：

> **路径名 `/docs/a.txt` → 目录项 → FCB/inode → 文件描述符 `fd=3` → 文件逻辑块 1 → 磁盘物理块 9007 → 数据进入进程内存。**

> [!warning] “贯穿各层”不是数据流过所有结构
> 路径、目录项、FCB/inode、文件描述符和逻辑块都在提供**寻找数据的线索**；文件内容不会依次存入这些结构。真正的数据传输方向是：**磁盘物理块（或已有缓存）→ 操作系统缓存 → 进程内存**。

> [!warning] 三层不要混
> 文件的**逻辑结构**是用户怎样看内容；**物理结构**是数据块怎样组织；目录/FCB 负责怎样找到并管理这个文件。

## 文件系统还必须管理什么

- 名称与目录层次；
- 元数据和访问权限；
- 空闲空间、数据块分配与回收；
- 打开文件状态、缓存与并发访问；
- 一致性与故障恢复。不同文件系统的具体结构不完全相同。

> [!warning] 掉电与写回题
> 若题目比较目录、FCB/inode 等管理信息和文件数据，先看哪一类信息尚未写回持久存储：管理信息未写回，可能影响文件名、权限、长度或块定位；数据未写回，则表现为文件内容没有更新。不要把“在缓存中”直接等同于“已持久化”，写回先后以题干为准。

## 考试怎么认

- “按名字组织、长期保存、权限与空间管理” → 文件系统。
- “连续/链接/索引” → 物理分配方式。
- “流式/记录式” → 文件逻辑结构。
- “目录项、FCB、inode” → 名称到元数据的定位链。
