# 线程与进程：资源容器与执行路线怎样分工

> [!summary] 快速复习卡片
> **作用/定位**：进程主要负责拥有一套相对独立的资源（如地址空间、打开文件等）；线程是在进程内部真正被调度执行的更轻量单位。
> **核心结论**：不同进程默认各自拥有自己的地址空间和资源，不能随便直接访问彼此；同一进程内的线程通常共享这些资源，但每个线程仍有自己的运行状态、程序计数器和栈等执行现场。
> **题干怎么认**：看到“资源分配单位”优先想到进程；看到“CPU 调度/执行的基本单位、轻量级并发”优先想到线程。
> **易错点 / 考试重点**：线程共享资源不等于“所有东西都共享”；不同进程之间默认具有更强的地址空间隔离。

## “进程隔离”到底隔离什么

这里的“隔离”不是说进程彼此完全不能通信，而是说：

> **不同进程默认各自拥有自己的地址空间和资源，不能像同一进程里的线程那样直接随便访问彼此。**

例如：

- 进程 A 有自己的虚拟地址空间；
- 进程 B 也有自己的虚拟地址空间；
- A 不能拿一个普通内存地址就直接修改 B 的内存；
- A 打开的文件或资源，也不是 B 天然就能直接使用。

因此可以把进程理解成：

> **一个独立的“资源房间”。**

而线程是在这个房间里工作的“执行者”。

所以最适合考试和理解的记法是：

> **进程重在“拥有资源”，线程重在“执行任务”。**

不同进程如果要交换数据，需要通过进程间通信等受控方式，而不是直接随便读写对方内存。

## 先定位：进程装资源，线程执行任务

进程提供地址空间、资源和保护边界；线程是进程内可被调度的执行单元。一个进程至少有一个线程，同一进程的多个线程共享大部分进程资源，但各自必须保留独立执行现场。

| 对比 | 进程 | 线程 |
| --- | --- | --- |
| 核心角色 | 资源与隔离的容器 | CPU 调度和执行路线 |
| 典型私有内容 | 地址空间、资源表（进程之间通常独立） | 程序计数器、寄存器、栈 |
| 同进程内是否共享代码/堆/打开资源 | 不适用 | 通常共享 |
| 切换成本 | 通常更高 | 同进程线程间通常更低 |
| 故障影响 | 隔离较强 | 一个线程破坏共享内存可影响整个进程 |

“线程切换一定比进程切换快”是常见概括，不是无条件定律；成本还与内核实现、地址空间、缓存和调度路径有关。

## 为什么线程协作快，也更容易出错

线程可直接访问共享变量，不必像独立进程那样默认经过进程间通信。但并发读写会产生竞态，需要互斥锁、信号量、条件变量或消息传递等同步手段。

~~~mermaid
flowchart LR
    A[线程1] --> C[共享代码与数据]
    B[线程2] --> C
    A --> D[私有栈和寄存器]
    B --> E[私有栈和寄存器]
~~~

> [!warning] 并发不等于并行
> 单核上多个线程可以交替推进，属于并发；真正同一时刻执行通常需要多个处理器核心。

## 考试怎么认

- “资源分配、地址空间、隔离” → 进程。
- “独立栈/寄存器、共享进程资源、调度执行” → 线程。
- “共享数据竞态” → 需要同步，不是线程天然自动安全。
