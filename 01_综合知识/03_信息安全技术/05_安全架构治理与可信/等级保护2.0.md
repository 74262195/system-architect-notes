# 等级保护 2.0：为什么要先定保护对象和等级，再谈建设措施

> [!summary]- 快速复习卡片（学完再看）
> **作用/定位**：按保护对象受破坏后的影响确定安全保护等级，再开展相应建设、测评和监督。
> **核心结论**：先明确对象和影响，再定级；典型工作链是定级、备案、建设整改、等级测评、监督检查。
> **题干怎么认**：网络安全等级保护、定级对象、五级、备案、测评、监督检查。
> **易错点**：不能只凭行业名称或“核心系统”字样直接定级；也不要把旧版评估准则中的等级名称套成等保 2.0 定级名称。

## 为什么不能先买设备再定级

同样是网站，普通公开信息页和承载重要业务的平台，受破坏后的影响不同，需要的保护强度也不同。等级保护先界定保护对象，再根据受损影响确定等级，后续措施才有依据。

```mermaid
flowchart LR
    A[确定保护对象] --> B[分析受损影响并定级]
    B --> C[备案]
    C --> D[建设整改]
    D --> E[等级测评与监督检查]
```

安全措施应与信息化建设同步规划、同步建设、同步使用。这里的重点是安全进入系统全生命周期，而不是上线后临时补设备。

## 五级怎样减负记忆

只先记“由低到高共五级，保护和监管要求逐级增强”。具体系统属于哪一级，要依据定级规则和受损影响判断。

旧教材或旧题可能出现“用户自主保护级、系统审计保护级、安全标记保护级”等术语，它们来自 GB 17859 的计算机信息系统安全保护能力等级口径，不能直接当成等保 2.0 的五个定级名称。

### 遇到旧教材的五级名称怎样答

大纲保留的旧口径依次是：**用户自主保护级、系统审计保护级、安全标记保护级、结构化保护级、访问验证保护级**。它们用于识别教材所说的“安全保护能力等级”；而当前“等保 2.0”的定级与建设语境按保护对象和受损影响展开。题干给出哪套词，就在那套口径内作答，不能把名称交叉替换。

## 法规制度与安全协议放在什么位置

本章范围还要求识别安全法规与制度、反病毒制度、个人信息保护规则、防泄露/数字水印等保密管理，以及 SSL、PGP、IPSec 等安全协议。它们不是一张“万能治理卡”：

| 题干强调什么 | 先回到哪里 | 不要误答成 |
| --- | --- | --- |
| 定级、备案、测评、监督 | 本篇等级保护流程 | 只配置一台安全设备 |
| 组织制度、责任、培训、持续改进 | [[信息系统安全为什么需要治理]]、[[ISO27001信息安全管理]] | 具体加密算法 |
| Web 传输安全、SSL/TLS | [[TLS与HTTPS]] | PGP 或 VPN 的同义词 |
| 网络层安全隧道、IPSec | [[VPN]] | 只做应用层 HTTPS |
| 个人信息、反病毒、防泄露管理 | 相应制度与控制组合 | 单靠一份证书或一套等级名称 |

这里保留的是考试定位，不把教材中的某个历史制度名称当作今天仍不变的具体法规条文。

## 与 ISO/IEC 27001 的关系

等级保护属于我国网络安全制度与合规语境；[[ISO27001信息安全管理]]关注组织如何建立 ISMS。实际组织可能同时采用，但考试中要先分清题目问制度流程还是管理体系标准。

> [!question] 自测
> 1. 为什么“政府系统”四个字不足以直接判定保护等级？
>
> > [!answer]- 第 1 题答案与解析
> > **答案**：保护等级要先界定具体保护对象，再分析其受破坏后的影响，不能仅按所属行业或名称直接判断。
> > **解析**：同一行业内不同系统的重要性、承载业务和受损影响可能不同。
>
> 2. 旧版“系统审计保护级”等名称为什么不能直接写成等保 2.0 五级名称？
>
> > [!answer]- 第 2 题答案与解析
> > **答案**：这些术语属于 GB 17859 的计算机信息系统安全保护能力等级口径，与等保 2.0 的定级名称和制度语境不同。
> > **解析**：遇到版本敏感术语，要按题干与标准口径区分，不能把两套名称混用。
>
> 3. 题干出现“结构化保护级”，应先把它视为哪一套口径的术语？
>
> > [!answer]- 第 3 题答案与解析
> > **答案**：旧教材中的计算机信息系统安全保护能力等级口径。
> > **解析**：它与用户自主、系统审计、安全标记、访问验证同属一组，不能直接替换为等保 2.0 的定级名称。
