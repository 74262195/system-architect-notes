# 纵深防御

> [!important] 软考定位
> ⭐ 概念题+案例设计题的框架。**"多层防线"是安全架构设计的默认答案**。


## 零基础先抓住

> [!question] 为什么要学这个
> 任何单一安全控制都有可能失效，不能把全部安全寄托在一道边界上。

> [!tip] 讲人话
> 像城堡同时有护城河、城墙、门禁、巡逻和内堡，一层失守还有下一层。

> [!important] 考试怎么认
> 看到“多层互补、防护+检测+响应、最小权限、审计”，想到纵深防御。

---

## 一、一句话定义

**纵深防御（Defense in Depth）** = 在网络的多个层面设置**相互补充的防护**，单层被突破还有后续防线。

---

## 二、典型分层（⭐）

| 层 | 防护手段 |
| :--- | :--- |
| 物理层 | 门禁、机房管控 |
| 网络层 | 防火墙、IPS、VPN、VLAN隔离 |
| 主机层 | 加固、杀毒、HIDS |
| 应用层 | 认证授权、WAF、代码审计 |
| 数据层 | 加密、备份、脱敏 |
| 管理层 | 制度、审计、演练 |

---

## 三、配套安全原则（⭐）

- **最小权限**：只给够用的权限
- **默认拒绝**：没允许就是禁止（白名单思维）
- **失效安全**：故障时回到安全态（断电默认锁门）
- **审计兜底**：一切操作可追溯

---

## 四、安全模型：PDR / P2DR

| 模型 | 组成 |
| :--- | :--- |
| **PDR** | 防护（Protection）→ 检测（Detection）→ 响应（Response） |
| **P2DR** | **策略（Policy）为核心** + 防护/检测/响应 |

> 🧠 **记忆**：先设防、再监测、快响应；策略贯穿始终。

---

## 五、考场避坑

1. 纵深防御 ≠ 堆设备：强调**多层互补、各司其职**
2. 案例安全设计题：按"网络→主机→应用→数据→管理"分层作答是采分框架
3. "默认拒绝/最小权限/失效安全"是设计题的加分原则

---

## 六、一句话总结

> **一层破还有一层，层层设卡各司其职；策略定魂、审计兜底。**

---


## 自测

1. 为什么纵深防御不等于简单堆叠安全设备？
2. 网络层和应用层各举一种互补控制措施。
