# 纵深防御：一道防线失效以后，系统怎样继续保护核心资源

> [!summary]- 快速复习卡片（学完再看）
> **作用/定位**：在不同位置部署互补控制，让单点失效不直接演变成全面失守。
> **核心结论**：纵深防御强调多点、分层和支撑性基础设施，同时覆盖预防、检测、响应与恢复。
> **题干怎么认**：边界 + 主机 + 应用 + 数据、多层互补、一道失守仍有后续控制。
> **易错点**：设备数量多不等于纵深；多个同类设备若存在相同缺陷，仍可能一起失效。

## 它在信息安全主线中负责什么

安全架构已经要求组合多种控制，但还要进一步避免“一道防线被绕过，系统就全部失守”。**纵深防御通过在不同位置安排互补控制，把单点失败的影响限制在更小范围。**

| 定位 | 纵深防御在这里的答案 |
| --- | --- |
| 要防的风险 | 单个账号、规则、设备或漏洞失效后攻击直接到达核心资源 |
| 主要交付 | 多点、分层且相互补充的预防、检测、响应和恢复能力 |
| 依赖/边界 | 依赖不同控制避免共同失效；设备数量多、配置相同或共用管理面不等于有效纵深 |
| 在主线中的位置 | 它是安全架构的防线组织原则；后续数据库安全等专题把保护落到具体核心资产 |

## 从一次被盗账号看多层防线

攻击者拿到一个员工口令后，登录这一层已经失守。但如果还有 MFA、最小权限、网络隔离、敏感操作复核、异常检测和可恢复备份，攻击影响仍可能被限制。

这就是纵深防御：假设某一控制会失败，为关键路径安排不同类型、相互补充的后续控制。

## 三个观察角度

| 角度 | 要回答的问题 | 示例 |
| --- | --- | --- |
| 多点 | 攻击可能从哪些位置进入 | 网络基础设施、边界、主机/计算环境 |
| 分层 | 一层失守后谁继续拦截 | 防火墙、主机权限、应用校验、数据加密 |
| 支撑设施 | 各层靠什么共同运行 | PKI、日志、检测与响应平台 |

```mermaid
flowchart LR
    A[外部请求] --> B[边界控制]
    B --> C[身份与网络隔离]
    C --> D[应用与主机控制]
    D --> E[数据保护]
```

图里的层次不是固定产品清单。设计时要从真实资产和攻击路径出发，避免所有防线依赖同一个账号、同一种规则或同一个管理面。

## 与零信任有什么区别

纵深防御回答“怎样用多层互补控制限制失败影响”；[[零信任架构]]回答“为什么不能仅凭网络位置授予隐式信任”。二者可以同时采用，不是新旧替代关系。

## 自测

1. 两台配置完全相同、共用同一管理账号的防火墙，为什么未必形成有效纵深？

> [!answer]- 第 1 题答案与解析
> **答案**：它们可能因同一账号泄露、同一配置错误或同一种漏洞一起失效，缺少独立性和互补性。
> **解析**：纵深强调不同障碍共同限制风险，而不是简单重复相同设备。
2. 数据备份在纵深防御中主要承接哪一类失败后果？

> [!answer]- 第 2 题答案与解析
> **答案**：承接破坏、勒索、误删或系统故障后的恢复需求，主要帮助恢复可用性和数据可恢复性。
> **解析**：备份不能单独阻止攻击发生，但能减少攻击或故障造成的持续损失。
