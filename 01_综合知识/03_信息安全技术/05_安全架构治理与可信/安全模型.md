# 安全模型：规定谁能读、谁能写、信息能往哪流

> [!summary]- 快速复习卡片（学完再看）
> **一句话**：安全模型就是给系统规定一套“谁能访问什么、信息允许往哪流”的安全规则。
> **BLP**：保机密性，不上读、不下写。
> **Biba**：保完整性，不下读、不上写。
> **Clark-Wilson**：重要数据只能通过受控程序修改，并强调职责分离。
> **Chinese Wall**：防利益冲突，访问一家客户后限制访问其竞争对手。

## 为什么需要安全模型

比如公司把文件分成“普通、机密、绝密”。

系统不能只知道“张三登录成功了”，还要继续判断：

- 张三能不能读这份文件；
- 张三能不能把内容写到另一个位置；
- 这份信息能不能从高等级流到低等级。

**安全模型就是把这些允许和禁止的规则事先定下来。**

## 五种模型一句话认出来

| 模型 | 一句话 |
| --- | --- |
| 状态机模型 | 系统从安全状态开始，每一步变化后仍然必须是安全状态。 |
| Bell-LaPadula（BLP） | **保密**：防止秘密泄露到低密级，记“不上读、不下写”。 |
| Biba | **保完整**：防止低可信数据污染高可信数据，记“不下读、不上写”。 |
| Clark-Wilson | **保商业数据完整**：不能随便直接改数据，要通过受控程序，并进行职责分离和审计。 |
| Chinese Wall | **防利益冲突**：访问了甲客户后，不能再访问同一冲突组中的竞争客户数据。 |

## BLP 和 Biba 为什么正好相反

> **BLP 怕“秘密往下泄露”，Biba 怕“脏数据往上污染”。**

所以先看题目保护的是**机密性**还是**完整性**，再判断读写方向，不要死背四句话。

### 用同一组等级逐项判访问

下面的访问者与文件是为演示规则而设的**教学假设**。BLP 看密级，Biba 看完整性级别；不要把两个级别体系当成一个。

| 模型与访问请求 | 规则判断 | 结果与原因 |
| --- | --- | --- |
| BLP：机密级主体读取绝密文件 | 低密级主体不得向上读（No Read Up） | **拒绝读取**，避免主体读到更高密级的秘密 |
| BLP：机密级主体写入普通级文件 | 高密级主体不得向下写（No Write Down） | **拒绝写入**，避免把机密信息写到低密级位置 |
| BLP：机密级主体读取普通级文件 | 没有触犯“不上读” | **按 BLP 密级规则允许**；其他访问控制权限仍须另行检查 |
| Biba：中完整性主体读取低完整性文件 | 高完整性主体不得向下读（No Read Down） | **拒绝读取**，避免低完整性数据污染高完整性判断 |
| Biba：中完整性主体写入高完整性文件 | 低完整性主体不得向上写（No Write Up） | **拒绝写入**，避免低可信来源改坏高完整性数据 |
| Biba：中完整性主体写入低完整性文件 | 没有触犯“不上写” | **按 Biba 完整性规则允许写入**；其他权限仍须另行检查 |

判题时明确说出“主体级别、客体级别、读/写、规则、结论”五项。例如“机密主体→普通文件→写：违反 BLP 不下写，拒绝”。这能避免只背规则名却把读写方向说反。

### Chinese Wall：第一次访问会改变后续许可

假设咨询师尚未访问客户资料，甲公司与乙公司属于同一竞争利益冲突组，丙公司属于另一组：

1. 咨询师先读取甲公司的资料；系统记录其已访问甲公司所属的数据集合。
2. 他仍可读取甲公司的其他资料，因为它们属于同一公司数据集合；也可读取不同冲突组的丙公司资料。
3. 他再请求乙公司资料时，系统拒绝，因为乙与已访问的甲同属一个利益冲突组、却是不同公司数据集。
4. 关键是访问历史改变了许可范围：未访问前可能可选不同客户；首次选择甲后，冲突组内的乙被动态屏蔽。

这不是“只能服务一个客户”的普遍组织制度，而是模型按访问历史限制同一冲突组中不同公司的数据访问；其他利益冲突组不因此自动禁用。教材还规定写访问要满足额外条件，因此做写权限题不能只套“同公司可读”的规则。

## 考试第一动作

- **机密性、密级、秘密泄露** → BLP。
- **完整性、低可信污染高可信** → Biba。
- **受控程序、职责分离、审计** → Clark-Wilson。
- **咨询公司、竞争客户、利益冲突** → Chinese Wall。
- **每次状态变化后仍满足安全规则** → 状态机模型。

## 自测

1. 为什么 BLP 和 Biba 的写方向相反？

> [!answer]- 第 1 题答案与解析
> **答案**：BLP 防止高密级秘密向下泄露，所以不下写；Biba 防止低可信数据向上污染，所以不上写。
> **解析**：先看保护目标是机密性还是完整性。

2. 银行要求制单和复核必须由不同岗位完成，更接近哪个模型？

> [!answer]- 第 2 题答案与解析
> **答案**：Clark-Wilson。
> **解析**：它强调受控程序、职责分离和审计。

3. 机密级主体要把内容写入普通级文件，按 BLP 如何判？

> [!answer]- 第 3 题答案与解析
> **答案**：拒绝。
> **解析**：这是高密级向低密级写，违反 BLP 的“不下写”规则。

4. 中完整性主体要读取低完整性文件，按 Biba 如何判？

> [!answer]- 第 4 题答案与解析
> **答案**：拒绝。
> **解析**：高完整性主体不向下读，避免低完整性信息污染高完整性判断。

5. 咨询师已访问甲公司后，甲乙同属一个利益冲突组；丙属另一组。他还能访问哪些？

> [!answer]- 第 5 题答案与解析
> **答案**：可继续访问甲的数据集合，也可访问不同冲突组的丙；不得访问同一冲突组的乙公司数据集合。
> **解析**：Chinese Wall 按访问历史动态限制竞争客户，不是永久只能访问一个客户，也不会自动封锁其他利益冲突组。
