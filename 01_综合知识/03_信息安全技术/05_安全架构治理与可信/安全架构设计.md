# 安全架构设计

> [!important] 软考定位
> 📌 案例分析可选方向 + ✍️ 论文可选「安全加固」方向。**方法框架比细节重要**，运维做等保/加固的素材可直接用。

---

## 一、一句话定义

**安全架构设计** = 从系统整体出发，把安全**内建**（built-in）到架构里，而不是事后打补丁。

---

## 二、设计步骤（⭐⭐案例采分框架）

```mermaid
flowchart LR
    A[1 威胁建模] --> B[2 安全需求分析]
    B --> C[3 分层安全设计]
    C --> D[4 安全评估与监控]
```

### 第1步：威胁建模
- 识别资产 → 分析威胁（**STRIDE**：欺骗/篡改/否认/信息泄露/拒绝服务/提权）→ 评估风险

### 第2步：安全需求
- 映射质量属性：**机密性、完整性、可用性、可追溯性**
- 明确合规要求（等保级别）

### 第3步：分层设计
- 网络层：安全域划分（DMZ/内网/管理网）、防火墙、VLAN
- 主机层：系统加固、补丁、HIDS
- 应用层：统一认证（IAM/SSO）、RBAC、WAF、输入校验
- 数据层：加密（传输+存储）、密钥管理（KMS）、脱敏、备份容灾

### 第4步：评估与监控
- 渗透测试、等保测评
- **SIEM/SOC** 集中日志与告警

---

## 三、常用架构元素（⭐⭐）

| 元素 | 作用 |
| :--- | :--- |
| 安全域/网络分区 | 隔离不同信任级别 |
| **IAM + SSO + RBAC** | 统一身份与权限 |
| 加解密服务 / KMS | 集中密钥管理 |
| WAF / 防火墙 / IPS | 分层防御 |
| 堡垒机 | 运维操作审计（**运维最熟**）|
| SIEM / SOC | 日志集中、威胁分析 |
| 备份容灾 | 可用性兜底（联动 [[纵深防御]]）|

---

## 四、运维背景的论文素材点（✍️）

- 等保三级整改项目（从定级到测评落地）
- 堡垒机/运维审计体系建设
- 零信任远程接入改造
- 备份容灾与数据加密体系
- 安全运营中心（SOC）告警治理

---

## 五、考场避坑

1. 案例安全题**按步骤答**：威胁建模→需求→分层设计→监控，缺步丢分
2. 设计要"**内建**"（安全左移），别写"上线后加防护"
3. 论文写安全方向：**一个真实项目 + STRIDE/纵深防御理论 + 量化效果**

---

## 六、一句话总结

> **先想谁会打你（威胁建模），再按层设防（网络主机应用数据），最后审计兜底（SIEM）。**
