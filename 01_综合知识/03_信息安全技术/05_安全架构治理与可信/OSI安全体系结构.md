# OSI安全体系结构：要什么保护，用什么办法实现

> [!summary]- 快速复习卡片（学完再看）
> **一句话**：OSI 安全体系结构把“需要什么保护”叫安全服务，把“具体怎么做到”叫安全机制。
> **五类服务**：鉴别、访问控制、数据机密性、数据完整性、抗抵赖性。
> **易错点**：加密、数字签名、防火墙属于实现手段，不是五类安全服务本身。

## 为什么要分“服务”和“机制”

例如网上转账，银行要同时解决：

- **是不是本人** → 鉴别；
- **有没有权限转这笔钱** → 访问控制；
- **别人能不能看到金额** → 数据机密性；
- **金额有没有被改** → 数据完整性；
- **事后能不能证明是谁操作的** → 抗抵赖性。

这五项回答的是“**我要得到什么安全效果**”，所以叫**安全服务**。

加密、数字签名、访问控制规则等回答的是“**具体用什么办法实现**”，所以叫**安全机制**。

## 五类安全服务一句话记

| 安全服务 | 一句话 |
| --- | --- |
| 鉴别 | 确认“你是谁”或“数据是谁发的”。 |
| 访问控制 | 确认“你有没有权限做这件事”。 |
| 数据机密性 | 不让未授权的人看懂数据。 |
| 数据完整性 | 发现数据是否被未授权修改。 |
| 抗抵赖性 | 发生争议时，能够证明谁做过这件事。 |

## 服务和机制不要混

- **数据机密性**是服务，**加密**是实现它的机制；
- **数据完整性**是服务，MAC、HMAC、数字签名可以作为机制；
- **抗抵赖性**是服务，数字签名、公证和可验证证据可以支撑它。

同一个机制也可能支持多个安全服务，所以不要看到“数字签名”就只对应一个作用。

## 考试第一动作

题目问“五类安全服务”，直接检查：

> **鉴别、访问控制、数据机密性、数据完整性、抗抵赖性。**

如果选项出现“审计、安全防御、漏洞扫描”等，不要因为它们也很重要就误当成五类服务。

## 自测

1. “加密”和“数据机密性”是什么关系？

> [!answer]- 第 1 题答案与解析
> **答案**：数据机密性是要实现的安全服务，加密是实现这种服务的一种安全机制。
> **解析**：先分清“要什么保护”和“怎么实现”。

2. 数字签名为什么不能直接等于“机密性”？

> [!answer]- 第 2 题答案与解析
> **答案**：数字签名主要用于完整性、来源鉴别，并在适当条件下支撑抗抵赖性；它本身不负责隐藏数据内容。
> **解析**：保密通常还需要加密。
