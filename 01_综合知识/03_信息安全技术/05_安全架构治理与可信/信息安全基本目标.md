# 信息安全基本目标：说“系统要安全”，究竟要保护什么

> [!summary]- 快速复习卡片（学完再看）
> **作用/定位**：先把安全问题翻译成明确目标，再选择控制措施。
> **核心结论**：机密性防泄露，完整性防未授权修改，可用性保证授权者需要时可用；教材还强调可控性和可审查性。
> **题干怎么认**：窃听/泄露 → 机密性；篡改 → 完整性；服务中断 → 可用性；留痕追责 → 可审查性。
> **易错点**：一种措施通常只解决部分目标；“加密了”不等于整个系统已经安全。

## 它在信息安全主线中负责什么

这是信息安全模块的起点。后面会学到加密、认证、访问控制、防火墙、审计等技术，但在选技术以前，必须先回答：**到底要保护信息的什么性质？** 信息安全基本目标把模糊的“系统要安全”拆成可判断、可匹配控制措施的目标。

| 定位 | 信息安全基本目标在这里的答案 |
| --- | --- |
| 要解决的困难 | 只说“加强安全”而无法判断某项风险和某种技术是否对症 |
| 主要交付 | 机密性、完整性、可用性、可控性、可审查性等目标语言 |
| 依赖/边界 | 它不提供具体技术实现；每个目标通常需要多种控制共同实现 |
| 在主线中的位置 | 它先定义“要保护什么”；风险评估接着判断“哪些目标和资产最值得优先保护” |

## 先把“安全”拆成可以判断的问题

想象一个网上办事系统：材料不能被陌生人看到，审批结果不能被偷偷改掉，群众办理时系统还必须可用。这里已经出现三个不同问题，不能只用一句“加强安全”带过。

| 目标 | 用人话说 | 典型题干 |
| --- | --- | --- |
| 机密性 | 不该看的人看不到 | 泄露、窃听、越权读取 |
| 完整性 | 数据不能被未授权修改或破坏 | 篡改、伪造、非法删除 |
| 可用性 | 获得授权的人需要时能正常使用 | 宕机、资源耗尽、拒绝服务 |
| 可控性 | 能控制信息流向和系统行为 | 授权范围、传播控制 |
| 可审查性 | 发生问题后能查清过程和责任 | 日志、审计、追踪 |

机密性、完整性、可用性常合称 CIA 三要素；当前主教材还列出可控性、可审查性。做题时按题干问法判断，不把两个口径互相排斥。

## 同一措施为什么不能包办全部目标

- 加密主要保护机密性；若缺少完整性校验，密文仍可能被破坏。
- 数字签名可支持完整性、来源认证和抗抵赖判断，但不自动隐藏原文。
- 备份和容灾帮助恢复可用性，却不能阻止未授权者读取在线数据。
- 日志审计提供追查依据，但记录本身还要防篡改并限制访问。

因此，正确做题顺序是：**先认受损目标，再匹配机制**。

## 考试怎么认

历年题常把安全属性放进场景中辨析。不要先背产品名，先圈出动作：

1. “看到了不该看的”——机密性；
2. “改了不该改的”——完整性；
3. “合法用户用不了”——可用性；
4. “事后要追查”——可审查性/审计；
5. “限制信息怎样流动”——可控性。

## 一句话记住

> **不泄露、不乱改、用得上、管得住、查得清。**

> [!question] 自测
> 1. DDoS 首先破坏哪项安全目标？
>
> > [!answer]- 第 1 题答案与解析
> > **答案**：可用性。
> > **解析**：DDoS 通过耗尽带宽、连接或计算资源，使合法用户无法正常获得服务。
>
> 2. 为什么“使用加密”不能推出系统同时具备完整性和可用性？
>
> > [!answer]- 第 2 题答案与解析
> > **答案**：加密主要保护机密性；它不自动阻止未授权篡改，也不能保证服务不中断。
> > **解析**：先识别受损目标，再选择对应控制，不能用一个技术替代所有目标。
