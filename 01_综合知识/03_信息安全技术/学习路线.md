# 信息安全技术 · 学习路线

> [!summary] 学习方法
> 先用 [[00_信息安全技术开篇：系统建好了，为什么还不够]] 建立因果地图，再学具体技术。每到一站都追问：**上一站解决了什么 → 现在还剩什么风险 → 为什么必须学这一站 → 它解决后又留下什么问题。**
>
> 全章总链：**资产 → 威胁 → 脆弱性 → 攻击 → 风险 → 安全目标 → 安全机制 → 剩余风险**。

## 入口 · 先知道为什么突然开始学安全

先读 [[00_信息安全技术开篇：系统建好了，为什么还不够]]。

它只做一件事：把你已经学过的“系统怎样提供业务”接到“系统怎样在攻击、误用和故障面前仍然可信地提供业务”。第一次读完，先不要背算法名，闭卷说出：

> **系统能运行 ≠ 系统能安全运行。安全先保护资产，再识别威胁和脆弱性，判断风险，定义安全目标，最后选择安全机制，并接受仍会存在剩余风险。**

如果这句话还说不顺，先不要直接跳到 AES、RSA、防火墙。

## 起点 · 先建立“目标—对象—风险”框架

1. [[信息安全基本目标]]：先把模糊的“要安全”拆成机密性、完整性、可用性、可控性、可审查性等明确目标。
2. [[信息安全范围与存储安全]]：再把这些目标落到设备、数据、内容和行为等实际保护对象。
3. [[安全风险评估]]：最后把资产、威胁、脆弱性、可能性、影响和控制优先级连起来。

这三步解决的是“**保护什么、希望保护成什么样、什么风险最值得先处理**”。它们仍没有告诉你具体怎么保护，所以接下来才进入技术机制。

## 第 1 站 · 数据怎样保密、验真和验完整

风险评估会让你看到：业务数据可能被偷看、被改，消息来源也可能被伪造。于是第一类技术先直接保护**数据本身**：

[[对称加密]] → [[非对称加密]] → [[哈希算法]] → [[数字签名]] → [[数字证书与PKI]] → [[密钥管理]]

这一站不要把六个名词背成并列清单：

- 对称加密先解决“怎样高效把大量数据藏起来”；
- 非对称机制进一步缓解共享密钥分发与公私钥使用问题；
- 仅有保密仍不能判断内容有没有被改，所以要学哈希；
- 仅有摘要又不能证明“是谁发的”，所以要学数字签名；
- 有签名还要确认“这把公钥到底属于谁”，所以进入证书与 PKI；
- 最后还要管理密钥的生成、分发、轮换、吊销与销毁。

切换到下一站前，应能回答：为什么业务数据常用对称加密、签名为什么不等于加密、证书为什么不等于无条件可信。

**但到这里仍有一个大问题：数据可以被加密，签名也能验证来源，系统处理一次登录或访问请求时仍要确认“现在操作系统的人到底是谁”。** 所以下一站进入身份认证。

## 第 2 站 · 系统怎样认人并限制操作

先走主线：[[身份认证]] → [[访问控制基础]]。

为什么是这个顺序？因为**认证回答“你是谁”，访问控制回答“你能做什么”**。即使某个用户身份是真的，也不意味着他能读取所有材料、修改所有审批结果。

再比较：[[DAC自主访问控制]]、[[MAC强制访问控制]]、[[RBAC基于角色访问控制]]。最后用 [[Kerberos认证]] 看一次真实认证流程；[[单点登录SSO]] 放到拓展复习。

学完应能先区分“认证失败”与“权限不足”，再根据属主、标签、角色等题眼选择模型。

**身份和权限已经管住了，但请求还要穿过互联网、内部网段和不同信任域。** 这时问题从“谁能操作资源”扩展到“通信路径和网络边界怎样保护”。

## 第 3 站 · 通信路径怎样分层保护

先读 [[网络安全-从漏洞威胁到安全措施]] 建立“漏洞—威胁—措施”框架，再走：[[防火墙]] → [[IDS与IPS]] → [[VPN]] → [[TLS与HTTPS]]。

顺序含义是：先控制哪些流量能通过，再检测异常，用安全隧道或 TLS 保护传输。[[无线网络安全]] 作为这一站的**接入补充分支**：它不是 TLS 之后必然产生的新层次，而是单独补“无线信号广播以后，谁能接入、空中数据怎样保护”。

这一站解决了“流量怎样通过、异常怎样检测、通信怎样保密验真”。**但即使 HTTPS 正常、边界防火墙也配置正确，应用自己的代码仍可能把恶意输入当成 SQL、脚本或伪造请求处理。** 所以还不能停。

## 第 4 站 · 攻击识别与应用安全

这一站分成两段，不把“网络攻击”和“Web 应用漏洞”混成一个层次。

先走攻击识别主链：

[[常见网络攻击]] → [[网络欺骗-ARP、DNS与IP欺骗]] → [[端口扫描-怎样用响应判断服务暴露]] → [[TCPIP协议攻击-SYN、ICMP与SNMP]]

这一段练习从资源耗尽、伪造对象、服务探测、协议状态与管理面等现象判断攻击机制。然后把视角上移到应用输入边界：

[[SQL注入]] → [[XSS跨站脚本]] → [[CSRF跨站请求伪造]]

学完应能解释“攻击为什么成立”，并给出对应的首要防线，而不是统一回答“加密、防火墙、加强管理”。

**到这里我们已经有很多单点控制了，但“每个地方都装了安全技术”仍不等于“形成了安全体系”。** 还要解决控制之间怎样配合、谁负责、怎样持续检查和改进。

## 第 5 站 · 把单点措施组成安全体系

主线统一按下面顺序收口：

[[信息系统安全为什么需要治理]] → [[安全模型]] → [[OSI安全体系结构]] → [[安全架构设计]] → [[纵深防御]] → [[数据库安全与完整性设计]] → [[软件脆弱性分析]] → [[等级保护2.0]] → [[ISO27001信息安全管理]]

顺序不要背成目录，而要理解它为什么继续：

1. **治理**先回答谁定目标、谁负责、怎样持续运行；
2. **安全模型**把机密性、完整性、利益冲突等目标变成可判断的信息流规则；
3. **OSI 安全体系结构**把“需要什么安全服务”和“用什么机制实现”分开；
4. **安全架构设计**才把身份、网络、应用、数据、审计、响应和恢复控制放到系统不同层次；
5. **纵深防御**继续处理“一层失效以后谁接着保护”；
6. **数据库安全、软件脆弱性**把整体原则落回核心数据与软件弱点；
7. **等级保护 2.0、ISO/IEC 27001**最后从制度合规和管理体系两个角度收口持续治理。

[[可信计算]]、[[零信任架构]] 作为拓展：先理解定位，再按复习时间决定深度。

这一站最终把前面零散的控制收成一个原则：**安全架构不是产品采购清单，而是从风险出发，把技术、组织、制度、检测、响应和恢复连成持续运行的体系。**

## 闭卷通关检查

- [ ] 能复述：**资产 → 威胁 → 脆弱性 → 攻击 → 风险 → 安全目标 → 安全机制 → 剩余风险**
- [ ] 能解释“系统能运行”为什么不等于“系统能安全运行”
- [ ] 能从安全目标解释为什么需要某项控制
- [ ] 能区分加密、哈希、签名、证书和密钥管理，并说明为什么按这条链继续
- [ ] 能解释为什么“加密以后还要认证，认证以后还要访问控制”
- [ ] 能区分防火墙、IDS、IPS、VPN、TLS 的职责
- [ ] 能解释为什么网络边界安全不等于应用没有 SQL 注入、XSS、CSRF
- [ ] 能说出 OSI 五类安全服务，并把服务与机制配对
- [ ] 能用“风险 → 控制 → 监测 → 响应恢复”组织案例题答案
- [ ] 能解释为什么最后还需要安全架构、纵深防御、等保和治理
- [ ] 能用 [[信息安全技术-考前速记]] 完成一次快速闭卷回忆
