# DAC 自主访问控制：为什么资源属主可以决定谁来访问

> [!summary]- 快速复习卡片（学完再看）
> **作用/定位**：把访问授权的较大自主权交给资源属主或其委托主体。
> **核心结论**：题目看到“属主自主决定权限”优先想到 DAC；ACL 是常见实现方式之一。
> **题干怎么认**：属主、共享、访问控制列表、可自主授予/撤销权限。
> **易错点**：DAC 不等于“一定允许无限转授权”，具体委托能力取决于实现和策略。

## 它在访问控制主线中负责什么

访问控制已经确定要对“主体访问客体”的请求作出判决；DAC 进一步选择一种策略依据：**把较大的授权决定权交给资源属主或其委托者。** 它适合需要灵活共享的场景，但不会替代统一的安全策略治理。

| 定位 | DAC 在这里的答案 |
| --- | --- |
| 要防的风险 | 未获资源属主授权的访问 |
| 主要交付 | 由属主主导的授权、撤销和共享控制 |
| 依赖/边界 | 依赖属主正确管理权限；不能单独解决权限分散、转授权失控等治理问题 |
| 在主线中的位置 | 它是访问控制的一种策略模型；MAC 改为由系统强制判决，RBAC 改为按角色统一授权 |

## 核心机制

DAC（Discretionary Access Control）强调授权决策与资源所有者相关。操作系统文件权限、文档共享等都可能体现这种思想。

ACL 常按对象记录“哪些主体拥有哪些权限”；能力表等其他机制也可以表达自主访问控制，因此不要把“DAC = ACL”写成唯一等式。

## 与其他模型怎么区分

| 模型 | 第一判断入口 |
| --- | --- |
| DAC | 属主/资源所有者可自主授权 |
| [[MAC强制访问控制]] | 安全标签和系统强制策略 |
| [[RBAC基于角色访问控制]] | 用户通过角色获得权限 |

DAC 的主要风险是授权较分散，权限传播和治理更难统一；但不能据此简单说“DAC 不安全”或“企业不用 DAC”。

> [!question] 自测
> 1. 为什么“属主自己决定共享对象给谁”更像 DAC？
>
> > [!answer]- 第 1 题答案与解析
> > **答案**：因为 DAC 的授权决策与资源属主相关，属主或其委托者可决定共享范围。
> > **解析**：题干强调“标签强制”时应改选 MAC；强调“岗位角色”时应改选 RBAC。
>
> 2. ACL 为什么只是 DAC 的常见表达机制，而不是 DAC 定义本身？
>
> > [!answer]- 第 2 题答案与解析
> > **答案**：ACL 是按客体记录权限的一种实现方式；DAC 的核心是属主自主授权这一策略思想。
> > **解析**：能力表等其他机制也可表达自主访问控制关系。
