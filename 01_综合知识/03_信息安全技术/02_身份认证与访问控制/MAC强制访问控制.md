# MAC 强制访问控制：为什么资源属主也不能绕过系统安全策略

> [!summary]- 快速复习卡片（学完再看）
> **作用/定位**：由系统依据安全策略和标签强制做访问决策，普通用户不能凭“我是属主”就绕过规则。
> **核心结论**：MAC 关键词是强制策略、安全标签、多级安全；BLP 偏机密性，Biba 偏完整性。
> **题干怎么认**：密级、安全级别、主体/客体标签、Bell-LaPadula、Biba。
> **易错点**：MAC 不是“绝对最安全”；安全管理员仍需要管理策略和标签，普通属主只是不能自行越过强制规则。

## 它在访问控制主线中负责什么

DAC 允许属主较灵活地授权，但在密级、涉密信息等场景，系统不能把规则交给资源属主随意改变。**MAC 用安全标签和预定义强制策略作出判决，重点保证统一的多级安全约束不会被普通用户绕开。**

| 定位 | MAC 在这里的答案 |
| --- | --- |
| 要防的风险 | 属主或普通用户自行改变授权，破坏统一安全级别规则 |
| 主要交付 | 基于标签和系统强制策略的一致访问判决 |
| 依赖/边界 | 依赖正确的标签、策略和管理员配置；不等于不需要认证、审计或其他安全控制 |
| 在主线中的位置 | 它与 DAC、RBAC 是并列策略模型；后续安全模型会进一步解释机密性和完整性的规则 |

## 标签与强制决策

主体和客体被赋予安全属性，系统根据预定义规则判断能否访问。重点是：**授权权力不由普通资源属主随意决定**。

经典模型的考试口径：

- **Bell-LaPadula（BLP）**：主要保护机密性，经典简化记忆为“不上读、不下写”。
- **Biba**：主要保护完整性，经典简化记忆为“不下读、不上写”。

这些口诀依赖相应多级安全模型语境，不应脱离模型扩展到所有系统。

## 与 DAC / RBAC 区分

- DAC：属主自主授权。
- MAC：系统强制执行标签/安全策略。
- RBAC：通过组织角色间接授予权限。

> [!question]- 自测（展开查看答案）
> 1. 为什么 MAC 中“文件是我创建的”也不代表我能任意修改访问规则？
>    > **答案**：MAC 的规则由系统安全策略强制执行，普通资源属主不能凭所有权绕过标签约束。
>    > **解析**：这是它与 DAC 的核心区别。
> 2. BLP 与 Biba 分别主要关注哪个安全目标？
>    > **答案**：BLP 主要关注机密性；Biba 主要关注完整性。
>    > **解析**：口诀只在相应多级安全模型语境中使用，不要扩展成所有系统的通用规则。
