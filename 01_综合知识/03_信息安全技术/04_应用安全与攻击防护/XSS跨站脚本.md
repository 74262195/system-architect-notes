# XSS 跨站脚本

> [!important] 软考定位
> ⭐⭐ Web 三兄弟之二。区分**存储型/反射型/DOM型**和**防"输出"**是核心考点。

---

## 一、一句话定义

**XSS（Cross-Site Scripting）** = 攻击者把**恶意脚本**注入网页，在**其他用户浏览器**中执行。

---

## 二、三种类型（⭐）

| 类型 | 特征 | 例子 |
| :--- | :--- | :--- |
| **存储型** | 脚本**存进服务器**，所有人访问都中招 | 论坛帖子、评论区 |
| **反射型** | 脚本在 **URL 参数**里，诱导点击触发 | 搜索框回显 |
| **DOM型** | 纯前端 DOM 操作触发，不经过服务器 | 前端解析 URL 片段 |

> 🧠 **记忆**：存储型="下毒在源头上"；反射型="钓鱼饵里藏刀"；DOM型="纯前端事故"。

---

## 三、危害

- 盗取 **Cookie**（劫持登录态）
- 钓鱼、篡改页面
- 键盘记录、恶意跳转

---

## 四、防御（⭐⭐）

| 手段 | 说明 |
| :--- | :--- |
| **输出编码/转义** ✅首选 | 对输出内容做 HTML/JS 转义，脚本变文本 |
| **CSP（内容安全策略）** | 限制页面可加载的脚本来源 |
| **HttpOnly Cookie** | 脚本读不到 Cookie |
| 输入校验 | 过滤 `<script>` 等危险字符 |
| 纯前端渲染 | 不用 `innerHTML` 直接拼 HTML |

---

## 五、考场避坑

1. **XSS 防"输出"**、[[SQL注入]] 防"输入拼接"——方向反了必错
2. XSS 的受害者是**浏览器**（其他用户），不是数据库
3. "盗取Cookie"是 XSS 最典型危害

---

## 六、一句话总结

> **脚本借网页寄生，在别人浏览器作恶；输出转义+CSP，让脚本变纯文本。**
