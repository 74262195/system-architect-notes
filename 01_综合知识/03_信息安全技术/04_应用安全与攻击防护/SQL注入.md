# SQL 注入

> [!important] 软考定位
> ⭐⭐ Web 安全三兄弟之首，**原理+防御**选择题常客，案例题可能让写防御方案。


## 零基础先抓住

> [!question] 为什么要学这个
> 如果应用把用户输入直接拼进 SQL，数据和代码的边界会被打破。

> [!tip] 讲人话
> 本来用户只能填写“姓名”，却把一段新的数据库命令塞进表格，系统还把它当命令执行了。

> [!important] 考试怎么认
> 看到“登录绕过、拼接 SQL、数据库异常、拖库”，优先想到 SQL 注入；首选防御是参数化查询。

---

## 一、一句话定义

**SQL 注入** = 攻击者把**恶意 SQL 代码**拼进用户输入，让数据库执行非预期查询。

---

## 二、原理示例

```sql
-- 正常：WHERE username = 'admin' AND password = 'xxx'
-- 攻击输入：' OR 1=1 --
-- 拼接后：WHERE username = '' OR 1=1 --' AND password='xxx'
-- 恒真 → 绕过登录！
```

**本质**：用户输入被**直接拼接**进 SQL 语句执行。

---

## 三、危害

- 绕过认证、拖库（数据泄露）
- 篡改/删除数据
- 提权（拿到数据库管理员权限）

---

## 四、防御（⭐⭐采分点）

| 手段 | 说明 |
| :--- | :--- |
| **参数化查询/预编译** ✅首选 | 输入只当"数据"，不当"代码" |
| 输入校验 | 白名单校验格式/长度 |
| 最小数据库权限 | 应用账号不给 DBA 权限 |
| 错误信息脱敏 | 不把 SQL 错误返回前端 |
| WAF | 应用防火墙兜底 |

> ⚠️ 注意：过滤关键字（如屏蔽 `'`）**不是首选**，可被编码绕过。

---

## 五、考场避坑

1. 问"SQL注入防御首选"→ **参数化查询**（不是过滤、不是加 WAF）
2. 注入目标：**数据库**；和 [[XSS跨站脚本]]（浏览器）、[[CSRF跨站请求伪造]]（冒充用户）区分
3. 案例题出现"登录可绕过/数据被拖"→ 先想到 SQL 注入

---

## 六、一句话总结

> **输入当代码执行就是注入；参数化把输入当数据，注入就地死亡。**
