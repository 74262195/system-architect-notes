# 网络欺骗：ARP、DNS 与 IP 欺骗分别把通信骗到哪里

> [!summary]- 快速复习卡片（学完再看）
> **作用/定位**：三者都是“冒充”，但伪造的对象分别是局域网转发表、域名解析结果和报文源地址。
> **核心结论**：IP-MAC 对应错了看 ARP；域名被解析到假地址看 DNS；报文自称来自不该出现的地址看 IP 欺骗。
> **题干怎么认**：先找“被替换的对应关系”，再选同一层的校验或过滤措施。
> **易错点**：ARP 欺骗不等于 DNS 欺骗；DNS 欺骗未必入侵目标网站；IP 欺骗不是修改目的地址。

## 它在攻击防护主线中负责什么

[[常见网络攻击]]先帮助你从现象识别攻击类型。本篇把其中容易混淆的“欺骗”单独拉出来：**同样是让人信错了信息，攻击者究竟替换了哪一份对应关系？**

直接答案是：ARP（地址解析协议）欺骗改的是局域网里“IP 对应哪块网卡”的记录；DNS（域名系统）欺骗改的是“域名对应哪个 IP”的回答；IP 欺骗伪造的是报文声称来自哪个源 IP。三者都可能把通信导向错误对象，但发生的位置和首要防线不同。

## 先抓住：被伪造的是什么

| 类型 | 被伪造的对应关系/字段 | 典型后果 | 最小防线 |
| --- | --- | --- | --- |
| ARP 欺骗 | 局域网中的 IP → MAC 映射 | 本应发给目标主机的帧被送往攻击者网卡 | 静态或双向绑定、可信 ARP 服务/检测 |
| DNS 欺骗 | 域名 → IP 的解析应答 | 用户输入正确域名却连到假地址 | 把监听/交叉查询作为线索；使用可信递归解析并验证 DNSSEC（适用于已签名且验证通过的数据），访问网站时另校验 HTTPS 服务身份 |
| IP 欺骗 | IP 报文的源地址 | 目标误以为报文来自另一台主机 | 过滤从外部进入却声称源自内部网段的报文 |

不要只背“都叫欺骗”。题干若出现 **IP-MAC**，先锁定 ARP；出现 **域名查询、解析应答、假网站地址**，先锁定 DNS；出现 **伪造源地址、外部报文声称来自内网**，才锁定 IP 欺骗。

## 用一个访问网站的例子走完三种变化

小王想访问公司网站。正常情况下，他先拿到网站域名的 IP，再把局域网帧交给正确的下一跳网卡，报文中的源地址也应真实可验证。

### ARP 欺骗：最后一跳的网卡认错了

小王的电脑要把数据交给局域网中的网关时，需要从 ARP 缓存中查“网关 IP 对应哪个 MAC 地址”。MAC 地址是网卡在局域网通信中使用的硬件地址。ARP 应答能触发缓存更新；攻击者若伪造“网关 IP → 攻击者 MAC”的应答，小王看到的网关 IP 没变，实际帧却被送到攻击者的网卡。

所以它的关键词是：**同一局域网、ARP 缓存、IP-MAC 映射、流量被转走**。防御的本质是让这份映射不能被随意替换，例如固定/双向绑定，或由可信机制验证 ARP 信息。它不能替代对域名解析或报文源地址的校验。

### DNS 欺骗：网站名字被指到了假地址

小王输入的域名本身没有错，但攻击者冒充 DNS 服务器回答：“这个域名的 IP 是攻击者的地址。”客户端信了这个回答，就会主动连向假地址；目标网站的服务器未必被攻破，问题在于用户被带错了路。

教材给出的检测思路是：监听同一请求是否出现互相矛盾的多个应答、对可疑地址发送探测，或对返回 IP 做反向交叉查询。这些都只能作为告警线索，不能单独证明遭到欺骗：被动监听的多应答判断依赖教材描述的请求/响应模型；主动探测依赖攻击者不会核验探测目标的假设；反向查询只返回该 IP 配置的 PTR 名称，不能证明原来的“域名 → IP”映射真实。合法的多地址、分流解析和不同管理域也可能造成交叉结果不一致。

更强的校验要分清两层：**DNSSEC 验证**在域名区域已签名且解析器验证成功时，为 DNS 数据提供来源认证和完整性；它不验证网站页面内容，也不替代传输加密。浏览器访问网站时还应验证 HTTPS 证书对应的服务身份，确认连上的服务与请求域名匹配。[RFC 4033](https://www.rfc-editor.org/rfc/rfc4033.html)说明 DNSSEC 的服务与限制；[RFC 9525](https://www.rfc-editor.org/rfc/rfc9525.html)规定 TLS 中的服务身份校验。考试仍按题面识别教材列出的检测方法，但不要把反向查询或多应答线索当成充分防线。

### IP 欺骗：报文的“寄件人地址”是假的

IP 欺骗是发送报文时伪造源 IP，让目标把报文当成来自另一台主机。若题干说“外网进入的包，源地址却写成内网地址”，这是典型异常：边界防火墙应过滤这类报文。

对 TCP 而言，仅改源 IP 不等于就能完成可靠连接，因为 TCP 还要经过三次握手和序号确认。教材举例中，攻击者可能先让被冒充主机失去响应，以减少真实主机对握手的干扰。因此，**“伪造源 IP”是 IP 欺骗的动作；“能否完成连接”仍受协议交互限制**。

## 考试怎么做

遇到“欺骗”题，按下面三步判断：

1. 圈出被伪造的对象：映射表、DNS 应答，还是 IP 报头源地址。
2. 对应到层次：局域网地址解析 → ARP；名称解析 → DNS；网络层源地址 → IP。
3. 选择同层防线：ARP 绑定/检测、DNS 应答检查、边界源地址过滤。

## 自测

1. 一台主机访问网关时，网关 IP 没变，但 ARP 缓存中该 IP 对应的 MAC 被攻击者替换。这是哪种攻击？

> [!answer]- 第 1 题答案与解析
> **答案**：ARP 欺骗。
> **解析**：被伪造的是局域网中 IP 到 MAC 的映射；帧会按错误的 MAC 被发送到攻击者网卡。

2. 用户输入正确域名，却被引到攻击者 IP 上的仿冒页面；原网站服务器并未被入侵。最符合哪种攻击？

> [!answer]- 第 2 题答案与解析
> **答案**：DNS 欺骗。
> **解析**：攻击者伪造的是“域名 → IP”的解析应答，不必直接攻破原网站。

3. 边界设备发现一个从互联网进入的报文，其源地址属于本企业内部网段。它主要在防范什么？

> [!answer]- 第 3 题答案与解析
> **答案**：IP 欺骗。
> **解析**：外部报文却声称来自内网，是伪造源地址的典型信号，应做入口源地址过滤。
