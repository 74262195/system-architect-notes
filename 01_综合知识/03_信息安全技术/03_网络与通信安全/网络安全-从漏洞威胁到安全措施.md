# 网络安全：从漏洞、威胁到安全措施怎样连成闭环

> [!summary]- 快速复习卡片（学完再看）
> **核心结论**：漏洞是可被利用的弱点，威胁是可能造成损害的因素，攻击是威胁真正利用弱点采取的行动，风险是这种事情发生并造成损失的可能性与影响，安全措施用于降低风险。
> **题干怎么认**：弱口令、配置错误、未修补缺陷 → 漏洞；攻击者、恶意代码、窃听者等潜在危险因素 → 威胁；扫描、爆破、利用漏洞、篡改报文等实际动作 → 攻击；“可能泄露多少数据、业务会停多久” → 风险与影响；认证、访问控制、防火墙、检测、审计、加密 → 措施。
> **易错点**：威胁不等于攻击，漏洞也不等于已经发生了事故；安全措施不是只装防火墙，同一措施通常只降低一部分风险。

## 它在主线中负责什么

前面的 [[身份认证]] 与 [[访问控制基础]] 已经解决了**“请求者是谁、他能对哪个资源做什么”**。但这些规则只约束主体和资源之间的身份、权限关系；一次真实请求在到达系统之前，还要经过互联网、内部网段、不同信任域以及客户端与服务器之间的通信链路。

因此即使身份和权限完全正确，仍可能出现：不该进入的流量到达受保护网络、恶意连接探测服务、攻击流量混入已允许连接、通信内容被窃听或篡改、对端被冒充。**网络与通信安全继续解决的是：这些合法或非法请求在通信路径上怎样被控制、检测和保护。**

这时仍然可以使用“漏洞—威胁—攻击—风险—措施”框架，但它不是把信息安全从头再讲一遍，而是把上位风险思路落到**网络路径与网络边界**：先找弱点，再判断谁可能利用、会怎样攻击、造成什么风险，最后选择边界控制、检测阻断和通信保护机制。

## 先建立全局视图：网络安全在保护什么

**一句话先记住：网络安全不是“装一个防火墙”，而是保护网络边界、通信链路以及通过网络访问的系统和数据，使合法通信能够进行，同时尽量阻止、发现和追溯恶意行为。**

从零基础视角，可以把一次网络请求想成这样：客户端准备访问服务器，途中要经过网络链路和若干控制点，最后才能到达应用。安全问题会出现在不同位置，所以不可能靠一种设备解决全部问题。

| 需要回答的问题 | 对应的安全思路 |
| --- | --- |
| 这个请求者到底是谁？ | 身份认证 |
| 已经确认身份后，他能操作哪些资源？ | 访问控制 |
| 哪些网络流量可以进入或离开？ | 边界控制，例如防火墙 |
| 已经进入或经过的流量里有没有攻击行为？ | 检测与阻断，例如 IDS/IPS |
| 数据经过不可信网络时会不会被窃听、篡改？ | 通信保护，例如 VPN、TLS |
| 出了问题以后能不能知道谁做了什么？ | 日志与审计 |

所以本篇真正要建立的不是若干设备名，而是下面这个判断顺序：

**先识别漏洞和威胁 → 看威胁怎样形成攻击 → 判断会产生什么风险 → 明确要保护的安全目标 → 再选择对应措施。**

## 漏洞、威胁、攻击、风险不是一回事

这四个词经常连续出现，但它们处在同一条因果链的不同位置。

| 概念 | 人话理解 | 例子 | 它在闭环中的位置 |
| --- | --- | --- | --- |
| 漏洞（Vulnerability） | 系统自身存在的弱点 | 弱口令、未修补的软件缺陷、错误开放端口、配置不当 | 给攻击留下可利用入口 |
| 威胁（Threat） | 可能造成损害的人、事物或能力 | 攻击者、恶意代码、窃听者、能够滥用权限的主体 | 存在“可能来利用弱点”的危险因素 |
| 攻击（Attack） | 威胁真正付诸行动，尝试利用弱点 | 爆破口令、利用远程代码执行漏洞、篡改报文、发起 DoS | 从“可能出事”变成“正在动手” |
| 风险（Risk） | 某种不利事件发生并造成损失的可能性与影响 | 管理后台被攻破后可能导致大量数据泄露、业务中断 | 用来判断这件事有多值得优先防 |

例如，一个暴露在公网的管理后台使用弱口令：

- **弱口令**是漏洞；
- **能够发现并尝试入侵的攻击者**构成威胁；
- **攻击者实际进行口令爆破并登录**属于攻击；
- **后台被接管后可能发生数据泄露和业务中断**体现风险；
- **MFA、限速、最小权限、访问控制和审计**属于降低风险的安全措施。

因此不要把“攻击已经发生”叫作漏洞，也不要把“威胁”和“攻击动作”当成同一个词。

## 网络安全最终要守住什么：CIA

前面的 [[信息安全基本目标]] 已经给出信息安全目标。本篇只把它们落到网络通信场景中。最基础的三个目标是 **CIA：机密性、完整性、可用性**。

| 目标 | 人话理解 | 网络场景中的典型问题 | 常见保护方向 |
| --- | --- | --- | --- |
| 机密性（Confidentiality） | 不该看的人看不到 | 报文被窃听、敏感数据泄露 | 加密、访问控制、TLS/VPN |
| 完整性（Integrity） | 数据不能被偷偷改掉 | 报文被篡改、传输内容被替换 | 完整性校验、认证加密、TLS |
| 可用性（Availability） | 需要时系统还能正常提供服务 | DoS/DDoS、链路或服务被打瘫 | 流量控制、冗余、防护与恢复 |

身份认证、访问控制和审计等机制并不是“第四种防火墙”，而是在 CIA 之外继续回答“谁能访问、能做什么、做过什么”。考试遇到安全措施题时，先判断题目究竟是在保密、防篡改、保可用，还是在解决身份、权限与追责问题。

## 从风险到安全措施：每种技术解决什么

**安全措施必须对着具体问题选。**下面这张表就是进入后续网络安全卡片前最重要的总览。

| 题目真正问的问题 | 首先想到的机制 | 它主要解决什么 |
| --- | --- | --- |
| “你到底是谁？” | [[身份认证]] | 确认主体身份 |
| “你登录后能干什么？” | [[访问控制基础]]，进一步看 DAC / MAC / RBAC | 决定主体对资源的操作权限 |
| “哪些流量允许经过网络边界？” | [[防火墙]] | 按规则允许或拒绝网络流量 |
| “经过的流量里有没有攻击特征或异常行为？” | [[IDS与IPS]] | IDS 偏检测告警，IPS 还能在线阻断 |
| “跨越不可信网络时怎样保护整个通信连接？” | [[VPN]] | 建立受保护的逻辑通信通道 |
| “浏览器与具体 Web 服务之间怎样防窃听、篡改并认证服务器？” | [[TLS与HTTPS]] | 保护应用层通信 |
| “事后怎样追查谁在什么时候做了什么？” | 日志与审计 | 提供记录、追溯和责任认定依据 |

这也解释了为什么防火墙、IDS/IPS、VPN、TLS 不能互相替代：**它们站在通信链路的不同位置，解决的问题也不同。**

## 身份认证、访问控制和网络防护怎样接起来

这一段最容易在学习时产生“怎么又重复了”的感觉，所以只记三个问题：

1. **身份认证：你是谁？** —— 先确认主体身份。
2. **访问控制：你能做什么？** —— 身份确认后，再决定能访问哪些资源、执行哪些操作。
3. **DAC / MAC / RBAC：按什么规则决定权限？** —— 它们是访问控制的不同授权模型，不是另一套身份认证。

做到这里，只能说明“某个已识别主体理论上拥有什么权限”。真实请求还必须经过网络，因此下一步才进入：

**访问控制 → 网络边界控制（防火墙）→ 攻击检测/阻断（IDS/IPS）→ 不可信网络通信保护（VPN）→ 具体 Web 通信保护（TLS/HTTPS）。**

这就是身份与权限安全为什么会自然接到网络与通信安全，而不是两个互不相关的章节。

## 措施要对着风险选

教材归纳的措施方向包括访问控制、认证、完整性、审计和保密。它们与 [[信息安全基本目标]]、[[身份认证]]、[[访问控制基础]]、[[TLS与HTTPS]] 等卡相互连接。

做题时不要看到“安全”就默认选加密，也不要看到“网络”就默认选防火墙。例如：

- 防止未授权主体操作资源，重点是认证与访问控制；
- 控制哪些连接能跨越边界，重点看防火墙；
- 判断通信流量是否包含攻击行为，重点看 IDS/IPS；
- 防止传输内容被窃听或篡改，重点看 VPN/TLS 等通信保护；
- 要求事后可追溯，重点看日志与审计。

## 考试怎么做

1. **先贴标签**：题干描述的是漏洞、威胁、攻击、风险，还是安全措施？
2. **再找目标**：题目主要在保护机密性、完整性、可用性，还是在解决身份、权限、检测、追责？
3. **再看位置**：问题发生在主体权限、网络边界、流量检测、不可信网络，还是具体应用通信？
4. **最后选机制**：回到相应主事实源——[[身份认证]]、[[访问控制基础]]、[[防火墙]]、[[IDS与IPS]]、[[VPN]]、[[TLS与HTTPS]]。

## 自测
1. 系统存在未修补的远程服务缺陷，但尚未被利用，最准确称为什么？

> [!answer]- 第 1 题答案与解析
> **答案**：安全漏洞。
> **解析**：它是系统自身可被利用的弱点；真正利用它的行为还没有发生。

2. 攻击者已经利用这个远程服务缺陷执行恶意代码，这一步最准确称为什么？

> [!answer]- 第 2 题答案与解析
> **答案**：攻击。
> **解析**：威胁已经从“可能造成损害”变成了实际利用漏洞的行动。

3. 用户已经通过登录认证，但系统还要决定他能否删除某个文件，这一步主要属于什么？

> [!answer]- 第 3 题答案与解析
> **答案**：访问控制。
> **解析**：身份认证回答“你是谁”，访问控制继续回答“你能对资源做什么”；DAC、MAC、RBAC属于不同访问控制模型。

4. 题干要求事后能确认交易发生过并追查责任，首要安全措施方向是什么？

> [!answer]- 第 4 题答案与解析
> **答案**：审计。
> **解析**：审计提供记录、追溯和责任认定依据；加密主要保护机密性或通信内容，并不自动提供完整的责任追踪。
