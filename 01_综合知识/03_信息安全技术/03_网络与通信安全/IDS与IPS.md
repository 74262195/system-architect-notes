# IDS 与 IPS：发现攻击和在线阻断有什么区别

> [!summary]- 快速复习卡片（学完再看）
> **作用/定位**：IDS 重点是检测与告警，IPS 重点是检测后在线采取阻断/防御动作。
> **核心结论**：经典网络部署题常把 IDS 画成旁路、IPS 画成串联；这是典型架构，不是所有产品形态的唯一实现。
> **题干怎么认**：镜像/旁路/告警 → IDS；在线/阻断/串联 → IPS。
> **易错点**：IDS 不能绝对写成“只告警、永不联动”；IPS 也不是“检测到就一定正确阻断”，误报会影响业务。

## 它在信息安全主线中负责什么

防火墙按预先配置的策略过滤流量，但攻击可能伪装在看似允许的通信中，或通过尚未被规则覆盖的手法发生。**IDS/IPS 负责观察可疑行为：IDS 侧重发现、记录和告警，IPS 则把检测结果用于在线阻断或改变流量处理。**

| 定位 | IDS/IPS 在这里的答案 |
| --- | --- |
| 要防的风险 | 已绕过或未被边界规则直接识别的可疑攻击行为 |
| 主要交付 | 攻击检测、记录、告警，以及 IPS 的在线响应/阻断能力 |
| 依赖/边界 | 依赖检测规则、可见流量和误报处置；不能保证检测结果永远正确，也不替代访问策略 |
| 在主线中的位置 | 它补足防火墙的“检测与响应”环节；后续 VPN/TLS 处理跨网络传输时怎样保护通信内容 |

## 经典对比

| | IDS | IPS |
| --- | --- | --- |
| 核心目标 | 发现可疑活动并告警/记录 | 发现后在线阻断或改变流量处理 |
| 经典网络部署 | 旁路获取镜像流量 | 串联在流量路径中 |
| 主要权衡 | 可见性、误报、告警处理 | 误报可能直接影响可用性 |

除了网络型设备，还存在主机型 IDS/IPS 等实现，因此考试看到“旁路 vs 串联”时按经典网络场景作答即可，不要把它写成整个概念的唯一定义。

## 与防火墙的关系

防火墙偏策略控制与访问边界，IDS/IPS 偏攻击检测与响应；现实系统经常组合成纵深防御，而不是谁完全替代谁。

> [!question] 自测
> 1. 为什么 IPS 的误报比旁路 IDS 更容易直接影响业务？
>
> > [!answer]- 第 1 题答案与解析
> > **答案**：IPS 在线处理流量，误报可能导致正常连接被阻断或改变处理方式。
> > **解析**：IDS 经典旁路部署主要告警，通常不会直接中断流量。
> 2. “IDS = 事后发现”为什么也过于绝对？
>
> > [!answer]- 第 2 题答案与解析
> > **答案**：IDS 可对正在发生的可疑活动实时监控、记录和告警，只是通常不直接串联阻断。
> > **解析**：检测、告警、联动响应的边界要按具体部署和策略判断。
