# IDS 与 IPS：发现攻击和在线阻断有什么区别

> [!summary]- 快速复习卡片（学完再看）
> **作用/定位**：IDS 重点是检测与告警，IPS 重点是检测后在线采取阻断/防御动作。
> **核心结论**：经典网络部署题常把 IDS 画成旁路、IPS 画成串联；这是典型架构，不是所有产品形态的唯一实现。
> **题干怎么认**：镜像/旁路/告警 → IDS；在线/阻断/串联 → IPS。
> **易错点**：IDS 不能绝对写成“只告警、永不联动”；IPS 也不是“检测到就一定正确阻断”，误报会影响业务。

## 流量已经获准通过，怎样发现里面藏着攻击

防火墙可能允许用户访问网站的 443 端口，但“允许访问网站”不代表每个请求都安全：攻击者也能把恶意内容装进看似正常的网页请求里。

**IDS 像报警员，发现可疑行为后记录并告警；IPS 还站在流量必经之路上，可以立即阻断。**两者都要先看得到相关流量，并依靠检测规则或行为判断，因此可能漏报，也可能把正常请求误判为攻击。它们补上防火墙放行后的检测环节；VPN 和 TLS 则继续解决通信经过不可信网络时如何防窃听和篡改。

## 经典对比

| | IDS | IPS |
| --- | --- | --- |
| 核心目标 | 发现可疑活动并告警/记录 | 发现后在线阻断或改变流量处理 |
| 经典网络部署 | 旁路获取镜像流量 | 串联在流量路径中 |
| 主要权衡 | 可见性、误报、告警处理 | 误报可能直接影响可用性 |

除了网络型设备，还存在主机型 IDS/IPS 等实现，因此考试看到“旁路 vs 串联”时按经典网络场景作答即可，不要把它写成整个概念的唯一定义。

## 一次可疑请求怎样变成告警或阻断

假设某台外部主机在短时间内连续尝试多个管理接口。IDS/IPS 不能只凭“这台主机看起来可疑”下结论，而要把观察到的通信变成可检查的线索，再按规则或正常行为基线判断。

1. **获得流量或主机行为**：网络型设备从镜像流量或串联链路获得通信；主机型实现则可观察进程、文件或系统行为。
2. **提取可判断的线索**：从中取得来源、目标、访问频率、报文特征或行为序列等信息。
3. **与规则或基线比较**：特征检测检查是否命中已知攻击规则；异常检测检查行为是否明显偏离正常基线。两种判断都可能出现误报或漏报。
4. **形成检测结果并告警**：系统记录时间、对象和命中依据，把可疑事件交给安全人员或其他系统处理。经典旁路 IDS 的核心动作通常到这里。
5. **IPS 在线采取动作**：串联的 IPS 可以按策略丢弃报文、阻断连接或限制流量。它必须及时作出决定，否则正常通信也会被拖慢。
6. **复核误报并调整**：若正常的批量运维被误判为扫描，人员需要恢复业务，并调整规则、阈值或白名单；否则 IPS 可能持续误伤正常请求。

这条闭环说明了两者真正的差别：**IDS 和 IPS 都需要先看见行为、提取线索并作出检测判断；IPS 多承担在线执行动作，因此误判更容易直接影响业务可用性。**

## 与防火墙的关系

防火墙偏策略控制与访问边界，IDS/IPS 偏攻击检测与响应；现实系统经常组合成纵深防御，而不是谁完全替代谁。

## 自测

1. 为什么 IPS 的误报比旁路 IDS 更容易直接影响业务？

> [!answer]- 第 1 题答案与解析
> **答案**：IPS 在线处理流量，误报可能导致正常连接被阻断或改变处理方式。
> **解析**：IDS 经典旁路部署主要告警，通常不会直接中断流量。

2. “IDS = 事后发现”为什么也过于绝对？

> [!answer]- 第 2 题答案与解析
> **答案**：IDS 可对正在发生的可疑活动实时监控、记录和告警，只是通常不直接串联阻断。
> **解析**：检测、告警、联动响应的边界要按具体部署和策略判断。

3. IDS/IPS 从看到流量到作出响应，要经过哪些关键步骤？

> [!answer]- 第 3 题答案与解析
> **答案**：获得流量或行为，提取线索，与规则或基线比较，形成检测结果并告警；IPS 还可在线执行阻断，之后需要复核误报并调整策略。
> **解析**：只背“IDS 告警、IPS 阻断”会漏掉共同的检测判断过程和误报处置边界。
