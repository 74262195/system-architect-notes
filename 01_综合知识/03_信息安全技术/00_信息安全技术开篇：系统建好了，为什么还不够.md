# 信息安全技术开篇：系统建好了，为什么还不够

> [!summary] 这一章先别急着背算法和设备
> 前面学习信息系统、计算机和网络时，我们一直在解决“**系统怎样把业务跑起来**”。信息安全接着追问的是另一件事：**系统已经能运行了，如果账号被冒用、材料被偷看、审批结果被篡改、服务器被打到不可用，这个系统还能算真正可用吗？**
>
> 先记住本章总链：**资产 → 威胁 → 脆弱性 → 攻击 → 风险 → 安全目标 → 安全机制 → 剩余风险**。

## 先承接前面的知识：能运行，不等于能安全运行

假设我们已经建好了一个**网上办事系统**。群众可以注册账号、登录、提交材料，工作人员可以审核，系统把材料和审批结果保存到数据库，服务器和网络负责把这些功能提供出去。

从“信息系统建设”的角度看，它已经能工作；但从安全角度，还要继续问：

| 系统里的东西 | 正常情况下做什么 | 一旦出安全问题会怎样 |
| --- | --- | --- |
| 用户与账号 | 登录并发起业务 | 账号被盗后，攻击者冒充本人操作 |
| 申请材料 | 上传、传输、保存 | 被无关人员偷看，隐私泄露 |
| 审批结果 | 记录最终办理结果 | 被偷偷修改后，业务事实失真 |
| 数据库 | 保存业务数据 | 被越权查询、篡改或删除 |
| 服务器 | 持续提供业务 | 被攻击到宕机，合法用户无法办理 |
| 网络 | 在用户、服务器之间传输数据 | 被窃听、篡改或冒充通信对象 |

所以，**“功能实现了”只说明系统会做事；“安全”要求它在面对错误、滥用和攻击时，仍能保护重要东西并把风险控制在可接受范围内。**

## 安全问题到底怎样产生

先不要背 CIA，也不要先背防火墙。沿着网上办事系统追一遍问题：

1. 系统里有值得保护的东西，例如账号、材料、审批结果、数据库和服务能力，这些叫**资产**。
2. 外部攻击者、恶意软件、内部滥用、设备故障等都有可能伤害资产，这是**威胁**。
3. 系统本身可能存在弱口令、越权配置、未修补漏洞、输入校验错误等弱点，这是**脆弱性**。
4. 威胁通过具体动作去利用脆弱性，例如撞库登录、利用漏洞、注入恶意输入，这就是**攻击**。
5. 攻击一旦成功，资产可能泄露、被改、不可用；结合发生可能性和影响，就形成需要处理的**风险**。
6. 面对风险，先要说清“希望保护成什么样”，这就是**安全目标**。
7. 为实现目标，再选择加密、认证、访问控制、防火墙、审计等**安全机制 / 安全控制**。
8. 控制措施只能降低风险，通常不能把风险绝对清零，因此还会留下**剩余风险**，需要接受、继续降低或持续监控。

> [!important] 这条链是“思考顺序”，不是数学公式
> **资产 → 威胁 → 脆弱性 → 攻击 → 风险 → 安全目标 → 安全机制 → 剩余风险**
>
> 它真正想让你养成的习惯是：先问**保护什么**，再问**会被怎样伤害、哪里有弱点**，然后才决定**要达到什么安全状态、用什么控制**。

### 用一个例子把整条链走完

网上办事系统的“审批结果”是一项资产。假设后台账号只使用弱口令，这是脆弱性；攻击者是威胁来源；攻击者通过撞库获得账号并修改审批结果，是具体攻击。这样就形成“审批结果被未授权篡改”的风险。

此时我们才会提出目标：审批结果不能被未授权修改，操作还应该可追查。对应会用到强认证、访问控制、完整性保护和日志审计等机制。但即使部署这些控制，也仍可能出现凭据泄露、新漏洞或内部滥用，所以系统还存在剩余风险。

## CIA 等安全目标是从哪里来的

安全目标不是凭空背出来的，而是从“资产可能受到什么伤害”反推出来：

- 申请材料被不该看的人看到 → 需要**机密性**；
- 审批结果被偷偷修改 → 需要**完整性**；
- 网上办事系统被打到无法使用 → 需要**可用性**；
- 信息流向和系统行为必须受控 → 需要**可控性**；
- 出事后要查清谁在什么时候做了什么 → 需要**可审查性**。

因此下一站不是先背产品名，而是进入 [[信息安全基本目标]]，先把“安全”翻译成能够判断的目标语言。

## 为什么目标之后还要做风险评估

即使知道了“要保密、要完整、要可用”，我们仍然不知道：**具体保护哪些对象？哪些资产正在面对什么威胁？系统哪里有脆弱点？哪个风险应该优先处理？**

所以会先用 [[信息安全范围与存储安全]] 把目标落到设备、数据、内容和行为等保护对象，再进入 [[安全风险评估]]，把资产、威胁、脆弱性、影响和控制优先级真正连起来。

## 为什么后面会连续出现这么多技术

风险评估以后，你会发现安全问题不是一个技术能包办的。仍然用网上办事系统看：

| 现在暴露的问题 | 为什么前一层还不够 | 接下来学习什么 |
| --- | --- | --- |
| 材料可能被偷看、篡改，来源可能被伪造 | 只知道风险，还没有保护数据本身的机制 | [[对称加密]]、[[非对称加密]]、[[哈希算法]]、[[数字签名]]、[[数字证书与PKI]] |
| 数据已经加密，但登录的人可能是假冒的 | “数据加密了”不能回答“对方到底是谁” | [[身份认证]] |
| 已经确认身份，但这个人未必有权看所有数据 | “知道你是谁”不等于“你什么都能做” | [[访问控制基础]] 与 DAC / MAC / RBAC |
| 身份和权限有了，但请求还要穿过不可信网络 | 安全问题也发生在通信路径和网络边界 | [[防火墙]]、[[IDS与IPS]]、[[VPN]]、[[TLS与HTTPS]] |
| 网络通道安全了，应用代码仍可能把恶意输入当成指令 | 边界安全不等于应用自身没有漏洞 | [[SQL注入]]、[[XSS跨站脚本]]、[[CSRF跨站请求伪造]] 等 |
| 每个点都有安全产品，但措施可能互相脱节、责任不清 | 零散控制不等于完整安全体系 | [[信息系统安全为什么需要治理]]、[[安全架构设计]]、[[纵深防御]]、[[等级保护2.0]] 等 |

这就是整章真正的递进关系：

> **保护数据 → 管住身份与权限 → 保护通信路径 → 防应用攻击 → 把零散控制组成安全体系。**

## 第一次学习时只抓这一张地图

第一次进入本章，不要求一次记住所有算法、协议和产品。先保证能解释七个“为什么”：

1. 为什么系统已经能运行，还要学信息安全？
2. 资产、威胁、脆弱性、攻击、风险是什么关系？
3. 为什么风险之后要先定义安全目标？
4. 为什么有密码学？
5. 为什么加密以后还要认证和访问控制？
6. 为什么网络安全以后还有应用安全？
7. 为什么最后还要做安全架构与治理？

能回答这七问，再进入具体卡片，后面的名词就会有“挂钩的位置”。
