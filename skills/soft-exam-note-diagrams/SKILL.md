# 软考笔记画图 Skill

这个 Skill 只负责**调用并执行仓库最新画图规范**，不维护第二套独立视觉标准。

目标仓库：

- GitHub：`74262195/system-architect-notes`
- 默认分支：`main`

## 一、运行前必须读取 GitHub 最新规范

每次只要任务涉及以下任一内容，就先读取 **latest `main`**，不能使用上一次会话记忆中的旧版本：

- 新增 Mermaid；
- 修复 Mermaid；
- 新增/修改 Excalidraw；
- 章节知识看板；
- 原子笔记教学插图；
- 流程图、结构图、映射图、状态图、层级图；
- 把纯文本/ASCII 伪图改成正式图。

### 永远必读

1. `AGENTS.md`
2. `prompts/00-全局写作规范.md`
3. `prompts/40-Mermaid与Obsidian样式修复.md`

### 按任务追加读取

- **章节 Excalidraw 导航看板**  
  追加读取：`prompts/30-Excalidraw章节知识看板.md`

- **在原子考点卡中新增或大幅改教学图**  
  追加读取：`prompts/10-原子考点卡生成.md`  
  并实际读取目标笔记正文；需要理解叙事上下文时，再读取该提示词要求的黄金样例。

- **整章检查、拆目录、重构后同步画图**  
  追加读取：`prompts/20-章节检查与重构.md`

- **教材驱动补全后需要重画机制图**  
  追加读取：`prompts/65-教材证据与笔记校验.md`

### 读取失败时

只要上述“本次任务必读”的任一 GitHub 文件无法读取：

- 不得凭 Skill 内的旧规则继续画图；
- 不得自行猜测仓库当前规范；
- 明确报告缺少哪一个必读文件；
- 在恢复读取之前，不提交新的图形改动。

这样保证 **GitHub 提示词始终优先于 Skill 自身的历史版本**。

## 二、规则优先级

发生冲突时按以下优先级执行：

1. 当前系统/产品安全要求；
2. 用户当前明确要求；
3. 最新 `main` 中的 `AGENTS.md`；
4. 本次任务对应的最新 `prompts/*.md`；
5. 目标笔记、章节索引和相邻笔记的真实结构；
6. 本 Skill 的调度说明。

本 Skill 不得用自己的默认习惯覆盖仓库提示词。

## 三、先读目标，再决定要不要画

画图前至少确认：

1. 这张图要回答的**唯一主问题**是什么；
2. 紧邻正文是否已经用自然语言或表格讲清；
3. 图是否真正降低“空间、映射、层级、状态或流转”的理解成本；
4. 是否会与正文/表格重复；
5. 是否把多个独立考点硬塞进一张图。

如果一张图需要回答多个独立问题，按仓库“原子性”原则拆图。

**一图一主要问题**与**一卡一主问题**保持一致。

## 四、图形工具由 GitHub 提示词路由

不要在 Skill 中固定“优先 Mermaid”或“优先 Excalidraw”。

必须根据最新：

- `prompts/40-Mermaid与Obsidian样式修复.md`
- `AGENTS.md` 的“可视化工具自动路由”

现场判断：

- 不需要图 → 不画；
- 简单对比/分类 → 表格；
- 公式/计算 → LaTeX；
- 简单流程、映射、状态关系 → 按最新规则使用 Mermaid；
- 中大型复杂结构、精确布局 → 按最新规则使用 Excalidraw；
- 章节固定导航看板 → 按最新 `prompts/30-Excalidraw章节知识看板.md`。

**禁止用 `text` / `plaintext` / 普通代码块 / ASCII / Unicode 字符拼教学图。**

## 五、Excalidraw 必须遵守仓库路径和链接规则

生成 Excalidraw 前必须确认它属于哪一类：

### 原子笔记教学插图

按最新仓库规范保存到：

`05_画图素材/Excalidraw/原子笔记插图/`

保留可编辑 `.excalidraw` 源文件；若仓库当前规范要求 SVG，则同步导出并嵌入正文。

### 章节导航看板

严格读取 `prompts/30-Excalidraw章节知识看板.md` 后执行。

不得把教学插图混入章节导航看板目录，也不得把章节看板当知识事实源。

## 六、修改已有图时先做“重选工具”判断

用户要求“修图”不等于必须保留原工具。

先依据最新 `prompts/40-Mermaid与Obsidian样式修复.md` 判断：

- 图重复 → 删除；
- 对比更适合表格 → 改表格；
- Mermaid 太密 → 拆图或改 Excalidraw；
- Excalidraw 过度复杂 → 拆成多个主要问题；
- 纯文本伪图 → 必须按仓库路由重构。

不要为了保住旧图而持续堆 CSS 或缩小字号。

## 七、生成后必须验收

### Mermaid / 正文图

按最新 GitHub 规范实际检查：

- 正文宽度内是否可读；
- 是否需要横向滚动；
- 字号是否过小；
- 箭头是否连接真实节点；
- 阅读顺序是否正确；
- 是否与正文/表格重复；
- 是否存在 `text/plaintext` 伪图。

### Excalidraw 导航看板

按最新 `prompts/30-Excalidraw章节知识看板.md` 做 JSON 验收，至少核对仓库当前要求的：

- 链接元素数量；
- 唯一目标数量；
- text 与 shape 的 link 分布；
- 重复链接；
- line/arrow 数量；
- `viewModeEnabled`；
- 每个 target 是否指向真实文件。

不要只看 JSON 能解析就算通过。

## 八、GitHub 写入规则

只要任务要求修改仓库：

1. 写入前再次确认 latest `main`，避免覆盖并发修改；
2. 只改用户要求范围内的笔记和图；
3. 不 force push；
4. 同一逻辑任务尽量形成清晰提交；
5. 按 `AGENTS.md` 直接交付到 `main`；
6. 能运行时执行仓库要求的校验；不能运行必须明确说明，不能伪称通过。

## 九、Skill 的设计原则

这个 Skill **故意不复制 Mermaid 节点数、卡片宽度、颜色、链接绑定等详细数值规则**。

原因是这些规则已经存在 GitHub 提示词中，而且还会继续演进。

因此本 Skill 的职责只有三个：

1. 找到本次任务应该读哪些 GitHub 提示词；
2. 强制读取 latest `main` 后再画；
3. 按 GitHub 当前规则完成生成、修复和验收。

最终目标：

> **只维护 GitHub 一套规范，Skill 每次运行实时跟随，不产生第二套会过期的画图规则。**
